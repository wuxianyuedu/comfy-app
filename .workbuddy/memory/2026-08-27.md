**方案与落地**

   - `_monitor_headless` 阻塞到 Tauri 主窗口出现后退出生成 `ready`；保留状态文件 30s 供启动页读取。
   - 设置 `COMFYAPP_PROJECT_ROOT` 环境变量给 Rust 侧定位状态文件。
   - 保留 `--splash` 旧窗口模式并修复：窗口 520×210、title 18pt、消息区折行、去掉 `WS_EX_NOACTIVATE` 让 ESC/关闭按钮可聚焦。
2. `scripts/dev-launcher.ps1`
   - Tauri 分支增加 `http://127.0.0.1:3000` 端口探测，就绪后输出「服务器已就绪」，让进度可走到 85%。
3. `src-tauri/tauri.conf.json`
   - `windows[0].url` 改为 `"splash.html"`：Tauri 窗口一出现即加载启动页。
4. `public/splash.html`（新建）
   - 暗色极光风格内嵌启动页：品牌、阶段、进度条、日志消息、已用时间。

5. `src-tauri/src/lib.rs`
   - 新增 `AppState` 保存 `project_root` / `app_url`。
   - 新增 `get_launch_status` / `navigate_to_app` commands。
   - 开发模式默认 `app_url = http://localhost:3000/workspace`；生产模式由 sidecar 端口更新。
6. `scripts/build-desktop.mjs`
   - 生产构建时将 `public/splash.html` 复制到 `src-tauri/static/splash.html`，并生成同内容 `index.html` fallback。

## 应用日志：长行换行 + 过滤 React Query 内部日志刷屏

**用户问题**
- 超长日志被单行截断，看不全；希望换行展开。
- 打开「工作流库」界面时，日志面板被 `workflow.list` / `workflowModel.list` 等 query 日志不断刷屏。

**根因**
- 日志面板通过 `LogProvider` 劫持 `console.*` 捕获所有前端日志。React Query 在 tRPC 组件每次重渲染时，会向 console 输出 `%c << query #488 %cworkflowModel.list` 形式的内部查询日志，被一并捕获后淹没业务日志。
- 旧 `LogPanel` 用固定 22px 行高 + 虚拟化渲染，超长消息 `truncate` 截断。

**方案与落地**
1. `src/components/studio/log-provider.tsx`
   - 新增 `isReactQueryLog`：正则 `/^\s*%c\s*(<<|>>)\s*query\s+#\d+/i` 匹配 React Query 内部日志，在 `addEntry` 前 `return` 直接丢弃（仅过滤捕获，不影响 console 正常输出）。
2. `src/components/studio/LogPanel.tsx`
   - 移除固定行高虚拟化（`ROW_HEIGHT`/`OVERSCAN`/绝对定位切片），改为 `flex flex-col` 直接渲染全部日志（单次运行已清历史，量级可控）。
   - `LogRow` 支持 `wrap` 开关：开启时 `break-words whitespace-pre-wrap` 自动换行；关闭时 `truncate`。
   - 工具栏新增换行/折叠切换按钮（默认换行开启）。

**验证**
- `tsc --noEmit` 与 `eslint` 均通过（其余报错在 `HistoryList.tsx`/`CanvasNode.tsx`，属已有 WIP，非本次改动）。
- 提交 `4ad8964`。

## 启动体验再优化：预编译 Tauri 壳实现窗口秒出

**用户问题**
- 双击 `start-tauri.exe` 后仍需要 ~33 秒才出现 Tauri 窗口（log: 09:54:02.650 → 09:54:35.706）。
- 需要 Tauri 壳秒级显示。

**根因**
- 默认走 `dev-launcher.ps1 -Tauri` → `pnpm tauri dev`，每次启动都要先编译 Rust、再跑 `beforeDevCommand`（pnpm dev），最后才创建 WebView 窗口。
- 启动页（splash.html）只能等 Tauri 窗口创建后才能显示，所以被 `tauri dev` 的编译耗时卡住。

**方案与落地**
1. `src-tauri/src/lib.rs`
   - `app_url` 改为优先从 `COMFYAPP_DEV_URL` 环境变量读取（默认 `http://localhost:3000/workspace`），便于 launcher 注入目标地址。
2. `scripts/dev-launcher.ps1`
   - 新增 `-Prebuilt` 开关：先启动 `next dev`，再**立即**启动预编译的 Tauri 壳 `src-tauri/target/debug/app.exe`。
   - 预编译壳与 dev server 绑定到同一 Job Object，关闭窗口一键清理整棵进程树。
   - 保留 `-Tauri` 旧模式用于需要 Rust 热重载的开发调试。
3. `scripts/start_tauri_launcher.py`
   - 默认改为 `-Prebuilt` 模式；新增 `--tauri-dev` 选项走旧慢模式。
   - 更新启动阶段映射：新增 `tauri-shell-started`（进度 0.58）。
   - 设置 `COMFYAPP_DEV_URL` 环境变量给预编译壳。
4. `public/splash.html`
   - 阶段标签增加 `tauri-shell-started: '桌面壳已启动'`。
5. 预编译壳
   - `cargo build` 重新生成 `src-tauri/target/debug/app.exe`（已包含 `COMFYAPP_DEV_URL` 读取逻辑）。

**构建与部署**
- `cargo build` 通过（2.14s，仅未使用 `set_app_url` 的 warning）。
- PyInstaller 重新打包 `start-tauri.exe`（8.67MB），覆盖根目录旧 exe。
- 清理 `build-prebuilt/` 临时目录。
- 提交 `5673fa7`。

**预期效果**
- 双击 `start-tauri.exe` 后，预编译 Tauri 壳几乎立即弹出（秒级），显示内嵌启动页。
- 启动页随后展示 dev server 启动进度；服务就绪后自动导航到 `/workspace`。
- 如需 Rust 热重载，可命令行运行 `start-tauri.exe --tauri-dev`。
