## 应用日志：长行换行 + 过滤 React Query 内部日志刷屏

**用户问题**
- 超长日志被单行截断，看不全；希望换行展开。
- 打开「工作流库」界面时，日志面板被 `workflow.list` / `workflowModel.list` 等 query 日志不断刷屏。

**根因**
- 日志面板通过 `LogProvider` 劫持 `console.*` 捕获所有前端日志。React Query 在 tRPC 组件每次重渲染时，会向 console 输出 `%c << query #488 %cworkflowModel.list` 形式的内部查询日志，被一并捕获后淹没业务日志。
- 旧 `LogPanel` 用固定 22px 行高 + 虚拟化渲染，超长消息 `truncate` 截断。

**方案与落地**
1. `src/components/studio/log-provider.tsx`
   - 新增 `isReactQueryLog`：正则 `/^\s*%c\s*(<<|>>)\s*query\s+#\d+/i` 匹配 React Query 内部日志，在 `addEntry` 前 `return` 直接丢弃（仅过滤捕获，不影响 console 正常输出）。
2. `src/components/studio/LogPanel.tsx`
   - 移除固定行高虚拟化（`ROW_HEIGHT`/`OVERSCAN`/绝对定位切片），改为 `flex flex-col` 直接渲染全部日志（单次运行已清历史，量级可控）。
   - `LogRow` 支持 `wrap` 开关：开启时 `break-words whitespace-pre-wrap` 自动换行；关闭时 `truncate`。
   - 工具栏新增换行/折叠切换按钮（默认换行开启）。

**验证**
- `tsc --noEmit` 与 `eslint` 均通过（其余报错在 `HistoryList.tsx`/`CanvasNode.tsx`，属已有 WIP，非本次改动）。

## 启动失败：dev-launcher 提前退出（exit code 1）

**用户问题**
- 双击 `start-tauri.exe` 后，`log/start-tauri-launcher.log` 报 `dev-launcher process exited early with code 1`；`log/dev-launcher.log` 未被更新，仍保留上一次运行的旧内容。

**根因**
- 上一次预编译模式运行后，PowerShell 脚本 `dev-launcher.ps1` 仍在后台运行（PID 106760）并持有 `Start-Transcript` 对 `log/dev-launcher.log` 的句柄。
- 新实例启动时执行 `Set-Content -Path $currentLog -Value "" -Encoding utf8 -Force`，因文件被占用而抛出终止错误，`$ErrorActionPreference = "Stop"` 使脚本立即退出，退出码 1。
- 根本诱因：预编译模式下脚本末尾 `$p = $devProc` 并 `$p.WaitForExit()`，只等待 dev server；用户关闭 Tauri 窗口后 dev server 不会自动退出，导致 PowerShell 脚本挂起并持续锁住日志文件。

**方案与落地**
1. `scripts/dev-launcher.ps1`
   - 新增 `Clear-CurrentLog`：若 `dev-launcher.log` 被占用，先尝试 `Move-Item` 重命名为 `dev-launcher-locked-YYYYMMDD_HHMMSS.log`，再创建新文件；若重命名也失败，回退到 `dev-launcher-<PID>.log`，避免永远起不来。
   - 将本次实际日志路径写入 `log/dev-launcher-current.txt` sentinel，供启动器和应用内面板定位。
   - 修复预编译模式生命周期：改为等待 Tauri 或 dev server 任一退出，退出后主动终止另一方，最后释放 Job Object。关闭 Tauri 窗口即结束全部进程与日志句柄。
2. `scripts/start_tauri_launcher.py`
   - 新增 `_resolve_dev_log_path`：优先读取 `log/dev-launcher-current.txt` sentinel，回退到 `log/dev-launcher.log`。
   - `_start_log_tailer` / `_monitor_headless` 启动及循环中跟随 sentinel，支持回退文件名切换。
   - `launch_dev_server` 将 PowerShell stdout/stderr 重定向到 `log/dev-launcher-stdout.log` / `log/dev-launcher-stderr.log`，便于排查「提前退出但无日志」的情况。
3. `src/app/api/logs/current/route.ts`
   - `GET` 接口通过 `log/dev-launcher-current.txt` sentinel 解析当前实际日志文件，回退到 `log/dev-launcher.log`。
4. 清理现场
   - 终止 stale 进程 PID 106760（pwsh，持有日志锁）与 PID 102668（残留 cmd 包装器）。
   - PyInstaller 重新打包 `start-tauri.exe` 并覆盖根目录旧 exe。

**验证**
- 用 Python 源码直接运行 `scripts/start_tauri_launcher.py`，新实例成功启动：端口检查 → 启动 dev server → 启动预编译 Tauri 壳 → Tauri 窗口出现 → launcher 退出。
- 关闭 Tauri 窗口后，PowerShell 脚本应随 Tauri 退出并释放 `dev-launcher.log`。
