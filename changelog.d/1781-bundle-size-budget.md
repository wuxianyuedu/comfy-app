## Added

- **bundle 体积预算：client chunk 的 gzip 总量 + 文件数棘轮**（ISSUE #1781，从 #1777「性能优化」清单里分出来的真缺口）。清单原稿写「在 CI 里加 bundle size budget」——**方向对，但本仓没有 CI**（`.cnb.yml` 随 #623 删除），所以落点不是「阈值定多少」，而是「挂在哪、谁来跑」。选定形态 **B + C**：`pnpm check:bundle` 是按需入口，同一脚本也挂在 `pnpm build` 收尾（构建已经发生、不额外买成本）。**不进 pre-commit**：`next build` 实测 26–33s（冷 / 热一样），半分钟 × 每次提交仍然不值，还会推高 `--no-verify` 的动机。
  - 判据 `scripts/check-bundle-budget.cjs`，基线 `scripts/.bundle-budget-baseline.json`（头部记 raw / gzip / 文件数三个**实测初值**）。测量面是 `.next/static/chunks` 下所有 `.js`（Turbopack 默认链，与 `pnpm analyze` 的强制 `--webpack` 别混着比）。
  - **抖动实测**：同环境连续两次构建、乃至 `rm -rf .next` 全冷构建，215 个 chunk 的**文件名与 sha256 全部一致**（新增 0 / 消失 0）—— Turbopack 的 chunk 名**就是内容哈希**。
  - **口径订正（第二版）**：第一版按 **basename** 逐文件对账，把「同内容换名」当成变化，于是在**基线过期**时产出一串无法复核的行（源码动过之后，旧名字既不在新产物里、又没留下可对照的内容）。现在判定只看 **gzip 与文件数两个总量**；逐文件账降级为**诊断**、按 `sha256` 对齐（同内容换名不计变化）；`raw` 一并量、一并打，但**不判**（gzip 才是用户要下载的，两者会因可压缩冗余分叉）。
  - **不是空转**：把基线掏空 4 KB 即红；新增一个 chunk 让文件数上升也红（文件数比总量更敏感 —— 实测 shiki 探针 gzip +49.6% 的同一次文件数 +193）。
  - **例外流程**：确认体积值得，就在 PR 里贴 before/after 两档读数 + 理由，评审确认后带 `--allow-increase` 重跑 `--update` —— 不带它 `--update` **拒绝抬高**基线（同 `check-overlay-z.cjs` 那批棘轮）。

## Fixed

- **bundle 体积预算的逐文件对账口径会把「同内容换名」记成一笔变化**（ISSUE #1781 第二轮实测）。第一版按 basename 对齐、并断言「唯一的抖动是 `BUILD_ID` manifest」——实测两头都不成立：`chunks/` 里也有名字随构建变的内容，而更根本的是**名字就是内容哈希**，按名字对账在基线过期时只会产出一串无法复核的行。判定改为只比 `gzip` 与 `文件数`，诊断改按 `sha256` 对齐（`raw` 一并量、不判）。

## Fixed

- **`pnpm build` 收尾恒红的那一格：基线过期时判红不说是哪一版源码，读者只会往「抖动 / 量错了」猜**（ISSUE #1781）。现场：`086e16a0` 落的基线是**诚实读数**，之后 `50c1845f`（模型库首屏骨架屏）改了 17 个组件文件，体积真涨 **1074 字节 raw / 493 字节 gzip** —— 而判红输出只说「涨了 493 字节 gzip」，于是「这涨是不是那次改动换来的」这个决定下一步（压回去 vs 认账）的问题没有任何数据可答。
  - 基线新增 `baselineRev`（与 `check-file-structure.cjs` 同口径，§12.13.3）：`--update` 记下当时 HEAD，判红时先归因 —— `其后本检出上有 N 次提交` / `就是本检出的 HEAD` / `取不到`（旧格式基线、不在 git 检出、修订号不可达都算，**说清取不到而不拿猜测顶替**）。
  - 基线本身按 `--allow-increase --update` 重落（这是**认账**动作，不是放水）：`gzip 2279817 → 2280310`（+493 B）、`raw 9773025 → 9774099`（+1074 B）、文件数 215 不变。同时它从 `086e16a0` 的第一版格式（`entries` 是对象、无指纹）升到当前格式（数组 + `sha256`），逐文件诊断那一段随之恢复。

## Tests

- `tests/check-bundle-budget.test.ts` 新增 3 条（共 14 条），钉的是「基线过期」这一格的三种形态：**取不到修订号时必须明说取不到**（无 git 的临时工作区）/ **其后有 N 次提交时点名 N 与「取自基线之后的源码」** / **基线就是 HEAD 时说清上涨来自未提交改动**（后两条跑在真 git 检出的夹具上，`gate-repo` 的 `setup` 里 `git init` + 一次 seed 提交）。变异核过：删掉整段归因 → 3 条全红；`--update` 只写 `baselineRev: null` → 后两条红（「记了但没记全」这一档不许静默）。
