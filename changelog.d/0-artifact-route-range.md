## Added

- **产物读取口支持 `Range`**（台账 A13 残留的第二条，本批关）。产物根从 `public/generated`
  搬到 `generated/` 之后，所有字节都只走 `/api/generated/[...path]` 这一条 handler ——
  归属闸补上了，但 `Range` 顺手掉了：静态文件服务时代浏览器拖进度条是白送的分段读取，
  折进 handler 后一句 `fs.readFile` 只会把整份文件读进内存再整个 200 回出去。
  表现不是报错，是**拖一下进度条 = 重下一份成片**（视频与大图都吃这一条）。
  - 形状判据收成一处：新增 `src/server/lib/range-request.ts`（RFC 7233 的单档字节范围），
    三种结论写在返回形状里 —— `full`（没发 / 不认识 / `first > last` 这种语法无效，
    **忽略并回整份，不判成 416**）、`partial`（合法一档，已按文件长度裁剪）、
    `unsatisfiable`（语法对而这份东西满足不了，才是 416）。端点只负责把它翻成状态码。
  - 读法一起换：`fs.open` + `read(buf, 0, length, start)` **只读要的那一段**，
    不是整份读进来再切 —— 否则这条支持本身是空的。
  - `Accept-Ranges: bytes` 三种响应（200 / 206 / 416）都在场；416 配
    `Content-Range: bytes */<总长>`；短读（同名产物在请求内被重新生成、文件变短）时
    把 `Content-Range` 与 body **一起收窄** —— 承诺 6 个字节而只给 2 个，
    客户端会照着承诺拼出一个坏产物，比回 404 更糟；一个字节都没读到则按不存在处理。

## Tests

- `src/server/lib/range-request.test.ts`（18 条，四项门槛按实测登记 100）：三种结论各自的形状、
  后缀形式 `bytes=-n`、终点越界裁剪、开放终点、`bytes=-0` 与 0 字节文件、
  超出安全整数的数字三个位置各自判「不认识」、以及一条**顺序**判据 ——
  `bytes=500-100` 在 10 字节的文件上仍然算语法无效（回整份），不能因为起点已越过
  文件末尾就被后面的 size 判定抢走、变成 416。
- `src/app/api/generated/[...path]/route.test.ts` 整份重写（32 条）：
  · 闸门顺序那组全部改成断 `stat`/`open` 都没被调（旧的断 `readFile` 没被调，
  换读法之后会一路「假绿」—— 断言的对象已经不存在了）；
  · 新增一组 `it.each`：**带 `Range` 也不许绕过会话与归属闸**（无会话 401、
  别人的 404、三种 Range 形状都打一遍），防止「读哪一段」那层长出第二套权限逻辑；
  · 目录那一档从「靠 `readFile` 抛 EISDIR」改成断 `isFile()` 就判掉、**不去 open**；
  · 句柄必须关（正常路径与抛错路径各一条）—— Windows 上漏关会把产物自己锁住，
  同名重生成当场失败；
  · 短读两条（分段与整份各一条）断 body 与 `Content-Range` 一致。
- 变异核过三条：摘掉 `first > last` 的优先判定 → 恰好那条顺序用例红；
  后缀形式的 `Math.max(size - last, 0)` 去掉夹零 → 恰好后缀那条红；
  把 `read(..., start)` 的起点写死成 0 → 恰好四条「只读那一段」的用例红（其余全绿）。

## Docs

- 台账 A13 的残留清单里那条 `Range` 勾销（含实测数据与「为什么不是回归而是搬家时掉下来的」）。
- 规范 §11.2.1 新增一条口径：**把静态通道折进 handler 那天，要逐条清点静态服务白送的能力**
  （`Accept-Ranges` / `Range` / 条件请求 / `HEAD` / 编码）。这类缺陷不会由任何一次
  「写坏代码」产生 —— 只是新代码没继承旧能力，所以自己的 diff 照不出它。

## 实测（本机 `next dev` 起服务，打一份真实产物）

目标 `/api/generated/<taskId>/img_0.png`，`size = 1 154 930` 字节：

| 请求头                      | 状态    | `Content-Range`                 | body 字节 |
| --------------------------- | ------- | ------------------------------- | --------- |
| 无 `Range`                  | 200     | —                               | 1 154 930 |
| `bytes=0-99`                | **206** | `bytes 0-99/1154930`            | 100       |
| `bytes=200-`                | **206** | `bytes 200-1154929/1154930`     | 1 154 730 |
| `bytes=-50`                 | **206** | `bytes 1154880-1154929/1154930` | 50        |
| `bytes=99999999-`           | **416** | `bytes */1154930`               | 0         |
| `bytes=0-1,2-3`（多档）     | 200     | —                               | 全量      |
| `bytes=500-100`（语法无效） | 200     | —                               | 全量      |

`Accept-Ranges: bytes` 与 `Cache-Control: private, max-age=31536000, immutable` 各档都在场
（`private` 那条是 A13 的既有口径：响应取决于「你是谁」，标 `public` 等于让共享缓存代读）。
