## Changed

- **项目内八个文档型视图收进统一容器，宽度上限收进三档令牌。** 原先「外层滚动 + 居中列 + 宽度上限」这一串形状在八个视图里各写一遍，三个宽度数（960 / 1100 / 1200）散在三处，改一处必然漏一处。
  - 新增 `src/components/studio/ViewContainer.tsx`：`DocumentFrame`（文档型 —— 整屏一条纵向滚动条 + 居中窄栏）与 `WorkspaceFrame`（工作区型 —— 吃满父级、**不**产生页面滚动条，滚动与分栏归视图）。两类的分界判据不是「内容多不多」，而是**滚动归谁**：把画布 / 成片 / 工坊这类塞进窄栏等于砍掉一半工作面积。
  - 新增三档宽度令牌 `--container-narrow / medium / wide`（60 / 68.75 / 75rem，即从前的 960 / 1100 / 1200px）。`--container-*` 是 tailwind v4 里生成 `max-w-*` 的命名空间，所以档位名直接当类用。**数值一个都没动**：这一刀承诺的是收口，不是改版 —— `medium` 与 `wide` 的分界是继承来的、不是设计出来的，并档会真的改到那一屏的排版，那是另一次独立的布局决定。
  - 收口的八个视图：首页、项目主页、作品库、模型库、历史记录、队列与运行、资源库、产出。设置页的分区壳（`SettingsShell`）不并入容器（它是「导航 + 内容」双栏，没有整屏单列滚动这一说），但它那个写死的 1100 改成取同一颗令牌 —— 同一个数字不该有两个家。
  - 顺带去掉首页外框上那条内联 `style={{ fontFamily: "var(--font-sans)" }}`：实测 `--font-sans` 在运行时解析为空（见 #1434），这条样式今天不改变任何东西，而它想表达的事已由 `body` 的 `font-sans` 负责，两处各写一份只会将来互相「救」。
  - 原先写在首页那四层的两条解释（flex 链每层为什么要 `min-h-0`、内容列为什么是 `<div>` 而不是 `<main>`）跟着形状一起搬进容器 —— 说明该跟着它约束的东西走，不然形状搬家而理由留在原地，下一个人只能猜。

## Tests

- 新增 11 条容器形状判据（`src/components/studio/ViewContainer.test.tsx`，jsdom）：文档型恰好一层滚动、居中列带 `mx-auto` + 唯一档位名、三档互斥、`className` 是追加不是替换、铺底挂在外框且排在滚动层之前、内容列不是第二个 `<main>`；工作区型不给页面滚动条、也不出现居中列与宽度档位。
- 新增 10 条接入约定判据（`tests/project-view-container.test.ts`）：清单里每个视图都真的引了容器，且源码里不再出现手写的 `h-full overflow-y-auto` / `mx-auto … max-w-` / `max-w-<数字>`；传给容器的 `className` 里不许有第二份宽度。扫描面为空会先红（`it.each` 在没人可判时会假绿）。
- 新增 3 条真浏览器判据（`e2e/view-container.spec.ts`）：读 `getComputedStyle().maxWidth` 判窄栏落在 **960 / 1200 / 1100px**，与收口前散在视图里的那三个数逐一对上；并判首页容器内 `overflow-y-auto` 只有一层。
- 反向验证做过：往某个视图的 `className` 里塞回 `max-w-300` → 接入约定当场红，且只有被改的那个文件红（说明判据是逐文件的，不是一把抓）。
- 一条实测纠正了原本的设想：想让调用处在 `className` 里写 `max-w-*` 覆盖档位，**盖不掉** —— 合并器认不出 `--container-*` 派生的档位名，两份类并存、谁生效取决于样式表顺序。所以宽度只有 `width` 一个入口，这条约定由判据钉住，而不是写在注释里等人自觉。
- 登记：`src/components/studio/ViewContainer.tsx` 两处同批（隔离实测四项均 100）。
