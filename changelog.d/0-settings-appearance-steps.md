## Added

- **设置 → 外观 新增两档：圆角、标题字阶。**
  - 两档各只改一个全局 CSS 变量（`--radius` / 新增的 `--font-scale`），数值基准仍留在 `globals.css` 一处 —— 若在 JS 里重算成绝对值，基准就有两个家，改一处漏一处。
  - **圆角**是总闸：`--radius-sm…4xl` 全部由它 calc 派生，所以改一处，卡片、按钮、输入框一起跟手（实测运行时改它，卡片 21.6px→39.6px、按钮 9.6px→17.6px）。默认档「中 · 12px」就是引入前的原值，**升级后第一眼看到的不该是变化**。
  - **标题字阶**只作用于四档标题令牌（`--text-section/page/stage/hero`），正文固定 13px 不随它变。这一点写进了界面文案，并由用例在真浏览器里判住 —— 承诺和现实不符比没有这一档更糟。
  - 偏好由根布局的引导组件应用，**跨路由、刷新后仍然成立**。只在设置页里 `setProperty` 的话，用户一离开设置页偏好就悄悄失效，那种"有时管用有时不管用"比没做更难查。
  - 存储被拒（隐私模式等）时：本次立即生效，但明确提示"下次打开回到默认值"，不静默。
- **设置 → 应用更新 显示当前版本号。** `appUpdate.currentVersion` 早就在 state 和类型里，但界面一次都没单独列出来过（只被拼进 detail 文案）—— 用户想知道"我装的是哪一版"时，这一屏一个字都没给。未读取到时不留空白，而是说明它从哪来（点「检测更新」后由本机应用信息读取）。

## Notes

- **刻意没有「界面密度」这一档**：仓库里没有全局密度令牌（唯一的 `DENSITY_CLASS` 是画布编辑器内部的局部常量）。做一个只影响半屏的假开关，比不做更糟。
- 坏数据整份回落：存储里任何不认识的取值（未知档位 id、缺字段、类型不对、一半合法一半非法）都**整份**回到默认，不做"认哪个用哪个" —— 半份生效会让界面出现"圆角是新的、字号是旧的"这种无法解释的组合。
