## Added

- **`setting.router` 第一批执行者（34 条）+ 两处判据加强**（体检清单 ⑦ 第三批，继续并到
  安全台账 A 系列）。用例不按 procedure 顺序铺，按三条线组织：
  **拒绝发生在写之前**（端口 `-1` / `65536` / `1.5` → `BAD_REQUEST` 且 `saveSettings`
  一次都没被调用）、**协议白名单的两个方向**（`HTTPS://x` 放行、`http://␣␣` 拦下）、
  **闩锁的清除条件**（`comfyuiAutoStart:true` 才清「手动关闭后不启动」；改了安装路径或
  启动参数才清「启动失败后不再重试」；只改端口不许清 —— 那是 ISSUE #290 / #335 的判据）。
  另含 `dbStudioStatus` 的降级形状（探测挂了按「未运行」回，而不是抛错把三个按钮全禁掉，#92）。
- **台账 A4 复算勾销 + 判据加强**：`getConfigForClient` 的脱敏早在 `8740948` 就做了（与
  A2/A3/A6/A7/A10 同一批、同样没勾）。原判据只断「`apiKey` 是 undefined」，而这一族故障的
  表现是「密钥跟着配置接口发到浏览器、再跟着日志落盘」—— 现在改成**显式把两把密钥种进库里**
  （顶层一把、远端条目一把），再把整个出口对象序列化后断「一个字都不出现」。
- **新开台账 A11：远端模型密钥会被「保存一次设置」清掉**（A4 那次脱敏的副作用）。
  脱敏后的条目不带 `apiKey`，而 `llm.configSave` 走的 `replaceAll` 是「整份覆盖」——
  设置页把刚拿到的清单原样回写一次，每条远端密钥就被写成 `null`；同一条批量语句里
  `workshopAdapters` 却是从既有行继承的，一个函数内两种语义。客户端也给不出区分
  （「用户没重填」与「显式清空」都发 `null`），所以修必须同时改两端，建议形状写在条目里。
  现状由 `src/lib/core/repository.test.ts`「replaceAll 不保留已有密钥」钉住 ——
  真去修时这一条必须一起改，免得把数据丢失静默带回来。
- **两个入口进覆盖率门槛**（§18.6 实测登记）：`src/lib/url-scheme.ts` 100/100/100/100、
  `src/server/api/routers/setting.ts` 100/90/100/100。`open-in-browser.ts` **不单列**：
  它已在 `src/lib/shell/**` 这一组里，而没覆盖到的分支只有 darwin / linux 两条平台分叉
  （本机 win32 跑不到）—— 单列等于把「测不到的那支」写进门槛。
- 配套文档：规范 §11.2.1 加一条「**一条口径要把它的所有落点列出来再收**」（A5 就是漏了
  第四个落点才存活至今）；台账 P1 段的复算说明补第二批（A4 / A5）与「修一个洞的同时
  挖出一个洞」这条记录；`docs/guides/TESTING.md` 的 E3 同步到 6/16 router。
