## Changed

- **平台留痕收成开头一行粗体署名：`**[评论人：<短名>]**`**。此前四条写文字的出口各写各的：
  提单 / PR 正文**末尾**一行 `提单人:<短名>`，领取 / 结束评论**末尾**一行 `处理人:<短名>` ——
  同一件事（谁发的这段文字）被写成两种形状，而角色分工其实已经由标签承担，正文那两行
  只是重复。现在只有一处实现 `commentHeader()`（`scripts/ship-ticket.mjs`），
  issue 正文、PR 正文、领取评论、结束评论四份都**开头**一行同一格式、空一行再接正文；
  未配时如实写 `**[评论人：未配]**`。`--whoami` 念的也是这条格式。
- **状态判定跟着改认正文那句，不认开头署名**：claim 与 release 的开头逐字相同，拿它当
  「最新一条是不是我的状态评论」的判据会把每一条 release 读成 claim（于是重领后第一次
  `--release` 不再发评论）。`handleCommentState()` 现在认「开发者 <短名> 已接单，正在开发中。」
  / 「开发者 <短名> 开发结束。」这两句（`commentSentence()` 一处生成，写、判、日志共用）；
  **旧形态（结尾 `处理人:<短名>`）仍然认**，历史评论不需要重写。
- 规范 §13.10.10 / §13.10.11 / §13.10.12 与 `ship` Skill 同步；回归在 `tests/ship.test.ts`：
  `commentHeader` 三向（正常 / null / 空白）、`buildPullBody` 与 `readIssueBody` 的开头断言、
  领取 / 结束评论的首行断言，以及旧形态 release 评论仍被判成 release 的那一条。
