- **闸门类端点第二批用例：68 条，并到安全台账 A 系列（「写断言 → 照出越权 → 顺手修」）**。
  与第一批（#1260，5 个端点 / 34 条）同一配方，这一批全部落在**归属与注入闸门**上：
  - `src/lib/media/output-paths.ts` 16 条 —— 产物布局的唯一定义（见同日另一条修复）。
    用例的分工不是凑行覆盖，而是把两类真事故各自钉住：**分叉**（磁盘与 URL 必须由同一份
    segments 派生）与**越界**（`../` 形状的 id 返回 null，而不是一个能交给
    `fs.rm(..., { recursive: true })` 的路径）。
  - `src/server/api/routers/project.test.ts` 17 条 —— 该路由**第一次**有执行者。id 全由客户端
    生成，所以每个读 / 写 / 删都逐条证明「越不过去」：越权写（upsert）、越权读
    （get / patch / outputs 三个出口对他人项目给同一句话，不给探测 id 用）、跨用户删
    （`deleteForUser` 的 id+userId 双条件必须是「什么都没删」）。
  - `src/app/api/custom-nodes/route.test.ts` 35 条 —— argv 注入闸门（A6）。判据分两层：
    坏形状必须在 **spawn 之前**就被拒（`expect(spawn).not.toHaveBeenCalled()` —— 只在响应码上
    打勾等于没拦住），合法包名则钉住 argv 的**形状**（`--only-pkgs` 永远是一个值、
    `--out` / `--report-out` 的位置与内容不许被客户端挪动）。21 种形态逐条过：
    前缀 `-`、`=`、引号、分片符、命令替换、非字符串、空、超长。
    另有一条**边界说明**：`"a,--out"` 通得过净化器，但它进的是单个 argv 元素，
    Python 侧按逗号切的是「值」，切完不会变成进程的 flag —— 危险从来不是「有没有逗号」，
    而是「客户端能不能让 argv 多出一个 token」。
  - `src/server/api/routers/task.test.ts` +4 条（现 23 条）—— 快照越权读（A2）与
    产物目录三条（越界不动磁盘 / 项目目录按 `projects/<pid>/<tid>` 删 / rm 失败不阻塞删库但原因可见）。
    反向验证逐条做过：去掉归属判定只有那一条红、净化器里删掉 `=` 只有那一条红、
    把 `taskOutputDir` 的包含判据摘掉恰好 7 条红。
