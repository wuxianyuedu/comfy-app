## Fixed

- **主题色扫描看不见写进 Tailwind 候选名里的 `rgba()`，把这类裸值全部放了过去**：判据写成
  `/\brgba?\s*\(/`，而候选名用 `_` 代替空格 —— 「`shadow` 的任意值写法里那段 `_rgba(`」，`rgba` 前面是单词字符、
  当场匹配不到，于是这类裸值既不进豁免也不进报告，`pnpm theme:check` 一直报「未豁免 0 处」。
  口径本是规范 03 §3.6.2 末段那句「认的是源码里写了字面色值」，属实现偏离口径。改正则后实测出 6 处，
  逐处定性：画布节点投影与模型卡 hover 投影引 `var(--color-shadow-strong)`（前者此前把深色档的
  `0.55` 恒定写死，浅色主题下按 3 倍强度用 —— 现在浅 `0.18` / 深 `0.55`，真编译 + Chromium 复算过）、
  两枚生成按钮的投影与库卡选中内描边改 `color-mix(… var(--color-primary*))` 跟着品牌走
  （那两处原本钉着深化前的旧品牌值，而同一条 class 上的渐变已经是 `from-primary`）、
  水幕百分比白字那道 `drop-shadow` 并入 `ui/water-fill-progress` 已有的固定暗色豁免条目并补全理由。
  判据两侧同钉用例：候选名里的裸值必须红、换成 token 必须绿。规范 03 §3.6.2 补这条口径与覆盖面边界。

## Changed

- **`--shadow-card` 的深色档到不了调用点，实测记档**：Tailwind 把 `@theme` 的值内联进 utility，
  `.shadow-card` 编出来是 `--tw-shadow: 0 4px 20px var(--tw-shadow-color, rgb(0 0 0 / 0.18))` ——
  浅色值被焊死，`.dark` 里那颗 `0.55` 只有直接写 `var(--shadow-card)` 的人才拿得到，而全仓没人那么写。
  所以「投影要跟主题」的写法是在 `shadow` 候选名的颜色位引 `var(--color-shadow-strong)`。`docs/DESIGN.md` 的 Elevation
  表与规范 03 §3.6.2 各补一条警示（与 `--radius-*` 那格「半个幽灵」是同一类错法：判据要问
  「哪条 utility 真会去读这颗变量」，不是「声明了几态」）。本次**不改** `shadow-card` 的现有调用点。
- **顺带踩到并记下的那条量具坑（本轮自己的改动造成的，已改回）**：在**被扫正文**里写全一条任意值候选名，
  Tailwind 就真把它编进产物 —— 本轮三处这样的写法（规范与碎片里的省略号写法、以及那条**用例夹具**里为了
  复现事故而写全的旧品牌值）各产出 1 条谁都不用的规则，其中一条正是「刚被治理掉的退役品牌紫」又被发回 CSS。
  改法：正文只写形状（「`shadow` 的任意值里那段 `_rgba(`」）或只写值本身；用例夹具把前缀换成一个不是
  utility 的名字（判据只看文本里有没有 `_rgba(`，不需要那条类真的存在）。**复算方式**：改完真编一次
  `globals.css`，逐条断「那三条死选择器一条都不在、本次要用的四条真规则一条条在」——**别看字节数差**，
  字节数会被同期其他源码改动带着走，本轮实测就是靠逐条点名才定住归因（省略号写法看着无害，`…_var(…)`
  那条却真被编成了 `--tw-shadow: … var(--color-shadow-strong)`）。
