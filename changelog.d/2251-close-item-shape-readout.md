## Added

- **`--close-issue` 关单之后多一行正文条目形态读数**（ISSUE #2251）：`###` 小节 /
  `- [ ]` 未勾 / 已勾 / 序号 各几条，并点明「关的是**整张**单，这些条目的处置不随之判定」。
  它是读数、不参与退码 —— 做成硬闸会逼人把正文删短来凑数（与 §13.10.9 那次「随手挂别人的号」
  同型）。为什么不合成一个「剩余条数」：真实单子的清单写法不统一，实测一张标题里列了 7 条
  待办的单，正文 `- [ ]` **一条都没有**（条目写的是 `###` 小节与序号），只按复选框数会把
  「列着 7 条」读成「0 条」，比不读更坏；而「某条做完没有」本就是人写在评论与 PR 里的判断。
  回读里没有正文那一格时念「正文没读到」，**不念成「零条」**。
- **口径补一条：一条诉求一张单**。清单式大单要么拆开立，要么在关之前把未处置的条目转成新单 ——
  号一关，剩下的条目就从 `list-issues --state open` 里消失，连「欠着」的可见性都没了。
  AGENTS 硬规则 29、规范 §13.10.9 与 project Skill 第 4 条边界同批。
- 用例：`issueItemShapes` 一组（真实那张单的形态——`###` 与序号在场而复选框为零 / 复选分未勾与已勾
  且缩进也算 / 空标题的 `###` 不计 / 空正文与非字符串输入归零不抛）+ 关单两格
  （`未勾 > 0` 时退码照旧是绿；回读缺正文时念「没读到」而不是念成零条）。
