## Added

- **`受影响用例` 那一格的清单带上每份用例的用时**（ISSUE #2683 的第二问 / 单子 #2751）：
  #2683 第一笔之后平台日志读得到「跑了哪些用例」（108 行文件名），但**一个时长都没有** ——
  绿了不知道哪一份最贵，红了想「先只跑最贵的那几份」也只能猜。用时本来就在 junit 里，
  缺的是它在这一格没有出口（`ci-affected-tests.mjs` 的收尾只念「分文件读数 N 份」）。
  新增 `scripts/affected-launch-file-timing-report.mjs` 的 `fileTimingReport()`，由启动器在
  **收尾**（`flush`，第一遍跑完才有读数）打出：用时前 15 份（降序）+ 门槛以上的最慢 5 份 +
  其余总账，并明写「合计是各份相加、不是墙钟」。
  三条边界与清单那一份同源：只在 quiet 档打（不 quiet 时默认 reporter 已经打过）；
  截断必须念出省了多少行；**读不到时说「读不到」而不是打一张全 0 的表** —— 全量档没有清单 /
  账本目录没造出来 / junit 一份没写出，三种形状在这一格同形、都不编数（§13.6.4.1）。
  进了清单却在 junit 里缺席的那几份单独点名（那是一次都没被计时，不是「很快」）。
  取数走账本那一侧的读者 `collectFileTimings`（由启动器转出，不自己扫目录）。判据一个字没动。
  钉它的是 `tests/hook-affected-launch.test.ts` 的「逐份用时」一组 10 条，规范 §13.5.8.3
  「第九笔账」补了对应小节 + 镜像。
