## Changed

- **P 系列判据全部升为硬闸**（`check-ui-primitives.cjs`，规范 §16.2.3）：12 条实测为 0
  的棘轮（P1 / P2 / P3 / P44 / P45 / P46 / P65 / P66 / P67 / P68 / P69 / P83）进
  `HARD_GATE_RULES`，棘轮基线归零 —— **82 条判据现在全部须为 0**。升闸的依据不是
  「数字是 0」而是**那 0 数得出来**：这 12 条每条都带正例用例（喂一段违规代码、断言它
  被数到并阻断），所以 0 是清完了，不是扫描器瞎了（P82 的教训：判据用粗锚时 78 看着像 0）。
  顺带消掉两处**名实不符**：P44 / P45 / P46 / P65 / P66 的段头与规范标题一直写着「硬闸」，
  而它们其实还在棘轮里 —— 差别不是「新增会不会红」（棘轮对没记过账的 rule id 一样红），
  而是 `--update` 能不能把新增量登记成「起点」：硬闸连登记都拒。另有 11 条已升闸的判据
  段头仍写着「棘轮」（P68/P69/P71/P75~P81/P83），一并改对。
- **删掉两处手抄的判据名字表**（脚本输出那行 `硬闸判据（P4 自绘滚动条 / … / P66 重入闸门）`
  与规范 §16.2.3 里那段同样的清单）：它们已经漂了 —— 写着 P4~P66，实际判据到 83，
  本轮升闸的 12 条一个都没提到。改成从判据自身派生（「82 条，响了几条」），
  名字与实时计数一律看 `--report`。
- **修一个自己锁死自己的前置**：缺基线文件时脚本先报「请先跑 `--update`」再退出，
  而全部判据都是硬闸之后 `--update` 会被硬闸拒收 —— 删掉基线文件就能让门禁**不去数**
  那 82 条。现在「基线必须存在」只对**仍是棘轮**的判据成立，硬闸与基线在不在无关
  （两条用例分别锁住这两个形态）。
- 棘轮这条路径**没有删**：它是新引入判据的起步形态（先冻结存量 → 清零 → 升硬闸）。
  为了保住这条路径的覆盖，测试里加了 `demoteToRatchet()` —— 把临时副本脚本里的某条
  判据摘回棘轮，验「只许降不许升 / `--update` 拒绝放宽 / `--strict` 要求收紧」这套
  语义仍然工作。不这样造形态，将来加新判据时这条路径坏了也没人知道。
