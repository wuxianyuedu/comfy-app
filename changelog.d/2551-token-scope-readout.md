## Added

**把「这一跑的 `CNB_TOKEN` 够得着哪些能力」打成构建日志读数**（ISSUE #2551）。
本仓引用「PR 那一族只有 `repo-code:r`」这句话的地方有十几处（#2339 / #2362 / #2365 /
#2472 / #2550），而出处始终是**别人先撞上 403 之后抄下来的那句话**
（`Missing required scopes: repo-cnb-history:r`）。于是「PR 上到底有没有 `repo-issue:r`」
这个问题，过去只能翻官方权限表再猜平台实现。

- 新增 `scripts/ci-token-scopes.mjs`：拿一串**只读**接口（分支 / 仓库元信息 / Issue / PR /
  构建历史 / 发行版 / 制品 / 知识库 / 管理面三格）挨个问一遍。403 里平台会自己点名缺哪一枚
  scope ⇒ **平台自报的授权面**进日志，不必等某一格真去写、真被拒。
- 排在 `.cnb.yml` 三个立案锚点（`每日档` / `pr_fail_stage` / `package_fail_stage`）里
  立案格**之前**：立案那两格自己就是「写平台」的消费方，它们写不动时第一件要看的事正是
  「这一跑的令牌面是什么样」。
- **权限本身从不构成红**（`--strict` 只提「一条探针都没拿到答复」= 这一格自己坏了）：
  平台按「事件 + ref」分配，缺 `repo-manage:r` 是预期形态。业务层 404（PR #1 不存在、
  仓库没建知识库）读成「平台认了这次请求」，不读成缺权限。
- **不打令牌值**（硬规则 17）：打的是「哪些能力够得着」。OIDC 兑换那一问的入参含
  `cnb_token`，默认不发、只有 `--probe-oidc` 显式点名才发。
