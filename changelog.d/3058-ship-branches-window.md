## Fixed

`pnpm ship --branches` 的 PR 取数窗口不再掐在 800 条（ISSUE #3058）。

**实证**：`fetchPullsForBranches` 原以「8 页 × 100 条 = 800 条硬顶」为翻页终点，
本仓 PR 总量早已越过 800（编号段 3000+），窗口恒取不满，窗口外的本地分支
只能全落 `no-pull-in-window` —— 入口覆盖面只剩约三成，且每一跑都退 2。

**改后行为**（终止只看平台形状，页数没有目标）：

1. 平台应答带 `has_more` / `hasMore` / `next` 键 ⇒ 听它的（`false` 停、`true`
   继续，哪怕这页不满）；新增 `readListHasMore` 三态读数（确认真 / 确认假 /
   **缺键**），缺键不按「没有更多」误读（与 #3059 同族口径）；
2. 键缺 ⇒ 回落既有「不足页 ⇒ 没有下一页」判断；空页也正常取满；
3. **空页必停**：平台喊「还有」却给空页按「取不满」如实报，不跟它无限翻；
4. 防失控上限 8 → **64 页**（6400 条，远高于业务面）：它只兜「平台页页喊还有」
   的失控形状，撞线显式报「取不满」（已翻几页 / 已取几条 / has-more 键在不在），
   不静默截断。

行为变更：窗口取不满的 note 文案由「只翻了 N 页就到顶」改为「**取不满**：防失控
上限 N 页（已取 M 条）翻满……」；返回值新增 `stopReason`（has-more-false /
short-page / empty-page / ceiling）与 `hasMoreKey` 两格读数。判据见
`tests/ship-branches.test.ts` 的 #3058 组（>800 条 / 正好 800 边界 / 缺 next 键 /
has_more 键优先 / 上限触发报取不满 / 空页防无限循环）。
