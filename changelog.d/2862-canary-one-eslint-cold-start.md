## Changed

- **「受影响用例」格里最重的那一份先减一次冷启动（ISSUE #2862）**。
  单子要求**先取带量具的基线再谈降本**，所以两臂都在本机、非并发、平台 `pending=0` 时取的：

  | 那一格 | 基线（改前） | 改后 | 形状 |
  | --- | --- | --- | --- |
  | `tests/eslint-gate-canary.test.ts` | **147s**（默认档 80s + 两条 sabotage 33s / 30s） | **89~94s**（默认档 **28s**） | 三条用例各起一个 eslint 子进程；开销大头是**每次调用的 project service 冷启动**（单次约 30s） |
  | `tests/base-check.test.ts` | **69s**（67 条用例，最重一条 9s） | 未改 | 11 条真 git 夹具用例 × 3~9s，**没有单点** |

  改的那一刀：`scripts/eslint-gate-canary.mjs` 原来默认档跑**两次** `eslint`（TS 面一次、
  scripts 面一次），两批文件的判定结果只是并进同一张 `byFile` 表 —— 也就是**付了两次冷启动
  换一次判定**。合成一次调用（`clean.ts` 照旧跟着 TS 面进、`node-global.mjs` 照旧只在
  scripts 面非空时进，sabotage 的最小集语义逐字保持）⇒ 默认档 **80s → 28s**，
  两条 sabotage 用例不动（33s / 31s ≈ 33s / 30s，它们本来就只调一次）——
  **这正是这一刀归因干净的证据**：动的只有该动的那一条。

  这一格在固定清单里（每次提交都跑），所以省的是**每一个 PR**，不只是墙钟：少起一次
  eslint 进程 = 同一格里别的用例文件少抢一份 CPU。

  ⚠️ **顺手纠正一处读数口径**（这一条比那一刀更重要）：那份「用时前 15 份」的榜上写的是
  canary **279.2s** / base-check **177.9s**，看着是"两份吃掉 457s"。同一台机、同一份代码、
  非并发重取，实数是 **147s / 69s** —— 榜上的数是**争抢下**的（1.9× 与 2.6×）。
  那份榜没留是哪一跑（没有 sn）⇒ 它只能回答"谁在最前面"，**不能当收益的分母**。
  所以本单的收益只跟上面那张带量具的表对账；引用它时连这一句一起引
  （§13.6.4.1「并发在场时墙钟不可读」在组 C 上的同一条）。

  新增一处**露面读数**：脚本把「这一趟起了几次 eslint」打在 ✓ 与 ✗ 两行里
  （`…（samples=11，eslint 调用 1 次）`），三条用例各钉一条 `= 1`。
  为什么要钉次数：拆回两次调用，**功能断言一条都不会红**，只是每次提交多付 30~50s ——
  这类"绿着变贵"的回归只有把代价本身做成读数才拦得住。
  **变异证明**：把计数改成 `+= 2` ⇒ 默认档那条当场红（`expected … 实际：… eslint 调用 2 次`），
  还原后绿。

  **没做的两件事，理由写在这里，别让下一个人重新查一遍**：
  - `base-check` 不共享夹具：它的 69s 摊在 11 条真 git 用例上（每条各自 init / commit /
    push / worktree），合并快照最多省十几秒，代价是**用例之间开始互相依赖同一棵树**
    —— 而这一族用例的存在理由恰恰是"两侧各自是什么"（#2791 那一格刚修完）。
  - `isolate: false` **对这两格无效**：它们的钱在子进程与 git，不在环境重建。
    要判它对全库值不值，得整档按两种顺序各跑一遍并证明互不污染 —— 本单没跑，
    所以**不给结论**（不猜）。
  - 外部那份分析给的另外三条在这台节点上不成立，逐条与出处都记在单子里：
    容器/分片并行（`Runner does not enable Docker`，且只有一台与本地同机的自托管节点）、
    "把 lint 移出用例"（它 lint 的是十几份自造样本，不是全仓）、
    "复用 ESLint 实例 / 走 API"（阳性对照刻意走门禁那一跳的 CLI）。
