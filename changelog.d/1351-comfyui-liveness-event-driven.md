## Changed

- **ComfyUI 存活判断从「只靠轮询」改成「事件驱动为主、轮询兜底」**（ISSUE #1351）：

  ① **崩溃靠事件，不靠轮询**。此前整条存活链只有一个判据 —— 客户端按固定间隔打
  `/api/comfy/stats`，进程死了要等下一拍才发现（上限就是一个轮询间隔）。现在服务端
  `child.on("exit")` 那条退出路径（bound 的退出回调与保活的窗口监督器都汇到
  `markComfySessionEnd`）会记下一次「进程退出」并**经 SSE 立刻推给浏览器**
  （新增 `GET /api/comfy/liveness`）；客户端收到后**立刻做一次 HTTP 复核**再切状态。
  复核是必要的一步：信号只说那个子进程退了，而这一拍 HTTP 仍可能通（端口被接管 /
  退的是被顶掉的那个实例）。

  ② **连续 3 次失败才判 crash**（`createCrashLatch`）。单次失败只累加计数、成功一次
  就清零 —— 出图高峰期单次超时太常见，一次失败就当崩了会把用户跑到一半的图杀掉。
  它与既有的离线迟滞（`offline-gate`）是**两台独立的计数机**：那台管「这一格读数还该
  不该按在线渲染」，这台管「进程是不是崩了」，共用一台会让先跑的那条把另一条的失败清零。

  ③ **轮询间隔按阶段给，出图期尤其降压**。此前恒为 4s，而 `/system_stats` 内部会调
  `torch.cuda.mem_get_info` —— 生成高峰期高频打它等于往已经排队的 aiohttp 里再插请求，
  既拖慢用户出图又更容易触发超时假阳性。新节奏（`src/lib/comfyui/liveness`）：
  启动等待 400ms（10s 后降到 1s）、稳定空闲 15s、**出图/队列执行中 30s**、
  窗口隐藏 60s、收到崩溃信号后**立即单次复核（间隔 0）**。

- **「指标展示」与「存活判断」的节奏拆开**：4s 那一档现在是纯粹的**展示**节奏（UI 上的
  显存/队列数字动起来），存活判断另有上面那张分阶段表。出图期间的进度看 WebSocket 推送
  （服务端主动推、零成本），不靠高频探 `/system_stats`。

- `~/lib/poll-timer` 的 `ms` 支持**函数**形态：每拍跑完重新问一次「下一拍等多久」——
  「按阶段给频率」的档位在运行中会变（用户点了生成 / 切走了窗口 / 刚收到崩溃信号），
  一个创建时就定死的数字表达不了。`0` 表示立刻再跑一拍，`null` 表示下一拍不排（两者
  不可混为一谈：把 `null` 当 `0` 会成为忙等）。

## Added

- `src/lib/comfyui/liveness.ts`：存活判据的三条纯判决 —— 阶段分类
  （`classifyLivenessPhase`）、分阶段间隔（`livenessIntervalMs`）、连续失败阈值
  （`createCrashLatch`）。无 IO、可逐分支钉死。
- `src/lib/comfyui/liveness-signal.ts`：进程退出事件的进程内信号总线（单调纪元 + 订阅），
  是「事件 → 客户端」通路的服务端一半。
- `src/app/api/comfy/liveness/route.ts`：把退出事件推给浏览器的 SSE 通道；连上时补发
  当前快照（崩溃之后才打开页面的客户端也能立刻知道），`seq === 0` 时不发假事件。
- `src/lib/comfy/comfy-liveness-client.ts`：SSE 客户端（按 `seq` 去重、主动关闭不派发脉冲）。
- `src/lib/comfy/comfy-busy-store.ts`：「ComfyUI 此刻忙不忙」的全页单点，供系统指标的
  持有者按阶段降压；黏滞只对「忙 → 闲」生效（闲 → 忙必须立即生效）。

## Fixed

- 进程退出事件此前**只落日志、不改状态**：客户端要等下一拍轮询才知道进程没了。
  现在同一次退出一并推给浏览器并触发即时复核。
