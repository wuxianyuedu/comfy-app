## Changed

- **规范补一节：把「秒级克隆不可用」与「`runner.cpus` 无效」收成一句话 —— 它们是同一条
  限制的两个后果，不是两件独立的事**（ISSUE #1959）。§13.5.3.4 那张表里这两行的措辞
  不一样（一条写「配置无效」、一条写「自动降级」），读起来像两处独立失效，于是很容易
  推出一个错误动作：「既然是两条，也许能单独保住其中一条」。新增 §13.5.3.4.2 说清它们
  要的是**同一个底座** —— 平台那套容器化构建环境：官方文档里「秒级克隆」的机制是
  **OverlayFS + `docker.volumes` 的 copy-on-write**（`pipeline-cache` 原文「基于 OverlayFS
  的缓存即时复制技术」），而 `runner.cpus` 的实现是 **Docker cgroups 的资源限额**；没有
  那个底座，进度条上那句「秒级克隆」也就没有东西可指。

  顺带把「那我们自己让它转起来」这条路的代价写清楚：宿主机装 Docker、或拿
  `git clone --reference` / `--dissociate` 手搓一份共享对象库**确实能让某一次 clone 变快**，
  但它换来一台要自己维护的宿主 / 一份自己维护的共享仓库，而省下的那点时间只落在**一次
  构建的开头**（后面 3000+ 用例、`next build`、Playwright 一件不减）；更要紧的是**没有
  判据** —— 「这份共享库还是不是那次 clone 的那个版本」在仓库里没有任何东西会红，属于
  §13.5.3.7 那一类「加一层没有执行者的机制」。

  **刻意不复制**表里「Linux 构建机仅支持 arm64/aarch64」那一行：它已经在表里，复述一遍
  只会多一处会过期的引用。这一节只收「同一个底座的另一个后果」，因为那一格**看起来像
  一件独立的事**。
  （顺带修掉本笔头一版留下的一处行宽回潮：§13.5.3.10 那条现场引文里
  `PLAYWRIGHT_DOWNLOAD_HOST` 那一行原文 84 字符、在 80 列上回绕成两行，与它上下
  两行逐字同形的引文不再对齐。引文保留逐字，只把 URL 折到下一行。）
