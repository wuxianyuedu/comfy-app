## Fixed

- **端口不再靠「8188 探不通就依次试 8189…8193」反推：配置了实例路径时先按路径问进程（ISSUE #449 追加）**。实例的端口是**进程监听出来的**，不是试出来的——旧链路即使在设置里配好了实例根目录，也要先把配置端口与邻近端口逐个探一遍，等全落空才写一句「连不上」；而 Comfy Desktop 的实例常由 `standalone-env`/`uv` 拉起，端口与设置里的默认值不一致，于是每次探测都必然空扫一整轮。现在 `resolveComfyBase()` 先按 `comfyuiPath` 走判据链找实例进程（main.py → 解释器候选 → setup 登记的启动器 → 环境反查），**一次进程表查询 + 一次端口查询**同时得到「在不在跑」与「在哪个端口」，命中即直连；这条判据链抽到新模块 `src/lib/comfyui/instance-port.ts`（无缓存、无 UI 语义，与 `status.ts` 同口径），进程表查询与端口查询收在 `proc-detect.ts`。拿不到进程事实（未配路径 / 查询失败 / 没命中）才退回原有的端口探测，口径与缓存语义不变。
- **设置页「ComfyUI 端口」文案改口径**：以前写「实际运行端口以设置为准」，会误导用户以为必须把端口改成实例实际监听的值；现在写明这是**默认端口**（启动时按它传 `--port`），实例已由别的方式跑起来时应用会直接按进程实际监听的端口连，端口不一致无需改设置。
