## Fixed

- **dev server / host 重启后留在 `QUEUED` 的任务被白判失败**（P3 §5 第 2 期 · Phase 4-B3，ADR §14 D1 第二刀）。这类行只有 host 那条领取循环会救回来：Next 侧的执行入口读的是进程内存队列，冷重启把队列清空后就再没人领它们，30s 后由回收器判成「任务卡在队列超过 Ns…请重新执行」，用户只能重跑。现在两宿主都按 `claimedBy` 从库里领行，遗留行会被自己那一片领走继续执行。
- **一条被回收的死任务能永久占住串行队列唯一的槽**：`MAX_CONCURRENCY=1` 时，reaper 把某行判成孤儿并收口后，原来的活跃计数器不会回落（收口路径不在执行链里），此后所有任务都卡在「永远 QUEUED 0%」。改成在飞集合记账后，三条回收路径（QUEUED 孤儿 / RUNNING 无 promptId / RUNNING 对账）都会归还槽位。
