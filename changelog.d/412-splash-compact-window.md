## Changed

- **启动页窗口不再是一大块空白：窗口即内容，右上角自带最小化 / 关闭（ISSUE #412）**：此前 splash 窗口按「窗口越大、日志一行越能放全」给到 1680×1000 并带原生标题栏，而内容卡片只有 720（收起日志）/ 1400（展开）宽——2K/4K 屏上启动时大半块屏幕是没有任何用途的空白，用户看到的像「弹了个空窗口」，最小化 / 关闭还被挤在原生标题栏里。现在改成：
  - **开窗就是紧凑档**（744×216，居中，高宽都贴着「收起日志时的内容」）：不再铺满屏幕，下方也没有留白；
  - **展开日志时窗口跟着内容长大**（1424×788）：页面把「展开 / 收起」告诉壳（新增应用命令 `set_splash_compact`），尺寸常量只在 `src-tauri/src/lib.rs` 各留一份，页面不写第二份 magic number；两档都按当前显示器可用区域收敛，小屏不越界；
  - **去掉原生标题栏**（`decorations: false`）：启动页自己在右上角画最小化 / 关闭，标题行整条可拖动（按钮用 `no-drag` 排除，点击不被拖拽吞掉）；日志面板不再写死 320px 高度，改 `flex: 1` 吃掉窗口剩余高度，展开后既不是窄缝、面板下方也不留空白。
- **打包启动器（`--splash`）那张 Win32 启动画面同款收拾**：从 640×300 收到 560×168 的窄条，右上角并排给出最小化与关闭（含悬停高亮）——此前只有一个 ✕ 且与标题挤在一起。

> 新增应用命令按既有约定三处同步：`build.rs` 的 AppManifest、`capabilities/splash.json` 的 `allow-set-splash-compact`。改动 `splash-assets/**` 与 `tauri.conf.json` 后**必须重编壳**（`cd src-tauri; cargo build --release --features custom-protocol`），否则跑的还是旧二进制。
