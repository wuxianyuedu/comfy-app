## Added

**桌面成品包那一档也有失败立案了**（ISSUE #2550）：两个触发口（`crontab: 0 2 * * *` /
`web_trigger_package`）接上 `*package_fail_stage` —— 一个 `endStages` 立案格。

- 之前这一档红了**没有任何一种自动出口**：只有每日档（`每日失败立案`）与 PR 档
  （`PR 失败立案`，而那一族今天只有 `repo-code:r`、写不动，见 #2339）各有一个；
- 入口是**同一个脚本** `ci-pr-failure-issue.mjs` 加一个 `--lane package`，读写链不抄第二份
  （§12.12）：定性 / 逐格 / 失败行摘录 / 建单 → 补标签 → 独立回读都还是原来那一份；
- `--lane` 是**显式声明**而不是从事件名推：不给它，非 `pull_request` 事件照旧判成
  「不归本格管」（那一刀今天仍然要留着）。档名进标题与去重键 ⇒ 桌包那一族的单子
  是 `ci(package): 桌包档红在「…」`，与 PR 那一族互不相混；
- 写不写得动这件事与 PR 那一族是**两种形状**：桌包挂在 `crontab` / 手点事件上，
  #2472 / #2462 那两张单就是 `crontab: 0 0 * * *` 那一跑自己建出来的；
- `fetchBuildList()` 因此多一个形态：`event` 为空 ⇒ 命令里**不带 `--event`**（什么事件的
  都要）。lane 模式按事件过滤就查不到自己那一跑（现场：事件念成 `(取不到)`、`self` 为 null，
  连「还没到终态」那一道都跳过）；
- 首张用新通路补立的正是今早那条红：#2560（`cnb-5j8-1k5v8acjd`，红在
  `打包·壳工具链自证`，被带下去 3 格）—— 建 → 补 `提单人:ci-pr` → 独立回读全过。

判据：`tests/ci-pr-failure-issue.test.ts` 的「`--lane`：只有显式声明的那一档才认非 PR 事件」
（含「没给值 / 没登记 ⇒ 退 2 且不退化成默认那档」「标题与去重键按档分开」与
「列表那一跳不带 `--event`」）＋ `tests/ci-build-readout.test.ts` 里 `fetchBuildList`
的那条空 `event` 形态。
