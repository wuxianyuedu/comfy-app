## Added

- **`pnpm check:daily-attendance` —— 「每日那一跑到底有没有执行」现在是一条可失败的判据**
  （ISSUE #2114 出路 1；口径与边界见规范 §13.5.23 末节，登记在 `quality-gate.mjs` 的
  `GATES.dailyAttendance`（`run: false`）+ `scripts/.on-demand-duties.json`，
  **不在** `.gate-executor-ledger.json` 的 `onDemand` 里 —— 那个位置留给「一个执行者都没有」
  的那一档，而 `check-gate-executors.cjs` 会当场指出这种不符）。
  它补的缝很具体：三档重档 + `ESLint 零警告` 的**唯一执行者**是平台上的每日那一跑（§13.5.21），
  而这句话过去只被**在册**那一半守着（`no-platform-ci-config` 数的是格名在不在清单里）。
  2026-10-18 → 10-22 **五派发零跑完**（两次没落到这台机、一次被 8640s 墙钟掐、一次被同一把锁取消、
  一次睡满 3.0h）期间账面全绿 —— `FRESHNESS_TRACKS[*].ciStage` 非空就把「今天必须有凭证」整层跳过，
  而跳过的理由当时没有任何东西在判。

- **形状上的四个决定，每个都有当场读数当依据**：
  - **按前缀认派发**：`crontab` 的事件名**含小时**，而 10-22 一天里换了两次
    （`0 4` → `0 2` → `0 0`）⇒ 写死钟点的判据第二次换时刻时就会静默变成「永远读不到派发」。
    三条触发口（定时 / 手点 / API）按 §13.5.23 跑的是同一件事，所以都算出勤；
    而 `pull_request` / `push` / **单跑口都不算** —— 否则「有人手点过一次单跑构建」会被读成
    「每日档出勤了」，那正是这条判据要拦的假绿。
  - **逐格判定复用 `ci-build-readout.mjs`**（那份「绿 / 真失败 / 被取消 / 没结论」四档是现成的，
    含「哪一格被取消、下面哪几格根本没跑」）—— 在这里重写一份格级判定就是 §12.12 的孪生。
  - **三态退码**：`0` 出勤 / `1` 缺勤（真失败，或窗口内没有派发）/
    **`2` 没结论、没跑到、取不到读数**。「被取消」与「拿不到测量」都落 2：说成红就是替平台
    编一个不存在的产物问题（`ci-build-readout` 那条口径同），落成绿则把这条判据变成会说谎的那种。
    窗口默认 36h（每天一次 + 半天余量，吃得下实测存在的延迟补派：`04:00` 的事件有过 08:42 才落的那次）。
  - **网络只在被要求时发生**（§13.5.13 同口径：判据自身不做网络请求，「现在去不去问平台」是人的动作）。
    `--from <JSON>` 那一档认两种形状，并且**故意不凑结论**：只有列表 ⇒ 没有逐格读数 ⇒ 落 2；
    一份没有 `event` / `createTime` 的详情（真那份 `get-build-status -v` 就是这样）⇒ 认不出它是
    哪一类派发 ⇒ 落 2。判据宁可念「未校验」，也不拿形状像的东西凑一次出勤。

- **第一次真跑的就是今晚那一跑**（这条判据不是只过用例）：
  `出勤 ✓ cnb-hk7-1k5i5euak 在 0.8 小时前跑完`，`逐格：10 格有结论 · 判定 green`。
  那一次也正是 `0 0 * * *` 的第一落点 —— 00:00:17 无延迟补派、本仓那 10 格全 success、整档 ≈ 26 分钟，
  「五派发零跑完」那条账在这里断掉（读数与本档同批进台账）。

- **新用例十条**（`tests/check-daily-attendance.test.ts`）：绿的一次 = 出勤 / 绿的但超窗口 = 缺勤 /
  被取消 = **2 且说出「重跑，不是去查产物」**并点名被带下去没跑的格 / 起步即败 = 缺勤 /
  列表里没有每日派发 = 缺勤 / 取不到逐格 = 未校验 / 前缀认事件（五个算、五个**不算**，含
  `api_trigger_daily_x` 那种相似名）/ 多条里取最近那条 / CLI 真起进程读 `--from`
  （列表那份落 2、带身份详情那份落 0、真那份 status-only 落 2）/ `--from` 指不到文件时退 2 并说清。
  夹具按平台真形状带 `stage-N` 的 id —— `classifyStages` 只把那一族算成「本仓的格」，
  不给 id 走的是它「认不出形状就全收」的兜底支，两条路各留一个样本。

- **它不解决的那一半写清楚**：睡过去的那一次不会有任何执行者当场判它 —— 这条只能被下一次核对
  读成「已经 N 小时没绿过」。电源侧（`powercfg` 关睡眠 / 定时唤醒，#2114 出路 2）改的是这台笔记本
  本身，等业主点头，仓库侧不代做。
