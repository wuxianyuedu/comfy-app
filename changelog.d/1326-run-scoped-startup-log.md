## Fixed

- **设置页「启动日志」现在能翻到已归档的历史运行**（ISSUE #1326）：下拉列的是**一次运行一包**（本次运行 + `log/runs/` 各历史包，新→旧），不再只是「当前文件里还没被冲掉的横幅段落」。此前那套的可见性止于应用退出 —— 进程退出时 `current/` 被归档进 `runs/` 再清空，下一次启动文件从空开始，`runs/` 里那一包**没有任何界面能打开**（用户原话：「之前能切换的也是历史，不能用 runs 中找吗」）。
  - **正文要减去前一包**（这条是必需的，不是优化）：那几份 runtime 日志追加不轮转、而归档是「整目录复制」，因此包 N 的文件 ⊇ 包 N-1。不减的话点开「上一次」看到的是从装应用那天起的全部输出，与「分不清哪次是哪次」是同一个毛病。判据取**字节长度差**（前缀关系由复制语义保证），纯函数在 `src/lib/log/log-run-sessions.ts` 的 `runSlice()`。
  - **基准不可得时整份给出并说出来**：保留策略会删包（`runs/` 只留最近 20 次或 7 天），这时猜一个基准去切会把真实内容切掉 —— 比多显示糟得多。响应回 `baselineMissing`，界面提示「这次运行之前那一包已被清理，因此这段含更早的内容」。
  - 下拉文案 = `09-30 19:36:12 · 正常退出 · a1b2c3`：时刻（同一次运行的标题逐字相同，只有时刻能区分；历史包跨天，日期也要带）、退出形态（崩溃那次的日志形态与正常退出完全不同）、runId（它是 `grep <runId>` 的唯一入口，界面上不给用户就说不清是哪一次）都由端点的 `formatRunLabel` 拼好，视图直接渲染 —— 两边各拼一次必然有一边先漂。
  - 只列**真有该来源文件**的包：一台机器上 ComfyUI 可能一直没装，把那些包列进下拉，用户点开每一项都是空窗口 —— 那不是历史，是噪声。`.zip` 形态的包（保留策略对超 32MB 的包先压再删）不列，理由同前。

## Removed

- **「按文件内横幅切会话」整条读取链已删除**（`parseLogSessions` / `formatSessionLabel` / `LogSessionChunk`）：跨运行那一层改由运行包承担后，它**零消费方**。留着它的代价不是行数，而是下一个人会以为「横幅切分」仍是有效口径（§12.15 第二条：写不出谁在什么时候用即删）。
  - 横幅的**写侧照旧**（`session-banner.server.ts`，`▶ ComfyUI 启动会话` 等）：它的价值是人直接打开文件时看得出边界（一次运行里 ComfyUI 可能被启动/停止好几轮）。写侧的判据与读侧的消费面是两件事，写侧不该因为读侧换了口径就跟着消失。
  - `src/lib/log/log-sessions.ts` 只剩两端共用的契约（`LogSessionMeta` / `LogSessionsPayload`），文件头写清了这里曾经有什么、为什么删。

## Notes

- 端点的 `current/` 与 `runs/` 路径**不在端点里拼**：直接 import 启动编排的 `LOG_LAYOUT` / `currentDir` / `runsDir`（写方用它归档）—— 两边一旦漂开，表现是「归档了但界面看不到」，而两边各自都「看起来是对的」。与 `POST /api/logs/diagnostics` 复用 `exportDiagnostics()` 同一手法。
- 本次运行那一项的判据用**列表项的 scope**而不是 id 形态：它的 id 是 `run:current`，而 `packNameOf` 对它返回 `"current"`（真值），拿它去 `runs/current/…` 找文件必然扑空 —— 这条是写用例时真踩到的，表现是「切回本次运行正文空白」，因此补了一条反向验证。
