## Added

- **主题 token 的「产物侧」判据落到 e2e**（`e2e/theme-token-consumers.spec.ts`、
  规范 03 §3.6.1.1 末段）：门禁 ②「幽灵 token」与 ③「拼接 token 名」都活在**源码**层，
  而「源码里有声明」离「浏览器解析得到」还隔着 Tailwind 的 tree-shake 与 Next 的
  `@source` 根这两步。该用例真开浏览器断言四件事：
  1. 10 颗「被 SVG 呈现属性或 JS 取色消费」的 token 在**两态**下都解析得到具体颜色；
  2. **负控制** —— 不存在的名字必须读不到，且 `fill` 退成 `rgb(0, 0, 0)`、`stroke`
     退成 `none`。**这一半是必须的**：少了它，「十颗都读到值」可以是一次全绿的假探针。
     顺带把规范里写的静默失效形态从「推理」变成「实测」。
  3. 图标 token 对**它实际所托的表面**（`bg-node-accent`）≥3:1（WCAG 1.4.11 图形档）：
     浅底 4.13:1 / 3.31:1，深底 6.09:1 / 10.95:1；
  4. 「做成两档」不是空话 —— 同一颗 token 两态取值必须不同（原设计稿那两颗压在浅底上
     实测只有 **2.44:1 / 1.36:1**，所以两档是必需项而不是审美偏好）。
