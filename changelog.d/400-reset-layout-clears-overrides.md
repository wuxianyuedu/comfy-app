## Fixed

- **工作流编辑器：「重置布局」改成真的清除改动过的位置，子图里改完再重置不再全乱套（ISSUE #400 四审）**。三处根因连在一起：① 子图视图把拖拽坐标写成 `宿主:内部` 拼接键，而服务端读子图时只认裸内部 id —— 写入与读取两套口径，子图里拖过的位置一重新打开就丢，看着像「改了没保存 / 重置后全乱」；② 「重置布局」原来的做法是把进入时的快照写回去，可客户端拿到的坐标是服务端把**原始坐标**与**用户拖拽覆盖**合并后的结果，客户端分不清哪个键是覆盖，于是把覆盖值当原始值又存了一遍 —— 用户点的是重置，写的却是它要清的那份数据；③ 快照不完整时判据会让重置退化成「清空本地坐标 + 自动重排」，于是整张图的布局被换掉。
  现在：服务端读子图按宿主链拼键（裸键兼容），拖拽与读取同一口径；`workflow.update` 新增 `resetPositionsScope`，「重置布局」直接删掉本视图命名空间的坐标覆盖，读路径自然只剩工作流自带的原始布局；重置只清本层（顶层清裸 id 与导轨，子图清 `宿主:内部` 这一层），别的层级与别的命名空间原样保留；重置后重新拉取当前视图，不再留下中间态。
