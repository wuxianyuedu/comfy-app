## Added

- **`ui/page-header` 与「一屏只留一个名字」进契约**（§Components 新增一节）。这个载体件与它的判据是别人落的（ISSUE #1423），契约此前一个字都没提，于是它有两个被误读的方向：下一轮可能把各处仍在手写的 `.u-title-page` 当漏网清掉，也可能把这个具名件当重复实现删了。写进去的口径：
  - 它是**三件事的唯一出处**：屏级 `h1` 走 `.u-title-page` + `font-title`、一行副说明走 `.text-sm text-ink-muted`、右侧动作组 `shrink-0` 而标题带 `min-w-0 truncate`；
  - `description` **不是第二个名字**，是「答案在别处拿不到的那句话」；同义反复就传 `undefined`（不传即不渲染那一行，标题区立刻矮下来）—— 这条就是 #1423 的原始现场（侧栏「队列」→ 页签「队列」→ `h1`「队列与运行」→ 副标题再解释一遍轮转）；
  - **名字口径与形状口径分两头**：名字唯一出处是 `NavItems.tsx` 注册表（`label` / `viewLabel` / `pageHeaderTitle(view)`），执行者 `tests/page-name-single-source.test.ts`（在 `FIXED_STRUCTURAL_TESTS`）；字阶档是 P83，它只判「是不是 `.u-title-page`」，**看不见形状**；
  - **三处刻意不迁**按角色登记（工具条形态四件 / `WorkspaceFrame` 那一族 / 页头即数据的两屏），并写明「不迁的是形状，不是名字口径」与后两屏为什么仍要走这个件。

- **两处漏网（合并 #1661 之后当场补的，同一刀没收干净）**：正文第 261 行那段「这份文件是什么」里还写着 **83 个 `ui/` 基元**，Known Gaps 里那句举例写成「几天内从 89/89 走到 90/90」。前者是同一个抄数习惯的第三处，比正文别处更醒目（它是文件自我介绍那句，读的人就当权威口径用）；后者的时间尺度是错的 —— 实测 `53d69793` 10:03:19 → `ed881689` 13:24:46，是同一天的 3 小时 21 分，不是「几天」。现在分别改成「份数随轮次变、本文不抄，复算见 §Components 开头」与带提交号的实测尺度。**这条 self-inflicted 的教训**：宣布「不再抄数」的一刀里，grep 只按自己刚写过的那些数找漏网是不够的 —— 要按**形状**找（把 `docs/DESIGN.md` 里所有「数量词 + 名词」与「`x/y` 比值」两种形状一次性列出来筛（`grep -nE "[0-9]+ 个|[0-9]+/[0-9]+" docs/DESIGN.md`），再逐条判它是不是会漂的那类），自我介绍那一句、举例那一句都不是「读数」的写法，最容易漏。
