## Fixed

- **探针还原的凭据改成「进用例那一刻的字节」，不再拿 git 索引/HEAD 清工作区（ISSUE #2593 /
  规范 §11.16.2）**：`tests/check-doc-references.test.ts` 的收尾网此前是「`git status`
  说名单里哪一份脏 ⇒ 对那一份执行 `git checkout --`」，注释里写的前提是「脏 = 探针留脏了」。
  **这个前提不成立**：`git status` 分不出「探针留下的脏」与「这条分支上本来就在做的未提交
  工作」，而两者的处置逐字相同 —— 实测两次把同一分支上正在写的文档整档退回 HEAD（一次
  92 行新增，第二次靠 `docs/generated/` 的同名镜像才恢复回来）。后果不对称：探针没还原
  = 工作区脏（可修、看得见），把工作区当探针还原 = **未提交的工作没了**（只能重放，
  且 `git reflog` 里没有任何痕迹）。

  新增共享件 `tests/helpers/probe-restore.ts`（`snapshotPaths` 在模块加载时拍字节、
  `restoreToSnapshot` 只把探针动过的那几格写回去，一致就一次都不写；`null` 与空文件是
  两种状态 —— 前者是探针造的文件要删，后者本来就在、不许删）。落盘口 `ProbeIo` 是注入的：
  这一族的回归必须跑在**临时目录**上，为了防丢工作而拿真实工作区测它，自己就成了那次丢
  工作（口径同 ISSUE #2415 把 `doc:render` 那组改成夹具仓库）。

  同一族的第二处现场同批改掉：`tests/freshness-ledger-backend.test.ts` 往真实入库的
  `scripts/.e2e-freshness.json` 写一份假账造「机器分支」提交，再用
  `git checkout HEAD -- <文件>` 收回去 —— 那一格工作树上若正躺着本机跑出来的新账就被抹掉。
  所以判据认**三种形状**（`execFileSync` 的数组形、`git("checkout HEAD -- <文件>")`
  的字符串形、`restore --`），它们是同一件事的三种写法。

  自测 `tests/probe-restore.test.ts`（9 格，实测 816ms）进 `FIXED_STRUCTURAL_TESTS`：
  前 4 格在临时目录上钉四条性质（进之前就脏 ⇒ 跑完还是那份脏 / 探针新建件被删且一次写
  都不做 / 写不进去落 `failed` 并点名路径与原因、**不许**顺手退回 HEAD / `null` ⇄ 空文件
  分开），后 5 格扫文本 —— 全仓 `tests/**` 零命中（剥注释后再正则，口径的叙述里必然出现
  被禁的形态本身）、被禁三形各自命中、相邻正当写法不误伤（`checkout --quiet -b` 那种
  切分支形态第一版就被误伤过，实测点名在 `tests/premerge-push-trigger.test.ts`）、
  两份吃过这次事故的文件各自点名钉一行。

  **刻意拆掉的一格**：还原之后再用 `git status` 判「名单里还有没有脏文件」。这一档没有
  能力分辨那两种脏，而它一响就必然要么误报、要么把人指去退回别人的工作 —— 上线实测它把
  全部 59 条用例判红，因为工作区里正躺着一份未提交的文档改动，而那正是本单的混淆本身。
  现在只有「还原做不成」才红，红里点名是哪一份、为什么。
