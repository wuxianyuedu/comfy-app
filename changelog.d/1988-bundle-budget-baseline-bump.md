## Fixed

- **bundle 体积预算基线在**完整**产物链上重记（+1.3 KB gzip / 文件数 221 不变）**：
  PR #1988 的「生产构建」红在 `[bundle-budget] gzip 总量上升 2275.4 KB → 2276.7 KB`，
  而这次的两侧读数都取自同一条 `pnpm build`（`next build` → 链接修复 → 私密输入减法 →
  数产物 → 本判据 → 宿主冒烟），所以在给出归因之前**先确认了分母**。

  **归因是实跑出来的，不是推断的**（§13.5.4 例外流程的第一步）：同一份 `.env` +
  同一棵树，在**干净 `origin/master`（`e643d51f`）的独立检出**上完整跑一遍 `pnpm build`，
  读数是 `gzip 2275.4 KB / raw 9669.3 KB / 221 文件` —— 与基线逐字相同（基线就是那一刻的
  诚实读数，因此它此后没被任何一次改动换掉）；本分支同一条链是 `2276.7 KB / 9672.3 KB /
221 文件`。按内容指纹对齐：

  | 档     | 读数                                                                                                                                                                |
  | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | gzip   | `2275.4 KB → 2276.7 KB`（+1297 B）                                                                                                                                  |
  | raw    | `9669.3 KB → 9672.3 KB`（+3109 B）                                                                                                                                  |
  | 文件数 | `221 → 221`（不变）                                                                                                                                                 |
  | 逐文件 | 7 换 7，**逐个一一对应**（`+106167/-106070`、`+48501/-48834`、`+24223/-24310`、`+13337/-12800`、`+13159/-12654`、`+11449/-10870`、`+876/-877`），最大一对 **+97 B** |

  七对里含本 PR 新增的 `useLazyChunkFallback`（`ChunkLoadError` / `重新加载页面` 两串只在
  本分支产物里）与它被三个调用点引用带来的模块图重排 —— 每个 chunk 只动几字节，**没有一笔
  可回收的体积**，「压回去」没有落点。故按例外流程 `--update --allow-increase` 认账，
  `baselineRev` 落到 `0a618c1c`、`generatedAt` → 2026-10-17。

  **同批订正一处会把下一个人带偏的口径**（规范 §13.5.4）：诊断里「新增内容 N 个」的判据是
  「指纹在基线里找不到」，于是任何让整体产物换一批 chunk 的改动都会被读成几十个「新增」。
  现场两次数写进了规范：`next build` **单独**跑一次是 79 个新增（最大 103.7 KB），同一源码
  走完整条链后是 7 个。所以这一档「回 0」不是「没问题」的证据 —— **先答「读数的分母来自
  哪条命令、哪一版源码」**，否则那几十个「新增」会把人推向「先压回去」这条错路。
