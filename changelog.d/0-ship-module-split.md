## Changed

- **`scripts/ship.mjs` 889/900 行 ⇒ 按变化方向拆成四份**（规范 §13.6 那条链的实现）。
  余量只剩 11 行时再拆，就只能按行数切，而按行数切会把「同一条理由的注释」和它守着
  的代码分到两份文件里 —— 那批注释正是那几段代码唯一可读的证据。这次切的是**变化方向**，
  四份各自只朝一个方向变：

  | 文件                | 职责                                                       | 它因什么而变                                 |
  | ------------------- | ---------------------------------------------------------- | -------------------------------------------- |
  | `ship-core.mjs`     | 判断：参数、阶段表、三态码合成、平台 JSON 里哪一格才是终态 | 判据口径                                     |
  | `ship-exec.mjs`     | 效应适配：`cnb` 垫片怎么起、`stderr` 怎么接、临时文件落哪  | **只**因宿主而变（Windows 垫片 / argv 上限） |
  | `ship-platform.mjs` | 平台侧四段：PR / 轮询 / verdict / 合并并回读               | 平台动作                                     |
  | `ship.mjs`（入口）  | 本地三段（preflight / commit / push）+ 那一处 `codes` 记账 | 流程顺序                                     |

  拆完入口 **584 行**（另两份 160 / 349），三份都在同一个 900 硬闸下。平台侧那四段的
  形状约定写进它自己的文件头：**函数只返回结论，不改调用方状态** —— 往 `codes` 里追加
  与那句「结论：exit N」的收口只留入口一处，否则每个阶段都会自己下一次总结论。
  对外命令行、退出码与各段打印原文一律保持原形（这是拆分，不是改版）。

- **拆的第一刀当场抓到一处判据的取数面本来就是坏的**：`tests/ship.test.ts` 那条
  「计划 ⇄ 真执行面逐条对账」按**单个文件的源码**做正则提取，cnb 调用搬进
  `ship-platform.mjs` 之后它抽到 **0 条** —— 靠它自己那条前置断言报红
  （「一条都没抽到 ⇒ 提取正则坏了」），而不是两侧都空集、于是恒绿。取数面改成
  `scripts/ship*.mjs` **整个族**；改完拿变异复验一次：把新模块里那个工具名改一个字母
  ⇒ 那条对账红，改回 ⇒ 43/43 绿（这一格是那条断言存在的理由第一次被真用上）。

- **指向搬了家的实现的注释一并订正**：入口原先指向 `cnbSpawn` 那段（它已不在同一份
  文件里），改指 `ship-exec.mjs`；`tests/ship.test.ts` 里那句「与 `ship.mjs` 里
  `makeRunner` 的逐字同形」改成指向 `ship-exec.mjs` 的 `ExecResult` typedef，并写明
  「同形」由 `main({ run })` 的入参类型钉着、少一个字段（尤其 `stderr`）会当场报 TS 错 ——
  不靠一句注释自己担保。Skill 里那句「逻辑只有一份，在 `scripts/ship.mjs`」按四份各自
  的职责重写，避免下一个读者拿入口去找 cnb 的起法。
