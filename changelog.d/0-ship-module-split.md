## Changed

- **`scripts/ship.mjs` 865/900 行 ⇒ 按变化方向拆成四份**（规范 §13.6 那条链的实现）。
  触发面是真的：下一段要加的东西还没写，行数已经只剩 35 行余量，而 `check-infra-file-size.cjs`
  是**硬闸**（900 行即退 1，无 `--update`、无基线）—— 等到撞闸再拆，就只能按行数切，
  而按行数切会把「同一条理由的注释」和它所守着的那段代码分到两份文件里。
  这次按**变化方向**切，四份各自只朝一个方向变：

  | 文件               | 职责                                                       | 它因什么而变                          |
  | ------------------ | ---------------------------------------------------------- | ------------------------------------- |
  | `ship-core.mjs`    | 判断：参数、阶段表、三态码合成、平台 JSON 里哪一格才是终态 | 判据口径                              |
  | `ship-exec.mjs`    | 效应适配：`cnb` 垫片怎么起、`stderr` 怎么接、临时文件落哪  | **只**因宿主而变（Windows / argv 上限） |
  | `ship-platform.mjs` | 平台侧四段：PR / 轮询 / verdict / 合并并回读               | 平台动作                              |
  | `ship.mjs`（入口） | 本地三段（preflight / commit / push）+ 那一处 `codes` 记账 | 流程顺序                              |

  平台侧那四段的形状约定写进新文件头：**函数只返回结论，不改调用方状态** ——
  往 `codes` 里追加与「结论：exit N」那句收口只留入口一处，否则每个阶段都会自己下一次总结论。

- **拆的第一刀就把一处判据的取数面暴露成坏的**：`tests/ship.test.ts` 那条「计划 ⇄ 真执行面
  逐条对账」是把 `scripts/ship.mjs` 一份文件的源码当执行面正则抽的；cnb 调用搬进
  `ship-platform.mjs` 之后它抽到 **0 条**，于是靠它自己那条前置断言报红
  （「一条都没抽到 ⇒ 提取正则坏了」）而不是两侧都空集、恒绿。
  取数面改成 `scripts/ship*.mjs` **整个族** —— 这正是那条断言存在的理由第一次被真用上。

- **撤掉一条不存在的规范引用**（三处注释里都写着「本仓按规范只有一个叫 `cnb` 的远端
  （硬规则 6 / §13.6：远端名 `cnb`，无 `origin`）」）：`grep` 过 `docs/standards/13-提交与-code-review.md`
  ——**没有**任何一节给远端命名；硬规则 6 判的是「不在 `master` 上直提」。
  当场取到的事实是 `git remote -v` 在本检出**只有 `origin`**，而审计
  `docs/audits/2026-10-12-architecture-risk-review.md` R12-01 记的正是「并行检出里见过 `cnb`」
  ⇒ 那句话把「某台克隆机器上的事实」写成了「仓库的规范」，而它被三处注释当成设计理由引用。
  改成陈述真的那件事：**远端名是每台克隆自己定的，所以判据必须现算**
  （`resolveUpstream` 本来就是干这个的）。这一改只动文字，不动那条链的行为。

- **指向搬了家的实现的注释一并订正**：入口原先指向 `cnbSpawn` 那段（现已不在同一份文件里），
