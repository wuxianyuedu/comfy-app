## Changed

- **`pnpm ship` 的「本地两段」从 `ship.mjs` 搬进 `scripts/ship-local.mjs`（ISSUE #2189，规范 §13.6）**：
  这条不是顺手整理，而是**下一条改动已经撞闸**。当场读数：`ship.mjs` 在主干上是 **885 行**，
  而 #2199（`--close-issue` 收号 + 只补关那一格）的实现把它推到 **928 行** —— `check-infra-file-size.cjs`
  那条 900 硬闸（无基线、无 `--update`，出口只有「拆」）会把一次功能改动变成一次格式纠纷。
- **搬的是变化方向，不是行数**（四个模块各自因什么而变）：
  - `ship-core.mjs` —— 外部执行者的形状 → 三态结论（平台 build / PR / git 的输出形状变了才动它）；
  - `ship-platform.mjs` —— 平台侧四段：PR / 轮询 / verdict / 合并并回读（cnb 那一侧的形状变了才动它）；
  - **`ship-local.mjs`（新）**—— commit 与 push，含 `git status --porcelain` 三列状态的读法。
    这一族只动本地 ref 与远端同名分支，**不碰 cnb、也不需要平台回读** —— 与上一行正相反；
  - `ship.mjs` —— 装配 + preflight + 那一份 `codes` 记账（加一个阶段才动它）。
    装配、阶段顺序、以及「谁跑了、各段结论是什么」的那一处记账**仍只有一处**（`ship.mjs` 的
    `codes` + `finish()`）：#2156 那本账防的就是它长第二处，所以这次搬出去的是**效应**，不是结论。
- **等价证据换了口径**（本次自查里最容易被糊过去的一格）：`--dry-run` **不能**当 oracle ——
  它在阶段 0 之前就返回，被搬的那两段本来就走不到，「dry-run 输出没变」证明的是一条没执行的路径。
  本轮实际用的是**不改任何断言的 128 条用例**（`tests/ship.test.ts` 一字未动 ⇒ 它们钉的还是搬动前
  那句话）：`pnpm exec vitest run tests/ship.test.ts` = **128 passed**，`tsc --noEmit` 与 `eslint`
  两个文件均 0 错。命令行、退出码、打印原文、失败即停的位置全部不变；`{stop, codes}` 的返回形状
  也照搬动前的推码顺序逐字对齐（含「没读到证明 ⇒ 先 `NOT_RUN` 再 `GREEN`」那种两条同格的情形）。
- **两个已知代价写在这里，不藏在 diff 里**：① 「有没有要提交的东西」这个判断现在跨两个文件才能读全
  （装配层取三列、`ship-local` 用它们），换来的是加阶段不再撞 900；② porcelain 那条
  「**绝不能先 `trim()`**」的注释（ISSUE #2073 的根因）是**逐字搬**过去的 —— 它属于被搬的那段逻辑，
  留在原文件里会和实现脱钩。后续 #2187 / #2188 落地时都不必再动 `ship.mjs` 的行数。
