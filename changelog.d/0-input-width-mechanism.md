## Fixed

- **03 §3.8.1.1 里那句「调用处写的不保证赢」被补成有前提的命题**。原文把两件事写成一件：
  「基础件不要预设 `w-full`」（一条**取向**）与「预设了就没法覆盖」（一条**物理定律**）。
  后者只对**裸拼接** `className` 的件成立：

  | 件里的写法 | 调用处再写 `w-auto` / `w-56` |
  | --- | --- |
  | 裸拼接 `` `… w-full … ${className}` `` | 不保证赢 —— 同族两条都在产物里，胜负看 Tailwind 的**输出顺序** |
  | `cn(…, className)`（本库绝大多数基元） | **调用处必赢** —— 合并阶段就删掉前一条。实测 `cn("h-8 w-full min-w-0","w-auto")` → `h-8 min-w-0 w-auto` |

  为什么值得单独订正：拿着「不保证赢」这条普适说法去审 `ui/input.tsx`，下一步就是把它预设的
  `w-full` 拆掉「合规」—— 而那一拆**不是修越界，是换默认值**：所有不传宽度的调用点会一起退成
  `<input>` 的固有宽度（约 20 字符）。那是一次全站排版变更，得按排版变更处理（要读数、要复看），
  不该借合规名义顺手做。
