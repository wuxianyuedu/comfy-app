## Fixed

- **`docs/reference-facts.md` §3.6 把「这条判据管什么」的答案写死在自己的一部分上**（ISSUE #2389）。
  原文开头一句「判据分三类」，表里三行（C1/C3 路径存在性、C2 章节锚点、C4 台账命令口径）——
  而 `checkAgentsMdDrift()` 里其实**只有两个调用**（`checkAgentsMdPaths()` = C1/C3、
  `checkAgentsMdSectionAnchors()` = C2），C4 是 `checkLedgerCommands()`，在 `main()` 里**平级**被调。
  当场读数（`node scripts/check-doc-references.cjs` 的 `main()`，逐条点名）：
  ```
  checkFactKeysMatchDocs()  checkScopeCoverage()          checkLedgerCommands()
  checkGateStepIndexRefs()  checkGateStepCounts()         checkGateChecklistMatchesHook()
  checkPaths()              checkAgentsMdDrift()          // 它自己 = checkAgentsMdPaths + checkAgentsMdSectionAnchors
  + 对 SCOPED_DOCS 每份跑一次 checkDoc()
  ```
  ⇒ 「三类」与「五族」都不是现在的形状（本单标题给的「五族」也是一次快照）。
  这条脱钩的性质与 §3.7 整节讲的是同一件事（副本落后于源，而账面一条红都不出现），
  而执行 §3.7 的那份脚本自己就是受害者 —— 所以修法是**不再写条数**。
- 改法（只动文字，判据侧一字未加）：
  - §3.6 表头那句改成「**本节这张表只列与 AGENTS.md 直接有关的那两族**（就是上面那个函数里的
    两个调用）」，表里把 C4 那一行**摘掉**；
  - 表后新增一段「**本节不是『`pnpm doc:check` 管什么』的那份清单**」：列出其余几族各自的
    落点（登记表 ⇄ `FACTS` 键、§2 路径类引用、§3.1 范围守卫、§3.5 编辑文档裸值、§3.7 序号与
    裸计数、规范 §13.1 自查清单 ⇄ 钩子逐字一致），并把**唯一权威**指到 `main()` ——
    新增一族改的是 `main()`，本节永远只指到它、不抄它；
  - 原 C4 那行的两条口径（遍历集合是 `[AGENTS_MD_PATH, ...SCOPED_DOCS]`；AGENTS.md **刻意不进**
    `SCOPED_DOCS` 的理由 = 进则被复制成 `docs/generated/AGENTS.md` 那份没有 `{{占位符}}` 的
    同内容产物、误导读者去改产物；以及那条判据已有的说明性引用豁免）**原样保留**，
    挪到表下并写明它「与 AGENTS.md 有关但不住在 `checkAgentsMdDrift()` 里」。
- **为什么不新写一条「数一数有几族」的判据**（单子给的期望就是「判据侧不必新增」，这里把理由也落下来）：
  族数是随实现变的东西，写进判据等于再造一份会被同一件事过期的副本；真正承重的形状是
  「本节不许出现条数」。硬要机器判它，就得先给「文档里哪句话算声明」下定义 —— 那正是
  硬规则 24 / §12.18 说的「会误报一片的启发式扫描器」。
- 验证：`pnpm doc:check` 绿（`[doc:check] ✓ 文档引用与权威源一致。`）；
  `tests/check-doc-references.test.ts` 56 条全绿（它判的是脚本那几族的**行为**，不读 §3.6 的文字，
  所以这条改动不会让它红，也不会被它挡住 —— 这条账本来就归 review）；
  改后清点：`判据分三类` 在这一份文档里只剩**被引用的那一句历史**（新段落里作为被修掉的东西出现）、
  `C4` 作为表内标签已不存在（只剩一处「原表里那行 C4」的历史指称），而「台账命令口径」作为
  **判据本体的名字**在 §2 / §3.6 表末 / §3.7 三处按本体称呼 —— 三处说的是一件事，且都不依赖行号或标签。
  `docs/generated/` 里没有 `reference-facts` 的镜像（它不在 `doc:render` 的产物面里），
  所以这一条没有同批镜像要带。

  **没有定义处**了（而它长得完全正常，`doc:check` 不会红 —— 路径存在性判据判的是仓库相对路径，
  不判这种段内别名）。改成按**判据本体**称呼：「豁免与『台账命令口径』那条同族
  （`checkLedgerCommands()`，它的 AGENTS.md 边界写在 §3.6 表末）」—— 名字不随表格行数变。

  CP936 的 `A1C1` 都是**另一个名字空间**，没有第二处跨节引用这个标签。
- **第二遍（这一条是给第一遍记的账）**：第一笔落地后复读 §3.6，发现我自己还留着两处条数 ——
