## Fixed

- **体积预算的例外流程现在有签字的人了：带它合入的那条 PR**（ISSUE #2149；规范 §13.5.4 同步改写）。
  两处红话（判红那档的收尾、`--update` 拒涨那档）原先都写「**评审确认后**带 `--allow-increase` 重跑」，
  而那个抽象的签字者从来不存在 —— 六天内实到四笔账
  （#1988 `+1.3 KB` 10-17 / #2082 `+543 B` 10-21 / #2132 `+539 B` 10-22 上午 / #2149 `+41 B` 10-22 下午），
  **没有一笔是造成它的那条 PR 认的**，全部挂在主干上等下一次构建。代价不只是「多写一句话」：
  每笔要有人重做一遍「一次完整 `pnpm build` + 一次逐文件对账 + 一个专门 PR」，而挂着的那段时间里
  `每日生产构建` **之后的四格一天没有读数**（ESLint / 浏览器安装 / 全量 E2E / 全量单测 ——
  §13.5.21 记着其中两格的唯一执行者就在那条链上）。一条防劣化的判据成了四格出勤的堵头，
  与它存在的理由正好相反。
- **落点选「谁带进来谁签」，而不是给这类增量加一个自动档**。只有那条 PR 同时有三样东西：
  为什么加了客户端字节、before/after（同一次构建就量得到）、「压回去」这条路还来不来得及（还没合）。
  否掉的另一条是「净差小于 N 字节就自动抬 + 留痕」：那会把「有人说值」换成一个**可以被反复小步撞穿
  的阈值**，而 #1811 收掉各家棘轮的 `--update` 通道时否掉的正是这个形状。
- **顺手修掉那句让所有人都觉得「不是我的」的窄写法**：拒涨那档把触发面写成「新增依赖」
  （ISSUE #1781 那一版想到的只有它），而这四笔**全是代码增量** —— 台账 E4 那条线把
  `as` / `as unknown as` 换成服务端与客户端**共用**的运行时 schema，而「共用」在这里必然意味着
  它被打进客户端。这句话让每个人（包括刚写了 99 行共享 schema 的人）都不觉得这条流程是自己的。
- **加一条「不是你的账：立案，别替别人签」**。判红那档本来就会打
  `其后本检出上有 N 次提交`（#2082 那条归因通道），拿它自证：那些提交都已进主干、且没有一笔在你
  这条线上 ⇒ 这是上一批人留下的。替别人签的代价是**这笔体积的来源从此不可追** —— 签的人不知道它
  换来了什么，而那正是这条流程唯一在防的东西。
- ⚠️ **执行者是判红那句话本身，不新增启发式扫描器**：「哪笔改动动了客户端可达图、加了多少字节」
  没有便宜的可靠量法，写一个只会多一条会静默失效的清单（§12.18 / 硬规则 24）。
  便宜的独立读数已有 —— 单跑口 `api_trigger_build`（§13.5.23），但它**不改本地账**，
  认那一次 `--update` 读的还是本地产物。
- 新用例一条（`tests/check-bundle-budget.test.ts`，25 条）：两处出口都必须出现
  「谁把这批客户端字节带进来的谁签」/「造成它的那条 PR」，且**不许**再出现「评审确认后」；
  反向复算实测过 —— 把那句话改回旧写法，这一条当场红（`1 failed`），改回来又绿。
  同批订正 `tests/helpers/ratchet-refusal.ts` 头注里对这一形的描述（它还写着旧的「评审确认后」）。
