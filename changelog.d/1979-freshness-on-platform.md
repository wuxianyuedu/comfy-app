  `vitest` 那一档（以及 e2e / 产物两档）此前只有「本地钩子判、本地脚本跑」这一条链，
  平台侧即使在跑**同样内容**的步骤，也不经过跑法脚本 —— 于是「这一步绿了」只落在日志里、
  账面上一个字不变，本地「改了就当天跑」照旧拦人。

  **判据一个字没改，多的是执行者**（同 §13.5.17 的口径）：

  | 位置 | 改动 |
  | --- | --- |
  | `.cnb.yml` 的「生产构建」 | 入口从裸 `pnpm run build` 换成 `node scripts/artifact-run.mjs`（它内部就是那条命令，外面多出来的一跳是**记账**） |

  ## 读数：`上次自证` 带上**具体时刻**，不再只有天数

  `上次自证 —— e2e：今天` 这种读数里，日期是**判据**要的、时刻是**人**要的 ——
  「今天 08:45 跑过」与「今天 23:50 才跑过」在天数口径下**同形**，而排障时决定性的
  恰好是差出来的那几个小时。现在每一档由 `freshnessReading` 拼成
  `距今多久（具体时刻）`，时刻是**本地时间 + 显式时区偏移**（`2026-10-17 08:45 (+08:00)`）：

  - **本地时间**：判据按本地日历日（`isSameLocalDay`），用 UTC 打时刻会在东八区
    把 00:30 的提交显示成昨天；
  - **带偏移**：只写 `2026-10-17 08:45` 在时区不同的两个人眼里是两个瞬间。

  账里存的 `verifiedAt` **照旧是 ISO UTC**（跨机器可比、无歧义），变的只是给人读的那一句。
  顺带：`freshness-gate.mjs --ledger`（人主动看账面）现在把 `who` / `how` 一并打出来 ——
  账存在的全部意义是「谁、什么时候、按哪条命令复核的」，此前只打第三栏的半句。

  ## 边界：这一步**不**替本地那笔账作证

  CI 的工作区是只读检出，`writeFreshness` 写下的账留在这个一次性检出里、**不落回任何分支**。
  把它落回去要动「CI 能不能回写分支」这条平台能力（`repo-code:rw` 在 push / 定时任务这类
  **可信事件**上有；⚠️ PR 类事件是**不可信事件**，那时只有 `repo-code:r` ——
  这条正好是「不能回写 PR 源分支」的另一半理由），但 `master` 走分支保护、回写还会
  产生新提交，进而再触发一轮流水线。
  **本档不动它**：平台侧这一步的价值是「**源分支上账是旧的**会在合并之前被机器说出来」，
  而不是「本地那笔账可以不管了」—— 两处判的是同一个事实，账只有一个作者（本地的提交）。

  ## 回写仓库：形状已定（**设计落在这里，实现另开一笔**）

  口径写进了规范 §13.5.4，要点与**实测**依据：

  - 回写推给**机器自有分支** `ci/freshness-ledger` —— 不推 `master`（有分支保护）、
    更不推作者的源分支（会让他的下一次 `push` 变成 non-fast-forward，且**每次回写都会
    推动 PR head**）；
  - **它不触发流水线，两条独立机制**：① 本仓 `.cnb.yml` 的**唯一分支键是 `master:`**，
    推 `ci/*` 没有匹配的配置 ⇒ 不产生构建（2026-10-17 实测：两个探针分支各推一笔，
    构建历史里没有对应条目）；② commit message 带 `[ci skip]`（官方口径，
    在 `push` / `commit.add` / `branch.create` 上生效）。⚠️ ② **掐不掉 `pull_request`** ——
    这正是「不能回写 PR 源分支」的机器层面的理由；
  - 触发者是**定时任务**（可信事件 ⇒ 同仓 `repo-code:rw`），不是 PR ⇒「谁能让账被写」
    不在任何作者手里；
  - 读取侧仍是**只读本地 ref、不发网络请求**（钩子离线），机器分支是**第二出处**、
    只在工作树那份缺该档时兜底。

  三半都由 `tests/doc-check-hook-wiring.test.ts` 的「新鲜度账：平台侧的第二个执行者」
  一组钉住（平台侧那一步在、入口是跑法脚本、**本地那一半不许撤**），顺序约束另有专条。
