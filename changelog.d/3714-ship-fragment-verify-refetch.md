## Fixed

- **ship 合并验真的「碎片不在」先复取一次主干再下结论，判 false 时念出比对对象**
  （ISSUE #3714）。squash 回执与 git 服务端 ref 传播之间有窗口：合并回执已给
  `is_merged=true` + 合并 sha，而紧跟着的那次 `git fetch` 可能还取在上一笔上——
  此时按合并 sha 查碎片会得到假阴性，自动关单与清分支被误跳过（现场：PR #3708，
  事后 `git show` 证明碎片就在合并提交里）。修法：首查不在 ⇒ 重取一次主干再判；
  仍不在才落红，并把比对对象（哪个合并 sha、缺哪些碎片路径）念进日志——
  「没找到」从此可归因（本地滞后 / 传播窗口 ≠ 平台没落地）。
