## Added

- **主题色门禁补两条「反向」硬闸**（`scripts/check-theme-colors.cjs`、规范 03 §3.6.1.1）：
  写死色值那一侧已经收到零基线，但零基线管不到两个反方向的失效，两条都不报错：
  - **死豁免 = 负债**：登记在 `EXEMPT_TABLES` / `EXEMPT_FIXED_DARK` 上却一处都不再命中的
    条目，会把那个文件**今后**新写的死色值一并静默放行。现在命中不了就 `exit 1` 并点名。
    口径按**文件**、不按条目 —— 同一份文件可以有多条豁免（整文件 / 按顶层声明 / 按行），
    命中归到谁头上取决于数组顺序，按条目判会把「被前一条遮蔽」误报成死条目（实测第一版
    就是这么误报了 2 条活豁免，已改成按文件）。
  - **幽灵 token**：`fill` / `stroke` / `stopColor` 呈现属性上写 `var(--color-x)`
    而 `--color-x` 在 `src/**/*.css` 里从没声明（被注释掉的声明不算声明）→ 阻断。
    这类「半截 token 化」的表现是图标变黑块、描边图形整条消失，且没有任何报错。
- **两条判据的边界写进规范，不假装全覆盖**：带兜底值的 `var(--x, …)` 不判（取不到也有色）；
  Tailwind 裸变量 `text-(--x)` / `w-(--x)` 与 `style={{}}` 一律不判 —— 实测那种形态里
  「CSS 查无此名」是常态（base-ui 注入 `--transform-origin` / `--available-height`、
  宿主代码注入 `--sidebar-width`：310 处引用里 43 处如此），硬判等于造一台误报机，
  那部分留给 review（同 §12.18「不要再写会静默失效的启发式扫描器」）。
- `tests/check-theme-colors.test.ts` 加 8 条用例钉住两条判据的正反两面（含「注释里的声明
  不算定义」「带兜底不判」「真实仓库 seed 5 颗 token 必须有定义」）；测试夹具的 `run()`
  顺带改成 `spawnSync` 并拼接 stderr —— 告警走 `console.warn`，旧夹具成功分支只拿得到
  stdout，等于测不到「只提醒不判失败」那一半。
