## Changed

- **测试超时与并发按实测重定**（`vitest.config.ts`，规范 §11.13 新增一节）：vitest 的
  默认预算（用例 5s / 钩子 10s）低于本仓库的实测下限 —— **串行隔离跑**的最慢单条用例
  已经 5469ms（客户端打包可达性、全 `src/**` DFS）、4770ms（库表就绪判据），一条贴着
  默认值、一条在默认值之上，即「不开并行都会红」。并行时约 15 个 worker 各起 Node /
  git / prettier 子进程，一轮实测 28 条报 `Test timed out in 5000ms`、2 个主题用例报
  `Hook timed out in 10000ms`。现取「最慢实测值 ×3.6」的预算（用例 20s / 钩子 30s），
  并把并发压到 `maxWorkers: 8`（16 逻辑核约 8 物理核）。同一台机器同一份代码的全量
  三档实测：默认并发 + 默认预算 红 20 文件 / 42 用例 / 599s → 只抬预算 8 / 18 / 461s →
  再降并发到 8 **4 / 14 / 659s，且超时类红归零**（剩下 14 条全是真实断言失败，属启动器 /
  壳 / 产物三条线）。代价写清楚：墙钟 +43%，买的是「红即可归因」，判红不再需要先补一次
  隔离重跑。各用例上手写的显式预算（10s ~ 120s）仍然优先。
- 同步改掉 `docs/standards/13` §13.5.2 里「顶穿 vitest 默认 `testTimeout`」那句的口径：
  默认值已按实测抬升，但那条教训本身不变（慢的是子进程冷启动，不是断言）。
