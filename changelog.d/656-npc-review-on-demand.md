## Changed

- **「PR 评审」改为按需召唤的 NPC，不再需要任何平台侧流水线配置（ISSUE #656）**。
  `.cnb.yml` 删除后（#623：免费额度 160 核时/月用不起），全量单测 + 覆盖率门槛、
  构建产物护栏、E2E 这几条「原来只在 CI 上跑」的判据一度没有执行者，规范 13.5.3
  把它们登记成了欠账、却没写欠账的**去处**——读到的人很容易理解成「把配置贴回去」。
  现在口径补完整（规范 **13.5.4「按需召唤」的那一层**）：这一层**不写任何配置，
  因此不花核时**。平台的 `issue.comment@npc` 机制会把 Issue / PR 评论里的
  `@npc/<slug>(<name>)` 解析成召唤事件——仓库里不需要任何文件承载它，本仓库的
  `.cnb.yml` 删除后仍能被 `@CodeBuddy` 唤起跑任务，就是这个机制在生效。所以
  「走一轮 PR 评审 / 全量单测 / 产物护栏 / E2E」的动作就是**在 PR 里 `@` 对应 NPC**：
  人 `@` 一次就跑一次，不 `@` 就一次都不跑，与 #623 的额度结论不冲突。
- 同步改写三处会误导的表述，避免「评论区按需召不回来、只好把 `.cnb.yml` 贴回去」：
  - `.githooks/pre-commit` 第 2 步的 ⚠️ 注释：R5 `--strict` 棘轮的「没有执行者」
    改为指向按需召唤，并写明**不是**把 `.cnb.yml` 贴回去；
  - 规范 13.5.3 表尾的一句「要恢复哪一条，就按『先把它做成可接受的耗时』再挂回
    `.githooks/pre-commit`」改为「去处不是把配置贴回去，而是 13.5.4 的按需召唤」；
  - 规范 11.7 的「完整验证」命令块补一句「这组是按需跑的」，并指向 13.5.4。
- 规范 13.5 的 24 步门禁清单后补一段说明：`test:coverage` / `build` /
  `check-standalone-contents.cjs` / E2E `@critical` / `db:push` / R5 `--strict`
  是**按需那一层**，不要塞回每次 commit。13.5.4 同时写明三条边界——机器判据仍然
  只在 `.githooks/pre-commit`（按需召唤是「另一次运行的机会」，不是新的唯一事实源）、
  不要为它写 `.cnb.yml`、不要在自动触发的流水线里 `@` NPC（`@` 是人的动作，
  写进流水线就等于按事件触发，绕回被删掉的形态）。
