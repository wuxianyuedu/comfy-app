  `scripts/check-app-port-vectors.cjs` 取 Python 侧回答时带 30 秒预算，`python3 --version`
  探测带 10 秒预算。第一刀（已合）把超时与「四侧真不一致」拆成两条出口，但判定没放宽 ——
  没拿到测量照样退 1，一笔纯文档提交仍会被它拦在 A/B/C 三组（约 4 分钟）之后。
  这一笔把剩下的那一格口径拍掉，**与 C 组同构**：让**第二遍测量自己的形态**说话，
  不看 `os.loadavg()`（Windows 恒 0，C 组早在 ISSUE #1747 就否掉了这条判据）。
  第一遍超时 ⇒ 打一行日志、当场再取证一次；第二遍答上了就按第二遍判（绿或真不一致照旧，
  **不许把已取证的一侧继续点名**）；两遍都只是超时形态 ⇒ 记「未校验」并**放行**、逐条点名。
  顺带关掉一句一直静默的账：`missing`（`--version` 非零退出，**不是**超时）以前是
  「那一侧既不参与比对也不报红」—— 于是「四侧一致」悄悄变成「三侧一致」而输出一个字都没有；
  现在它同样进「未校验」，并明说「这一侧本轮没有取证，四侧实际只答了三侧」。
  放行不等于绿：标题是「通过，但**未完全取证**」，并说明同一趟里 Node 侧逐条真跑、
  Rust / PowerShell 侧的锁引用照旧在判。真不一致**一次都不复跑、照旧阻断**。
  代价与触发面：只有第一遍超时才多花一趟（最坏探测 2×10s + 真跑 30s），一切正常时不复跑。
  判决抽成纯函数 `decidePythonVerdict`，网格（answered / timeout / missing × 有没有第二遍）
  在任何平台逐格钉住 —— 夹具造不出「30 秒不回答的 Python」，那一格由真机高负载场景负责。
