## Fixed

- **双击启动弹出红色「启动失败：Next.js dev server 提前退出（exit=0）」，而 `nextjs-stdout` / `nextjs-stderr` 里只有 `[dev.mjs] COMFYAPP_PORT=…` 和 pnpm 回显的启动命令行，用户完全看不出原因**（ISSUE #553）：Prebuilt 链路的生命周期本就是「壳在，dev server 才在」——桌面壳一退出，dev-launcher 立刻 `taskkill /PID <dev> /T /F` 回收整棵进程树，而 `/F` 走的 TerminateProcess 不给进程任何收尾机会，dev server 于是表现成「exit=0 且几乎无输出」（连 `Ready in xxs` 都没来得及 flush）。触发它的常见成因是**关掉启动页 = 放弃本次启动**（壳按约定 `exit(0)`），也可能是壳被另一次启动顶掉 / 任务管理器结束 / 壳崩溃——三种成因退出码一样，而旧文案只写 exit=0，等于把用户引向「dev server 编译失败」这条没有现场的排查方向。现在判定 dev server 退出时带上壳侧证据再定性（`Test-ShellLaunchAbandoned` 读壳 stderr 的 `launch abandoned` 标记 + 壳是否已退出 → `Get-DownstreamExitKind`）：用户放弃 → 写 info 并按**正常退出码**收尾，不再弹失败框（与 python 启动器的 `cancelled` 语义一致）；壳被外部终止 → 提示明确指向 `log/shell/shell.log` 与 `log/launcher/dev-launcher-stderr.log`；壳仍在 → 保持原有「dev server 自身退出」提示与 stderr/stdout 现场。成因与判据写进规范 §5，回归测试见 `tests/dev-launcher-downstream-exit.test.ts`。
