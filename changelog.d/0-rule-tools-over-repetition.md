## Added

- **新规定 §12.20「重复的手工流程收成有名字的入口（能做成工具的就做成工具）」**
  （同步进 `AGENTS.md` 硬规则 27 与 §13.1 提交前自查清单）。口径来自业主在会话里的那句话：
  开发中遇到可复用的逻辑，**能做成工具的都尽量做成工具**，免得每次都重复踩坑。
  它管的是**动作面**，与硬规则 24 / §12.18 的分工写死在正文里：那条管代码落笔前别抄实现，
  本条管别把同一串命令人肉敲第三遍；§12.12 / §12.16 抓的是**已经抄出来的**代码孪生，
  而命令序列不在 import 图里，任何扫描器都看不见。

- **标本就是 `pnpm ship`**：在它之前「分支 → 提交 → push → PR → 等 CI → 合并」由每个执行者
  临时手写一遍，同一件事长出 N 套走法，每一套都可能在自己没想到的地方静默判错。实测那一套是
  **把平台信封上的 HTTP `status: 200` 读成流水线终态**（非 JSON 输出里两个字段同名，
  `grep '^status:'` 恒取到 200），于是对一条从没跑起来的 build 白轮询几十次。
  收成入口之后这类错只会被犯一次，并且会在入口自己的用例里红。

- **形态表给出四种出口与各自的登记面**（`package.json` 脚本 / `scripts/*.mjs` 判据 /
  `tools/<分类>/*.ps1` / 仓库外一次性探针），每条都点名它的执行者
  （`check-on-demand-duties.cjs`、`check-gate-executors.cjs`、`check-ps1-consistency.mjs`）——
  「做成工具」不等于「随便挑一种放」，登记面缺哪一格就有一条判据红。

- **四条硬约束写在条文里**：入口只编排既有判定、不另立第二套结论；不许藏 `--no-verify`
  那类绕过通道；降档 / 跳过必须被念出来（`--light` 那一族同源）；效应必须完整转述
  （转述型工具丢 stderr 是这一族最重的事故）。抽的门槛与 §12.15 第三条、§12.18 同口径：
  ≥2 次真实发生过的手工执行，只做一次的先把正确走法写进文档，别急着写脚本。

- **顺带实测掉一条看起来很能机器化的判据**（写在 §12.20 末节，防止下一个人再试一遍）：
  「文档里出现的 `pnpm <名>` 必须是 `package.json` 的脚本」。当场扫 48 份文档拿到 52 处
  「不在脚本表里」的命中，而命中几乎全在三类误报里 —— `pnpm tauri` / `pnpm playwright`
  那类是 pnpm 直接解析的 `node_modules/.bin` **二进制名**（名字空间是三层：脚本 / 本地 bin /
  pnpm 内建动词），`pnpm v12.4.1` / `pnpm ENOENT` 是散文里提到 pnpm 这个词，
  `pnpm check:visual` 是**历史叙述**（那条入口连同 `GATES.visual` 已被撤销，文档讲的是撤掉了什么）。
  第三类尤其致命：文档合法地会写已经不存在的入口，那不是漂移是记录。这一格的兜底用已有两条
  （`check-doc-references.cjs` 判路径与 § 锚点必须存在 + review 读语义）。

- **索引那行顺手补了缺的两格**：`docs/README.md` 的 12 章一行里原本只列到 12.18，
  12.19（barrel 把重依赖拖进入口静态图，ISSUE #1777）落地时没登记 —— 正是这条新规定要治的形状，
  当场补上，同批带上 12.20。
