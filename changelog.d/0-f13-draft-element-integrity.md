## Fixed

- **工坊草稿里「形状不认识」的元素不再静默流下去**（台账 F13″）：`parseDraftDto` 与服务端镜像只判容器（`Array.isArray`），元素是 `as Character[]` / `as Shot[]` 强转 —— 于是「一条 `styleTags` 是字符串的角色」照样能从 localStorage 进数据库镜像、再喂进 prompt 拼装与 React key。按已定口径走第三条路：**既丢弃**（等于静默删用户自己的数据、没有撤销）**也不继续不判**（现场是「生成结果莫名其妙」或「两行卡片长得一模一样」，比丢数据更难归因），而是**原样保留 + 标成需要修复 + 界面给出口**。
  判据是**读时派生**的，不是草稿里的一个字段：`workshopDraft` 表一列一字段，往 DTO 顶层加标记**没有落库的家**（`draftToRow` 不认识它，写进去就在下一次读时消失）。派生还白拿一条性质 —— 结论永远与当下这份数据同版本，不会出现「数据修好了而标记还挂着」（那正是画布镜像那一族的账）。

## Added

- `src/lib/workshop/draft-integrity.ts`：三类元素共一张检查表，**只报下游无保护解引用会真出事**的字段，每条原因写着炸在哪（`styleTags` 非数组 → `.join` 抛错；`prompt` 非文本 → `shot.prompt.trim()` 当场抛；缺 `id` → 生成任务回写找不到这一镜；`status` 不在已知取值 → 完成度计数算错一边）。可选字段整体缺席一律不报 —— 否则每条老草稿都被念一遍，提示条三天内就会被当噪音关掉。状态值域直接引 `types.ts` 的 `SHOT_STATUSES`，新增一个状态不必改判据。
- `src/components/workshop/DraftIntegrityHint.tsx`：常驻横幅 = 汇总句 +「是哪几条、坏在哪」的清单 + 跳到那一类元素所在的屏。刻意**不进** `notice` 那条通道（那条说的是「刚发生了什么事」，可关闭、新提示替换旧提示；而这里是数据的当前状态，关掉等于把脏数据藏回地毯下），也刻意**不复用** `StageHint`（那块写死「去完成 →」，为省一个文件把「数据坏了」指成「你还没做完」是把话做错）。依赖方向是视图 import lib：判据那一侧不认识页签，`KIND_TAB` 映射留在组件里（硬规则 22）。
- 两扇门共用同一份判据，并在文件头写明：服务端镜像 `parseDraftDto` 与浏览器缓存 `draft-store.ts::parseDraft` 都注明「元素原样留着，形状问题去 `draft-integrity` 判」；新增第三种元素或给现有元素加**必填**字段时判据表要同步。

## Tests

- 34 条用例（判据 27 + 出口 7）。其中一组是**配对断言**：同一份脏数据喂 `parseDraftDto` 之后，① 那条元素必须还在原下标上（改成过滤就是红 —— 那是静默删用户数据），② 它必须同时被 `auditDraftElements` 点名（漏判就是红 —— 那是「保留 = 不校验」的老路）。两边各红一次才算锁住这条口径。另有双向不挑刺证明：干净草稿（含可选字段缺席、空数组）一条都不报 —— 只测脏的那一半的话，判据会一路报到把正常数据也念成坏数据。
- 覆盖登记 `coverage.include` + `thresholds` **两处同批**：判据本体四维满档；出口组件分支实测 87.5 → 门槛 85，没盖到的那一支是 `lines[0]?.tab ?? "script"` 的右半边，**按构造不可达**（`issues` 为空时组件已早退）。没有为凑数去 mock 一个「有问题但一条元素都组不出来」的输入形状 —— 那测的是今天不存在的输入，数字好看而判据是空的。
