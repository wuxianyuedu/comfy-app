## Fixed

**回读格读到 0 条不再被兜底的 403 判成「没权限」**（ISSUE #3136）：

- `scripts/ci-github-verdict-read.mjs`：`main.empty`（主路径 200 但认领不到本跑，
  即「读到 0 条」）此前与同轮兜底 checks 的 401/403 拼成「两条路径的权限这枚令牌
  都没够上」并当场 exit 2 —— 实测 PR #3133 那一格 3.8s 就退掉，45m 轮询预算一秒
  没用，而令牌的 `actions: read` 是生效的（否则主路径会是 401/403）。
  现在 `empty` 按 30s 间隔继续轮询主路径到预算耗尽；耗尽仍 0 条 ⇒ exit 2，原因写
  「读到 0 条（GitHub 侧没起跑 / display_title 未认领本跑）」。
- 「权限」这句只在**两条路径都被拒**时才说（`reportBothDenied`）；兜底的 403 降级为
  事实记录「兜底不可用（无 checks: read，仅降级读数）」，不参与结论、不再催补权限。
- 兜底 checks 的条目只在**主路径被拒**时才承重（那时它是唯一读数）；主路径读到 0 条时
  兜底读到什么都不改变「本跑还没起跑」那一判，不许顶掉主路径的形状。
- 三态语义不变（0 绿 / 1 红 / 2 没结论），`--readout` 仍只折对外退码那一位数。
- 用例按行为重写：新增「0 条不死退、按 POLL_INTERVAL 继续轮询」「预算耗尽后原因文案」
  「不许出现补权限话术」三条；假件里每轮**新造** `Response`（body 只能读一次，
  复用会抛 `Body has already been read` 而被误诊成 egress 故障），时钟只由 `sleep` 推进。
