## Fixed

- **`/api/custom-nodes` 的 GET 侧此前零执行者**（台账 E7 的最后一格，收完之后 E7 归零）：这个端点是自定义节点面板唯一的「读盘 + 探测」入口，摘要按 `(size, mtime)` 指纹短路缓存、报告原样透传、冷路径推 ndjson / 热路径直接 JSON。26 条用例把这三件事逐分支钉住（清单不存在 / 是标量 / 是坏 JSON / 包条目不是对象 / `nodes` 缺省、指纹相同不必重读、`size` 或 `mtime` 任一变了必须重读、stat 取不到时**不许**缓存、报告坏 JSON 按 null 而不是抛、5 秒 TTL 内外的两种返回形态、一个扫描根都没配、流内部起进程失败要出一条 `error` 事件并收尾、`byPath` 的键归一）。门槛按实测登记 35/35/45/40 → 77/70/83/80；余下没盖到的是 POST `streamParse` 里解析器 stdout 协议那几支，归下一批，没有为凑数造假事件。
- **一处守卫选错，把「清单坏了」冒充成「解析过了、0 个节点」**：`readManifestSummary` 用 `isRecord` 判 JSON 体，而 **`isRecord` 认数组** —— 根被写成 `[]` 的坏清单会走完整份投影，产出一份形状正确、内容全空的摘要。界面对「还没有清单」和「清单有 0 个节点」给的是两种话（前者提示去点解析，后者提示 ComfyUI 里确实没有自定义节点），这正是台账 E9 那一族「不同因同形」。改成仓库里现成的 `isPlainRecord`（`~/lib/is-record` 的注释早就写着「需要 JSON 对象体这一层时用本函数」），`nodes` 写成数组时也不再拿元素个数冒充节点数。
- **两条夹具自身的不隔离**（写完 GET 用例做变异时才照出来，它们会让「绿」不代表「跑过那条路」）：① 被测模块的 `discoverCache` 是模块级的、TTL 5 秒，同文件内跨用例存活 —— 后一条用例沿用同一个父目录就悄悄落进「全命中缓存」那条热路径分支，判的分支与它想判的不是同一条；现在每条用例发一个自己专属的扫描根。② `mockImplementationOnce` 的队列**不被 `clearAllMocks` 清**（它只清调用记录，`mockReset` 才清实现与队列），上一条排完没用完的假子进程会漏到下一条头上，表现是「换个顺序就红」；现在三个替身每条用例显式重置。造指纹的 `mtime` 也不再每条用例归零 —— 归零会让「第一次读」命中上一条留下的摘要缓存。

## Added

- 规范 §11.2.1 新增一条口径：**用例之间必须显式切断「同文件内的共享可变状态」**（模块级缓存给每发一条用例一个专属键；替身每条 `mockReset`；造指纹的计数器别归零）。
- 变异七刀各红各的（退回宽松守卫 / `nodes` 按元素数 / 摘掉缓存短路 / 指纹取不到也缓存并命中 / 空扫描根也走热路径 / 报告读不出时伪造空报告 / 探测缓存 TTL 近乎无限）。其中「指纹取不到也缓存」那一刀必须**同时**改读侧 `stamp &&` 与写侧 `stamp !== null` 才看得出差别 —— 两处互为兜底，只拆一半的「变异」在行为上没有任何后果，不算证据。
