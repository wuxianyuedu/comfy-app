## Changed

- **`repository-task.ts` 抽出 `repository-task-impl.ts`（P3 §5 Phase 2-A-1）**：12 个 exec-chain 方法（findExecutionMeta / updateProgress / markRunning / finalizeSuccess / finalizeFailure / cancel / finalizeFromReaper / findStatusAndPromptById / replaceLogs / listStaleQueued / listStaleRunning / createImages）的 SQL 主体整体搬到 `./repository-task-impl.ts` 的 `createTaskRepoImpl(db)` 工厂；`TaskRepository` class 里对应 12 个方法各 delegate 一行 `(args) => impl.method(args)`、签名通过 `TaskRepoImpl["method"]` 反推与 impl 单点绑定。设计依据 P3 §5 ADR 附录 §11.1（`docs/superpowers/specs/` 目录下 `p3-phase2-executor-host-design.md`）。
  - **为什么是 impl + delegate、不是「class 参数化 db」**：现 `TaskRepository` extends 基类 `DrizzleRepository<Task>`、基类也静态引 `db`；把整条构造链改成 db-param 会波及全部 12 个 repository-\*.ts 子类，是「数据层整体双宿主」议题（ADR §11 明确不做）。exec 链**只用**这 12 方法、且**没有一个**走 relational query（`db.query.task.findMany`），所以抽出来 scope 小、破坏面零。relational 三方法（`findById` / `listByUser` / `findByProject`）留在 `repository-task.ts`、host 不加载。
  - **不孪生**（§12.12 判据：逐行重合 ≥75% **且** 两边 ≥60 行）：SQL 主体只活在 impl；`repository-task.ts` 的 delegate 每行是 `(id, ...) => impl.xxx(id, ...)` 的转发，与 impl 里的 select/where 结构完全不同形态。`check-code-duplication.cjs` 实测「孪生对 0 对」保持。
  - impl 文件是 §18.4 **第三类**（无 `import "server-only"`、只有 `drizzle-orm` + `~/server/db/schema` + `../task-state` + `./repository-task-impl-types`）；顶层没有 Node 内建 value import，因此**不进** scanner 的 `nodeImports` / `unguarded`。`TaskRepoDb` 类型抽到独立 `repository-task-impl-types.ts`（`import type` 无运行时），impl 与测试共用、避免两处漂移。
  - 新增 `src/lib/core/repository-task-impl.test.ts` **25 条契约**（12 方法各至少 1 条正/反例）：`updateProgress` / `markRunning` 的 compare-and-set 判据（三种终态行返 false 不改写）、`finalizeSuccess` 有/无 `workflowSnapshot` 两分支、`finalizeFailure` undefined 与空数组归一存 null、`replaceLogs` 未知 id 走 `.catch(→undefined)` 咽下、`listStaleQueued` 的 4 条件 AND 逐个破一条都不返、`listStaleRunning` 与 Queued 版对偶 + `promptId IS NOT NULL`、`createImages` width/height 缺省存 null。用现有 `tests/helpers/test-db.ts`（`drizzle(createClient({url:":memory:"}))` 那套），一次 `tdb as unknown as TaskRepoDb` 断言解决「drizzle 名义类型不同、结构上 builder 链一致」的接线。
  - 顺手清 `repository-task.ts` 里不再用的 drizzle 函数 import（`notInArray` / `lt` / `isNull` / `isNotNull`）与 `TERMINAL_TASK_STATUSES` / `TERMINAL_STATES` const——都跟 exec 方法一起挪进 impl 了。
  - **零行为变化**：`taskRepository` 单例的方法签名与返回类型完全一致（`TaskRepoImpl["method"]` 从 impl 反推），所有 Next 侧调用点（tRPC routers / api routes / executor-\* 内部 / SSE route）不动一行；`../core/repository` barrel 不动；`lib-node-only-scan.mjs` 现 `unguarded=22` 与 #1090 一致、impl 未加进 unguarded 集合。
