## Fixed

- **`pnpm db:migrate` 不解析 argv：未知旗标被静默吞掉后照样落迁移并记账**
  （`scripts/db-migrate.mjs`，ISSUE #2096；同族的 `db:push` 那一格是 #1956 / PR #2093）。

  这个入口此前整个文件没有一处读 `argv`，而它默认动的是**写库**那一句
  （`drizzle-kit migrate` + 往 `__drizzle_migrations` 记一条账）。于是
  「我以为让它别写」的那一句被当成「没有参数的那一次调用」照跑。探针（临时目录里
  的一份新库，开发库未碰）：

  ```
  node scripts/db-migrate.mjs --dry-run
    退出码 = 0
    [db:migrate] 应用 1 份迁移 → …probe.sqlite（库还不存在 / 是空的）
    [⣷] applying migrations…[✓] migrations applied successfully!
    [db:migrate] ✓ 用户表 23 张，账本已记 1/1 份迁移
  落库读数：库文件存在 = true · 376832 字节 · 23 张用户表 · __drizzle_migrations = 1
  ```

  比 push 那一格更值得拦的地方：push 留下的结构漂移还能被指纹读出来，而 migrate
  一旦落了账，下一次它是从账本断点**续跑**，谁都不会再问一次那条记录是谁批准的。

  修法按 #2096 的口径：**破坏性入口拒绝未知参数**（而不是给它补一个假的 `--dry-run`
  —— 那只是让「我以为它在干 A / 它其实在干 B」这对错认多一个看起来正规的写法）。
  守卫排在**所有作动之前**，也在原有那道「`drizzle/` 没有 .sql 就拦」的前置判决之前 ——
  后者挡的是另一格（drizzle-kit 在前提不成立时先建出 0 字节的库再退 1，#1624），
  两格不许互相冒充：新那档的用例刻意**不**挪开真 `drizzle/`，判的就是「迁移文件在场、
  写库那条路是活的」那一形。

  话术按本入口自己的事实写，不照抄 push 那句「无 TTY 时它停在确认那一步」——
  `migrate` 的 SQL 是生成好的，它压根不需要交互；要「先看会跑什么」的出口是
  直接读 `drizzle/<那份>.sql` 与查账本条数。

- **「拒绝未知参数」这同一判据收成一处**（`scripts/cli-arg-contract.mjs`）。

  #2093 当时只有 `db:push` 一个调用方，所以就地写了（§12.18「只有 1 个又看不出第二个的，
  先就地写」）；这一单是第 2 个调用方，两个入口各抄一份就是 §12.12 的孪生形态。
  共用件只交「哪些认不出」+ 一份统一形状的正文；**退出形态与因果句留在各入口**
  （注入的 `fail`），共享内核里不放任何一侧的传输层。

  配套判据三层：共用件自己那条按**形状与方向**判（含「声明了认得的旗标就不得被一起拦」
  —— 防的是守卫长成无条件 `fail`，也防有人为了让它过而把 `--dry-run` 顺手「认」掉）；
  两个入口各判**库里的事实**（库文件没被建出来），不判话术 ——
  「打印了拒绝的话」与「没动库」是两件事，这条链要的是后者。
