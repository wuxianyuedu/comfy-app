## Fixed

- **组 C 的隔离复跑不再重跑整块**（ISSUE #2022 的账，口径见 §13.6.4.1 第 3 条；新模块
  `scripts/affected-launch-retry-scope.mjs`，与话术层同一刀拆法，因为机制层加上第五件事就会
  越过那条「读不动 ⇒ 判据恒绿」的长度线）：一版实现把
  整块清单原样再串行跑一遍，于是**一份**带超时指纹的文件会拖着 90~115 份全部重跑 ——
  一次改了 `.cnb.yml` 的提交实测组 C **1411s**、全钩子 **1412s**（同一次里 A/B/D 只有
  11.7s / 109.0s / 125.1s，也就是整条钩子的时长几乎全是这一格）。本地钩子超过 5 分钟的实际
  后果不是「等一等」，而是人们改用 `--no-verify` —— 那是这条链上唯一不能换的东西。
  现在复跑面取自本档自己写下的 junit 读数（`retryScope()`，与分文件耗时共用同一份形状知识，
  不各写一遍正则），并与本次清单取交集、按清单顺序排（并行时 suite 先后是完成次序，
  拿它当顺序会让同一份输入产出两条不同命令行，而「不丢不重」与命令行长度都有判据在数）。
  **三条读不出来的形态一律退回整块**（没有账本目录 / 文件取不到 / 读数里一份失败都没有），
  方向单边化：宁可多跑，绝不漏跑一份真失败的文件。判据强度、旗标、预算、结论档位一字未改 ——
  这一格收窄的只是「重跑多少份」，不改变任何一次判决。
  「未校验」那份点名也跟着收窄：第一遍已经绿过的文件不再被写成「这次没测」。
