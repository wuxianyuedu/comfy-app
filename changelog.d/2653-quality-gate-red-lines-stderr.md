## Fixed

- **`pnpm check:all` 的红行整块改走 stderr —— 「能被 `2>` 单独捞出来」这句话第一次覆盖到
  失败路径自己（ISSUE #2653 / #2588 的残留那一半）**：`scripts/quality-gate.mjs` 里
  `reportVerdict()` 的注释写着本文件的口径（「绿走 stdout、红走 stderr：红的那些行要能从
  一屏绿里被 `2>` 单独捞出来」），而它自己用两个 `for` 各写一遍这个分流；同文件的
  `fail()`（ISSUE #2588 由 #2644 补上的实现）取了「形状收进 `renderVerdict()` 一份」
  那一半、流别那一半按四个调用点原本的 `console.log` 保留 —— 于是**同一个文件里两份答案**，
  五条红的来路全在 stdout。当场读数（`master` = `2f99a7e0`，`--mode nope`）：
  退 2、stdout 一行 `[红] quality-gate（未知门禁：nope…）`、**stderr 0 行**。
  第二处更常被读到：整轮小结那三行（`[红] 一键门禁（1 档里红 1 档）` + 下一动作 +
  红的是谁）也在 stdout，而同一次运行里各档自己那行红**在** stderr ——
  用 `--mode dailyAttendance` 一次跑出两处分流同屏的读数（读数写在单子里）。
  表现不是「哪里坏了」，而是「拿 `2>` 捞出来的那一屏里有各档的红、**没有这一轮的红了几档**」，
  而后者恰好是决定下一动作的那一行。

  修法是把那句口径做成**一处实现**：新增 `emitVerdict({ state, before, after, … })`
  （按 `state` 选流，判决行 + 它前面那段头 + 它后面那几行出路 **同一条流**），
  `fail()` 换成 `fail(message, { gate, before, after })`，五个站点全部走它 ——
  `reportVerdict()` 那两个分流 `for` 与整轮小结那个无条件 `console.log` 一起收掉，
  重复从「两份」回到「一份」（§12.12 同一维度）。红行内容一字未改：
  `[红] <gate>（<detail>）` + `      → <hint>` + 缩进的逐条事实，仍由
  `renderVerdict()`（纯函数）给。

  四个调用点的退出码**仍是各自的原值**（`resolvePnpm` 取不到 → 1、`result.error` → 1、
  未知门禁 → 2、依赖漂移 → 1），这一条刻意没被顺平 —— #2644 的注释写着它们为什么不同。

  **同批把一条边界写进文件头**（`scripts/quality-gate.ps1` 是本文件的并行实现，
  345 行、`$Blocks` 与 `GATES` 手工同批同步）：「同契约同产出」指的是**门禁清单 /
  退出码 / 话术形状**三份，**不含两条流的分派** —— `.ps1` 那一侧是人对着控制台看，
  两条流落在同一屏里，分派没有消费者。写在这一格的文件头而不是去改 `.ps1`，
  是因为「不要为此改它、也不要反过来把红行拉回 stdout」这句话只有读得到的人才用得上。

  回归加在 `tests/quality-gate-fail-paths.test.ts` 同一文件里（它此前把两条流**拼在一起**
  断「那句中文在场」，那一格对本次缺陷天然无感）：新增一格跑生产入口本身，断 `[红]`
  在 stderr、而 stdout 里没有它。
