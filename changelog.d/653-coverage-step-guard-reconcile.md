## Fixed

- **`master` 自己的测试跑不过自己的 `.cnb.yml`，两个 PR 的判据互相打架**：#648 给覆盖率上报加的护栏要求「`script` 与 `type` 必须写在同一 step」，而 #650 把上报拆成测试**之后**的独立 step（因为同一个 stage 里的 `script` 与 `type` 是两个**并行任务**，插件会在用例还没写出报告时就去找文件、`breakIfNoCoverage` 缺省 `true` 即退出）。两者先后合入后，`tests/cnb-pipeline-gates.test.ts` 对 `master` 当前的 `.cnb.yml` 判红，任何 PR 都过不了「单元测试」这一步（`#651` / `#652` 均如此）。
- 护栏改为把**两条各自独立的口径一起锁**：①「用例必须在上报之前真的跑完」——同一步自带 `script`（顺序天然成立）**或**排在前面的某一步；②「上报那一步底下不许嵌 `stages:`」——平台会静默丢掉同 step 的 `script`。拆分版在真实构建里已被验证可行（插件读到 `/workspace/coverage/lcov.info`，行覆盖率 63.48%），故不再把「同一 step」当成唯一合法形态。
- 规范 11.7 记下这两个现场各自的表现与成因（都会以「没有找到覆盖率报告文件」收场，但根因不同），13.5 的 gate 清单与核时表同步。两条变异（把上报挪到用例之前 / 在 `type:` 底下嵌 `stages:`）都能让护栏失败，已本地实测。
