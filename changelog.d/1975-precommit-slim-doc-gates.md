## Changed

- **三条「文档面」判据从 pre-commit 挪到平台侧流水线，本地提交门槛少 3 步**（ISSUE #1975）：
  `.cnb.yml` 已在 ISSUE #1959 重新启用（跑在自托管节点、不参与核时计费），于是同一批判据
  第一次有了第二个执行者。而这一批里有一条共同的形状 —— **结论挡不住任何一次代码回归**：
  判的是文档、文档生成物、台账这些**读者面**的一致性，漂了的最坏后果是「有人照着一份错的
  文档去做」。这类判据留在每次提交里，买到的只是「更早半小时知道」。

  挪走的三条（判据**一个字没改**，改的只是执行者）：

  | 判据 | 钩子档实测 | 为什么它不该占「提交那一刻」 |
  | ---- | ---------- | ---------------------------- |
  | `check-docs-api.cjs --staged`（`docs/api/**` 生成物与源） | **触发即 31s** | **D 组最贵的一步**。它的 `--staged` 输入面是 `src/lib\|server\|trpc` —— 本仓最常见的提交类别正落在里面，「跳过」在真实提交上几乎不生效（实测：改一个 `src/lib` 文件即走满 31s） |
  | `render-doc-placeholders.cjs --check`（`docs/generated/**`） | 72ms | 判的是「编辑文档改了却没重渲染」，而忘了重渲染在本地跑一次 `pnpm doc:render` 就知道 —— 那是「人顺手做」的动作 |
  | `check-doc-references.cjs`（= `pnpm doc:check`） | 154ms | 同上。ISSUE #1371 把它翻进钩子时回答的是「**能不能**进」（零网络、0.6s），不是「**该不该留」 |

  平台侧那三步跑的是**同一份脚本、同一个档**，其中 `check-docs-api.cjs` 走**全量档**
  （平台侧的工作区就是这次要判的那份源码，带 `--staged` 会让它恒跳过 = 白挂）。
  本地出口一字未动：`pnpm doc:check` / `pnpm doc:render` / `pnpm run docs`。
  口径、逐条实测与「为什么偏偏是这三条」（判据是「结论的作用面」，不是「步骤有多贵」）
  见规范 §13.5.17。

  **判据跟着挪，不是只挪实现**（两半都要判，只判一半的话「钩子撤掉 + 平台侧忘了加」会全绿，
  而它的失效形态正是「谁都没跑它」）：`tests/doc-check-hook-wiring.test.ts` 那三组断言从
  「钩子里有」翻成「**钩子里没有 + 平台侧那一步在**」，并新增 `platformStages()` 现算
  `.cnb.yml` 的 stage 清单（复用 `no-platform-ci-config.test.ts` 的 `stageBlock()`，
  不抄第二份解析器）。三个脚本头「自称在哪跑」那句承诺同批改掉 —— 否则读的人会被指到
  钩子里去找一步不存在的步骤。§13.1 清单、§13.5 的「平台侧 / 本地」对照表、
  `docs/README.md` 两处指针同步。
