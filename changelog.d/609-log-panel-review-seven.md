## Fixed

- **应用日志面板把一条多行 JSON 拆成十几条 INFO 行**：结构化 payload（zod 报错 / 异常对象）被 pretty-print 成多行后写进行式日志文件，解析层按 `\n` 切分，于是 `{`、`"inputs",`、`1` … 各自成了一条日志，且读不到时刻与级别（一律 `info`）。现在解析前先把物理行还原成**记录**（新增 `log-record.ts` 的 `splitLogRecords`）：未闭合的 `{`/`[`、顶格单排的 `{`/`[`、以及窗口截断后的 JSON 片段都并入同一条，级别与时刻只取自记录头。括号深度只数结构里的括号（跳过字符串字面量），记录头永远开新记录，独立裸文本行（`npm notice …`）不被吞并。
- **浅色主题下看不出选中的是哪个日志类别**：选中态此前只有 `bg-subtle`，而它与行头底色 `surface-1` 在浅色主题下是同一个值（`#f7f8fa`），等于没画。现在选中态由底色（`bg-primary/12`）+ 描边（`ring-primary/45`）+ 字重（`font-semibold`）三层表达（`log-row-style.ts` 的 `FILTER_SELECTED_STYLES`），「自动换行」开关的按下态同样修正。
- **「复制全部日志」不分范围**：面板里的「复制」此前倒出所有行（含其他来源与启动噪音），用户还得自己挑。现在复制/下载的范围 = **当前筛选下的全部日志**（来源 × 级别 × 搜索词，跨所有页），范围写进按钮 `title`。

## Added

- **应用日志面板新增「保存到本地」**：桌面壳里浏览器下载不保证落盘，用户「点完本地什么都没有」。新增 `POST /api/logs/export` 由服务端把当前筛选写进 `log/exports/logs-<label>-<时间戳>.txt`（鉴权与既有两个日志端点一致；**文件名由服务端生成**，标签走白名单，杜绝任意路径写入；内容封顶、失败如实报错），面板在按钮旁显示保存后的路径。
