## Fixed

- **日志面板路由用例不再依赖开发者本机的 `log/` 目录（ISSUE #436）**。`GET /api/logs/current` 的「应用服务转录（`source=app`）仍下发会话起点」用例只 mock 了 `APP_RUNTIME_LOG` / `DEV_LAUNCHER_LOG`，**漏了 `NEXTJS_LOG_DIR`**——而 `source=app` 走的正是「取 `log/nextjs/` 下最新一份 `nextjs-panel-*`」这条链。`log/` 在 `.gitignore` 里，CI 与干净检出上并不存在：此时 `panelCaptureLog()` 取不到文件，路由走「来源无文件」的空切片分支、`sessionStart` 硬编码为 `null`，用例断言 `typeof === "number"` 必然失败；而本机跑过一次 dev 的人 `log/nextjs/` 已存在，同一条用例又是绿的。于是它表现成一条「master 上也红、与本次改动无关」的 flaky，实际根因不是 `dev-launcher.log` 的 mtime（锚点路径本就被 mock 成临时文件、稳定可得），而是**用例对 Git 未跟踪的目录状态有隐式依赖**。现按 `capture-streams.server.test.ts` 的既有口径把 `NEXTJS_LOG_DIR`、`START_TAURI_LAUNCHER_LOG` 一并落到用例自己的临时目录，`beforeEach` 重建转录目录并落一份 `nextjs-panel-*`，`source=app` 的判定从「环境碰巧有目录」变成「用例自己造文件」。同时给该用例补一条 `content` 断言：目录缺失时会退化成空切片，正是它此前在 CI 上失败的形态——现在这条退化被显式钉住，而不是靠环境把它掩盖过去。无 `log/` 与有 `log/nextjs/`（含额外 `nextjs-panel-*`）两种环境下 13 个用例均通过。
