## Fixed

- **「`check-docs-api.cjs` 触发即 31s」这一族成本读数不再散着写了（ISSUE #2839）**：
  同一个秒数在仓里被复述成 **20 行 / 10 份文件**（单子列的是 10 处，实际把钩子注释与
  **四份用例 + 三份脚本**里「typedoc 冷跑 31s」那一族也数进来才对得上），而它**已经不是那个数**了：
  本回合按同一格当场取的两份平台原值是 103s（`cnb-btq-1k5uq6pl7`）与 137s
  （`cnb-imr-1k5unh2r9`，两跑都是接槽形态、同一入口同一旗标），单子上另有一笔 3m5s（≈185s，
  没留 sn ⇒ 只当量级），本机暖态非并发一次 169.4s —— **与那十处写的 31s 差 5 倍，而账面
  一条红都不会出现**（没有任何执行者读文档里的秒数，判据在场、执行者不在场）。

  根因与 #2694（固定清单份数在三处当现值写）逐字同型：**会漂的量被抄进散文，抄一份就会漂第二次**。
  修法照 #2694 已经定的那条口径：**成本读数不写成现值，写成取法**，而整个仓只留一份出处 ——

  - 那一份出处落在 `docs/standards/13` **§13.5.17 末**：两条取法
    （`pnpm ship --stage-log <sn> API 文档生成与自检` 取平台原值 / `node scripts/check-docs-api.cjs`
    取本机全量档）+ 本回合带量具的样本 + 那句「同一个入口在 100~190s 之间走 ⇒ 没有单一现值」。
  - 其余各处（规范里另外 8 处、`AGENTS.md`、`.githooks/pre-commit` 的挪档理由、
    `tests/check-docs-api.test.ts` / `tests/doc-check-hook-wiring.test.ts` /
    `tests/typedoc-run.test.ts` / `tests/generate-api-docs-args.test.ts` /
    `scripts/typedoc-run.mjs` / `scripts/generate-api-docs.mjs` /
    `scripts/fixed-structural-tests.mjs`）改成「**百秒级** + 见 §13.5.17」的形状。
    用例名那条也一起改了（「不给普通提交加那 31s」→「…加一整轮重生成」）——
    理由写错了要连用例名一起改全，否则七处不一致比一处没注释更糟。
  - **历史论证那一族只加限定语、不改数**：§13.5.17 那张「钩子档实测」表列头现在明写
    「那一次的取样，不是现价」，行内改成「三十秒级（触发即付满）」；组 C 那两笔拿它当分母的
    论证（「D 组最贵的一步才…」）保住原意，只把数换成量级并指向取样口径那句。
  - ⚠️ 这一族的**半衰期**写在出处里：**ISSUE #2843** 在提案给 typedoc 带 `--skipErrorChecking`
    （实测能把这一跳压到二十几秒），它一落地 §13.5.17 里每个样本都过期 —— 所以要价的时候当场取。
  - **没有为这条新写判据**（硬规则 24 末句）：对账「文档里的秒数 ⇄ 实测一致」要按字面量扫文档，
    正是最脆的那一型，而秒数本来就该带量具，机器判不了量具。账面不再出现现值，
    就没有会过期的读数需要对账。

  计数口径照单子里那句守住：`grep 31s` 会假匹配 `131s`（构建时间）、`0.31s`
  （另一条判据的耗时）与 `15m31s`（时长格式化用例的夹具）—— 上列每一处都读过主语，
  不是整档替换的产物。镜像 `docs/generated/13-提交与-code-review.md` 同批渲染，
  `pnpm doc:check` 绿。
