## Added

- **流水线上多了一步「环境前提」，专门回答「在，但够不够用」—— 排在 `Install dependencies`
  之前**（ISSUE #1959）。用户那一句诉求是「别等到执行几十分钟后才发现环境安装不上」，
  而此前最便宜的位置只答了「缺件」那一半。

  缺件那一半已有执行者（`工具链自证` / `Python 可用性`，见 §13.5.3.5.1）。这一步补的是
  它旁边两格，两格的红法都不是「没有」、而是**「晚」**：

  | 面                  | 缺了会怎样（红在哪）                                                                                                                                                                                                                                                                                       |
  | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
  | **解释器的版本**    | **哪一步都不会红**：门禁的 Python 侧探到解释器就把那一侧拉进四向比对（版本不够时它自己先抛 `SyntaxError`，报出来的是一句看不懂的 Python 栈），那几条真跑的用例走 `env` 档跳过并登记 —— 「版本不对」与「装好了」在日志里**逐字同形** |
  | **`.cnb.yml` 的语法面** | 不在解析期报错，只在跑到那一段时整段炸。实测落点在 `Install dependencies`（宿主是节点上的 Windows PowerShell 5.1，而 `?.` / `??` 是 pwsh 7 才有的）—— 而它前面的预算已经花掉了                                                              |

  **三条边界**（这一节最容易做过头的三处）：① **不重复判缺件** —— 命令根本不在那一半
  归 `工具链自证` / `Python 可用性`；② **判据不重写** —— 「解释器在哪」走
  `ci-toolchain-python.mjs` 的 `findPython()`（与 `Python 可用性` 同一份候选表、同一个
  探针），`.cnb.yml` 的语法面复用 `tests/no-platform-ci-config.test.ts` 导出那一份
  （`.ts` 在装依赖前 import 不到，故留**文本副本** + 一条逐项对账判据，与
  `check-app-port-vectors.cjs` ⇄ `python-candidates.ts` 同一处置）；③ **「不知道」不放行
  也不拦** —— 版本号解析不出、探测本身出错、裸名字起不来 pnpm 一律只记读数
  （§13.6.4.1），退非零的只有「低于下限」与「配置里有 host 认不了的写法」两条真判据。

  代价几秒，跑在**任何依赖安装之前**（只 import `node:*`）。

- **`Install dependencies` 那一步补了 1 秒的自证：判在 `pnpm install` 之前**
  （`node scripts/check-pnpm-available.mjs`）。它判的是「**host 自己的解析面**起不起得来
  pnpm」，而 `工具链自证` 那份探针**刻意按形态解析**（corepack 的三个形态里 Node 只起得来
  一个，见 §2.1.1）—— 两者不是同一条链，也不该被压成一条。两者不一致时此前的形态是
  「第一步绿、几十步之后才以一个看不懂的错收场」。⚠️ **不是新写的一份判据**：判据全在
  `scripts/launcher-core/corepack.mjs`，那个脚本自己是薄壳（文件头写着这条边界）。
  放在这里而不是更早的 stage，是因为这条判据**在更早的位置上做不出来**。

  规范 §13.5.3.9 新增一节（「同一族的第二个面：在 ≠ 够用」），记下三处边界与那句顺序约束。
