## Fixed

- **净零 PR 的「空改动面」判据不再被 squash 拓扑骗成「没判」**（ISSUE #3644）。
  `confirmEmptyChangeFace()`（口径 ⑥）的第二半旧读法是「两个父的对称差」
  （`第一父...第二父` 三点 diff）：目标分支已用 squash 落地同批改动、PR 分支从
  旧分叉点把它们重带一遍时，merge-base 退回旧 fork point，分支自己那批**已经
  落地**的提交被误算成「这个 PR 带进来的」⇒ 退 2 假红（现场：PR #3641 的
  `affected-tests`，两父间 16 个文件分叉、而合成 merge 树与第一父逐字节相同）。
  第二半改读 **`第一父..HEAD` 的两点树差**——它就是「这个 PR 的净贡献」：
  空 ⇔ 合成树与第一父逐字相同 ⇔ 零个文件；两半任一取不到照旧退 2（fail-closed
  不变）。负控「两父分叉 ⇒ 退 2」的夹具同步改按新读数注入、仍红；补 squash
  拓扑正控一条（旧读法在它上面确实读出 3 个分叉，新读法判「零个文件」）。
