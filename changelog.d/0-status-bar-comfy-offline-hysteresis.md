## Fixed

- **状态栏偶发误报「ComfyUI 未运行」**：ComfyUI 明明一直在跑，底部状态栏却时不时闪一下「未运行，显存/内存暂不可用」。根因是轮询 `/api/comfy/stats` 的 controller 只要**一次**失败就立刻翻离线，而服务端 `getSystemStats()` 对 ComfyUI 的 `/system_stats` 设了 2.5s 超时——跑图时该接口响应变慢、或单拍网络抖动都会返回 `online:false`，于是状态栏忽明忽暗。
  - 改为**连续失败迟滞**：抽出一个共享原语 `useOfflineGate`（连续 N 次失败才提交离线、任一次成功立即清零），显存/内存通道与排队/当前执行通道**两路都接入**，消除「资源格不闪了、排队格还在独立闪」的口径不对称。
  - 容忍期内保留上一次的好数据、不翻离线，同时给占用条加一档**「数据陈旧」弱化**（降不透明度 + 悬停说明），既不被瞬时抖动误触发，又诚实反映「此刻显示的可能不是最新值」。
  - 两条轮询各加**自增 request-id**，丢弃乱序迟到的旧回包，避免慢/抖动场景下晚到的 `online:false` 污染连续失败计数；`/api/comfy/stats` 客户端补一个宽松超时（10s）兜住病态挂死的连接。
  - 补 `use-comfy-stats.test.ts` 回归测试锁住「成功后单次失败不翻离线 / 连续 3 次才离线 / 成功清零」三条语义（此前 readiness 用例首帧即通过、根本没走到迟滞分支，是假绿灯）。
