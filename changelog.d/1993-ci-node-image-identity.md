## Added

- **流水线上多了一条「镜像身份」读数：这一跑的机器长自哪一版**（`scripts/ci-image-identity.mjs`，
  ISSUE #1993）。自托管这条路上镜像只在**宿主侧**被用：装机时 `docker pull` 一张钉了版本标签的
  节点镜像、按它装好，再把身份钉进两个机器级环境变量（`COMFYAPP_NODE_IMAGE` /
  `COMFYAPP_NODE_IMAGE_DIGEST`）。缺了这一步，「这台节点跑的是哪一版工具链」只能靠翻上一次的
  红色日志反推 —— 而工具链清单反复被重写，根因正是**环境是隐形的**（规范 §13.5.3.5）。
  这一步把磁盘上真有什么（发行版 / 内核 / 主机名）与声明的身份一起打出来，并按三档给判读：
  `pinned`（有版本标签）/ `floating`（`latest` 或无标签）/ `missing`（没声明）；digest 只判形态
  （`sha256:` + 64 位十六进制）。
  **恒退 0 —— 它是读数不是判据**：工具链靠断言守（`工具链自证` 判四件、`环境前提` 判版本下限），
  那些是实际能力、镜像是期望身份，不一致时以能力为准；而且「没有标识」是本路径的历史形态
  （裸装机），第一次接进节点的一跑不该被一条与新事实无关的红拦住；再加上「标签 / digest 对不对得上
  镜像库」构建容器里判不了（没有 docker daemon）。
  排在 `工具链自证` 之后、一切安装之前（跟着那台机器的身份、贴着那台机器的自证），并登记进
  `COMFYAPP_CI_GATES` 与 `MUST_ALWAYS_RUN`（它描述的是「本次跑在哪台机上」，收窄成任何 glob
  都丢掉它存在的理由）。

## Docs

- **规范 §13.5.3.4.1.1（新增）**：把「那张镜像在宿主机上怎么被用起来」写成一份可执行的顺序
  —— 拉取、取 digest、钉机器级环境变量三条命令，与「三类用法里只有『当拉取源』要宿主机有
  docker」那张对照表；并写清这一步**不**是「流水线跑在镜像里」的证据（`.cnb.yml` 里没有、
  也不该有 `image:`）。
