## Added

- **录制环境的字体档能力上报**（`scripts/recording-font-capability.mjs`，接在 `settle` 上，
  §11.8）：每张像素截图**之前**先问一句「这台机器有没有字体覆盖中文」。判据把**同一串中文**
  与**一串保证没有字形的码位**（Unicode 私用区 `U+E000` 起）在同一串栈下各画一次、比墨迹量，
  相等就是「中文与缺字形画成了同一个东西」⇒ 这台机器录不出这一档的基线，当场红并给出动作
  （换机器 / `fc-list :lang=zh` 先看一眼），而不是让人从一堆中文块的 diff 里去猜。

  它治的是 ISSUE #1620 收尾时实测出来、此前整套账里没有位置的一层：基线文件名带**平台名**
  （`-linux.png`），而平台名担保不了**字体栈** —— 同一个 linux 平台名下，一个装了 CJK 字体的
  容器与一个没有的，跑同一份 spec / 基线 / 代码差 **1767 像素**，差的是整页中文的字形
  （中文全走 fallback，「模型库」渲染成「模型」）。此前 `visual-baseline-pairing.test.ts`
  只管仓库里那几套 PNG 的形态、`checkRecordingEnv` 只管 `CI` 的真假，这条红没有任何判据能命名。

  **判据刻意不认字族名**（不维护「要哪几族字体」那张会静默失效的清单，§12.18 第二条）——
  三条实测堵死了按字族名判那条路：① `PingFang SC` / `Microsoft YaHei` 在**健康的** linux
  容器上同样不在（它靠别的 CJK 字体），「声明族不在 ⇒ 红」会把健康环境判红；② 按族名量 CJK
  宽度分不出覆盖（同一串中文在四种字体下宽度**都是 120**）；③ `document.fonts.check()` 对
  一个**不存在**的族照样返 `true`。

  两个方向都实测过：本容器（系统装了文泉驿）放过，`FONTCONFIG_FILE` 指向只含 DejaVu 的
  配置时停在 `settle`、不进截图。**装了「别的」CJK 字体的机器这条判不出来**（它能出墨、
  9/10 张基线照样绿），那一档仍留在人这边 —— §11.8 写清了这条边界。
