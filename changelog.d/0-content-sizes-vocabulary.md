## Added

- **`docs/DESIGN.md` 补全「内容尺寸住在 `@theme` 之外」那一节**：上一版只记了两条来路、三枚值
  （`.json-view` 的 11px、`.cb-code-block` 的 11.5px、markdown 渲染器 `pre` 的 10.5px），
  而这片字号其实有**三处来路、16 个值**：① 调用点的 arbitrary 字面量（49 处 / 9 个值，
  与 `TEXT_BASELINE` 同一本账）；② `globals.css` 里 `@theme` 之外的裸 `font-size:` 声明（2 处）；
  ③ `src/lib/markdown/styles.ts` 拼的**内联样式串**（h1–h6 18/16/14/12.5/12/11、`pre` 10.5、
  行内 `code` 10、`table` 11 —— 这一处既不经过 token 也不是 Tailwind 候选名，所以
  §Typography 那句「10.5px 整批并入 `text-2xs`」不覆盖它）。逐值给了角色与「为什么不是某一档」。
- **新判据：那张词汇表是形状判据**（`tests/design-md-contract-sync.test.ts` 的
  「住在 `@theme` 之外的字号是一张词汇表」）。三处来路并成一个值集合，三个方向都判：
  用了却没登记角色 → 红；登记过却已经不在用（还债把某一档并掉了）→ 红；在册且仍在用但
  `docs/DESIGN.md` 那一节没写它 → 红。文档侧按**词边界**匹配，不让 10px 靠 10.5px 那一行蒙过去。
  它不判处数（处数归 `TEXT_BASELINE` 那条棘轮），判的是形状 —— 进来一个新值而不说清它是干什么的，
  就红。三条判据各做了一次变异复演（删一条在册值 / 加一条不在用的在册值 / 把文档里那一行的值
  改成汉字），三条都当场红在该红的那一格。

## Fixed

- Known Gaps 里那两条关于这片字号的条目合成一条并指向新小节 —— 同一组数字从此只有一个出处，
  不再需要「两条旧话 + 没人数的剩下十几处」。
- 明确写下**为什么不落档**（三条实测理由，不是审美）：内联串落成 `--text-*` 也不会被那个渲染器读到；
  这些尺寸绑的是元素自己的几何（序号圆 `size-9`、胶囊的 `py-px`、代码块行距），跟总闸走会一起推离；
  每多一颗「只有几处在用」的档，「改一档全站跟手」就多一个永远不会被维护的落点。
