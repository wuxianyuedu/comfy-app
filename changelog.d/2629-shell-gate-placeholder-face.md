## Fixed

- **跑过一次壳的 `cargo test` 之后，`pnpm build` 不再恒红在产物层**（ISSUE #2629）。
  `scripts/shell-gate.mjs` 的编译前提格曾往 `src-tauri/static/` 写一枚
  `.cargo-test-placeholder`，而**这一层正是 `check-standalone-contents.cjs` 数的第二层**
  （真被 `bundle.resources` 装进安装包、编译期内嵌进 exe 的那份载荷根）。于是判据报
  「顶层出现白名单外的条目 .cargo-test-placeholder」——读起来像谁把脏文件塞进了出厂件，
  而真因是「同一目录有两个写者（`build-desktop` 的装配 与 `shell-gate` 的编译前提），
  判据只认识其中一个」。
  ⚠️ 这是一格**只在开发机上存在**的红：CI 不跑 `pre-commit`、平台工作区每跑完一次被整棵删掉
  ⇒ 那个占位文件在节点上从来不出现 ⇒「每日 / PR 都是绿的」替不了它。
  反证做过：只挪开那一个文件 ⇒ 两层全绿、退 0；放回来 ⇒ 又退 1。
- **开发期编译前提不再往出厂件的扫描面里放任何东西**：`shell-gate.mjs` 只 `mkdir`。
  「空目录就够」不是推测而是实测 —— 清空 `src-tauri/static/` 之后
  `cargo test --offline` 照样 `56 passed`（壳内全部 `#[test]` 那个唯一执行者，硬规则 5）。
  判据侧同批钉住边界：`tests/shell-gate.test.ts` 断言跑完 `readdirSync(static)` 为空。
- **判据自己的那道门补齐**：顶层白名单那一格此前**不带**「这是不是一份装配产物」的前置，
  而同一个函数里的三条**缺件**检查早就是 `files.includes("server.js")` 这道门 ——
  不对称的形态就是把「从来没装配过」的目录当成出厂件数。现在同一个口径，并打一行
  「顶层这一格不判，不是『已检查通过』」；这一句**不管目录空不空都打**（空目录时它以前打的是
  `✓ 产物干净（共 0 个文件）` —— 那一句把「没装配」说成了「查过且通过」，正是 §13.5.25
  禁止的那种读法）。白名单一个字没改：装配过的层照旧逐个顶层条目判。
- 判据两侧同批钉（`tests/dist-artifact-hygiene.test.ts`）：未装配的目录里放一枚杂项 ⇒
  退 0 且念出「不判」、**不出现**「产物干净」；同一份目录补上 `server.js` ⇒ 那枚杂项
  立刻被点名红。少第二侧，「不判」就与「把检查删了」同形。
- 规范登记：`launch-and-build.md` §7.3「装配之后必须再数一次产物」那一段之后新增
  「数第二层的前置：那一层得真的是产物」，含两条落地的分工表与「为什么不去改白名单」
  （加一项要回答「谁在运行期读它」，而这件东西没人读）。
- 单子正文订正：立案时那句「组装不会去删一个它不认识的文件（`static/` 随下一次组装被替换
  是句没兑现的口头承诺)」**是错的** —— `build-desktop.mjs:157` 在装配前
  `rmSync(staticDir, {recursive,force})` 整棵删。真机制是「出厂件那条链会清场，
  而 `pnpm build` 数的是一层**还没装配**的目录」。已按实测改回单子正文。
