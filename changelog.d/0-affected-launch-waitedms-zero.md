## Fixed

- **C 组启动器把「一点没等」读成「等了 1ms」**：`waitForLoadToSettle` 的 `waitedMs` 是用 `Date.now()` 两次读数相减得到的，而 Windows 上它的粒度约 1ms —— 负载本来就在阈值下、一跳都没睡的那条路径，两次读数之间只要跨一格就返回 1。`tests/hook-affected-launch.test.ts` 里「负载已在阈值下 ⇒ 一点不等」钉的正是 `waitedMs: 0`，于是在 Windows 上稳定红（实测 6/6 次读到 1，同一函数在裸 node 里 5/5 读到 0 —— 差异只在 vitest 里被跨到）。现在按构造给值：**睡过几跳**才去量墙钟，一跳没睡就是 0。口径与本文件自己写下的那条一致 —— 这一层判的是「等没等」，不是「等了多久」（旁边「负载高 ⇒ 等到回落」那条早就不断墙钟、只断读了几次与睡了几跳）。
- 这条红落在**提交门槛自己的那一格**上：它拦住的不是某一次改动，而是从 `master` 分出的每一个提交（C 组的固定清单里带着它）。触发面与修法都只在这一条返回值上，没有抬任何超时预算，也没有放宽断言。
