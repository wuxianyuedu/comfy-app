## Fixed

- **启动页不再把「应用页面加载失败」藏成「服务已就绪」**（#4328）：
  双击壳启动时主窗页面已加载、交换窗口却被错误中止，启动页永远停在
  「服务已就绪，正在加载应用…」，出错原因只能翻日志才知道。根因是
  `tcp_probe` 只试 DNS 解析出的**第一个**地址——`localhost` 常把 `::1`
  排在前面，而 dev server 只绑 `127.0.0.1`，探测于是把好好的服务判成
  不可达（#4213 引入超时形态时收窄了探测面）。现在逐个尝试全部解析地址
  （每个仍带 1s 超时），壳自编排的回退导航地址也改写 `127.0.0.1`
  （对齐硬规则 20「回环主机不写 localhost」）。
- **交换失败进入重导航循环时，启动页给出可见的错误/重试态**：壳把
  重导航状态注入启动页轮询的启动状态（`navigateStalled`），页面从
  「服务已就绪」翻成红色「页面加载失败（重试中）」，恢复后自动回到
  常规进度；重试期间启动页不再重复 invoke 已被壳侧一次性标记挡掉的
  `navigate_to_app`。
- **启动页日志面板按级别着色**：ERROR 红 / WARN 琥珀 / OK 绿 / STEP 青，
  段头用品牌色弱化成结构线；Next.js 的 `⚠` / `⨯` / `✓` 记号与
  「Ecmascript file had an error」这类不带级别括号的错误行同样可辨。
  着色只按行首窗口判级别，逐行 `textContent` 渲染，不引入 HTML 解析面。
