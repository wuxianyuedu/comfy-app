## Changed

ship 补上「建 PR 后与 base 冲突 ⇒ 平台不跑 CI」的可见性，并把退码与进度输出
分型（ISSUE #3083；活证据 PR #3075：建 PR 时 `mergeable_state=conflict`、平台
无 CI，人工解完 8 份冲突 push 后 CI 才起跑）。

**冲突可见**：

- **建 / 复用 PR 后立即回读** `mergeable_state` / `blocked_on`：冲突当场收口
  并念出口命令；此前 `post-pull` 响应只取 `number`，复用路径更是完全不问
  PR 状态，`--no-wait` 路径下冲突完全不可见；
- **轮询读到冲突当场收口**：#2645 只念警告却继续轮满 10 眼（≈3 分 20 秒），
  「说别干等、行为在干等」自相矛盾；`mergeable_state` 缺键 / 平台还在算按
  「未知」念一句继续轮（#3059 口径，不 `=== true` 误读）；
- **判决格 / `--diagnose` 的「没拿到 build 终态」三分型**：冲突（报冲突 + 出口）/
  可合并（明说「可能仍在排队」）/ 缺键或回读没跑起来（照实念「取不到」）；
- 冲突面用 `git merge-tree --write-tree --name-only` **只读探测**列出（不改工作树、
  不改 ref；老 git 探测不到就照实说探测不到）。

**退码分型表**（用户拍板：不同情况必须用不同退出码，看到退码就知道是什么问题；
单一出处 `scripts/ship-codes.mjs`，`--merge` 与 `--diagnose` 同一套码）：

| 码 | 语义 |
| --- | --- |
| 0 | 走到终态且事实为绿（不变） |
| 1 | 有事实是红的（不变） |
| 2 | 没跑起来（泛化兜底：执行者不在 / cancelled / 归属不到 / 用法错） |
| 3 | PR 与 base 冲突，平台不派生 CI |
| 4 | CI 无终态（排队 / 在跑超预算 / 签名断流），PR 可合并 |
| 5 | 关键读数缺失（mergeable_state / is_merged / state 缺键、回读没跑起来、基线取不到） |
| 6 | 守卫拦住这一跳（已随 PR 落地 #2250 / 跑期内分支被切换 #2812） |
| 7 | 本地前置不成立（非 git 检出 / 在 master 上 / 缺碎片 / 依赖没装） |

0 / 1 / 2 的既有语义不变，「没跑起来家族（≥2）压 1、1 压 0」的合码口径不变，
CI 与自动化照旧按「非零即不过」消费。**行为变更**（旧码 → 新码）：

- 冲突各出口（建/复用 PR 回读、轮询、判决、诊断）：2 → **3**；
- 轮询签名断流 / 在跑超预算、判决「可合并但没终态」：2 → **4**；
- `mergeable_state` 缺键、回读没跑起来、预检基线取不到 / 新鲜度读数不可读 /
  `.env` 缺键不可读：2 → **5**；
- 已落地守卫（#2250）与跑期内漂移守卫（#2812，两道）：2 → **6**；
- 缺 changelog 碎片、在 master 上、依赖没装：1 / 2 → **7**；
- `--merge` 时平台把构建记成 cancelled：1 → **2**（此前混在「CI 是红的」里）；
- `--merge` 判决文案「CI 不是绿的」→「CI 是红的」（只有 1 才这么说）。

**同时修复 #3059**（get-pull / get-issue 应答间歇缺 `is_merged` / `state` 键，
调用点的 `=== true` 把「没取到」读成「未合并 / 没关成」）：所有消费这两键的
调用点改三态分型（确认真值 / 确认假值 / **缺键**，唯一出处 `ship-core.mjs` 的
`classifyIsMerged`），缺键一律 unknown、**不得按 false 处理**，按码表退 5：

- 落地守卫（#2250 路径）：closed 清单里 `head.sha` 逐字相同而 `is_merged` 缺键
  ⇒ 不建幽灵 PR，退 5；
- 合并后回读缺 `is_merged` 键 / 回读没跑起来：1 → **5**（不按「没合上」落红）；
- 关单回读缺 `state` 键：1 → **5**（不按「没关成」落红）；
- 关单证明扫描：标题点名目标单子而那条 PR 的 `is_merged` 缺键 / null ⇒ 念
  「证明读数缺」并退 5，不按「没证明」静默跳过；
- 判决格的 `is_merged` 显示：缺键照实念 `(缺键)`，不再念成 `false`。

**阶段化进度输出**（与退码两套信息：进度说走到哪，退码说结果分类；形状唯一
出处 `scripts/ship-stage.mjs`）：预检通过 / 分支推送 / 新建或复用 PR（PR 号 +
**平台回读**的标题）/ 等 CI（构建号）/ 冲突（PR 号 + 冲突面）/ 合并
（squash + 合并提交 sha + 目标分支）/ 关单（issue 号 + 回读 state/state_reason）/
清分支，每格一句 `[ship] ▶ <阶段> | key=value`，完整不截断、可 grep。

出口只做引导、不做动作（人工 `git fetch <远端> && git merge <基线>` 逐个解 →
push → 重跑 `pnpm ship`，PR 复用幂等接着等 CI）；**不自动解冲突** —— #3075 的
取舍要人判。「冲突 / 可合并 / 未知」分型与出口话术各只有一份
（`ship-core.mjs` 的 `classifyPrMergeable` / `conflictAdviceLines`），各格共用。
