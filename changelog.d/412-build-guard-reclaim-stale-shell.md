## Fixed

- **一键发布构建不再被「上一次启动的桌面壳还开着」卡死**：构建前置检查（`tools/build/build-all.ps1` → `build-tauri-release.ps1`）此前对任何运行中的 `app.exe` 一律中止，要求「先关掉桌面窗口再重跑」——可用户的实际动作正是「启动 exe → 关掉窗口 → 重新构建」，窗口早就没了，照提示做也关不掉，构建连编译都进不去。现在命中占用会先分类：
  - **陈旧壳**（起它的启动器已退出 = 无主孤儿壳）自动 `taskkill /PID <pid> /T /F` 回收后**直接继续构建**；
  - **双击构建 / 由启动器拉起的非交互构建**（没人能按任意键确认）同样自动回收后继续，不再留死胡同；
  - 只有「应用启动器（`start-tauri*.exe`）仍在运行、用户可能正开着应用」才中止，且日志明确点名要求**先结束启动器**——启动器会把新壳重新拉起来顶上 `target\release\app.exe`，届时只杀壳既丢了用户窗口、编译途中还会再次被占用而白跑一轮。
- **兜底回收不再可能杀错进程**：`log/launcher/tauri-shell.pid` 现在在拉起 `dev-launcher.ps1` 之前先删除。该文件是上一轮运行的残留，而 `dev-launcher.ps1` 由本次启动器另起进程写入——它写新 PID 之前文件里还是旧 PID，Windows 会复用 PID，兜底路径读到就可能杀掉无关进程。先删 = 窗口期内读不到文件，语义安全。
