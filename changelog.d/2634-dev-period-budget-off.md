## Changed

- **开发期暂撤 `bundle-budget` 的两条总量判据**（ISSUE #2634，业主口径 2026-10-29）。
  `scripts/check-bundle-budget.cjs` 新增 `TOTALS_ENFORCED = false`：`gzip 总量上升` 与
  `chunk 文件数上升` **照量、照打、不参与判定**（默认档退 0）。撤的是**执行**，不是量具，
  也不是基线 —— 三条结构量的测量、按内容指纹的逐文件诊断、`其后 N 次提交` 那套归因
  一句没少打；`--update` 的拒涨棘轮一条没动，基线仍停在 `224 / 2196.3 KB`，所以恢复那一天
  量到的是**整个开发期的累计涨幅**，不会被「边涨边重记基线」抹平。
- **为什么不是继续按 §13.5.4 等有人签**：触发点是每日那一跑的 `gzip +17.4 KB / chunk +1`
  （基线 `dd8d4647` 其后 **35 次提交全部已进主干**，没有一笔有 before/after 与「值这个体积」
  那句话）。按「不是你的账，立案，别替别人签」这一档没人能签，而不签的代价是一条**预算**判据
  把 `每日单元测试` / `每日全量E2E` / `每日 ESLint 零警告` / `每日浏览器安装` 四格拖成
  `skipped`（ISSUE #2114 那一族：防劣化的判据成了四格出勤的堵头）。此刻它的信号价值
  低于它挡掉的证据价值。
- **降档必须被念出来**（§13.5.25 那条纪律）：默认档在 **stdout** 打「这一格今天没判」+
  恢复方式 + 自查口，那句 `✓ 在预算内` 在这一档不出现。走 stdout 是有意的 —— 退 0 的判据
  在很多消费者那里只转述 stdout（`quality-gate.mjs` 的绿档、门禁自测夹具都是这个形状），
  「今天没判」若只落 stderr 就会被读成「它绿了，所以没东西可看」（硬规则 27）。
- **自查口 `--enforce-totals`**：走**同一段判定代码**把两条总量判据按硬档跑一次，
  恢复之前用它先看红在哪几笔。判据组 `tests/check-bundle-budget.test.ts` 因此成对钉：
  同一份超限读数 ⇒ 默认档退 0 且 stdout 有那句「没判」、带 `--enforce-totals` 退 1 且打
  `违规（阻断）`；另两条钉「默认档一次运行不得动基线一个字节」与「`--update` 的拒涨棘轮
  不受暂撤影响」。既有的判定/归因用例（19 处默认档调用）统一改成带 `--enforce-totals` 跑 ——
  它们测的是判据本体，不是撤档。变异验证：把常量改回 `true` ⇒ 默认档那两条当场红
  （这正是恢复日的信号，见 #2647）。
- **恢复条件登记在三处**：运行读数（每次）、规范 §13.5.4 那张「停掉的 / 没停的」对照表
  与两条形状讲究、以及单独立的一张 **P2 #2647**「出正式版前恢复 `TOTALS_ENFORCED`」
  （含恢复时的五步与验收读数 —— 恢复那天不许只剩一把 `--update --allow-increase`，
  那是把刚接回的判据换成一份没人评审过的基线）。
- **本单不动的东西**（免得被顺手放宽）：产物层那两层判据（硬规则 17/18 的
  `check-standalone-contents` / `standalone-private-inputs`）、逐文件指纹诊断的口径、
  `--update` 需要显式 `--allow-increase` 才能抬基线这一条。
