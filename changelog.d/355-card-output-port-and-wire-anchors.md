## Fixed

- **对外参数卡片：输出端口行改成「名称 + 类型」右对齐到端点，端口行不再重复标一遍落点（ISSUE #355 复审）**：上一轮把落点同时写在了两处 —— 端口行尾的「→ positive_prompt」与输出端口行的端口名，说的是同一件事，行尾那一段是纯冗余（用户圈出来要求去掉）。现在卡片上「这个口连到谁」只说一次：带类型的输出端口那一行写出名字与类型，并整组**右对齐到那颗小圆点端点**（圆点就是这一行在说什么的那个口，名字贴着它才读得出）；端口行回归本职，只列端口名与类型。多端口条目仍保留行尾落点说明（多行之间要能区分）。

- **工作流库画布上的映射连线补齐两端锚点，组合参数（宽高 / 比例像素）也能连（ISSUE #355 复审）**：线要画出来，两端都得量得到 —— 卡片那头是输出端口行右沿的小圆点，宿主这头是「被落到的那一行」。此前有两个缺陷让线整条消失：① 组合参数（宽/高、比例/像素、时长/画质/比例）由**同一个控件**录入，这类落点根本没有独立的一行，量不到就整条不画，「尺寸」这张卡看起来从没连上；② 锚点用 `querySelector('[data-io-key="…"]')` 拼字符串匹配，端口键里含 `::` 或引号时要么语法出错、要么匹配错元素。现在落点锚点分两种形状（独立行 `data-io-key` / 组合控件 `data-io-pins`），属性名收在 `workflow-io-types` 里由量测侧与渲染侧共用；量测改为按属性**精确比较**（不做 CSS 转义、不切分端口名）。同时线的起点改用圆点**外缘**（与画布上 React Flow 的连线口径一致，线不切进卡片里），并在挂载时先同步量一次再于下一帧量第二次 —— 此前只等被取消的那一帧，线头渲染晚于卡片时一条线都画不出来。

- **工作流库的画布预览与编辑器落在同一个模式上（ISSUE #355 复审）**：预览节点的模式 chip 上明明写着「单图生视频」，卡片列却按**工作流默认模式**派生条目、宿主表单也按默认模式解析必填与 seed 行为 —— 两处显示的是两套参数，看起来就像「我连的线丢了」。现在生效模式统一取 `resolveWorkflowMode`（选定的模式 → 模式集合第一项 → 任务类型），卡片列、表单 required / 可见性 / 组合参数、seed「控件后行为」、模式 chip 显示的名字全部按它解析；「在编辑器中打开」也把当前生效模式一起带过去（编辑器不再固定打开默认模式），用户在库里看到哪一套，编辑器打开还是哪一套。
