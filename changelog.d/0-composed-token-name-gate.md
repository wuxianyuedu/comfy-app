## Added

- **主题色门禁补第三条反向硬闸「拼接 token 名」**（`scripts/check-theme-colors.cjs`、
  规范 03 §3.6.1.1）：`var(--color-aurora-${tone})` / `"--color-" + name` 这种拼出来的
  名字，上一轮那条「幽灵 token」判据比对不到（引用不是字面量）。实测存量 **0**，
  出现即阻断。**只判两种形态**，刻意不判「反引号里出现 `--color-` 前缀」的宽形态 ——
  那种正则在 `globals.css` 的说明注释里命中 103 处散文引用，硬判就是造误报机（§12.18）。

## Fixed

- **`AuroraGlow` 的极光晕靠侥幸才没失色**（`src/components/ui/aurora-background.tsx`）：
  它用 `var(--color-aurora-${tone})` 拼名字，而 **Tailwind v4 会 tree-shake `@theme` 里
  没被引用的变量**、判断「有没有被引用」看的也是源码里的**字面名**。三颗 aurora token
  今天还在产物里，只是因为同文件上半段与 `TrainingStudio` 的 `stroke=` 恰好把整名写过 ——
  **是别人的代码替它保住了变量**；谁重构掉那几行，光晕当场失色且无任何报错。
  改成「整名 → 字面量」表 `AURORA_TONE_VAR`。
- **给 `AuroraGlow` 补了第一条用例**（此前零覆盖）：三个 tone 各自映射到哪颗 token、
  强度按本层 alpha 取整。说清它**判不出什么**：拼法与表法的运行时字符串逐字相同，
  「有没有拼名字」由上面那条静态判据守。

## 顺带量清的一件事（为什么门禁里不跑编译）

把 `globals.css` 真编译一次做过对照：谁都不引用的 `--color-zprobe-unused` 在产物里
出现 **0 次**；`globals.css` 声明的 111 颗 `--color-*` 里 **24 颗被 shake**，而这 24 颗
在 `src/**` 里**连名字都没出现过** —— 即「源码里有字面名」既是幽灵判据的条件、又是
Tailwind 的保留条件，**两条等价**，不值得为等价的东西每次提交付 7.3~11.1s 的编译。
真正会翻车的只剩拼名，而拼名一旦成行、产物侧断言同样比对不到，所以只能在源头禁止。
机制与实测数字全部写进 §3.6.1.1（下一个加 token 的人会默认 v3 的「声明即输出」）。
