## Fixed

- **R5 体积棘轮把「计数口径差」误报成「文件变大」，`master` 上每个 PR 都过不了「文件结构硬规则」**：基线记录 `baselineRev: 116666fab…`，而该提交在任何 ref 上都不可达（`git cat-file` 取不到，CI 检出同样取不到）。`git show <rev>:<file>` 恒失败 → 「按 `baselineRev` 同口径重数」整条前提不成立 → 退回**另一个计数口径时代**的记录值 → `LogPanel.tsx` / `use-workshop-pipeline.ts` 被判「988 → 993」「1054 → 1074 变大」。而按今天的口径，这两个文件在写基线的那次提交（`7b5e1ab`）时**就已经是** 993 / 1073 —— 判据一次都没指向真实膨胀；`--update` 又按设计拒绝放宽，棘轮既判不了、又改不动。此前被「覆盖率上报」那一步挡在前面（`skipped`）掩盖了它。
- **口径改为三分**：旧基线（缺 `baselineRev`）照旧退回记录值；可达 → 同口径重数（真实膨胀该拦仍拦）；**不可达 → 跳过并提示 `--update` 重记**。`--update` 在「不可达」情形下允许一次性重记（与「判据版本抬升」同性质），否则棘轮永久卡死。
- **判定「可达」改用 `git rev-parse --verify <rev>^{commit}`**：问的是 commit 对象在不在。此前用 `git show <rev>:<path>` 探会恒为真（拿的不是树内路径），「不可达」被判成「可达」，兜底静默失效。
- 基线按当前检出重记（`baselineRev` → `b874a5b`，同口径值 993 / 1074），规范 §12.13.3 补记这条口径与现场；`tests/check-file-structure.test.ts` 补两条用例（不可达 → 跳过不误报；不可达时 `--update` 能重记），两条都能失败（已实测）。
