## Fixed

- **设置页/整应用在内嵌浏览器标签中冻结修复（ISSUE #3771）**：根因是应用里三处原生 `confirm()`（历史任务删除 / 模型标签删除 / 分镜清空）——同步对话框在内嵌浏览器（IAB）里弹出后若未被处置，同源渲染进程的主线程会以 0 CPU 整体卡死，连无应用 JS 的 `splash.html` 新标签都冻结。三处全部改为既有的非阻塞 `ConfirmDialog`（跟随主题的居中确认弹窗）：hook 只记待确认目标，视图挂弹窗承接确认/取消；控制器类型与用例同批更新（待确认态挂起 / 确认 / 取消三路）。「轮询与系统消息不无限增长」核实现有闸已够：消息中心 `MAX_MESSAGES = 200`、日志 store `LOG_STORE_MAX = 5000`，不另加判据。
