## Changed

- **回调 status 红了分不清「送达失败」还是「GA 判红」：只补可读性**（ISSUE #3452）：PR #3448 上 GA 明明把结论送回了（`ci-ga-verdict-callback.mjs` 送达成功恒退 0），commit-status 那条 `cnb/api_trigger_ga_verdict/pipeline-1(GA 判决回调（骨架·休眠）)` 却显示 `error [2.2s]`。它其实是**GA 判决结论的镜像**（红 = 判红生效、拦合的证据），不是回调腿挂了；GA 侧「送达」恒绿与 CNB 侧「判决」这格颜色相反、两处都叫「回调」，于是「回调成功了还是红的」必然被问到。
- **先核平台能力，别凭印象改**：期望给这格 `description` 补原因。Swagger 里三条 commit-status 路径（`/build/status/{sn}` / `/git/commit-statuses/{commitish}` / `/pulls/{number}/commit-statuses`）**全是 `get`**、`dto.StartBuildReq` 也没有 `description` 字段 ⇒ 那行 `error [2.2s]` 是平台按 build 终态自动生成、外部写不进去。此路不通；能承载「不承重可读性文字」的只有 #3437 已落地的 PR 评论通道。
- GA 侧 `ci-ga-logs-relay.mjs`：那条**本来就会发**的判红 PR 评论里并列念两件事 —— `**判决**`（本次 `conclusion` → `GA_VERDICT`、这格红/绿各是什么）、`**送达**`（信使那一跳恒绿、与这格红绿无关、要查送达看 `[ga-callback]` 读数、这格是判决镜像不是回调腿检查）。新增纯函数 `renderVerdictReadout()` **复用** `ci-ga-verdict-callback.mjs` 已导出的 `conclusionFromJobResults` / `verdictFromConclusion`（§12.18 / 硬规则 24），不另抄结论词表、不另立判据（复用 #3102 那族「红格可见性」思路）。解释不进 marker，`parseRelayComment` 只认 marker 与附件链 ⇒ 本地读者 `ship-ga-logs-cnb.mjs` / `ship-gh-logs.mjs` 一行不改。
- 接线：`pr-gate.yml` 的 relay step 补 `GA_JOB_RESULTS`（与结论回调那一跳同源），step 仍 `if: always()` + step 级 `continue-on-error`；判绿不发评论（无失败 job），`GA_JOB_RESULTS` 缺席时如实念「读不出」、不猜结论。
- **不碰承重**：恒做成绿会让 `GA 回调结论回读` 永远读到绿、承重失效、§13.6「PR 跑绿才合并」被架空 —— 红恰恰是判决生效的证据。`.cnb.yml` 的 `质量门禁` / `GA 回调结论回读` / `COMFYAPP_CI_GATES` / 停用清单 / 流水线 `name`（context 含它）/ `GA_VERDICT` 折叠 / 三态退码**一字未改**；评论里那两行是只读解释，日志搬不到 / 结论读不出都不改三态、不改本 run 的 conclusion、不拦合。「回调成功 = 绿」那条属重做数据源（要同批改 `STATUS_PREFIX` / 回读格 / 保护分支 / 契约用例），倾向不做、本单不做。
