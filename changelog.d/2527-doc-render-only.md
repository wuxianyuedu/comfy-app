## Fixed

- **`doc:render` 现在能只写自己那几份镜像（ISSUE #2527）**：带 `--only <源相对路径[,…]>`
  （可重复），入口话术改成 `pnpm run doc:render -- --only docs/standards/x.md`。

  治的形状：D0 那格 `文档源 ⇄ 生成态镜像同批` 要求「改了源就得带上镜像」，而能满足它的唯一
  现成动作是跑 `doc:render` —— 那一档**无条件**重生成 `SCOPED_DOCS` 全部 38 份，于是
  「带上自己那一份」顺带把**别人留在 HEAD 上的陈旧镜像**一起改脏进自己这批。当场读数
  （#2503 那批）：`git diff --stat docs/generated` 里 `13-提交与-code-review.md` 带出
  **126 行纯表格重排**，而我一个字都没动它的源；处置是 `git checkout --` 退回、只提交自己那份。

  同批把两个方向的分工写成口径（规范 §13.5.5 新增一张表 + AGENTS 硬规则 7 那段的指针）：
  「我这批该写哪几份」用 `--only`，「全量现在漂了谁」用 `--check`（只判不写）。
  **判据本体没有第二条**：`--only` 就是 `writeAll()` 少写几份，比对与报告一字未改
  （§12.18 —— 为「少带点噪音」再写一份比对器，得到的就是两处迟早各漂一份）。
  认不出的名字**退 1 且一份都不写**（否则「以为写了自己那份」与「什么都没写」同形）。

  顺手订正一处我自己写错的因果（记在单上，别让它以讹传讹）：这条漂移**不是**「渲染器带出
  格式差异」，也不是 mtime 跳过 —— 当场复算：干净工作区跑 `pnpm run doc:render` ⇒
  **零改动**（生成器确定且无条件）。真因是那一刻 `docs/generated/13-…` 在 HEAD 上就**落后于它的源**
  （定义即「镜像 ≠ 用当前源渲染出的内容」）。今天再跑同一条命令 ⇒ 零改动，说明那段落后已被
  别的并行批次并上（`git log` 显示 13- 的源与镜像在同一天由多条提交同时改动；具体哪一条并上的
  没有去追，也不是本单要答的问题）。
  另有一条不对称留在 §13.5.5 里写明：平台那格跑 `--check --autofix`（先就地修再判），
  所以「镜像在 HEAD 上已陈旧」在平台读数里从不出现 —— 与 #2231 对 `docs/api/**` 处理的是同一族，
  这一格不换执行者，只补「谁漂了」那一句读得出。
