## Fixed

- **`pnpm check:comment-headers` 不再把每一条 open PR 判成「缺署名」（ISSUE #2788）**：
  PR 那一侧的正文取自 `pulls list-pulls` 带回来的 `item.body`，注释写的是
  「PR 列表自带 `body`（实测字段表里有）」—— 那句**半真**：键在、类型是 string，
  而列表形态里它的值是**空串**（本回合实测四张 open PR：#2786 / #2784 / #2649 / #2787
  的 `list-pulls.body` 长度全为 **0**，同几张 `get-pull` 的 `data.body` 都有正文）。
  于是 `typeof body === "string"` 那道守卫**放行**，`headerShape("")` 逐张给「缺」，
  而第 178 行 `bad.some((r) => r.shape !== "读不到")` 把这份假阳性一路带进退码 ——
  与本单自己的口径 ③（「单张读不到 ≠ 缺」）正好相反：**它把「没读到值」读成了「有值且不合规」**。

  改法：PR 那一侧逐张 `get-pull` 取 `data.body`，与单子那一侧（`get-issue`）同一个形状；
  取不到落「读不到」，不改判、不变红。省下的那一次网络往返就是洞的全部代价。

  **同一批把那条长反的教义翻过来**（这是本件更值得记的一半）：
  `tests/check-comment-headers.test.ts` 里原本写着
  ④「PR 正文用列表自带的 `body`，不逐张再问一次 `get-pull`（多一问就是一轮网络）」，
  并有一条 `expect(calls.some((c) => c.includes("get-pull"))).toBe(false)` ——
  判据的 bug 在被测面长成了**要求**，于是那条断言把取数错误钉死了：谁以后想改成逐张问，
  先会被这条用例拦下。所以夹具现在**照实测形态**给（`list-pulls` 的 `body` 一律空串），
  断言方向反过来：
  列表空串 + `get-pull` 有署名 ⇒ 「正常」（修这里是「缺」）；每张 PR **确实各问一次**（数次数）；
  `get-pull` 取不到 ⇒ 「读不到」；PR 侧全合规 ⇒ 退 **0**（修前这一条是 1 —— 退码那一半
  必须由 PR 侧答一次，原有那条「读不到 ⇒ 0」走的是单子侧，碰不到这个洞）。

  修前 / 修后的真机读数（同一条 `pnpm check:comment-headers`）：

  ```
  修前：样本 37 条：正常 27 · 缺 10        EXIT 1
  修后：样本 36 条：正常 31 · 缺 5         EXIT 1
  ```

  剩下这 5 条逐张对过 `get-pull` 的正文首行，**确实没有署名**（3 张别人手工建的单 +
  #2787 / #2770 两条手写正文的 PR）—— 样本数从 37 到 36 是因为本回合关掉过一张单，
  与本次改动无关。⇒ 这一格的「缺」从**结构性假阳性**变成**可读的存量**；
  回填别人的正文是共享面写动作，**不在本批做**（由人点名，见 #2788 期望第 3 条）。

  变异证明：把 PR 那一份 `body` 改回 `item?.body` ⇒ PR 侧**四条**用例当场红
  （三条新增 + 一条被改写的既有用例「单张读不到记『读不到』…；PR 那一侧同一口径」；
  其中含退码那条），改回后全绿。第一次打变异时 perl 的非全局替换命中了**单子**那一侧同形的
  那一行（两处语句只差上下文），红的是三条不相干用例 —— 同形语句的 mutation 必须把
  上下文锚进 pattern，否则「红了」不等于「打在对的那一份上」。
