## Changed
- CI：把每日档与桌面成品包两条定时流水线从 CNB 自托管节点撤下，改由 GitHub Actions 的 `.github/workflows/daily.yml` / `package-desktop.yml` 的 schedule 承担 —— 自托管节点是开发用本机，定时重档（生产构建 / 全量E2E / 全量单测 / cargo 整棵冷编译）与日常开发抢核。`*daily_gates` / `*package_gates` 锚点、`COMFYAPP_CI_DAILY_GATES` 清单、`web_trigger_*` / `api_trigger_*` 手动与 API 触发口一字未动：撤的是时钟，不是判据，需要本机产物或复验某一格时仍可手点。`tests/no-platform-ci-config.test.ts` 把「必须挂两条 crontab / 桌包两个触发口 / 定时·手点·API 三口同一份清单 / `lock_daily` 三把锁」逐条重写为「CNB 不许再挂 crontab + GA 两条 schedule 的 cron 对位北京 01:00 / 03:00 + 手动口仍跑同一份清单」，形态契约里那条 crontab 正则改成「迁移决策锚点句」，反向断言与变异用例全部保留，没有靠删断言放行。
- CI（出勤判据）：`scripts/check-daily-attendance.mjs` 的 `DAILY_LANE_PIPELINES` 收成 CNB 现役的两个触发口；迁移前叫「每日生产构建」的历史派发另立 `DAILY_LANE_RETIRED_PIPELINES`，与现役名单合成 `DAILY_ATTENDANCE_LANES` 供 `pickDailySubject` / `judgeAttendance` 使用。两件事不能互相顶替：前者由 `no-platform-ci-config` 与配置双向核对，收一个已不存在的名字就是账面替它作证；后者读平台历史构建，不认就会在窗口跨过迁移点时把「前一天还绿过」念成缺勤。`isDailyDispatch` 保留 `crontab:` 前缀识别，同因。
- CI（GA 侧补齐）：`daily.yml` 追加 `comfyapp-coverage` artifact（`if: always()` + `if-no-files-found: warn`，对位 CNB 覆盖率上报格「没有报告时跳过而不是判红」的口径；GitHub runner 没有 `cnb` CLI，判据本体不重抄）；`package-desktop.yml` 除 14 天 artifact 外新增滚动 `nightly` GitHub Release（runner 自带 `gh` + workflow 级 `permissions: contents: write`，`--clobber` 保证每天同资产名可覆盖，缺产物时判红而不是静默空发布），作为「现在要拿一个包」的常驻落点。
