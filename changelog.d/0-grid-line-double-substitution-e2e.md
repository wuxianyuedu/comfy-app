## Added

- **补上画布网格线的「二次代入」那条缝**（`e2e/theme-token-consumers.spec.ts` 第 6 条、
  规范 03 §3.6.1.1）：上一批把网格线收进 `gridLineColor()` 后验了两半 —— jsdom 验
  「值送到 `--xy-background-pattern-color-props` 里」、e2e 验「`stroke: color-mix(…)`
  解析得了」。但画布真正走的是**第三条路径**：React Flow 写成自定义属性，样式表再
  `stroke: var(--props, var(--xy-background-pattern-color, var(…-default)))` 取它，
  也就是「一个 `var()` 嵌在自定义属性里、又被外层带兜底的 `var()` 二次代入」。
  三段各有各的失效方式，只验两头等于没验中间。现在在真样式表上钉住：浅 `[0,0,0]`、
  深 `[148,163,184]` 都能穿过这条链取到（用例带反空转 —— 先断言那 3 条真规则在场，
  否则「退成默认灰」会被误读成「token 生效」；样式表由画布组件模块级 import，
  所以必须走 `/workspace`，`/login` 上没有这三条规则）。

## Fixed

- **修正一条我自己写进规范的不准确概括**：规范原话「幽灵 token 的表现是 `fill` 退黑 /
  `stroke` 退 `none`」**只适用于直接引用**。走带兜底的自定义属性链时，实测降级结果
  **取决于作用域**：`.react-flow` 之内退回库默认灰 `rgb(238, 238, 238)`（看着就像
  「网格线本来这么淡」），之外才是 `none`（线直接消失）—— 两种都不报错，而前者比退黑
  **更难发现**。规范里补了这张对照表与结论：判据不能停在「画面有没有变黑」，
  只能靠静态那条（引用必须是已声明的字面名）+ e2e 的不变量（幽灵 token 绝不会解析成
  我们的色相，具体退成什么不断死）。
- 负控制的第一版断言本身是**基于错误预测写的**（我猜会退成默认灰），实测 `parseColor()`
  直接对 `none` 抛错。这个红是有价值的：它证明「我以为我理解这条路径」不成立，
  于是才有了上面那条规范修正。
