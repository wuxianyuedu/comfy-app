## Fixed

- **每日档的出勤判据不再由别的定时档替它作证（ISSUE #2873）**。
  `pnpm check:daily-attendance` 过去只有**一层**认法：按 `crontab:` **前缀** + 两条手点 / API
  触发口挑「最近一次每日派发」。前缀那一半是刻意的（事件名里带小时，而小时在 10-22 一天内
  换过两次 `0 4` → `0 2` → `0 0`，写死钟点的判据第二次换时刻时就静默变成「永远读不到派发」），
  但它成立的前提是「`crontab:` 只有一条档」。#2503 / #2611 把桌面成品包做成第二条定时档
  （`crontab: 0 3 * * *`）之后这个前提没了，而判据没跟着分档。当场读数（本机，2026-10-31）：

  ```
  $ pnpm check:daily-attendance
  [daily-attendance] 缺勤 ✗ cnb-uuu-1k672u3j6 那一跑有格真失败：Prepare
  最近一次每日派发：cnb-uuu-1k672u3j6 · 事件 crontab: 0 3 * * * · 2026-10-30T19:00:11Z（21.0 小时前）
  逐格：6 格有结论 · 判定 failed（平台原文 error）
    · 真失败 Prepare
    · 被它带下去、根本没跑的格：打包·安装依赖、打包·壳工具链自证、打包·桌包工具预置、
      打包·桌面成品构建、打包·发布到常驻目录
  ```

  被念成「每日派发」的那一条是**桌包档**（五条格名全是 `打包·*`，Prepare 死于
  `runner … not connected`），而同一时刻每日那一档的最近一条是另一跑
  （`cnb-tc7-1k66s2i6j`，`crontab: 0 1 * * *`，红在 `每日单元测试` 1805.6s）。
  两档各自的结论被合成了一句，而主语是错的那一个。

  改的是**认档那一层**，不是候选那一层：候选仍按事件前缀收（小时继续不承担身份），
  收来之后按平台自己写进 `get-build-status -v` 的**流水线名**认档 ——
  与 `ci-daily-failure-issue.mjs` 的 `--lane` 是同一条认法（#2595 早就立了，这一格一直没跟上），
  名单是 `DAILY_LANE_PIPELINES`。三种「挑不着」分成三格下一动作：
  窗口内只有别档 ⇒ **缺勤**并点出让开的是谁；有几条取不到逐格详情 ⇒ **没结论**
  （列表那份没有流水线名，「认不出是不是本档」不等于「不是本档」，退 2 不算绿也不算红）；
  一条定时派发都没有 ⇒ 话术与旧的一致。让开的别档**念在证据行里**，不是一路 `continue` ——
  读数里只剩一条而窗口里有两条，与没有读数等价。

  名单与配置**双向对账**（新增判据）：`tests/no-platform-ci-config.test.ts` 拿
  `pipelineLockAssignments()` 比「跑 `*daily_gates` 的流水线名」⇄「`DAILY_LANE_PIPELINES`」，
  两个方向的漂各自都有名字：配置改了名而名单没跟 ⇒ 这条判据从此**恒缺勤**；
  名单里留着一个已经不存在的名字 ⇒ 它照旧"认得出"而那一档其实早没了，于是**恒出勤**。
  两种都不会让别的判据红，所以比的是「跑哪份清单」而不是「挂在哪个事件名 / 几点」。
  另钉一条：跑的不是 `*daily_gates` 的定时档**不许**出现在名单里（桌包那条就是它的对象，
  以后再加一条定时档也在这条的量程里）。

  用例：`tests/check-daily-attendance.test.ts` 新增一组 6 条（交错两档时判本档并点名让开的、
  只有别档时缺勤且话术不说「一次派发都没有」、取不到详情落没结论、三个触发口都算本档、
  **反向对照**「把桌包名注进名单 ⇒ 同一次派发就成了本档」（少它则「按名单挑」与「写死一条」
  在断言里一模一样）、平台没给流水线名时不凑形状）。
  **变异证明**：`pickDailySubject` 里 `wanted.size > 0` 单 token 翻成 `> 99` ⇒ 这一组
  **4 条红 / 2 条照常绿**，而红的第一条打出的正是今天那份错读数原文
  （`缺勤 ✗ cnb-uuu-1k672u3j6 那一跑有格真失败：Prepare`）；还原后 25 条全绿。
  旧有 19 条一条未动地通过（夹具里的流水线名本来就在名单内 ⇒ 这次改的确实是「多档交错」那一格，
  不是把判据整体收窄）。

  规范 §13.5.23 末节那条「每日类按 `crontab:` 前缀 + 两条触发口认」同步改成两步口径并带上
  这份现场（镜像 `docs/generated/13-提交与-code-review.md` 同批）。

  **这一单没做的事**：桌包档自己的空转由 #2874 管（那一跑连 `endStages` 的立案格都是
  `skipped`）；`ci-token-scopes.mjs` 里那份按小时正则分档的 `whereItLives()` 仍是小时口径
  （它自己的注释已经声明「时刻再挪这里要同批改」），换认法是第三件事、另开单。
