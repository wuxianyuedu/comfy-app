## Fixed

- **`db-schema-ready` 的临时目录不再在进程内等删**（`src/lib/db-schema-ready.test.ts`）：
  上一轮给这条 Windows `EPERM` 加的补丁（先 `close()` 再带 `maxRetries` 删）只是把窗口
  撑大了，没消掉赌局 —— 实测 libsql 的 sqlite 句柄由其工作线程持有，`client.close()`
  **不返回 Promise**，句柄还要 **1–9s** 才释放（并行负载下更久、没有上界；探针实测
  6 个 CPU 满载时 9s 内一次都没释放）。安静机单跑赶得上，钩子里 108 个文件一起跑就
  赶不上，表现为「只在提交时红一次的 EPERM、隔离跑反而绿」—— 最难查的那一类。
  改成：本轮只关不删，**下一轮开头扫一次**上一轮留下的目录（只认自己的前缀，
  跳过 60s 内还在写的，避免误删同机另一条 vitest 正在用的）。删除因此退出关键路径：
  锁多久都不影响红/绿，临时目录也不会累积（每轮至多留一份，下一轮清掉）。
