## Changed

- **pre-commit 多了一档 D0「形态前置档」：判「这次提交自身形态」的 14 条改在其余四组启动
   之前串行跑完**（规范 §13.5.8.2.1）。立案现场是**本机账**
   （`.git/comfy-precommit-timing.jsonl`，最近 17 次提交、6 次红）：D 组带 `set -e`，一次红的
   记录里「记到哪一条」就是拦下你的那一条。那六次读出来是 `freshness-gate.mjs` ×3、
   `render-doc-placeholders.cjs --check` ×2（这一条已随 ISSUE #1975 挪到平台侧，本地不再付）、
   `check-changelog-fragments.cjs` ×1 —— 全都不是代码内容的错，却都要付满一堵 C 组的墙才知道：
   **最早的一次 D 跑到 14.2s 就判红，整条钩子照旧付满 C 的 156.6s 才退出**
   （exit 1、D=14.2s、C=156.6s、总 157.6s），另几次在 87–233s 之后才轮到那一条，总付 182–3630s。
  为什么不在原来的形状里修：**四组是「并行且全部等完」的**（收尾 `for id in A B C D; do wait`），
  墙钟 = max(各组) = C 组，所以在 D 组内部把便宜的挪到前面**不会让任何一次提交变快**；同理
  「把 D 组改并发」也**不做** —— 账里绿的那几次 C 组中位 207s / 地板 141s，D 组中位 115s，
  D 从来不是关键路径，这与钩子文件头那条既有测量（ISSUE #1610：并发净零、峰值内存反涨
  0.3GB）是同一个结论的第二次复现。能省的形状只有一个：在 A/B/C 启动之前先拿到这一档结论。
  **入选口径两条**（缺一就留在 D 的并行档）：① 判的是这次提交自身的形态（暂存内容 / 提交
  元数据 / 登记台账），违例的修法是「改你刚 stage 的东西」，不依赖其它组的结论；② 稳态代价
  ≤ 2.5s。**贵的判据留在并行档里是免费的**，挪进串行档等于给每一次绿提交加税 —— 所以
  `文件结构硬规则(R1-R12，R5 硬闸)`（中位 9.4s）与 `jsx-a11y 规则开关⇄判据（§6.12）`（12.8s）
  **明知同属形态这一族也留在 D**。
  **这笔税写清楚：D0 整组串行实测 25.0–25.7s（四个并行检出抢核的现场）⇒ 绿提交 141s 变
  ≈166s（+18%）**，换来那 6/17 从 157–3630s 变 ≈25s。这是拿绿档换红档，不是免费午餐；
  名单与顺序都由判据钉住，往串行档加一条必须过人的眼。
  标签与命令与它们在 D 组时期**逐字一致**：钩子里所有 `run` 行的解析面是整份文本
  （`check-gate-executors.cjs` 的执行者在场、`check-declaration-readers.cjs` 的标签表、
  `base-check/hook-steps.mjs` 的合并前复算面、`check-doc-references.cjs` 与 §13.1 清单的逐字
  对账）—— 改标签或改命令会让那几处一起漂，而漂的表现是「判据还在、指错了地方」。
  编排改动**一条判据的内容都没动**：51 条 `run` 行一条不少，只是有 14 条换了组。
- **同批把两处「会静默放行 / 静默丢账」的坑一起收掉**（都出自本轮量这份账的现场）：
  ① `timed_step` 里裸跑 `"$@"` 会被 `set -e` 在 printf **之前**截断 ⇒ **失败那一条自己从不
  进账**，「哪一步拦下了我」这个问题正好落在缺失的那一行上，组的墙钟与步之和也对不上。
  改成 `"$@" || _ts_rc=$?`（不触发 `set -e`，退出码照旧由 `return` 带出去）⇒
  **阻断语义一字未变**，失败那条也留下读数。
  ② 收尾那段对四组的退出码原来是 `code=0` 默认放行 ⇒ **一个被 OOM 杀掉的组会表现成「tsc 与
  vitest 都过了」的绿提交**。改成读不到 rc 就拦下并回吐该组日志，与新加的 D0 那一档同口径
  （同 §13.5.15「读不到输入时报绿是最坏的一种」、§13.6.2 的 `inconclusive` 不是证据）。
- **记账自己的开销不再冒充判据的成本**：每步取两次时钟，而 `$(date +%s%3N)` 在 MSYS 上每次
  fork 约 467ms ⇒ 一份 14 条的组墙钟 54.0s、步之和只有 41.1s（差的 12.9s 全是取钟的钱），
  且这笔钱**藏在每条读数里**（`UI/逻辑分离硬闸` 报 4.2s，其中约 0.9s 是时钟）。
  `timing.sh` 新增 `set_now_ms`：走 bash 5 的内建 `$EPOCHREALTIME`（纯变量展开、零 fork），
  没有这个变量的 shell 自动退回原来的 `date` 探测路。改后整组 **25.0s**、步之和 26.2s。
  ⚠️ **跨这条线对比逐步读数时要记得**：本轮之前的每一条都含着 ≈0.5–0.9s 的取钟开销。
- **`run()` 从钩子里的 D 组块移进 `.githooks/timing.sh`，只定义一份**：钩子现在有两个
  `sh -c` 块（D0 与 D），各写一份的漂移形态与那份文件头里「两份时钟必然漂成两个刻度」同款。
  反向也钉住：钩子里不许再长出第二份 `run()` 定义。
- **新增钩子编排的共享解析件 `tests/helpers/hook-groups.ts`**（`runSteps` / `groupShBody` /
   `stepsInGroup` / `withoutCommentLines`）：三处判据问的是同一件事 —— 「某条判据在不在门禁链
   里、在哪个组、命令逐字是什么」（`doc-check-hook-wiring`、`precommit-timing`、
   `hook-affected-launch`），各写一份解析就会漂成「同一份钩子在三条判据里长成三个形状」
   （§12.12 / §12.18）。它顺带把两条口径钉在代码里：**只认步骤行**（`toContain` 会被注释命中
   —— 把那行注掉判据照样绿），以及「块正文里不许出现单引号」—— 那条是**被解析器判出来**的，
   不是靠人记住。

## 验证

- `tests/doc-check-hook-wiring.test.ts` 新增一档 describe：14 条成员逐条 + 名单与顺序不许
  无声变化 + D0 ∩ D = ∅ + **`wait "$D0_pid"` 排在 `run_group A` 之前**（否则这一档退化成
  第六个并行组）+ 缺退出码那一支必须 `exit 1` + **两组的步骤数之和 == 全文总数、且没有命令
  以 `'` 结尾**（这条是本轮重排把组收尾引号并进正文行里、`sh -n` 照样过时补的 —— 那时四个
  解析器读到的是 `…--staged'`，而「D0 有几条」会数成 51）。
- `tests/precommit-timing.test.ts`：三处 source（外层 + D0 + D）、`run()` 只在共享件里一份
  且反向钉住、两个块都真有 `run` 步骤，外加 `timed_step` 那条 `"$@" || _ts_rc=$?` 的形态判据。
  起 sh 真跑那一档**没有**做成用例：那要依赖 `sh` 在 PATH 上（CI 的 PowerShell stage 不保证），
  而「拿环境早退换一条会绿的用例」正是 §11.17 禁止的那种绿 —— 它的行为证据是下面那两次实跑。
- `tests/hook-affected-launch.test.ts` 的 `cGroupBody` 改为委托共享件（行为逐字不变，含原有
  那条「注掉一行必须被照出来」的反向证明）。
- **两次真实钩子跑**（`sh .githooks/pre-commit`，故意放一份首行写歪的碎片）：换组之前那一次
  「14 条里第 4 条拦下、总 19.3s、账里只有 3 条且缺拦下者」；修完之后那一次「第 1 条拦下、

- 整组串行的代价直接量（同一份 D0 正文、`LOGD` 指临时目录）：修时钟前 54.0s，修后 25.0 /
  25.7s 两遍。
- 三个测试文件合计 **145 passed**（`doc-check-hook-wiring` 单档 90 passed）；当时每核负载
  5–10，由 `run-affected-tests.mjs` 的负载判据与隔离复跑消化，**未抬任何预算**。

  因此也过 —— 它比的是整条命令，改一个字都会被照出来）。
- **订正上一笔里的两个数（合主干时读到 `docs/audits/2026-10-16-hook-baseline-map.md` 之后）**：
  ① **入选口径 ② 从「每条稳态 ≤ 2.5s」改成「落在整组预算里」**。按条筛是错的：这一档是
  串行的，它的墙钟**就是全部入选判据之和**，而那份快照用 9 个样本量到 `故事面` 中位 7.6s、
  `jsx-a11y` 31.3s —— 同一条判据在不同负载窗口差几倍是常态，拿单条阈值筛会把「一条就吃掉
  整份预算」的判据放进来。预算改为按组算，锚在一次真实绿提交的读数 **D0 组 16.1s / 步之和
  15.4s**；`文件结构硬规则`(9.4s) 与 `jsx-a11y`(31.3s) 继续留在 D，理由不变（贵的判据在
  并行档里是免费的）。② **税的数字换成真实读数**：先前写的是「整组 25.0–25.7s ⇒ 绿提交
  +18%」，那是把 D0 正文抽出来单跑的 harness 值（负载更重的窗口）；钩子里真跑那一笔读到的是
  **16.1s ⇒ +11%**。两个数都保留并标了量法，因为 harness 那次是**修计时前后的 A/B 对照**
  （54.0/41.1 → 25.0/26.2，组墙钟与步之和从此重合），那个结论只能由它给出。
  同时按那份快照自己的要求回来更新它（补记新形状、换了组的 14 条、以及「本表数取自改计时之前」
