## Fixed

- **脚本档的判决面不再跟着工作区飘**（ISSUE #2681，规范 §13.5.14.1）：`configFace()` 用
  TS 的 glob 引擎展开 `**/*.mjs`，它读的是**这台机器此刻的目录**而不是这份提交 —— 落在
  非点目录、非 exclude 里的一份构建产物就会把展开数顶大。当场读数（#2572 那一跑）：
  本地展开 **211** 份 = `git ls-files '*.mjs'` 的 **211**，平台同一份代码展开 **212**，
  而红只给「`配置展开 212 份，账上写 210`」两个数。那两个数读不出方向，而「差一份」的
  两种修法是**相反**的：新加了入库脚本没记账 ⇒ 该记账；磁盘上多一份没入库的产物 ⇒
  该归 `exclude` 或删掉 —— 照前者办就等于把一份不在版本控制里的东西写成全仓判决面。
- **改法是「账与棘轮按入库的那一份」，不是「别判了」**：`check-scripts-typecheck.cjs` 新增
  `trackedMjs()` + `splitTrackedFace()`（唯一实现，用例读同一份、不抄第二遍），把
  `configFace` 的结果与 `git ls-files '*.mjs'` 求交。三条边界各有一条用例：
  ① **取不到 git 清单 ⇒ 不筛并明写**（临时夹具不是它自己的 git 顶层 —— 那种时候筛成空集
  长得像「面缩了」，是反方向；所以 `null` 走「没筛」那一支，话术里念出来）；
  ② **被剔掉的必须点名**（`面外未入库 N 份：…` 与 `面外读数（未入库，不记账）：…`）——
  「不判它」与「看不见它」是两句话，后者让下一次同类污染再次无名；
  ③ **「include 有没有被改窄」那一问仍用未筛的展开** —— 它判的是配置，与磁盘落了什么无关
  （两条判据不许互相顶包，§13.5.29「一条判决一行」）。
- **端到端实测**（一份真 `git init` 的临时夹具，跑两遍）：
  未入库那一步 —— `展开 2 份 .mjs（入库的 1 份…）` + 点名 `scripts/stray.mjs` +
  `面外读数（未入库，不记账）：1 处` + **退 0、存量不涨**；
  把同一份 `git add` + commit 之后 —— `入库的 2 份`、`scripts/stray.mjs TS6133: 基线 0 → 当前 1`、
  **退 1**，且不再念「面外未入库」。第二跑是必须的：只证「剔掉」不证「入库就算」的话，
  这条改动就只是「永远不看新文件」的另一种写法。
- **真仓那一格改读同一份实现**：`tests/scripts-typecheck-ratchet.test.ts` 的「账本 `face`
  ⇄ 面同数」原先拿**未筛**的磁盘展开比对 —— 那正是会把 #2681 的耦合请回测试里的写法；
  现在它拿 `splitTrackedFace(configFace, trackedMjs(REPO_ROOT))`，并加一条
  「工作区里不该有未入库的 `.mjs`」（有就当场点名，不再伪装成「面与账不符」）。
- 话术同步：判据第一行念成 `展开 N 份 .mjs（入库的 M 份；…）`，`--update` 与绿尾巴
  那个「基线已重写：面 …」也改用筛后的数；`tsconfig.scripts.json` 的头注补一条
  「glob 读的是目录不是提交」的警告与去向。**没有**为此新写一条启发式扫描器（硬规则 24 末句）。
- 关联：#2572（撞上去的那一跑与它留下的 `driftReading()` 点名话术 —— 本单把同一件事
  从「红的时候才念」挪到「每跑都念」）、#2524 / #2589（这一档的建立与清账批）。
