## Fixed

- **共享机 / 小核 VM 上 pre-commit 的组 C 太慢**（ISSUE #1648）：`scripts/run-affected-tests.mjs`
  的钩子档并发此前是**写死的 4**，没有任何覆盖口 —— 钩子注释里那句「机器紧张把 C/D 也挪成
  串行即可」只是一句话，没有执行者，于是唯一的出路变成改钩子或 `--no-verify`（两条都不该是常态）。
  现在多一个**只调并发、不碰任何判据**的显式口子 `COMFY_PRECOMMIT_MAX_WORKERS`（缺省仍是 4；
  非法值按默认办并提醒，不静默降级成 0）。口径与实测曲线见规范 §13.5.8。
- `tests/base-check.test.ts` 的 `vi.setConfig` 里那条 `testTimeout: 30_000` 是**同值死代码**
  （全局 `testTimeout` 已经是 30s），注释却写着「负载高的机器上 5s 不够」，读起来像「本条把
  预算放宽了」，实际一个字都没改。删掉那一半、只留真的不同的 `hookTimeout: 30_000`
  （全局 45s 是给 `theme` 那种真编 CSS 的 beforeAll 留的），并把数字出处写进注释。

## Tests

- `tests/hook-affected-launch.test.ts` 新增四格：默认档＝4（缺省 / 空串 / 空白）、显式覆盖生效
  且提醒里说清「只调并发」、非法值落回默认并提醒、覆盖值真的接进 vitest 命令行；另加一格
  「环境变量由调用点读入」—— 防的是解析器自己兜底 `process.env` 后被**用例进程继承到的**
  环境变量污染（那种失效长得像「判据真的坏了」）。
