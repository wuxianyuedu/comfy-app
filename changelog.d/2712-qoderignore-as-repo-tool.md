## Added

- **`.qoderignore` 从「每台机器手搓一份」收成仓内工具**（ISSUE #2712，规范 §12.20）：
  索引器**不吃 `.gitignore`**，它吃自己那份 `.qoderignore`，而本仓真正重的几棵树
  （`src-tauri/target` / `.next` / `python-venv` / `coverage` / `log` / `data`）早被 git 忽略了
  —— 于是「索引为什么这么贵」每台机器重新发现一遍，排除表各写一份形状不一的，
  而没人知道该包含哪些目录。现在的走法是「拿到仓库执行一次」：`pnpm qoder:ignore` 装好，
  `pnpm qoder:ignore:check` 只比对（不一致退 1），`--print` 不落盘打到标准输出。
- **唯一写出者把「排除项」与「为什么排除」绑成一条数据**：`scripts/qoder-ignore.mjs` 的
  `IGNORE_SECTIONS` 每条 pattern 带一句 `why`，渲染时 `# <why>` 紧贴在其 pattern 上一行 ——
  一行没有理由的排除，下一个人只能猜它是不是漏配，而猜的结果通常是直接删掉那条
  （索引再贵回去）。三条形状约定各有用例：产物里**不写绝对体积读数**（那是「这台机器、
  这一刻」的数，写进去就是一条会过期的陈述）；代码里**只有一处落盘**且落点是仓库根那份
  （`.git/info/exclude` 只出现在说明里 —— 那是每台机器自己的本地状态，工具跑在谁身上
  都不该改变它）；渲染**幂等**（内容相同 ⇒ 一个字节都不写）。
- **登记面同批落**：`tests/qoder-ignore.test.ts` 进 `scripts/fixed-structural-tests.mjs`
  固定清单。理由与 `tests/build-desktop-step-readings.test.ts`（#2574）同因 —— 它判的是
  **两份文本**（入库那份 ⇄ 工具渲染那份），而 `.qoderignore` 不被任何代码 import、
  `package.json` 那条出口住在仓库根，静态 import 图两条都追不到：改那份表不会把用例
  带进增量面。不登记的表现不是红，是「装了等于没装」。
- **一致判据只证同步、不证够宽**，所以另立一条 `MUST_COVER`：把「哪几棵树必须被排除」
  单独钉住（判语义不判行形状）—— 谁把 `IGNORE_SECTIONS` 删掉一半，盘上那份跟着删一半，
  「逐字相同」那条照样绿。三态退出码另由 `tests/helpers/gate-repo.ts` 的临时工作区证：
  缺文件 `--check` 退 1 并明说「文件不存在」、手改产物报出增删行数后能刷回来、
  写不进去退 2 且**失败路上不念任何成功话术**（已生成 / 已刷新 / 没动任何字节）。
- 脚本档「面 ⇄ 账」同批重记（`face` 214 → **215**，存量 95 处一字未动）：本单新增一份
  入库的 `scripts/*.mjs`，#2681 那道「入库」闸在这里第一次被自己用上 —— 新写的 `.mjs`
  必须干净（新增脚本零容忍扩基线），实测 `qoder-ignore.mjs` 贡献 0 处报错。
- 文档同批：`README.md` 的「根目录文件用途」加 `.qoderignore` 一行（含「不要手改」与
  「改完要重启 Qoder CN 进程才生效」）、「常用脚本」加那条出口；§12.20 补第二件标本
  （与 `pnpm ship` 并列：一个治「同一串命令手敲三次」，一个治「同一个判断每次重做一遍」）。
