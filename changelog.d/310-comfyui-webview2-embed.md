## Fixed

- **ComfyUI 页签里的「已阻止此内容」：拦下它的其实是应用外壳，探测一辈子都看不到（ISSUE #310）**。应用级页签把 ComfyUI 内嵌进**同一个 WebView**，而两者不同源（端口不同即跨源），WebView2 默认按 Chromium 的「不同源不可嵌」执行并直接拒绝渲染该 iframe —— 页面里只剩一句 `已阻止此内容。请与网站所有者联系以解决此问题。`。它与 403 / `X-Frame-Options` / CSP 那几种的关键区别是**谁来执行**：那些由被嵌方发出、服务端探测得到；这一条由宿主自己执行，探测侧永远「一切正常」，所以只能在壳里修。现在由 `src-tauri/build.rs` 给 WebView2 下发 `--disable-web-security`（写成 `app.exe.manifest` 并复制到 exe 同级 —— WebView2 **只从 exe 同级读**，文件不在那里就静默失效；`scripts/build-desktop.mjs` 再放一份，不依赖构建顺序），参数整体替换默认集，故原样带上 `--autoplay-policy=no-user-gesture-required` 与 `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`。三处同源由 `tests/webview2-embed-manifest.test.ts` 守住（Rust 字符串与 JS 模板字符串之间没有类型系统，人一定会改漏一处）。**需重编 Rust 壳**（`cargo build --release --features custom-protocol`），只改前端跑旧二进制等于没改。
- **判据不再把「完全不知道」当成「同源、必然可嵌」（ISSUE #310）**。壳的 main 窗初始 URL 是 `about:blank`，页面传上来的 `window.location.origin` 就是字符串 `"null"`；`URL` 对非特殊 scheme 会把端口解析成 0，于是 `isSameOrigin("about:blank", "http://localhost:8080")` 返回 **true** —— 任何 about:blank / `file:` 页面都会被判成「与 ComfyUI 同源、可嵌」，页面于是无条件塞 iframe。现在 `judgeEmbeddable` / `probeComfyEmbeddable` 在任一侧不是 http(s) 时一律判不可嵌（也不发无意义的探测请求），回归见 `src/lib/comfy-embed.test.ts` 的「非 http(s) 源一律判不出」一组。
- **失败也要可读、可自查**：不可嵌时页签内的说明里现在带上**地址**（`ShellTab.blockedUrl`）与「也可以到 设置 → 创作后端 点『在浏览器打开』」。只剩一句「看不了」时，用户与排查者都无法判断是外壳拦的还是 ComfyUI 拦的；把地址复制到浏览器能打开 → 拦的是外壳，也打不开 → 拦的是 ComfyUI 自己。
