## Added

- **规范 11 新增 §11.17「测试环境：全局 `node` + 逐文件 opt-in，不用 `projects` 按目录分档」（ISSUE #1485）**：把「`@vitest-environment jsdom` 那 183 处注释能不能靠 vitest 5 的 `projects` 收掉」这个反复被提出、也反复被含糊否决的问题**量出结论**。
  - 实测 `src/components/**` + `src/app/**` 共 231 份用例：**70 份不带 jsdom 文件头，且全是 `*.test.ts`**（配置表推导 / store / `src/app/api/**` 路由断言，无一份 `.tsx`），今天在 node 下跑且就该在 node 下跑；反过来 `src/lib/**` 有 18 份要 jsdom。按目录分档 = 这 70 + 18 份要么被放错环境、要么退回逐文件覆盖。
  - 记下**两侧不对称**这条判据：node 下真碰 DOM 会当场红（响的），jsdom 下跑纯逻辑只是变慢（**静默的**）—— 后者的代价没有报错替你说话。
  - 结论：环境归属由「这份用例自己碰不碰 DOM」决定，而它在文件内部、不在路径上，逐文件 opt-in 是与事实一一对应的一侧，维持。判据同 §11.16 那条「能注入的一律注入」—— 依赖写在看得到的地方，不散成靠约定维持的目录规则。
  - `docs/guides/TESTING.md` 配置节同步补上这条（含「别再问一遍」的实测数字）。
