## Changed

- **`comment-language` 判据精确化（`RULE_VERSION` 2 → 3）**：一行注释要**同时**满足两条才算「用英文写的说明句」—— ① 剥掉三类**引用形态**（反引号内联代码、成对引号里的字面量、**连字符拼接的标识符整体**）后仍剩 ≥3 个英文词；② 剩余部分含英文虚词/动词（复用文件里已有的 `JSDOC_PROSE_WORDS_RE`，与 JSDoc 结构行豁免同源，不新增词表、不做块状态）。旧口径只数词数。
  - 为什么必须改：这条规则治的是「人读的说明文字用英文写」，不是「注释里出现英文」。中文段落把标识符 / 路径 / 类名 / ARIA 属性折到下一行是极常见写法，旧口径整片误判 —— 仓库实测 **21 行里 20 行属于这一类**（例：` * \`ui/tooltip\` / open-in-browser /`）。那种红只有两条消法：在引用行上垫一句中文，或放宽基线 —— 两者都把门禁推向噪音，而**噪音判据的终局是没人再看它**。
  - 连字符那半条不是装饰：`\bin\b` 会把 `open-in-browser` 拆出一个 `in`，不整体剥掉，一整串纯模块名清单就会被当成「含虚词的英文句子」（这正是第一次试算后残留的那一行）。
  - **代价写进规范**：不含虚词的纯实词英文短句（`// probe launch path timeout`）不再被机器拦，交 review 兜。反向锚点用例（裸写英文句仍计、URL 行仍计、指令的英文说明仍计）钉住「豁免不放过散文」。
- 判据变严后仍红的 2 行是**两句上游文档原文引用被折行**（`check-ui-primitives.cjs` 里 P77 引的 shadcn `forms.md` 与 P79 引的 `styling.md` 原则 4），改法是让引用与它的中文引导语同行 —— 引用原样保留，不改写、不翻译。
- 基线 `scripts/.comment-language-baseline.json` 随版本重记：**0 行 / 0 个文件**（版本 3）。这是「判据看得见真实存量」后的合法登记，不是放宽 —— 旧基线写着 0、真实 21 行，那份基线一直在说谎。
- `tests/comment-language.test.ts`：基线夹具的判据版本改为**从脚本里读**（`currentRuleVersion()`），不再在测试里硬写数字 —— 两份版本号谁新谁旧正是这类门禁最容易漂移的地方（§12.5.4）。新增 5 条差分用例（清单行不计 / 连字符里的虚词不计 / 反引号内原文引用不计 / 裸写英文句仍计 / JSX 锚点的 fixture 换成真英文整句并写明为什么），用例 23 → 27。
- 规范 §12.4.6 同步补上「机器怎么判」这一小节与代价说明（判据与文档同步演进，AGENTS.md 维护约定）。
