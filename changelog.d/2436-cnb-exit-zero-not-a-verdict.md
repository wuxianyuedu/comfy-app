## Changed

`cnb` 的手工口径补一句读数规则，落在它已有的两处出处旁边（不新开一节、不新写门禁）：
**`cnb … -v` 的结论只认 JSON 里的 `data.*`；退出码 `0` 既不许读成「写成功」，也不许读成
「取到了空结果」** —— 认不出的子命令打印的是模块 usage 而退 `0`，于是「一次也没写」在终端上
与「写成功」逐字同形（现场：把评论敲成 `create-comment`，`EXIT=0` 被读成「写了」，
独立回读评论列表才看出条数一条也没多；仓里既有的正确形状是 `post-issue-comment`）。

脚本侧早有防线，所以这次只补**人那一侧**那句话：`ship-exec.mjs` 的 `cnbJson` 以
「输出必须是可解析 JSON」为在场条件，拿不到就落「没结论」（`NOT_RUN`）。
登记面两处：规范 §13.6 那条「终态只认两个原值」的旁边 + project Skill `.qoder/skills/ship/SKILL.md`
的边界第 1 条。按 §12.20 **不加门禁**：要买的是一句口径，不是第二轮子。
