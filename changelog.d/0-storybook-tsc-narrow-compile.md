## Fixed

- **pre-commit 组 C 不再被一条与改动无关的超时拦下**：`tests/storybook-tsc-input.test.ts`
  的 ④ 原本在固定清单里跑**两遍全仓** `tsc --noEmit`（缺生成件一遍 + 在位一遍）。本机
  实测（空闲机器、同一份输入连跑三次，一遍全仓）20.7s / 26.7s / 131.9s —— 单遍自己就有
  6 倍抖动；进组 C 的并发池子（`--maxWorkers=4`，且 A/B/D 同时在跑）实测 181–182s，
  超 120s 预算。`--no-file-parallelism` 隔离重跑全绿 ⇒ 争用假红（定性手法见规范 §11.13），
  而它挂在固定清单上，意味着**任何人**的提交都可能被它拦下。
- 按 §11.13 的口径走「精确化判据」而不是再抬预算：
  ① 在位那一遍删掉 —— 同一趟提交里组 A 跑的就是「生成件在位 + 全仓 `tsc --noEmit`」，
    ④ 里再编一遍是第二轮子；只留一条 `--version` 活性证明（≈0.3s），防「解出来个空壳」。
  ② 缺件那一遍的编译面从全仓收到**窄项目**：临时目录放一份 `extends` 仓库真 tsconfig 的
    配置（`paths` / `jsx` / `strict` 全继承，不重抄第二份事实来源），`include` 只留
    `.storybook/**` 与它需要的环境声明 —— 报错只可能发生在解析得到那个模块的文件身上，
    也就是 ① 点名的三个被引方。窄配置里显式 `incremental: false`：真配置开着增量，
    缓存命中时这一跑可以什么都不查就退 0。实测 ④ 从 57s 降到 **9.0s**。
  ③ 判据换形必须补的在场证明：新增一条「窄项目不是空转」，用 `--listFilesOnly` 把类型
    程序的清单打出来，三个被引方一个不许缺（反向验证过：抽掉 `.storybook/**/*.tsx` 那行
    glob，这条当场红并点名 `data-sources.tsx`）。
- 预算 120s 不动 —— 现在它离天花板很远（④ 9.0s + 在场证明 2.3s）。
