- **「所有项目」屏补齐渲染层判据（ISSUE #1522 收尾）**：这一屏此前只有逻辑层用例，而「渲染出来才发现」的错在它上面没有判据 —— 收尾那轮撞到的 Markdown 星号原样印到界面上，正是这类错的形态（类型检查、lint、逻辑层用例一个字都不看渲染结果）。本轮按「空态 / 卡片 / 出处标 / 确认框」四档铺开 `src/components/studio/WorksGallery.test.tsx`，18 条判据都打在**渲染后的文本与可访问名**上（§11.2 行为断言，不 dump DOM 结构）：
  - **说明句**：把「服务端」排成强调而不是印出裸星号、词边界没带出多余空白、以及「服务端列表这一轮没拉到」那句降级说明的**两向**（没拉到要明说，拉到了不该出现 —— 不然用户会把「看不到」读成「不存在」）；
  - **出处标**：`仅服务端` / `未同步` 各标一份、`both` 不标（标出来是噪声，也让人分不清这一行从哪来），出处标带悬停说明；

  - **空态 / 加载态**：没有项目给空态、首次取数未落定说「正在读取」而不是把空列表当结论；头部「刷新」「新建创作」各自交回 controller / 容器。
  - 判据的**反向验证**逐条核过：出处标分叉、降级说明、`both` 也标、点卡片传错 id、空态标题、加载文案、名字兜底、刷新、新建、出处标整块摘掉 —— 十条变异各自**恰好红一条**（`both` 那条同时红两条）。**故意没有**为 `min-h-90` 这类纯装饰类写断言：那是像素层（§11.8）的事，在 Vitest 里钉它只会买到一条脆判据。
