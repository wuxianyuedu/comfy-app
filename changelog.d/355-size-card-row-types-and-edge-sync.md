## Fixed

- **尺寸子口的卡片行类型按形态固定**（用户口径）：宽度 / 高度 / 像素量 = `FLOAT`，分辨率档 / 倍数 = `INT`，宽高比 = `COMBO`；连上之后仍显示落点那一行的**真实**类型（落点是 INT 就显示 INT）。此前未连过时只从落点取，取不到就退成 `*`。
- **库内卡片圆点的 handle id 改用 ioKey**（原先按端口名）：两个节点各有一行同名 pin（提示词与负向提示词的两行都叫 `text`）时，同一张卡片上会出现多颗同名 `<Handle>`，React Flow 只认第一颗 —— 用户看到的就是「提示词连不上 / 负向提示词拖不出线」。现在同一节点内 handle id 唯一（尺寸卡仍取子口 id），`entryForHandle` 反查同步改按 ioKey；「按端口名换算」那一层（`wireHandleIdForIoKey`）删除。
- **尺寸卡「恢复默认」一次清掉六条形态线**：卡片头此前逐个上抛六个子口，消费方每收到一个就从同一份**旧**值算一次新表并落库，后一次把前一次的删除覆盖回去 —— 用户口径「尺寸那三项线变成固定连线，我重置也清不掉」。现在一次计算、一次落库（`resetMany`）。
- **库内新拖出来的线不再「一松手就消失」**：边集合此前是画布挂载时的快照（`useEdgesState` 初值 + `defaultEdges` 只在挂载派生一次），写入成功的线永远进不了画布。现在 `defaultEdges` 跟随 wires 重新派生，画布把派生结果同步回 edges 状态。
- 回归用例：同一卡片内端点 id 唯一（同名 pin）、形态固定类型（不是 `*`）、↺ 一次落库清空六条线、连线两端锚点都在（卡片行 + 宿主数值行）、边集合跟随派生（jsdom 量不到 React Flow 的边，锁源码形态）。
