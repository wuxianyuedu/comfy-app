## Fixed

- **卡片圆点的 handle id 必须「卡内唯一」**：三列卡片列是**一个** React Flow 节点，而提示词与负向提示词的候选行完全相同（都吃 text 族）—— 只用端口名、或只用 ioKey 都会撞车，React Flow 只认第一颗点，于是出现「负向提示词的线从提示词那张卡连出来」「第二颗点拖着没反应」。handle id 改为 `<条目 id>?<落点 ioKey>`（尺寸卡仍取子口 id），`entryForHandle` 同步按它反查，`wiredDotKeys` 直接用 handle id。
- **尺寸子口的类型与闸门按形态走**：卡片行**恒显示**形态自己的类型（宽度 / 高度 / 像素量 = `FLOAT`，分辨率档 / 倍数 = `INT`，宽高比 = `COMBO`），不随落点变化（用户口径：「尺寸上是什么类型就显示什么类型，不要跟连接的参数类型变换」）；闸门同步收紧 —— 宽高比（候选表语义）只接 `COMBO` 行，不再能连到「百万像素」这类数值行（用户口径：「现在宽高比能连到百万像素，这是不行的」）。数值形态之间仍互通（INT / FLOAT / NUMBER），类型未知（`*`）的行一律放行。「展示类型 + 可接受类型」同源于一张 `SIZE_SUB_SPEC`，两处不会再漂移。
- **尺寸卡「恢复默认」一次清掉六条形态线**：卡片头此前逐个上抛六个子口，消费方每收到一个就从同一份**旧**值算一次新表并落库，后一次把前一次的删除覆盖回去（用户口径：「我重置也清不掉」）。现在一次计算、一次落库（`resetMany`）。
- **库内新拖出来的线不再「一松手就消失」**：边集合此前是画布挂载时的快照（`useEdgesState` 初值 + `defaultEdges` 只在挂载派生一次），写入成功的线永远进不了画布。现在 `defaultEdges` 跟随 wires 重新派生，画布把派生结果同步回 edges 状态。
- **拖线落库的键跟上 handle id**：`onConnect` 手里只有 handle id，此前把**整串**当落库键写进 `paramMap`（`prompt?9::widget::text`），`resolveMapping` 按条目 id 查不到 —— 线画了却永远显示「未配置」。现在经 `parseLibraryHandle` 取回**条目 id** 再落库；右列输出卡的锚点也统一成输出口的 ioKey（原先按端口名，两个输出口同名 / 名字为空时会撞车，且落库键取错）。
- 回归用例：同一卡片内端点 id 唯一（同名 pin）、负向提示词的线从它自己那张卡出发、形态恒定的类型、宽高比 → 数值行被拒、↺ 一次落库清空六条线、连线两端锚点都在、`parseLibraryHandle` 两段解析 + 「handle id → 条目 id → 落库 → 读回」这条链、边集合跟随派生（jsdom 量不到 React Flow 的边，故锁源码形态）。
