## Fixed

- **工作流编辑器：子工作流里改了节点位置后「重置布局」回不到原始工作流（ISSUE #400 三审）**。子图视图下画布上的节点 id 是**裸内部 id**（`1670`），而 `positions` 列里同一批节点存的是**宿主:内部 拼接键**（`4:1670`，见 `extractPositions` 的 `${wId}:${iId}` 写法）—— 两套键各写各的：子图里的拖拽落盘到一个顶层永远读不到的裸键，下次下钻回来时又把这个裸键当成「已保存坐标」覆盖掉真正的原始位置。用户看到的就是「改过位置的节点重置后和原始工作流不一致，再改一次却回归到一个错误位置」。现在子图视图的拖拽与还原统一走 `runtimeNodeId` 拼前缀，与运行期链路同口径；还原时把快照里的裸内部 id 规范成拼接键再写回，顶层 wrapper 与导轨坐标原样保留。顺带修正「快照残缺」判据里把导轨数量硬编码成 2 的假设 —— 只拖过一条导轨就会被误判成残缺，现在按快照里实际存在的导轨键计数。
