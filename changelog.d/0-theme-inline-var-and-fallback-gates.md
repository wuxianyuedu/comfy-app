## Added

- **给两句「人读的口径」补上机器执行者**（都在 `scripts/check-theme-colors.cjs`，
  `pnpm theme:check`，硬闸、无基线、存量 0）：
  · **「属性前缀 + 裸 CSS 变量」**（`bg-(--color-node-accent)` 这一族，规范 03 §3.1.1 的 ❌ 条）——
  它编得出来、`hover:` 也生效，所以不是编译错误，而是越过语义层：拿不到语义名、拿不到兄弟
  token，而「未豁免写死色值」与「幽灵 token」两条判据都不会响（那颗变量是定义过的、这一行
  又没有字面色值）。判据形状只认一个：`-(` 紧邻 `--color-…)`。
  · **「已定义 token 上的色值兜底」**（`var(--color-ink, #EDEDF2)`，规范 03 §3.6.1.1 与
  DESIGN.md 的 ❌ 条）—— 幽灵判据只认「查无此名」，有定义的那一半它比对得到、当场放过，
  而那行**永远取不到兜底**：等于谎称随主题，且下一个人删掉声明时外观静默改变。与「未豁免
  写死色值」的分工是这条**不看豁免表**（类型色表照样能写出这种兜底）。
- **两侧边界都有用例钉着**（`tests/check-theme-colors.test.ts` 44 条）：关键字兜底
  `var(--color-x, currentColor)` 必须继续通过（已判定放行的防御性写法，收紧到「任何兜底」
  是改口径不是补执行者）；规定的取色出口 `useCssColorToken("--color-完整名", "#ffffff")`
  不抓（函数实参、没有 `var(` 外壳）；token 没定义时红在幽灵那一条、不重复报；
  夹具挑的是**整文件豁免**的类型色表，用来正面证明「豁免文件里也照判」这件事。
