## Fixed

- **工作流库页头筛选菜单重新排成一行，列表不再超框（ISSUE #716）**：用户反馈三件事，根因是两个宽度判据都缺一条 —— ① 三个筛选下拉（来源 / 类型 / 模型）在窄窗口里各自折行，竖着叠成一列，页头因此吃掉三行；② 列表项把名称与四枚徽标塞进同一行，名称不设上限时把徽标挤出侧栏、被根容器的 `overflow-hidden` 裁掉。现在筛选组 `flex-nowrap` + 每项 `shrink-0`（排不下时整组一起换行，绝不把控件压扁），列表项名称限长 `max-w-[132px]` + `truncate`（完整名称仍在悬停提示里）。

## Changed

- **列表项的「对外参数已配置 / 未配置」收成一枚单字标记**：整句中文标签与工作流名称争夺同一行宽度，是列表超框的主因。现在只留 `✓` / `！`（颜色 + 形状表达状态），已配置几个口、缺哪些口的完整口径挪进悬停提示 —— 信息一条没少，占用从约 7 个字降到 2 个字符。
- **新增 `ui/list-badge` 基元**：密集列表行的内联小徽标（`text-[9px]`、无边框、语义 token 取色）。与 `ui/status-badge`（独立胶囊，`text-xs` + 边框）按「出现在哪里」分工 —— 列表行高度按一行文字定，胶囊会把行撑成两倍高，正是原先每处各写一遍 `text-[9px]` 手写 span 的原因。
- **`ui/select-menu` 的触发器宽度改为调用处决定**：基础样式里原先写死 `w-full`，与调用处的 `w-auto` 是两个同族 utility，编译后按输出顺序决胜 —— 「写了 `w-auto` 但一排放不下、每个都铺满整行」就是这个成因。现在缺省随内容宽（并排控件要的），需要独占一行时传 `fullWidth`。

## Added

- **`--color-encap-pending`**：对外参数「未配置」的文字档 token（浅色 amber-700 / 深色 amber-400），收掉了列表里写死的 `text-amber-700 dark:text-amber-300`。
