## Fixed

- **画布 / 库内恢复显示组合控件，且它不再占满空间（ISSUE #355 复审）**：「比例 + 像素 + 倍数」这块组合卡上一轮被整块换成逐行参数，用户要的是「组合控件要显示出来、宽度缩小」。现在卡片回来了，但按内容收窄（`w-fit`）、不占满整行；卡内三项各一行、**只报「名称 + 类型」**（`· 宽高比 COMBO` / `· 百万像素 FLOAT` / `· 倍数 INT`），不显示可编辑的值 —— 值由下面的逐行参数各自录入，同一件事不在两处说。每个端口仍在下面各占一行，各有可连的输入端点与落点锚点（用户：「需要将这几个参数的输入端口显示出来」）。宽版表单保持完整录入能力不变。

- **工作流库的对外参数连线可以编辑了（ISSUE #355 复审）**：库里那份连线此前是只读呈现 —— 用户点端点拖不出线、也改不了落点。现在库里与编辑器一样可改：从卡片右侧的圆点按下并拖到宿主卡片的某一行松开即改落点（拖动中画一条跟随光标的预览线，悬停命中时转实线），点一条线选中后按 ⌫ 显式断开，卡片头的 ↺ 撤销该口的手工线。手势用指针事件实现（库里没有 React Flow 上下文），命中判定复用 `resolveDropTarget` —— 与编辑器画布的闸门**同一套判据**，同一个手势不会在两个界面一个受理一个拒绝。落库形状与编辑器逐字一致（`paramMap.source.mode:<模式> = { <entryId>: ioKey | null }`），本地叠加一层 overlay 让结果即时可见，`source` 之外的命名空间原样保留。

- **「覆盖默认」不再只藏在画布上**：库内编辑经 `hooks/use-param-wiring.ts` 编排、由父级 PATCH `paramMap`（与 seed 行为同一路径 + 失效两个 detail 缓存），落库后卡片与线读回新的落点 —— 页脚说「你改过的线」、被落到的那颗圆点实心、恢复默认按钮可用。
