## Changed

- **「滚动跟随底部」「触发外部动作」「标签 + 输入 + 校验错误的表单行」三件事各收成一处实现**（ISSUE #672 按形态扫描的第二十四 ~ 二十六条账），三条判据都是硬闸（P21 / P22 / P23，`pre-commit` 第 12 步阻断）。
  - **滚动跟随**：4 处各写「内容一变就 `scrollTop = scrollHeight`」，而「用户往上滚会不会被拽回去」取决于看的是哪个面板 —— 设置页运行日志会退出跟随并给出「恢复自动滚动」，画布步骤日志与工作流库运行日志只有一个 `autoscroll` 布尔（上滚会被按回底部），工坊 Agent 对话连开关都没有（读不到上一句回复）。统一走 `~/components/ui/use-scroll-follow` 的 `useScrollFollow`（贴底阈值 `NEAR_BOTTOM_PX` 一处定义、跟随态是 hook 的输出、受控模式让同一份跟随态跨多个滚动容器共享）。工坊对话**新增**「回到最新」的可见出口 —— 此前连「已暂停跟随」这个状态都不存在。
  - **外部动作**：9 处各写「置忙 → 调用 → `ok ? ok : err` → `catch → errorMessage` → finally 清忙」，而结果字段不统一（三个端点读 `ok`、更新器读 `triggered`）、空目标只有一处拦过（其余把空串发给服务端，用户看到的是 zod 的英文报错）、`comfyapp://` 的「协议助手未注册」探测只有一处写了（不判它的话「点了没反应」与「打开成功」在界面上长得一样）。收进 `~/lib/external-open`（目标类型 / 结果归一 / 空目标拦截 / 失败文案 / 助手探测，纯逻辑可单测）与 `~/components/ui/use-external-action` 的 `useExternalAction`（`busy` 用同步 ref 判重入 —— 同一次事件循环里连点两下时状态还没提交，那正是双击发两次请求的成因）。
  - **表单行**：15 处各写「`<label>` + 控件」，三件事在不同落点被漏掉 —— `htmlFor` / `id` 关联**没有一处**做过（点标签不聚焦输入框、读屏器把标签读成孤立文本）、`aria-invalid` + `aria-describedby`（只有 1/15 处写了 `aria-invalid`、**没有一处**关联错误文案）、错误行（训练工作室只报一句整表文案，改了某一行也没有任何标记指出是哪一行错）。统一走 `~/components/ui/form-field` 的 `FormField`（`htmlFor` 由 id 派生、错误态自动上两个 ARIA 属性、错误行有稳定 id；控件由调用处给，不硬包 `<Input>`）。

## Fixed

- **训练工作室的提交校验只报一句整表文案**：`validateTrainForm` 此前返回「第一条错误的文案」（`string | null`），被挂在提交按钮上方 —— 用户改了下面某一行也看不出是哪一行错，而逐字段判据本来就在这个函数里、只是被压成了一句。现在返回「字段 → 文案」映射，视图把错误行渲染在对应控件下方（`TrainJobInput` 侧的 `error` 收窄为上传 / 网络等非字段错误）。
- **`comfyapp://` 协议助手未注册时的静默失败**：导航后若窗口内失焦才算 OS 接管，否则给出安装引导 —— 这段判据此前内联在历史详情弹窗里，是**全库唯一一处**判它的地方，现在收进 `~/lib/external-open` 的 `detectFolderHelper`（`handled` / `missing` 两态可单测）。
- **表单字段的错误文案对读屏器不可见**：错误行此前只渲染成一段红色文字，没有一处把它关联给控件（`aria-describedby`）。现在 `FormField` 让「标记无效」与「关联错误文案」由同一个 `error` 推出，调用处不可能只写一个。
