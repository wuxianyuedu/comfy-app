## Fixed

- **工坊自动保存会用本机旧草稿整片盖掉 AI 侧写入的角色卡 / 场景 / 分镜（#5147）**。
  现场：AI 侧把 6 场景 / 6 角色 / 19 镜写进 `production`，界面那份是**挂载那一刻**从
  localStorage 读进来的旧副本（这三列全空），几秒后一次 `PUT /api/production 200` 就把
  同一行整片盖成 `scenes=[] / characters=[] / shots=[]`；随后的自主 run 判「还没有镜头」
  退回去规划分镜 → LLM 不可用 → 整条 run 失败。
  根因是「双操作者」在**写侧**没有对应保护：载荷是**整份**草稿，且没有「我这份基于
  哪个版本」的凭据 —— 草稿镜像那条路早有版本对账（#4023），生产数据这条路一直没有。
  处置三条：
  - **窄字段写入（主修）**：`PUT /api/production` 里**没带的键 = 这一列不动**，工坊自动
    保存只发相对挂载基线**真改过**的字段（`narrowProductionWrite`）。于是「界面那份没有
    角色卡」不再等于「把库里的角色卡清空」—— 整片覆盖在结构上不可能发生，而不是事后
    判一次要不要拒绝。副作用是这类无意义 PUT 也不再发（用户没编辑时一拍都不发）。
  - **与乐观并发合流**（#5221 的 `ifUpdatedAt`）：CAS 只拦**整份快照**（八条内容列全在）
    —— 那一形会盖掉别人的改动。窄写入即使撞上更新的行也照写（只覆盖用户改过的那几列），
    但把 `stale` 当读数带出去，界面据此提示「服务端也更新过」而不丢掉用户的改动。
  - **挂载采纳**：AI 写进 `production` 的内容在界面重新挂载时会被看见（本机草稿为空、
    或服务端严格更新时采纳，判据 `shouldAdoptProduction`），采纳后写入基线跟着换成那一份，
    否则下一次自动保存会把「刚采纳来的内容」当成用户改动整片重发。本机设备选择
    （`modelSelections` / `workflowId` / `videoWorkflowId`）不随采纳被换掉。
  - **应答带 `updatedAt`**（ISO 串，`production.updatedAt` 原值）：客户端据此推进写入
    基线，下一次的 `ifUpdatedAt` 才指向最新那一版。
  拆分：写穿与挂载对账收进 `use-workshop-production-sync`（§12.13 的函数长度闸）。
  用例：`payload.test.ts` 21 条（窄写入 / 采纳判据 / 内容转草稿）、`route.test.ts` 8 条
  （含「只带剧本的窄写入不许动那三列」这条现场复现）、端到端 4 条
  （自动保存 / 卸载兜底 / 无编辑不发 / 挂载可见）、`production-client.test.ts` 5 条三态。
