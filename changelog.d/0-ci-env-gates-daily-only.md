## Changed

- **只判节点事实的那四格不再每个 PR 都判**（业主口径：「这个环境不会经常改动」）：
  `工具链自证`（13.8s）、`Python 可用性`（2.8s）、`Python 探针读数`（3.0s）、
  `浏览器安装`（3.0s）从 `COMFYAPP_CI_GATES` 撤进 `COMFYAPP_CI_DAILY_GATES`，
  每日那份清单从七格变九格（新增 `每日工具链自证` / `每日 Python 探针读数`，
  另两格本来就有同名执行者）。留在 PR 上的是 `Install dependencies` 里的
  `check-pnpm-available.mjs` ——「这台机跑不动整条链吗」才是每个 PR 需要有人回答的那一问。
- **不走 `ifModify`**（那条按改动面跳过，而这三份脚本问的是 PATH / winget / 解释器 /
  浏览器目录，一次 PR 改不动任何一项）；也不做节点侧指纹（每个 job 都是全新工作区，
  指纹只能落进 git 或落进某个节点目录，前者要 CI 反推提交、后者让结论只在那台机上成立）。
- **撤拦 ≠ 撤账，这次有机器形式**：`tests/no-platform-ci-config.test.ts` 新增一条，对
  `PR_MOVED_TO_DAILY` 那四格逐条判「PR 清单里不许再出现 / 每日清单里必须有那一格 /
  那一格点的仍是同一个入口脚本、共用脚本时仍带那面分档旗标」。少了第三条，
  「撤到每日档」与「悄悄把块换成别的命令」在配置文件里逐字同形。
- 顺带：`.cnb.yml` 里几处**数量措辞**（「那七格」「三十七格」「前提三格」）改成不带数字的说法
  —— 清单每加一格它们就烂；`每日浏览器安装` 成为唯一执行者后，那两行实测换来的 `env`
  的历史注释搬进每日档，两处按名字取块的判据（`ci-env-probe` / `ci-container-plan`）
  同批改读新名，名字本身收成 `scripts/ci-env-probe.mjs` 的 `BROWSER_INSTALL_STAGE` 一个出处。
- 判据的每日清单常量随这次升到九格；`浏览器安装` 相关的两条（入口在盘上 / 套接字超时放宽）
  改点名 `每日浏览器安装`。
