## Changed

- **增量测试层的 import 判据换成反向闭包**（`scripts/affected-tests.mjs`，规范 §13.5.8）：
  上一片落地后实测撞到一个形状 —— 改 `studio/logs/LogFilterBar.tsx` 解析出
  「受影响 0 个用例」，因为它的用例在 `LogPanel.test.tsx` 那一层（测试 → 面板 →
  筛选条，两跳）。只走一跳时「改到哪、测到哪」是空话，现在沿 import 图走到测试为止，
  并把 barrel 的转出口当作图上的普通边（不再用「同目录就算消费」那种放宽 —— 没被
  出口转出去的 sibling 现在**不算**消费，反面用例钉住了这一点）。
  图按**说明符候选**建键、不按「目标文件是否存在」过滤：暂存删除之后路径已经不在索引
  清单里，而「谁还 import 着它」正是这次改动最直接的破坏面。
  判据从五条收敛成四条（直接 import 与 barrel 合成一条闭包）。代价实测：建图 + 解析
  约 1.0–1.1s（1.2k 个源码文件、6.4k 条说明符）；改一个基元 52 个用例（钩子那批实测
  1m40s）、改一条链路 83 个、改一个只被一块面板消费的组件 10 个。跑多少由改动半径决定，
  这正是这一层的定义，不给它加耗时天花板。
  仍然抓不到的写进文档而不是藏起来：运行时拼出来的路径（`import(base + name)`、
  `path.join(dir, …)`）与解析目录之外的消费方 —— 全量仍由 `pnpm test` /
  `pnpm check:all` 负责。
