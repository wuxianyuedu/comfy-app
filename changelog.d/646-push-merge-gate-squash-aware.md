## Fixed

- **门禁在「单元测试与覆盖率」这一步整段中断，vitest 一次都没跑完**：`script: pnpm run test:coverage` 与 `type: testing:coverage` 写在**同一步**，而同一个 stage 里的这两者是**两个并行任务** —— 插件容器在测试还在跑、`coverage/` 还没产出时就开始找报告文件，`breakIfNoCoverage` 缺省为 `true`，找不到即报错退出。现场是该步 1~2s 内失败（vitest 本地要 73s），日志 `Error: 没有找到覆盖率报告文件`。现在拆成 `单元测试` → `覆盖率上报` 两个相邻 stage，顺序成立。探针实测：同一份「找不到报告」的日志配上 `breakIfNoCoverage: false` 返回 0，证明失败正是该缺省值触发的。`tests/cnb-pipeline-gates.test.ts` 新增一条锁住「后置且独立」（合并回一步即失败，已实测）。
- **`master` 的 push 流水线每一次都是红的，且没有一次指向真问题**：`合并形态复核`（`check-branch-guard.cjs --merge-commit`）按「父提交数 > 1 才算 PR 合并」判，而规范 §13.6 优先 **Squash Merge** —— squash 落到 `master` 的提交只有 **1 个父**，与「本地直连主干提交」在拓扑上完全同形。实测 `master` 从 `611150b` 到 `8a9efb3` 的**每一个** push 构建都红在这一步，却一次真正的绕过都没抓到。判据改为「合并提交 **或** 提交信息带 PR 关联（平台 squash 时写下的 `PR-URL: #NNN`）」；两者都不满足时**保守放行**并留痕。真正的直推拦截在平台分支保护（§13.6.1），不在这条形态复核上。
- **判据版本 `2` → `3`**，并补三条回归用例：squash 形态（单父 + `PR-URL`）放行、单父且无 PR 关联保守放行、覆盖率上报必须后置且独立。`cnb-pipeline-gates` 另锁「push 复核不得退回纯拓扑判据」——**只断言 `evaluateLanding()` 函数体**（全文断言会让判据「只在注释里存在」也算过）；四条变异 + 两处合并回退均能失败（本地实测）。
- **规范同步**：11.7 记下「上报必须是测试之后的一步」与「报告格式两处必须对上」的完整口径，13.5 记下「一条永远在响的告警也是噪声」、13.5.3 核时表与 13.6.1 三层防线的表述一并更新。
