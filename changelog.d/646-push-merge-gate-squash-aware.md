## Fixed

- **`master` 的 push 流水线每一次都是红的，且没有任何一次指向真问题**：`合并形态复核`（`check-branch-guard.cjs --merge-commit`）按「父提交数 > 1 才算 PR 合并」判，而本仓库规范 §13.6 优先 **Squash Merge** —— squash 落到 `master` 的提交只有 **1 个父**，与「本地直连主干提交」在拓扑上完全同形。实测 `master` 从 `611150b` 到 `8a9efb3` 的**每一个** push 构建都红在这一步（`阻断:master 上出现非合并提交`），而它一次真正的绕过都没抓到。判据现在改为「合并提交 **或** 提交信息带 PR 关联（平台 squash 时写下的 `PR-URL: #NNN`）」；两者都不满足时**保守放行**并留痕。真正的直推拦截在平台**分支保护**（§13.6.1），不在这条形态复核上。
- **判据版本 `2` → `3`**，并补两条回归用例：squash 形态（单父 + `PR-URL`）必须放行、单父且无 PR 关联必须保守放行（不误报）。`tests/cnb-pipeline-gates.test.ts` 另加一条锁住「脚本不得退回纯拓扑判据」——这条判据能失败已在本地实测（改掉措辞即红）。
