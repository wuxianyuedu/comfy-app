  而后来加的两批都用了 `<<: *common`**：每日档三条触发口 + 单跑口六条 ⇒ 到今天就变成
  **九条非 PR 流水线共用一把字面 `pr-`**，没有任何一条判据在数这件事。

  **一个人为了排障刚点下去的那一跑**，不是每天一次的无人值守。
- **一把锁该挡的是「同一件事被重复排队」，不是「所有非 PR 的事」**。所以按触发类各一把，
  键名一律是**字面量**（不带变量 = 不存在「某个事件上它无值就退化」这条路，那正是本条的病根）：
  `push` / `daily`（三条每日触发口**仍然同一把** —— 那份互斥是刻意保留的，没被这次改动拆掉）/
  `oneshot-build` / `oneshot-e2e` / `oneshot-unit`。PR 那一把 `pr-$CNB_PULL_REQUEST_IID` 一字未动。
- **它不推翻 §13.5.21 那条「不动 `lock.key`、先有车道再分锁」**（那句话说的是
  **按车道分锁 = 给一台机造并行容量**）。这里做的是相反的一半：
  把「一件工作被另一件不相干的工作掐掉」修回去。而且几条重档在同一台机上叠加**本来就是现状**

  压力的答案住在 `scripts/ci-load.mjs` 那条按现场核数收敛里，不在锁里。
  ⚠️ 同批把 §13.5.21 那句「粒度正确」订正成「**PR 之间**的粒度正确」，并写明非 PR 那一半后来坏了。
