## Fixed

- **双击启动完成后窗口一直待在后台（用户就守在启动页前面、什么也没做也一样，窗口只在任务栏闪烁）**：启动期只判「双击入口还在不在前台」——那是一条几十秒后必然失真的判据，于是双击启动恒得「不给前台」，交接时一律只 `show()` + 闪烁提醒，把用户「一直等着」和「切去干别的了」当成同一回事。
  现在判据反过来：**只有用户手动让出前台才不抢**。壳在执行段（`show_main_window_without_focus()`）于**任何窗口动作之前**采样 `shell_owns_foreground()`（本壳的任一窗口此刻是否 `focused`）——前台还在本壳的窗口上（启动页一直待在他眼皮底下）= 他没让出前台 = 他还在等，加载完成就把前台给他；只有前台已换成别人的窗口（他在这几十秒里切去干别的了）才「只显示、不激活 + 任务栏闪烁提醒」。采样必须早于 `show()`：交接那一刻 Windows 会把刚显示的主窗当成「新窗口」放行前台，显示之后再问就分不清「用户还在等」与「系统自己给的」。
  显式给前台的路径不变（托盘「打开主界面」、二次启动唤起、`COMFYAPP_FOREGROUND` / `--cold-start`）。
  生效条件：桌面壳需重编（`cd src-tauri && cargo build --release --features custom-protocol`）。
