## Fixed

- **设置的跨进程失效判据分不出「同一时间刻度内的等长改写」—— 这是产品缺陷，不是用例写错了**
  （ISSUE #1961）。

  平台侧读数（`单元测试`，只这一格红、本地恒绿）：

  ```
  FAIL src/lib/app-settings/app-settings.server.test.ts > getSettingsSync 的跨进程失效
    > 指纹没变时走的是同一份缓存对象（不是每次都重读）
  AssertionError: expected 'A' to be 'B'
  ```

  `getSettingsSync()` 的缓存指纹原先是 `mtimeMs:size` 二元组，而它**分不出**这种形态：
  `"A"` 改成 `"B"` 长度一样，只要两次写的 `mtimeMs` 落在同一刻度上，指纹就恒等
  ⇒ 缓存照旧命中 ⇒ **读到的是旧值**。而「磁盘上的设置一变就重读」正是这条缓存存在的
  全部理由（跨进程：内嵌 server 写盘、执行宿主读）—— 漏失效就等于用户填完 comfy-cli
  解释器、执行宿主拿到的仍是空值，那个 FAILED 会原样复现。

  本机实测：200 次背靠背等长改写里 **66 次** 撞上同一个 `mtimeMs:size`。也就是说它
  **只在负载高、时机巧时才红** —— 而线上那台 16 核节点正好是那种时机。

  > ⚠️ **不要把这格「修」成用例换成长度不同的值（`"A"` → `"BB"`）**。那样 `size` 必然
  > 不同、红确实会消失，但消掉的是**判据**而不是缺陷：等长改写在真实配置里一点都不
  > 罕见（`comfyCliPython` 的各个取值长度高度相似），而它漏的正是本模块要防的那件事。
  > 红的形状看着像「用例把宿主 mtime 刻度写成恒真性质」，实质是**产品判据的粒度不够**。

  ## 修法：判据换**内容摘要**

  `sha1` 文件字节。设置文件是几百字节的本机配置，取值时哈希一遍的代价远小于
  「读到旧设置」的代价。这与 `comfyui/localWorkflows.ts` 那套**按内容寻址**同源 ——
  那边 `mtime+size` 只是「跳过重算」的加速键、结论始终取自内容，这里早先只取了加速键。

  同批把「先 `statSync` 取指纹、再 `readFileSync` 取内容」的两趟读收成一趟：摘要就是
  那一次的字节算出来的，中间没有可被插进来的窗口，原先靠「指纹先取」次序躲
  「新指纹 + 旧内容」的那条约定连同它的注释一起撤掉。

  ## 判据与反向复算

  用例新增一条**确定性**复刻：等长改写（`"A"` → `"B"`）+ `utimesSync` 把 mtime 钉成
  同一个值 —— 把那个概率事件变成确定事件，不需要去猜操作系统的 mtime 分辨率；
  原先那条用例也回填成等长值（`"B"`），因为它现在真的判得动了。

  反向复算：把指纹改回 `mtimeMs:size`，新增那条当场红，报的就是上面那句
  `expected 'A' to be 'B'`（已实测）。修复后 5 例全绿。
