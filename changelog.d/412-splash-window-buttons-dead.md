## Fixed

- **启动页的最小化 / 关闭点了没反应（ISSUE #412 二次回报）**：上一版把启动页改成无边框、右上角自绘按钮后，按钮画得出来、有悬停高亮，但点下去什么都不发生。根因是三件事叠在一起：
  - 按钮只挂在**一条** `addEventListener` 上——脚本没跑到绑定、监听被顶掉时，点击就没人接；
  - 兜底需要新的壳命令，而改了 `src-tauri/**` / `public/splash.html` 不重编壳时跑的是旧壳（命令不存在），症状同样是「点了没反应」；
  - `--splash` 那张启动器自绘画面用 `ShowWindow(SW_MINIMIZE)` 去最小化一个 `WS_EX_TOPMOST` 的无主弹窗——系统找不到可最小化的父窗口组，调用等于没发生。

  现在改成「三条互补路径 + 失败可见」，任一能成就成：
  - ① 事件监听（常规）；
  - ② 按钮内联 `onclick` → `window.__splashWinAction`（与①同一个入口 `performWinAction`，去重，不会关闭两次）；
  - ③ 应用自建命令 `win_minimize` / `win_close`（壳侧直接操作 splash 窗口，**不**把 `core:window` 的整面命令授权给启动页），按规范三处同步：`build.rs` AppManifest、`capabilities/splash.json`。

  三条都失败时不再静默，消息区写「当前壳缺少窗口命令，请更新（重编壳 / 重新打包启动器）」，8 秒后交还进度文案；`.win-buttons` 容器整体也声明 `no-drag`，个别按钮漏标时点击也不会被拖拽区吞掉。
- **启动器的 `--splash` 画面：最小化真的能把窗口收起来**：改为「隐藏 + 撤置顶 + 把前台交还给下面的窗口」，并由既有的 40ms 定时器维持（其它逻辑一 `ShowWindow` 就把它翻回来）；硬件/交接时先还原再关闭，避免「启动完成了但界面上什么都没发生」。
- **「壳过期」不再只存在于日志里**：启动器在启动前比一次 `app.exe` 与壳源码 / 启动页的文件时间戳（与 `dev-launcher.ps1` 的 `stale_shell` 同源），过期时记一条可定位日志，并在 `--splash` 画面上钉住提示——「窗口按钮没反应」最常见的成因就是它。
- **自绘启动画面尺寸与启动页对齐**：`SPLASH_W` / `SPLASH_H` 由 560×168 收到与 `tauri.conf.json`、启动页紧凑档同值的 744×216（同一张「启动中」画面有两个实现，尺寸各写一份就会改一处、两边不一致，现已由用例盯住）。
