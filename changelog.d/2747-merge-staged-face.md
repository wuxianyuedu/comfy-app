## Fixed

- **`check-format.cjs --staged` 在合并态不再把主干的存量当成本次提交（ISSUE #2747）**：
  `git merge` 解完冲突、提交还没落地时，`git diff --cached` 是**相对第一父提交**（合并前的自己）
  的全量差异 —— 也就是整份主干的改动面（现场：901 份），于是 D0 这一步会把主干上任何存量
  未格式化文件点名为「这次带来的」而阻断一次与本 PR 无关的解冲突（被点名那两份相对
  `origin/master` 是**零 diff**）。同一判据的 `--changed` 档对同一条链给出相反结论
  （「0 个在靶子内」）—— 两个入口不可能都对，错的是 `--staged` 这一头的**输入面**。

  取单子里的方向 1：**把面修回它自称的那个东西**（「本次提交带进来的改动」），
  收窄到「本分支相对目标分支带来的那一份」，与 `--changed` **同一个口径**
  （`changed-scope.mjs` 的 `resolveChangedFiles`，基线只有一份，§12.18 不抄第二份）。
  收窄后的面**逐份照判** —— 这不是降档，所以不动钩子那一行、不碰
  D 计数 / §13.1 / `declared-hook-steps` 那几处登记面。剔掉多少**必须念出来**：

  ```
  [format] 合并态（MERGE_HEAD 在场）：暂存面 1 份 → 收窄到本分支带来的 0 份（基线：master 的分叉点）。
           被剔掉的 1 份是主干那边的改动，不随本次提交走 —— 判据没降…（ISSUE #2747）。
  ```

  合并态的判据没有第二份实现：`hasInProgressMerge()` 从 `check-deps-freshness.mjs`
  **并进 `git-dir.mjs`**（`git-dir.mjs` 文件头那条「另案」清单点名过这份退回式实现），
  三处消费点（`check-deps-freshness.mjs` 自己两跳 + 本档）现在共用一份 —— 它走
  `resolveGitDir()`，链接工作树里 `.git` 是个文件那一形态本来就是这份实现存在的理由。
  `--changed` 那一档里内联的「取改动面 + fail-closed」也收成共通壳 `changedFaceOrExit()`，
  两档共用同一份取数与同一条「没算出来就退 2，不冒充干净」。

  判据 `tests/check-format.test.ts` 新增四条（①平台基线那一档 ②本地 merge-base 兜底那一档
  ③**收窄不是消音**：解冲突时动了本分支自己面内的文件仍被点名并退 1 ④对照：`MERGE_HEAD`
  一消失，同一批主干文件立刻回到判据面内 —— 缺这条，「把 `--staged` 实现成永远跳过」也能全绿）。
  变异证明：把 `mergeInProgress()` 改成恒 `false` ⇒ ①②③ 三条当场红（④ 仍绿，它判的正是
  非合并态），改回后全绿。改动前四条全绿、改动后也全绿的那种"用例"不算证据。
