## Fixed

- **`pnpm ship` 的文档面被 ISSUE #2022 改陈旧了，就地订正**（`scripts/ship.mjs` 文件头
  与 `.qoder/skills/ship/SKILL.md` 那张表）。两处都写着「提交门槛（**五组五十步**）」——
  那是 #2022 之前的事实：`pre-commit` 现在默认只跑形态档 D0，tsc / eslint / 受影响用例 /
  其余静态判据由 `COMFY_HEAVY_GATES=1` 那一档与平台兜底（规范 §13.5.25）。
  按本仓自己那条口径（**份数与档位随轮次变就不抄**），改成描述机制、不钉数字。
- **补一句要紧的**：`SKILL.md` 里明写「`ship` 提交段『全过』**不等于** tsc / eslint / 用例过了」。
  这句原先没有，是因为当时确实等价；现在不等价了，而 `ship` 是唯一一个会让人以为
  「它跑过了就是测过了」的入口 —— 它把钩子的输出转述出来，却转述不出「哪些根本没跑」这层意思，
  除非文档说清。钩子自己会打那句
  `本次提交本地**没跑**：组 A B C D（tsc / eslint / 受影响用例 / 静态判据全量）`
  与 `上面那句不是「已通过」`，收尾也从 `全部通过 ✓` 改成了
  `入选档位全部通过 ✓（D0 形态档…）`（三处均已回读 `.githooks/pre-commit` 核实，不是引用记忆）。
- **机制面不受影响，所以这一刀只动文字**：`ship` 判提交成败用的是 `git commit` 的**退出码**，
  不解析钩子的任何一句输出 —— 收尾话术改名不会让它误判。它委托的对象也没变
  （「跑 pre-commit，不重跑」），变的只是那个对象现在默认少跑几组。

## 顺带记一件事（这一格值得留着）

这条陈旧是**在我用 `pnpm ship` 交上一刀的同一段时间里**由并行会话改的：我的分支基点在
#2022 之前，所以那三轮提交真跑了全套（日志里能看到 组 A B C D 全 `[ok]`），
而我据此写下的「五组五十步」在合并落主干的那一刻就已经不是事实了。
形状与 `[[upstream-fix-supersedes-yours]]` 记过的那类一致：**同仓并行改治理面时，
「我这批看到的现状」与「主干合上时的现状」可以不同**。
所以这一族的新文字判据别钉具体组数 / 步数 / 档位 —— 钉机制，或按本仓既有做法写「份数以该文件为准」。
