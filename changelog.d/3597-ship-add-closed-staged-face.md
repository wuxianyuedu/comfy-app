## Fixed

- **`pnpm ship --add` 的暂存面现在是封闭的：点名之外、已在 index 里的文件不再随提交静默进历史（#3597）**：`--add` 的文档意图是「这一笔的提交面 = 我点名的这些」，而 `git commit` 吃的是**整个 index** —— 调用 ship 之前就已暂存的文件（`git apply --3way` 解基线冲突留下的东西、手工 `git add` 过的、并行检出的在途工作）会一起进历史，`--add` 对它们没有豁免力。#3596 的合并提交 `fc3f75c8` 就是这样把 15 行 `scripts/check-allow-builds.cjs` 带上了主干（不在点名名单里、没有配套用例、事后要三张单子披露）。现在提交段在 `git add` 之后、`git commit` 之前读一次暂存面（`git -c core.quotePath=false diff --cached --name-only -z`，`-z` 原值：转义形态的路径与 `--add` 原值逐字对不上，名单匹配会把提前暂存的中文名路径判成「没这回事」），逐条比对点名集合：点名目录 ⇒ 该目录下已暂存的文件都算声明过（`git add <目录>` 本来就是「这个目录下我都认」）；其余已在暂存区的文件 ⇒ 这一笔退 `2`，逐个念出路径与三条出口（补点名 / `git restore --staged` 撤出去 / 确认要一起走就显式 `--allow-staged`）。三条边界：只在给了 `--add` 时判（没给的那条路暂存面本来就由调用方负责，行为一字不变）；读不到暂存清单落 `2` 而不是放行（拿不到测量 ≠ 测量结果是绿的）；`--allow-staged` 单独出现 ⇒ 退 `2`（没有 `--add` 就没有可放行的对象，与 `--as-merged` 没带 `--close-issue` 同一条纪律）。判据本体是 `ship-local.mjs` 的 `classifyStagedSurface`，用例覆盖拦截 / 目录覆盖 / 前缀不误吞（`src/lib` 不吞 `src/libfoo.ts`）/ 显式放行 / 没给 `--add` 的负控 / 读不到清单那一格，并用真 git 跑了一遍端到端（拦截时 HEAD 不动、放行后两件都进提交）。
