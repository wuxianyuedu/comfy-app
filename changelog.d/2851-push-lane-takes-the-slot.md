## Changed

- **push 档（`master 合并复核`）的 `安装依赖` 开始走缓存槽**（ISSUE #2851）。
  这一档自 2026-10-28 扩成树级校验档之后背着六格，而它的安装格沿用了「按策略不接槽」那句话，
  于是**每一次合并到主干都在全新作业目录里从零装一遍**（两跑原值：`cnb-5bd-1k68jvmbt` 177.6s、
  `cnb-9jr-1k68hp05h` 308.4s）—— 而那句「不接」的理由（「每日档后面背着 `next build`」）
  在主语上就不是这一档：push 清单里六格没有一格真构建。
  - **先证伪，再落地**：真机 push 档只能由一次合并触发，所以取回**同一份入口、同一份旗标**的
    另一条臂 —— 文档链那三格与 `工作区出处` 在搬到 push 档之前本来就长在**接了槽的** PR 流水线上。
    两臂各自打印的臂与后面那几格的原值都在规范 §13.5.3.4.3 那张新表里
    （`cnb-btq-1k5uq6pl7` 走 `install-into-slot` · 整格 254s，`cnb-imr-1k5unh2r9` 走 `reuse` · 整格
    8.3s，两跑里 `API 文档生成与自检`（typedoc，这一档唯一真的解析 `node_modules` 的消费者）
    与各文档格**全绿**）⇒ 没有一格因为那条 junction 红，推断没被推翻。
  - **收益不当承诺写**：落地后第一个 push 跑按同一格取回原值
    （`pnpm ship --stage-log <sn> 安装依赖`），读数与它打印的臂一起记（本节那条量具纪律）。
  - 「这一档后面没有构建格」从注释升级成**判据**：`tests/no-platform-ci-config.test.ts`
    用 `BUILD_CONSUMER_MARKERS` 扫 push 那六格的命令行，出现 `ci-daily-build.mjs` /
    `build-desktop.mjs` / `next build` 任一形态即红并点名是哪一格 —— 往那份清单里加构建格的人
    必须先回答开关，而不是等一次 13.8s 的死法重演。
  - 镜像判据同批补齐并改名：`DAILY_SCRIPT_MIRRORS` → `CROSS_LANE_SCRIPT_MIRRORS`（它管的早就不止
    每日一条），push 的 `安装依赖` 与 PR 的 `Install dependencies` 按**命令行 + env + `timeout`
    三样**逐字对账。`.cnb.yml` 里那句「`timeout` 也在比对面里」写到这一批**才有执行者**（此前不在
    比对面里，而三格恰好都写着 `20m` —— 那句话一直在替一条不存在的判据背书）。
    push 那一格也同批补上 `timeout: 20m`：让 `ci-install-deps.mjs` 自己的 12m 预算先到，
    而不是等平台掐断（#2360 那条口径，此前只有 PR / 每日 / 单跑 / 打包那几格有）。
  - 四条坏形状各证过一次红（push 摘掉开关 / push 换成别的键 / push 改墙钟 / push 那档长出构建格），
    还原后 `.cnb.yml` 按 md5 自证逐字节回到改动后的那一份。

- **两处口径复述点按这一改动订正**（它们把「每日那一档的理由」当成了所有档的理由）：
  - `ci-install-deps.mjs` 里「开关没拨」那句打印，旧文案是「这一档按策略不接槽 —— **每日档**后面
    背着 next build」，而当时会念出这句话的共有**五格**（`每日安装依赖` + 四格 `单跑*·安装依赖`
    / `打包·安装依赖`）。其中只有每日与 `单跑构建` 那两档真的背着构建格，另外三格是被这一句
    **别人的**理由解释掉的 —— 读日志的人会把它当成「我这一档后面背着构建」的结论去处理。
    现在那句只说「这一档按策略不接槽 —— `COMFY_CI_SLOT` 没置成 1」，并把分档的那条线指向登记处
    （判据 = 后面有没有会真构建的格子），由 `tests/ci-install-deps.test.ts` 新增的两条断言钉住
    （必须点出键名、不许复述某一条档的理由）。那三格该不该接**另立一张单**，不在这里当代答。
  - `ci-install-deps.mjs` 文件头那句「实测 `Install dependencies` 一直是 59~61s」现在标明了它是
    **接槽之前**的历史读数，并给出现值的取法（按格当场取，别往散文里抄）。
  - 顺带改掉规范 §13.5.3.4.3 里一条**方向写反**的事实：「依赖面那套槽的键里带工作区路径 ⇒
    换目录即 miss」。键是纯内容哈希（`pnpmInstallFingerprint` = `DEP_FILES` 内容 + `patches/` 摘要），
    槽根由 `pnpm store path` 所在卷 + 包名推导，两者都不含作业目录 ⇒ **跨作业目录命中**才是实测形状
    （`reuse` 那一跑的链头是它自己独有的作业目录名，槽在 `G:\ci-cache\comfy-app-t3`）。
    这句话不只是写错 —— 它是「push 档接槽有没有收益」这个问题的**假否定答案**，所以随本单一起订正。
  - 每日那一档「不接槽」的性质也说准确：不是**无解**，是**没验过** —— #2521 已把官方
    `experimental.turbopackAdditionalRoots` 装进 `next.config.js`（只在 `COMFY_CI_SLOT=1` 时登记槽根），
    可这些档从不置那个开关 ⇒ 那份缓解在任何一条有构建格的档上一次都没被执行过。撤「不接」之前
    要先拿一次真构建验它承重。
