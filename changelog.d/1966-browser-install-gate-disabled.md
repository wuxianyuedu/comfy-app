## Fixed

- **`浏览器安装` 与 `E2E 关键流程` 临时停用（`COMFYAPP_CI_DISABLED_GATES`）：
  取证坐实了这台自托管节点取不回那 120 MiB，留着它等于让每个 PR 卡在仓库改不动的地方**
  （ISSUE #1966 的续集，现场 `cnb-ve6-1k51jaudm`）。

  ⑨ 之后那一跑专门取证：把 `浏览器安装` 那一步的根与超时**临时**改回内置族
  （`cdn.playwright.dev` / 30s），看它是不是「只有那一个第三方镜像不通」。读数是：

  ```
  内置族 + 30s              → 5 次 `timed out after 30000ms`、0 字节
  配着的 npmmirror 根 + 120s → `timed out after 120000ms`、0 字节
  失败分支的逐候选探测       → 三条都只取回**小段**字节（582 / 1889 / 442），大 body 停住
  ```

  **换根没用**（两个族一样）。这条链路是「握手能成、小响应能过、大 body 停住」的形态
  （代理 / 深度包检测 / MTU 黑洞那一类），而 120 MiB 无论等多久都走不完 ——
  这一格在这台机器上**永远不会绿**，而它要绿只有一个条件，那个条件**不在仓库手里**。

  所以按与 `单元测试` 同族的处置把它**停用**（`.gates` 里两段以注释形态留着，
  恢复动作 = 取消注释 → 名字挪回 `GATES` → 从停用清单删掉）。停用**不等于放行**：
  那一格的判据一个字没改、`.cnb.yml` 里那两行也照旧配着。规范 §13.5.3.5 新增 ⑩ 记这次取证。

  ⚠️ 这是「不替人做那个决定」那条边界唯一留下的尾巴：仓库能做的是「不因为一个改不动的
  环境格挡住所有 PR」，不能做的是「把那 120 MiB 取回来」—— 节点网络修好后取消注释即可。

- **停用期间「配置里那一个根」仍然量得对**：`stageBlockIn()` / `stageEnvValue()`
  从 ISSUE #1966 起**活的没有就看注释态**（与 `.ts` 侧 `commentedStageBlock()` 同口径，
  对账判据在 `tests/ci-env-probe.test.ts`）。停用不该让 `环境前提` 退回「铺开候选那一族」
  —— 那会换掉它要回答的对象（「**这一趟**装得成吗」），也会把那一格从「量配置里的根」
  变成「量某个还算通的根」。

- **`stageEnvValue()` 的键匹配从 `\s+` 放宽到 `\s*`**：停用形态里那一项的缩进已被压平
  （注释块按第 0 列读），键因此可能顶格出现。匹配面仍限在这一项自己的块内，不串到别的 stage。
