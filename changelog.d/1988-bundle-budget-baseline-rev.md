## Fixed

- **`--update` 不再能写出一份「修订号取不到」的体积基线**（ISSUE #1988）：`check-bundle-budget.cjs`
  的 `baselineRev` 是判红时唯一能把上涨归因到「哪几次改动」的东西，而 `headRev()` 在非 git
  检出里返回 `null`，写出来的基线于是带着 `baselineRev: null` —— 判据照旧跑、照旧绿，唯独那句
  归因永久失效。master 上躺着的就是这种基线（生成于 2026-10-15，修订号 `b6c3c353`，那个提交在
  检出里根本不存在），于是每一次判红都只说「基线修订号：取不到」，把读者推回「是不是抖动 / 是不是
  量错了」那条岔路。修法是把「写不下去」提前成一条当场能看见的拒绝：`--update` 取不到当前修订号
  就不写盘、退 1，并明说「请在完整 git 检出里重跑」。判据 `tests/check-bundle-budget.test.ts`
  两条互为反面 —— 非 git 检出里拒绝且**一个字都没落盘**、真 git 检出里落盘的 `baselineRev`
  必须是 40 位十六进制。口径见规范 §13.5.4「基线还要记 `baselineRev`」那一段。
