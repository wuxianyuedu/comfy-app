## Fixed

- **`lib` → `server` 的越界登记门禁此前形同虚设**（`tests/lib-server-imports.test.ts`，规范 §18.10）：判定写成 `!(e.from in REGISTERED)`，**只按源文件**判「是否登记过」—— 于是一个文件因为**任何**理由进过一次清单，它此后新增的**任意** `lib → server` 依赖都会被静默放行，且两条断言都不会红（新增边被当成「已登记」，`REGISTERED` 的**值**也没人比对）。

  实测复现：在 `lib/comfyui/client.ts`（已是登记项）追加一个指向 `~/server/lib/<新模块>` 的 import，三条用例全绿 —— 门禁对「新模块再引一次 server」这条**恰恰是它声称要拦的情形**没有作用。

  现在登记粒度是**边**（`from → to` 这一对）：判定改为 `!REGISTERED_EDGES.has(key(e))`，新增一条纯数据回归护栏钉住「同一源文件上新增的 server 依赖必须算未登记」。修复后同一逃避会被立刻拦下并打出完整引用链。

  > 这条缺陷的形态值得记下：**棘轮/清单一旦只按「一侧」记账，它就会把「同一侧的其它变化」一并放行**。判据要落在被约束的那个对象本身上（这里是「边」，不是「文件」）。
