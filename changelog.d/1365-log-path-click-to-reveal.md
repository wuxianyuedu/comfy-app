## Added

- **日志面板里那一列路径现在能点了**（ISSUE #1365）。启动报告里的项目根、编排脚本、`run/launch-status.json`、各来源日志的绝对路径此前只是紫字 —— 要打开得自己把整串抄进资源管理器，而启动排障时正是最需要「点一下就到现场」的时候。现在它们渲染成带虚线下划线的按钮，点一下就在系统文件管理器里定位（Windows `explorer /select,"<路径>"`、macOS `open -R`、Linux 打开所在目录）；回执挂在按钮自己身上：成功改口「已定位」、失败改口「打开失败」并把原因放进悬停提示（失败必须有可见出口）。

  判据分三层，各自有单测：

  - **认得出** —— `src/lib/log/log-path-tokens.ts`（纯函数，浏览器侧跑）。认 Windows 盘符 / UNC / POSIX 三种绝对路径形态；**刻意不认相对路径**（判不了相对谁，猜错会打开到一个不是那里的文件夹，比不可点更糟），也不认 URL 片段与 `1769 / 0 / 3` 这类除号分片。空格只对 Windows 形态吃进来（`C:\Program Files\…` 是一个整体），否则日志里由空格分隔的并列路径与散文会被连成一段 —— 两条都是实测撞出来的假阳性。尾巴标点（全角括号 + 句号两层）与尾随命令行开关（`--mode prebuilt`）都有各自的裁法；成对括号（`Program Files (x86)`）只丢落单的那一半。
  - **打得开** —— `src/lib/shell/reveal-path.ts`（纯 Node 宿主，第三类登记）。判据的最终形态是「磁盘上真有这个东西」：文本负责「像」，这里的**最长存在前缀**负责「是不是」 —— 从完整候选往回退，第一个存在的路径才是答案。退法**只在最后一段内**：跨段退会退出一堆「路径片断」（`F:\a`、`F:\a\b`）而它们可能真存在，于是用户点 `F:\a\b\c` 却打开了 `F:\a`，界面上没有任何东西解释为什么。同样不能退成「目录 + 尾分隔符」那一档（实测撞出来：`/workspace/no-such-file.txt` 被解析成 `/workspace/`）。
  - **闸得住** —— `setting.revealPath` 把「存在」与「在检出目录内」合成**同一个探针**。这一路是本仓库第二处「把控制权交给外部程序」的落点，而入参是**日志原文里扫出来的任意候选**（文本可以来自任何地方，包括用户贴进控制台的输出）；没有这道闸，一句精心构造的日志就能让面板去打开 `C:\Windows\System32`。比较走 `realpath` 归一化后的路径（检出目录里一条 `link -> C:\Windows` 就能绕过字符串前缀比较），根取不到时退化为**全拒**。

  重入判据走 `useReentrancyLock` 的同步 ref 而不是读 `busy` state：同一次事件循环里连点两下时 `setBusy(true)` 还没提交，读 state 的写法正是「双击打开两次」的成因。
