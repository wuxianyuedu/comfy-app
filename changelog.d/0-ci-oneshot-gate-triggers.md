## Added

- **三档重档各配一个「单独触发」口**（业主 2026-10-21 口径：「再加一些按钮触发单独构建的，比如
  全量e2e / 生产构建 等，同时这些也需要配备api执行」）。`.cnb.yml` 的 `master:` 下新增六条流水线
  （`web_trigger_build` / `web_trigger_e2e` / `web_trigger_unit` 手点 + 三个同名 `api_trigger_*`
  自动化口），`.cnb/web_trigger.yml` 新增三个按钮。整档手点付的是十格墙钟，而「我只想知道 E2E
  现在过不过」常常不需要另外六格陪跑。
- **每一跑自动带最小前提**，清单逐档不同（构建带安装+建库；E2E 再带浏览器；单测只带安装）。
  这不是保守，是取证：每次构建都是全新 job 目录、`node_modules` 恒不在场（`工作区复用读数` 两跑
  实测），缺前提那一跑会红在「找不到 next / 连不上库」——那是**已知的假红**，不是结论。
  前提集与「每日名 ⇄ 单跑名」的对照是一份数据（`scripts/ci-oneshot-gates.mjs`，**不含任何命令**），
  判据 import 它去比那六条流水线展开后的清单。
- 新判据（都在 `tests/no-platform-ci-config.test.ts`）：① 每档的 web 与 api 两条清单相同、且等于
  注册表的「最小前提 + 目标」，且这些名字必须在每日注册清单里；② **每个 `单跑<档>·X` 的正文
  与 `每日X` 逐字相同**（比 `script` / `env` / `timeout`，名字与注释不算 —— 见函数注释里那两条
  刻意）；③ 锚点清单里不许有同名 stage；④ **同一个顶层键不许出现第二行**（新开一个 `master:`
  会静默覆盖掉 `"crontab: 0 2 * * *"`，定时那一跑就此没有执行者，而配置读起来完全正常 ——
  #2114 那一族）；⑤ 反向自检四种坏形状（整项删掉 / 顺序颠倒 / 正文漂移 / 名字撞车）都必须被
  **各自的**判据点名，而现役形状一条都不许被抓；⑥ 这次的决定必须在规范正文里有原文。

## Changed

- **「锚点引用数必须是 5」那条评论数字撤掉**，改成「引用数 = 带 `stages:` 的流水线数」（现推）。
  写死条数等于把「今天有几条流水线」当判据：加一条就红，而红的不是任何缺陷。口径同时同步进
  §13.5.23 那张表。
- `.cnb/web_trigger.yml` 顶部那句「没写 `inputs`」的说明改成新事实：四个按钮各指一条固定清单，
  「单独跑某一档」是靠**多开按钮**做的，不是靠给一条流水线喂参数 —— 参数化的那份会长成
  「按输入内容分叉的档」，它红的时候没人能从配置里读出这次跑的是什么。

## Docs

- **§13.5.23 记下一条被否掉的形态**（这种结论不落笔就会被下一次重做一遍）：单跑口最初按
  「序列元素级 YAML 锚点」实现（`stages:` 里写 `- *stage_x`，零复制）。探针
  `cnb-7d7-1k5f9m3c5` 证明**平台会展开并执行**它（两格 `success`、节点日志里两条标记都在），
  但那种写法要求把列表项拆成两行（`- &anchor` 换行 `name: X`），而本仓有**六份各自独立的
  `.cnb.yml` stage 解析器**（`ci-autofix-duties` / `ci-env-probe` / `ci-container-plan` /
  `ci-image-identity` / `ci-incremental-gates` / `no-platform-ci-config`）认的都是
  `- name: X` 这一行形状 —— 平台「受影响用例」当场红三处（「解析出的 stage 数比 `script:` 少 6」、
  「某格解析不出内容」），且每条红的报都指不到「形状」这个真因，读起来像判据坏了。
  **不是能力问题，是这份配置的解析面付不起** ⇒ 换成整表锚点 + 副本逐字钉住。
  改完之后六个解析器的套件（204 条）与本文件（35 条）全部复跑绿。
