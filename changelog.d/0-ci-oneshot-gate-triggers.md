## Added

- **三档重档各配一个「单独触发」口**（业主 2026-10-21 口径：「再加一些按钮触发单独构建的，比如
  全量e2e / 生产构建 等，同时这些也需要配备api执行」）。`.cnb.yml` 的 `master:` 下新增六条流水线
  （`web_trigger_build` / `web_trigger_e2e` / `web_trigger_unit` 手点 + 三个同名 `api_trigger_*`
  自动化口），`.cnb/web_trigger.yml` 新增三个按钮。整档手点付的是十格墙钟，而「我只想知道 E2E
  现在过不过」常常不需要另外六格陪跑。
- **每一跑自动带最小前提**，清单逐档不同（构建带安装+建库；E2E 再带浏览器；单测只带安装）。
  这不是保守，是取证：每次构建都是全新 job 目录、`node_modules` 恒不在场（`工作区复用读数` 两跑
  实测），缺前提那一跑会红在「找不到 next / 连不上库」——那是**已知的假红**，不是结论。
  前提集是一份数据（`scripts/ci-oneshot-gates.mjs` 的 `ONESHOT_TARGETS`，只存格名与顺序、
  **不含任何命令**），判据 import 它去比配置里那六条展开后的清单。
- **单跑口结构上不可能长成第二份实现**：六条流水线的 `stages:` 每一项都是
  `- *stage_daily_xxx`，复用每日那一份的格（序列元素级 YAML 锚点，`- &stage_daily_install` +
  换行 `name:`），**一条 `script:` 都没有**；判据直接判「非引用项即违规」。
  平台会不会展开这种别名不是靠猜的 —— 先跑了一次探针 `cnb-7d7-1k5f9m3c5`（两格 `success`，
  节点日志里 `ALIAS-ELEMENT-OK-A/B` 都在）才动笔。
- 新判据（都在 `tests/no-platform-ci-config.test.ts`）：① 每档的 web 与 api 两条清单相同且等于
  注册表的「最小前提 + 目标」，且这些名字必须在每日注册清单里；② 单跑流水线不许自带 script；
  ③ **同一个顶层键不许出现第二行**（`topLevelKeys()` —— 新开一个 `master:` 会静默覆盖掉
  `"crontab: 0 2 * * *"`，配置读起来完全正常，正是 #2114 那一族「账面认为有人判」）；
  ④ 反向自检四把坏形状（漏前提 / 顺序颠倒 / 引用不存在的锚点 / 自带一格）都必须被点名，
  而现役形状必须过；⑤ 这次的决定必须在规范正文里有原文。

## Changed

- **「锚点引用数必须是 5」那条评论数字撤掉**，改成「引用数 = 带 `stages:` 的流水线数」（现推）。
  写死条数等于把「今天有几条流水线」当判据：加一条就红，而红的不是任何缺陷。口径同时同步进
  §13.5.23 那张表。
- 四个解析器（`pipelineStageNames` / `anchorStageNames` / `stageBlock` / `stageTimeouts`）改认
  **带锚点那种列表项**：`- name: X` 与 `- &anc` 换行 `name: X` 是同一件事的两种行形状。
  只认前一种时，带锚点的格会被读成「这条流水线一格都没有」，而 `timeout:` 会记到**上一格**头上。
  口径收在一个新导出 `stageItemNameAt()` 里，四个解析器共用（判据钉语义，不钉行形状）。
