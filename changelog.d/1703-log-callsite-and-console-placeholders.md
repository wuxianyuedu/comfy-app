## Fixed

- **日志面板：`console.*` 的占位符不展开、调用位置要么指错要么为空**（ISSUE #1703）。
  用户看到的是一条 React key 重复警告，既读不出是哪个 key，也看不出是哪里的问题 ——
  两个成因都在日志采集这一层，不在日志内容里：
  - **占位符没展开**：React 打的是 `console.error("… same key, \`%s\`. …", key)`，
`%s`是格式占位符。面板此前按空格把实参拼在末尾，用户读到的是一条「150 字符
模板 + 原样的`%s`+ 尾巴上挂着的实参」的怪行 —— 唯一有价值的 key 名离它该在
的位置最远。新增`formatConsoleArgs`展开`%s`/`%d`/`%i`/`%f`/`%o`/`%O`/`%c`/`%%`；缺实参的占位符原样保留（不凭空造 `undefined`），`%c`的
样式表消费但不进正文。噪判据仍看`args[0]` 原串，判决不受影响。
  - **拦截层自身的帧没被跳过**：`captureLocation` 的 self-skip 正则写的是
    `log-(?:store|provider)`，它从没匹配过真正的包装层 `LogProvider.tsx`（驼峰、
    无连字符），只匹配到采集函数**当年**所在的 `log-store.ts`。该文件拆出
    `log-analysis.ts` 后，这条正则连自己的帧都不认了 —— 每条 console 日志的位置列
    都指向 `log-analysis.ts:<行号>`，即日志器本身。判据改成「路径在 `logs/` 下、
    文件名以 `log-` 开头或叫 `LogProvider`」（不敏感大小写），拆文件 / 改后缀不再
    让它失效。
  - **库帧现在有出口**：业务帧一个都没有时（React 自己的警告整条栈都在
    `react-dom` 里），旧实现返回 undefined、位置列空着。新增第二层出口，
    返回 `包名 → 函数名`（如 `react-dom → printWarning`、`@xyflow/react →
MiniMapNodes`）；pnpm 的 `.pnpm/<pkg>@<ver>/node_modules/<pkg>/…` 中间那段
    不是包名，要往里再走一层。行内提示语据此区分「可点开的业务位置」与
    「库内部打出的日志」。
  - **位置与来源进复制 / 导出文本**：面板上有那一列、复制出去却没有，用户报障时
    能定位问题的那一半信息在粘贴这一步丢了。位置写在正文之前（多行正文不会把它
    挤到十几行之后），无位置 / 无来源的行与旧文本逐字相同。
