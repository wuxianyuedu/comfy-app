## Added

- `pnpm ship` 新增 `--no-commit`：「这一笔我自己已经提交（甚至已推送）过 ⇒ 跳过提交段、
  不看工作树，HEAD 原样进推送段」（#3619、#3676）。并行检出的工作树上常年挂着**别的
  会话**的常驻脏文件，而「树上哪些是我的」在 porcelain 里没有可靠判据（长得一样）——
  所以跳过提交段由**人点名**（说出来的判定），脚本不去猜；此前「我的活儿已在 HEAD」只能
  靠把上一轮的 `--add` 路径清单整串重抄一遍才能被表达（#3602 的豁免挂在 `--add` 前提里），
  纯合并那一跳（`--mode auto`，改动已全部在 HEAD、PR 已存在）也被堵在提交段。
  与提交段才有的对象矛盾：`--add` / `--message` / `--message-file` / `--allow-staged`
  任一同行 ⇒ 退 2（没有提交段，它们没有执行者）。dry-run 计划同步反映「不 add、不看
  暂存面、不 commit」。push / PR / 轮询 / 合并各段原样照走，不新增也不绕过任何门禁。
