## Added

- **缓存槽的键控读数档**（ISSUE #2022 第二步的第一增量，口径见 §13.5.3.4.3 末段）：
  新增流水线格 `缓存槽读数`（`scripts/ci-cache-slot.mjs`，恒退 0，与 `工作区复用读数` 同性质），
  只回答三问 —— 有没有槽（`COMFY_CI_CACHE_ROOT` 配没配）、该落哪个键、这一跑与该键的关系是
  `reuse` / `install-into-slot` / `no-cache` 中哪一档。四档关系分开且各自一句话：
  「没配槽」「算不出键」「槽不在」「槽在但键变了」合成一档之后，日志上那句 `install-into-slot`
  就说不清是第一次跑还是有人改了依赖面。
  键**复用** `ci-install-deps.mjs` 的 `pnpmInstallFingerprint`（锁文件 + 三份配置 + `patches/`），
  不在这里重算一份 sha：两处各算一份的漂移形态是「缓存命中判断」与「碰了依赖面就得真装」不再
  一致，那时的表现是依赖不对而门禁全绿。

- ⚠️ **这一格今天不复制、不链接、不装**，读数末尾就把这句打出来（开关没拨过去必须读得出来）。
  第二增量才把 `Install dependencies` 接向槽 —— 分两批不是谨慎：那一格每次构建都要过，
  键算错一次的代价是所有 PR 装不上，与 §13.5.25「先让判据在场，再把开关拨过去」是同一条纪律。
  第二增量的形状已被三条实测限定死：槽必须是**能就地跑 install 的真实目录**（不能穿链装、
  不能搬树）、作业侧只能把 `node_modules` 接过去、以及需要一把**单写锁**（并发 PR 同键时
  两个作业写同一个槽）。收益的三档实测（命中 / 未命中 / 键变）在那之前不给数。

**判据**：`tests/ci-cache-slot.test.ts` 7 例 —— 四档关系分得开且两两话术不同、槽路径 =
`<槽根>/<键>`、打印出的键与 `pnpmInstallFingerprint` 同源（数字不抄进用例，取真仓库那份
再比前缀）、恒退 0、以及在真临时目录里造出「槽在但指纹不合」与「槽指纹相同」两种事实各走
`install-into-slot` / `reuse` 一次（`readSlot` 的两种「读不到」被分开钉）。
