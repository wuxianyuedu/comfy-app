## Fixed

- **`pnpm ship` 建的 PR 正文不再随改动面等比例变长 —— 大改动面「建不出 PR」那一条路被收掉**
  （ISSUE #2248）。原形状是把 `git diff --stat` **原样**贴进正文的「改动量」小节：实测 #2231
  那次 2673 个文件 ⇒ 166324 字节，而平台对 PR 正文的硬上限是 65535（它自己的原文：
  `errcode 2000003 · body length exceeded the limit 65,535`），于是 PR 直接被拒；屏幕上那句
  读数只有「响应里没有 PR 号 ⇒ 没跑起来」，看不出是正文太长 —— 红的形态与被判对象毫无关系。
- 现在 diffstat 那一段是**摘要**：逐行明细最多留 40 条（`DIFFSTAT_SAMPLE_MAX`），末行的总数
  那一行（`N files changed, …`）永远保留 —— 裁之后读者唯一还能直接拿到的量就是它。
  **省略不许静默**：正文里明说「只列了前 N 条（共 M 条）：另有 K 条未列出」与为什么，
  并指出逐行清单在平台的「文件」那格看得到。`listed + omitted === total` 由用例钉住。
- 装不下时**样本数自己减半**，所以「正文长度与改动面无关」是做出来的、不是「40 条大概够用」
  的假设。碎片清单**不在裁剪面里**（少列一份就等于漏报这次带了什么），所以它自己就顶穿上限时
  唯一的出口是**不发**：`ship` 在建之前比一次长度，念出「不建 PR + 已经量到的上限 + 两条出口」
  （拆小 / 手工建），一次 `post-pull` 都不发 —— 不把已经量到的事实押给一次网络往返去重新发现。
- 平台给的拒绝理由现在**单独念一行**（`errcode` / `errmsg`，`readPullCreateError()`）：响应原文
  那一行是按字符截的，把外部拒绝的理由押在截断窗口里 = 让下一个执行者重查一遍已经有了的数。
  只认这两个键名，`message` 那类同名字段不猜（成功响应里它可能是别的意思）。
- 两个数同批进判据数值账（`scripts/.gate-thresholds.cjs` 那本账）：`PULL_BODY_LIMIT` 是外部
  量纲、`DIFFSTAT_SAMPLE_MAX` 是起始样本预算，两边都记 `kind: "report"` —— 它们不改变任何一次
  判决的红绿。
- 判定逻辑一字未改：`--stat` 怎么来的、标题怎么取、PR 怎么复用、终态怎么读，全部原样。
  用例 `tests/ship.test.ts` 205 → 210 条（新增 5 条：对账、上限、不谎报截断、顶穿时一次都不发、
  拒绝理由念得出来）。
