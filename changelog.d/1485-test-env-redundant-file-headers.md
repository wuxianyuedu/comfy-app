## Changed

- **用例环境档：183 处 `// @vitest-environment jsdom` 文件头里 **147 处是纯冗余**，已删；只剩 36 处承重**（ISSUE #1485）。分档（`projects` 两档）落地后没回头收尾，于是同一件事在 `vitest.config.ts` 与用例里各写一遍，读的人无从知道哪一份在说话。
  - **判据是可执行的**：`vitest list` 输出的 `[project]` 就是权威归属，逐份比「真实归属 == 文件头声明的 env」——相等即冗余。实测 147 份冗余 / 36 份承重；删完再跑同一条命令，608 份用例的归属映射**逐行零差异**（这才是「冗余」的严格证明）。
  - **前两轮「不动」的结论改口径**：原来的「178/183 承重」是「摘掉**全部**文件头会红多少份」，证明的是「文件头**整体**有作用」，推不出「**每一份**都有作用」。逐份该问的是「这份头**替目录档兜底了吗**」。
  - 36 份承重文件头继续留 —— 它们按定义就在混合目录里（目录档给 node、它自己要 jsdom），是归属的唯一声明。
  - **`exclude` 摘少数派的路实测否决**：`node` 档的 `exclude` 正是同一份 `JSDOM_TEST_GLOBS`，给 jsdom 档加 exclude 会让那些用例**两个 project 都不跑**（实测 `vitest list <文件>` 输出为空）。文件头就是这一档的正确机制。

## Fixed

- **`JSDOM_TEST_GLOBS` 里两条 `src/app/(main)/…` 条目一直在静默失效**（ISSUE #1485）。picomatch 把 `(main)` 读成分组语法，条目实际匹配的是**不存在的** `src/app/main/…`——`settings/components` 与 `settings/hooks` 两个目录从没进过 jsdom 档，那几份 `.test.ts` 一直靠文件头撑着。转义成 `src/app/\\(main\\)/…` 后立刻归位（实测 3 份从 `node` → `jsdom`，随后它们的文件头也归入冗余被删）。
  - 同族教训：仓库里「`(main)` 的括号必须转义」这句话**只写在覆盖率那一批旁边**，glob 清单漏了 —— 清单条目失效不报错，只是不见了（同 §11.7「门槛写着 100、报告里查无此文件」）。
