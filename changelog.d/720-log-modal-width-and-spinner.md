## Fixed

- **日志弹窗默认宽度只有 384px，且「加宽」按钮按了没反应**：两个现象同一个根因，而且不在日志面板里 —— `ui/dialog` 的弹窗基类带着 `sm:max-w-sm`，它是**带变体**的 max-width，Tailwind 把变体 utility 排在所有无变体之后，于是不只压默认、连调用处传进来的宽度一起压。真实 Chromium（1430×900）实测三种写法（`max-w-[96vw]` / `w-6xl` / 不传）量到的都是同一个 384px = 24rem：默认档 `max-w-5xl` 从来没生效过，加宽档同理（按钮状态在变、宽度不动）。现在基类删掉 `sm:max-w-sm`、只留无变体的兜底上限 `max-w-[calc(100%-2rem)]`，调用处一律用**另一族的** `w-*` 给结论（跨族才有确定优先级）；宽度档的单一出口是 `~/components/ui/dialog-width`。修后同一视口实测：默认 1152px、加宽 1398px。三个弹窗（应用日志 / 执行日志 / 工作流执行日志）共用这份档，默认档按行的内容密度各选（四列走 `w-6xl`、三列走 `w-5xl`）。
- **工作流库加载态显示成「一个不知道是什么的图案」**：`Spinner` 是个 `<span>`，默认 `display: inline`，而 `width`/`height` 对行内盒**不生效** —— `EmptyState` 的图标位正是非 flex 容器，`size-6` 被完全忽略，画出来的是「2px 上下边框叠在一个行内盒上」：约 4px 宽、20px 高的竖线。此前它唯一的落点都在 flex 容器里（flex 会把子项块化），这个前提从没被写下来。现在转圈自带 `inline-block`，尺寸的成立不再外包给调用处的布局。实测由 4×21 恢复为 30×30 的圆。
- **工坊封装页签里「可选 · 未落点」与前面的「可选」标签同义反复**：用户口径「这里显示的可选-未落地有些重复了，前面已经显示了可选标签」。那一列本来就有「必填 / 可选」标签，而它读的正是「没落点会不会挡住运行」这同一份事实（`ModeContract.required`）—— 再挂一个胶囊是把同一份事实换个说法说第二遍。现在「没落点」只在**必填口**上出一个状态徽标（那不是复述，是缺件状态），可选口没落点不再多挂。

## Added

- **`ui/dialog-width`**：居中模态卡片宽度档的单一出口（默认档由调用处按内容密度选、加宽档统一贴视线两边），把「为什么不能传 `max-w-*`」的 Tailwind 产序约束收在一处。
