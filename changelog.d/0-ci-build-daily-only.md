## Changed

- **PR 那一条流水线上的 `生产构建` 撤掉了，构建只剩每天 04:00 那一跑**（用户口径：
  「生产构建放到每日档」；`COMFYAPP_CI_GATES` 摘名 + `.gates` 那一格删除，§13.5.23）。
  **判据一字未改，动的只有执行者**（§13.5.17 那条口径的第三次使用）：`pnpm run build`
  那条链（`next build` → 剥私有输入 → 数产物 → 冒烟）与 `artifact-run.mjs` 的记账通道
  全部原样，只是现在**只有** `每日生产构建` 跑它。

  依据是三条这台机器的事实，不是偏好：① 同一份 `pnpm run build` 链**已经有另一个执行者**
  —— 立案那一刻它是本地那笔账（`FRESHNESS_TRACKS.artifact.dirty` = `next.config.js` /
  `src-tauri/` / `scripts/build-desktop.mjs` / 三份 standalone 脚本，命中 ⇒ 当天自己证一次），
  而**同一天稍后那一格把本地那半的「必须」也撤了**（`ciStage`，见
  `0-freshness-ci-owned.md` 那片碎片）；于是这句话今天的形态是「每日那一跑答的是
  **同一份命令**」。PR 那一格从来都是同一个判据的**第二次执行**，它多出来的只有
  「一个冷态、全新的 job 工作区」这一个条件。② 它是这条线上仅有的两档**没有并发旋钮**
  的重档之一（§13.5.21：`next build` 的 worker 数由构建器自己定），而不同 PR 之间仍然
  叠加 —— 在 PR 上它的耗时是变量，红了分不清是构建挂了还是机器被压死（§13.6.4 那一族）。
  ③ 实测 118s / 131.0s（整条 12m14s 的 17.9%），是「PR 太慢」那笔账里最大的一笔单项。

- **代价写进规范而不是留给运气**（§13.5.23 新增「第二次决定」那一节）：
  ① 最晚 24 小时才知道 —— 与全量单测搬进每日档是同一个取舍；
  ② **归因变粗**：每日那一跑取的是 master 的 HEAD，红的时候不知道是哪一笔改动带来的，
  而官方 crontab 的负责人机制把「去看的人」固定成**最后改这份配置的人**。下一动作写进
  `scripts/ci-daily-build.mjs` 的头注：按上一次绿的构建取提交区间定位，不要直接派单。

- **撤掉 stage ≠ 撤掉判据**，四处点名「谁还在管这件事」：`生产构建` 不许再回到
  `COMFYAPP_CI_GATES`（`tests/doc-check-hook-wiring.test.ts` 新钉的断言）；PR 上凡会刷新
  新鲜度账的档必须排在 `新鲜度账` **之后**（同一组里的另一半，今天 PR 上一格刷新者都没有，
  所以那一步读到的是源分支带进来的账）；`MUST_ALWAYS_RUN` 里**刻意留着** `生产构建` 这个名字，
  防的是「将来有人把它加回 PR 并顺手挂 `ifModify`」；每日那一格的入口与 `timeout` 由
  `tests/no-platform-ci-config.test.ts` 判。原先「生产构建的入口是跑法脚本」那条判据
  **删除而不是留空壳** —— 两处钉同一个事实，漂了没人知道哪份是真的（§12.12）。

- **顺手订正四处「说的有、实际没有」**：`COMFYAPP_CI_DISABLED_GATES` 旁边那句
  「`单元测试` 等环境好了再加回来」不再是全量单测的唯一事实（它已在每日档，PR 那一格仍停用）；
  定时那一跑的头注还写着「只跑一格」，现在是三格前提 + 两档重档；§13.5.4 的产物级护栏那一行
  写着平台侧「有」，现在写清它在哪儿、以及本地那半成了唯一即时的执行者；
  §13.5.20 / §13.5.21 那两句「`生产构建` 的时间一分没省 / 在这条线上没有答案」补了指针 ——
  当年的判断在它自己的轴上仍然成立（不该拿 `ifModify` 收），出路在另一条轴上。

- **顺手拆掉一颗会自己变红的行形状判据**（`tests/hook-affected-launch.test.ts`）：它拿
  `toContain('"run", "test:coverage"')` 在源码文本里找 `planRun` 的参数数组，而上一轮给
  `planRun` 加第三个入参之后 prettier 把这个数组折成多行 —— 于是**行为一个字没变，判据红了**。
  本仓栽过第二次的那条口径（判据要钉语义、不钉行形状）：现在改成 `await import` 真的调一次
  `planRun()`，断言 `args.slice(0, 2)` 等于 `["run", "test:coverage"]`。折行、加参数、
  挪位置都不会再误报，而「记账通道挂在 test:coverage 上」这件事判得比原文本更准。

- **`工作区复用读数` 那句「`.next` 恒不在场 ⇒ 生产构建从冷态起」仍然成立**，但读者变了：
  形态①（每次构建一个全新 job 目录）是**节点级**的，每日那一跑同样落在新目录里；而 PR 那一条
  现在连「`.next` 会不会在场」这个问题都不再产生。判据里那句
  「缓存侧·`.next` 不在场 → 生产构建冷缓存起」的话术跟着改指每日那一跑。
