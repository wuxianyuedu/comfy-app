## Changed

- **三档「每天首次自证」从此都不在本地跑，执行者整格移到平台侧每日档**（用户口径：
  「新鲜度都不要本地跑，都 CI 跑」；规范 §11.8 / §13.5.23）。落成的形状是数据不是开关：
  `FRESHNESS_TRACKS[*].ciStage` 一栏（`每日单元测试` / `每日生产构建` / `每日全量E2E`），
  非空 ⇒ `checkFreshnessLedger` 里「今天必须有凭证」那一层**整层跳过**，钩子 D0 那一步
  照旧打读数。**命令、用例、覆盖率门槛、预算一个字没动** —— 换的是「谁在什么时候跑它」
  （§13.5.17 那条口径的第四次使用）。

  为什么这次连本地那半也撤：上一格刚把 `生产构建` 挪走，而本地那笔账要求的是**同一份
  `pnpm run build` / 同一份 `pnpm run test:coverage`**，两次都付墙钟（实测：全量单测
  827s～组 C 中位 1108s，`next build` 冷节点 118~131s，全量 e2e 十几分钟）。

- **为这条决定新加一格 `每日全量E2E`**（前面挂着 `每日浏览器安装`）：`e2e` 那一档此前
  在平台侧**只有子集** —— PR 上的 `E2E 关键流程` 跑 `--grep=@critical`，而
  `isWholeTrackRun` 明写子集**不构成整档凭证、不记账**。不加这一格，「都 CI 跑」这句话
  到 e2e 这里就是一句空话。它带的参数与 PR 那格**必须不同**，所以镜像判据不许把它算进去，
  改由一条专门判据钉「`script` 点名 `e2e-run.mjs` 且**不带任何收窄参数**」—— 带了就会
  **绿着不记账**，而日志与账面看起来与真跑过一模一样。

- **`每日浏览器安装` 与 PR 那格比的不只是命令行，还包括两行 `env`**：`PLAYWRIGHT_DOWNLOAD_HOST`
  与连接超时是那四次取证读数换来的（`cnb-gt1-1k513ill4` 那一族）—— 只比 script 时，
  「一边改了根、另一边没改」会**逐字通过**，而红只在第二天 04:00 出现（Playwright 换版本的
  那个早上正好是这种形态）。镜像判据现在两处都比，实现是把 `env` 的**赋值行**（丢注释）
  与命令行拼成同一份比较，不另起一套解析。

- **四条边界，缺一条「本地不拦」就退化成「谁都不跑」**：① 每个非空 `ciStage` 必须出现在
  `COMFYAPP_CI_DAILY_GATES` 里（`tests/no-platform-ci-config.test.ts` 新增一条 —— 删一格
  或把名字打错都当场红）；② 撤的是「必须跑」不是**账面形状**：记录存在时 `who` / `how` /
  `verifiedAt` / `trackedBy` 照旧逐项判（拿一条抄混的记录喂进去仍然红），而**占位理由那一判
  顺手从「今天必须有凭证」那一层挪到了形状层** —— 留在原处它会随要求一起被撤，而它治的是
  「写一句『稍后』算不算回答过」，与谁去跑这一档无关（`tests/e2e-run.test.ts` 那一格仍然红，
  正是这次搬迁的读者）；③ 本地没有留痕
  从此是合法状态，不再算红，而「上次本地自证」那一句**照旧打**（撤拦 ≠ 撤账）；
  ④ 那几支在真实档上**再也走不到**的判据（今天动过面而账旧 / 超宽限 / 豁免过期）由
  `runGate` 的 `track` 注入点拿合成档继续打 —— 恒绿与放行在断言上同形，那是
  §11.23 那一族「写了没有读者」的形状，所以宁可留一个注入点。

- **代价比前两条更明，写在 §13.5.23 而不是留给运气**：合并之前，「这次改动能不能构建 /
  全量单测能不能过 / 端到端整链路通不通」**没有任何机器执行者**，最晚 24 小时由第二天
  04:00 那一跑回答；而定时那一跑的执行身份是**最后改这份配置的人**，不是改坏的那一个 ——
  归因的下一动作（按上一次绿的构建取提交区间）写进 `scripts/ci-daily-build.mjs` 的头注。
  顺带订正四处「说的有、实际没有」：§13.5.4 那三行「本地当天必须自证」、§13.5.3 那两行
  「平台侧回来不等于这张账可以不要」（这句已被处置权在人的一方改掉，原话连同理由一起记）、
  §11.8「为什么敢给 7 天宽限」那条的理由换成「每日那一跑有整档」、钩子 D0 那一步的注释。

- **同一件事把 PR 上的 `E2E 关键流程` 也挤出去了**（这是本 PR 自己那一跑教出来的，不是我推出来的）：
  `cnb-ob4-1k5828a36` 里那一格 185.8s 红，前面 34 格全绿 ——
  `[WebServer] Could not find a production build in the '.next' directory` ⇒
  `Timed out waiting 180000ms from config.webServer`。病根是 `playwright.config.ts` 旧那句
  `CI || PNPM_START ⇒ pnpm start` 把「是不是 CI」与「工作区里有没有构建产物」绑成了一件；
  撤掉构建之后前者仍成立、后者不成立 ⇒ 它去起一台没有产物的生产服务器。
  **这一族叫「红在没人声明过的东西上」**：现在多了一个显式旋钮 `COMFY_E2E_SERVER`
  （`dev` / `start`，认不出的值**抛而不回落**），`每日全量E2E` 用它把产物前提写在配置里，
  而配置文件与跑法脚本那两份实现由 `tests/e2e-runtime-budget.test.ts` 钉成同一个答案
  （两处刻意不互相 import，与 `resolveE2eWorkers` 同一条理由）。
  PR 那一格没有改跑现场编译档：dev 档在这台节点上**没有读数**，而它的历史形态是
  「首屏现场编译 ⇒ 冒烟集体超时」（ISSUE #1834）—— 拿一条大概会红、红了又分不清是链路还是
  负载的 lane 冒充「PR 上也端到端验过」，教人的是一致地忽略红；抬 `timeout` 换绿被 §11.13
  / §13.6.4 明令禁止。取舍与两条出路记在 §13.5.23 新增那节。**覆盖面没有变小**：
  每日那一跑是整档，`@critical` 是它的子集；失去的只是「合并之前」这四个字。
