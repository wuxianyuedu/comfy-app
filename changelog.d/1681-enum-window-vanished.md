## 口径

- **降级只认「已经不在了」**：`walk` 对 `ENOENT` 返回已收集的部分（等价于这一支不存在），
  权限 / 编码 / 形状错误照旧冒出去。放宽成「读不到就跳过」会把「判据读不到扫描面」
  变成静默放行 —— 那是这条兜底自身最坏的失效形态。
- **不靠逐个登记探针名**：登记忽略名单只挡住**已知的这一个**探针，而下一次「运行期写进
  仓库的瞬时文件」会带来第二个（`pnpm format:check` 撞同一份探针的 `ENOENT` 已经栽过
  一次，当时的修法也是登记名）。判据按**竞态形状**兜底一次，比逐个登记活得久。
- **没动扫描面 / 基线 / 任何棘轮数字**：本仓当前树上 `/test-sleep` 仍是
  裸 sleep 0 处（基线 0）/ 声明豁免 17 处，与改前逐字一致。

## Docs

- `docs/standards/11-测试与可观测性.md` 新增 **§11.17.1**：把「还有谁在扫这棵树」
  从 prettier 那一问补全到**纯文本扫描的静态判据**这一整族 —— 两个窗口的对照表、
  「只降级 ENOENT + 不许静默」的同一份口径、以及「不靠登记名字」的理由。
  附上那一族用例的写法边界：**夹具必须自证它真的走到了那一支**
  （`expect(removed, "夹具没跑到删目录那一步，这条用例是假绿").toBe(true)`），
  否则「只断言不抛」会在兜底被删掉时照样绿；给 `node:fs` 打 spy 必须
  **default 导入**（`import * as fs` 在 vitest 5 下是冻结命名空间）。
- 新增 **§11.17.2「钩子跑的是 HEAD 版判据」是一个已被证伪的假设**。ISSUE #1681 的
  第二半把「钩子 stash 回 HEAD ⇒ 修复判据形成鸡生蛋」记成了根因，**它不成立**：
  `.githooks/pre-commit` 全文没有任何 `git stash` / `checkout` / `reset` / `read-tree`，
  它只是 `node scripts/…`，cwd 就是工作树。推翻它只需看**报错行号跟着工作树走**
  （实测：`readFileSync` 打补丁前 `:257`、打补丁后 `:259`；报 `:257` 就说明跑的是未打
  补丁的那份，即补丁当时没落到工作树）。写在这里是为了下次再有人这么记时，
  拿它一对就能驳回 —— 而不是照着它去改钩子或开 `--no-verify` 的口子。
