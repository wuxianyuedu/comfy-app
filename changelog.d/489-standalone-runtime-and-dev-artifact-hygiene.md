## Fixed

- **桌面包里所有 API 路由都会 500，而页面一切正常**：`next build` 产出的 `.next/standalone` 缺了 Next 自带的 `app-route-turbo.runtime.prod.js`（Turbopack 对动态 `require("next/dist/compiled/next-server/<name>.runtime.prod.js")` 字符串的追踪不完整，只追到被 middleware 图带上的 `app-page-turbo`）。表现是运行时的 `Failed to load external module … app-route-turbo.runtime.prod.js`，看起来像业务 / 数据库 / 鉴权问题。修法是 `next.config.js` 顶层补 `outputFileTracingIncludes`（实测 +26 文件 / ≈2.6MB，API 全恢复 200），并新增产物层**反向**检查（缺件即非零退出）——此前没有任何门禁会启动 standalone，所以这条能长期潜伏。
- **安装包里带着 `AGENTS.md` 内部协作规范全文、`CHANGELOG.md` 与整套 `scripts/` 门禁脚本**：产物卫生清单漏了「根级 `.md`、各 `*.config.*`、整个 `scripts/`」，而剔除实现只剔目录名（这些都是文件），于是随 `src-tauri/static` 被编译期内嵌进 exe，解包即得。修法是新增 `stripDevArtifacts` —— `scripts/` 用**白名单**（只留运行时真的会读的 `install-comfyapp-helper.ps1` 与 `dev-launcher.ps1`，新增脚本默认不进产物），根级文件逐项点名；产物护栏改用同款白名单判据。
- **`pnpm test` 会随机非零退出，报错却指着不相关的文件**：三处同族的「游离异步链路在用例结束后才落地」——① `use-model-library` 的 `listQ.refetch().finally(() => setLoading(false))` 在 jsdom 环境拆除后才 resolve，React 读不存在的 `window` 抛 `ReferenceError: window is not defined`；② `use-custom-nodes-settings` 的「完成后提示停留 800ms」`setTimeout` 同源；③ `runner-state` 的 `schedulePersistLogs` 防抖定时器不属于任何生命周期，清空内存 state 后仍打到已撤销的 repository mock（`taskRepository.replaceLogs is not a function`）。三者都表现成「用例层面全绿、退出码来自 `Unhandled Errors`、报错点名的文件是当时恰好在跑的另一个」。修法：两处 hook 加卸载标记（先判存活再 setState），并新增公共取消 API `cancelPersistLogs` 让用例在 `beforeEach` 与 `afterEach` 两头都掐定时器；回归把偶发时序用「卡住回包 + 放行后记账」做成**必现**（只统计更新调度栈的 `window` 读取，避开 react-query / tRPC 的 ambient 噪声）。
