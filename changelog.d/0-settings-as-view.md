## Changed

- **设置从「workspace 里的一层全屏浮层」改成与历史 / 队列 / 控制台同形的视图**（用户要求：不要原先那种单独打开的界面）。侧栏、顶栏应用菜单、队列的「去设置」、首页算力卡的「去设置」现在都切到 `settings` 视图，页签条上多出一页「设置」，可开可关可与其他视图并列。
  - 旧形态的实际代价：那层 `FullScreenLayer` 铺满内容区、**盖住页签条**，且「当前在设置里」只活在一个布尔值里 —— 没有页签、也不能一边开着设置一边看别处。
  - 登记进 `WorkspaceView` / `NAV_ITEMS`（全局项，排在队列之后）/ `WORKSPACE_VIEWS` 白名单 / `renderCenter` 分支。排在全局项中部而不是尾部：尾部那一组（`workflows` + `console`）是「流程」链路的收尾，设置不属于它。
- **顺手把「设置怎么渲染」从两份收成一份。** 此前独立路由 `page.tsx` 与 `SettingsOverlay.tsx` 各写了一遍同样的三态（首帧 loading / 失败降级 / 就绪），而且浮层反过来从**路由文件** import 降级视图 —— 方向是拧的。现在两处共用 `SettingsView`，挂载点只剩**一条**真实差别：视口高度谁给。「关」这件事由页签自己的关闭按钮承担，视图内部不再另画一枚。
  - 这里一度还有一个 `onBack` prop，用来在失败态补一条「返回工作区」退路 —— 但两个挂载点都不传它，那条分支永远进不去，于是失败态**看着**有退路其实没有。按 §12.16 删掉：零消费者的分支不是「以后可能用」，是一句不成立的承诺。
  - `/settings` 独立路由**保留**（地址栏直达与外部链接要有落点，且它不依赖 workspace 的页签状态），但它现在只是同一份实现的另一个挂载点，不是第二套界面。

## Removed

- `src/components/settings/SettingsOverlay.tsx`（被 `SettingsView` 取代）。
