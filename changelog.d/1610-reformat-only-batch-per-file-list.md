## Changed

- **`check-reformat-only.cjs`（pre-commit D 组）从「逐文件回读 + 逐文件 stdin 兜底」改成整批口径：59 个改动文件的提交 15.2s → 2.0s，真钩子档该步 28.1s → 5.7s，判决一个字没变**（ISSUE #1610，ISSUE #1595 的收尾账）。
  - 判据本体没动（「改动前的整份文件过一遍 prettier 是否逐字等于改动后」仍是权威定义），改的是**怎么问**。`prettier --write <临时目录>` 的逐行输出本来就有三档语义，旧口径把它们混成两档（改写 / 其他）：
    - `<path> <ms>ms` → prettier **改写了它**，回读拿规范形态；
    - `<path> <ms>ms (unchanged)` → prettier 看过它、**它本来就规范** —— 这是**结论**，不是「不知道」；
    - **没有这一行** → **没有结论**（无 parser / 被 `.gitignore` 命中跳过），必须退回逐文件 stdin。
  - 旧口径把第二档也当「没有结论」退回 stdin，而实际提交里绝大多数文件都在这一档（实测 59 个改动文件里 **49 个 `(unchanged)`**）—— D 组那 14.8s 里占 ~13s 的白付就是它。读成结论之后，第二档的规模从「改动文件数」降到「prettier 不认识的路径数」（正常提交里是 0）。
  - 顺带两处**必须做对**的实现口径：① **颜色码先剥**（`(unchanged)` 那行整段被涂灰，带色时 `/ \(unchanged\)$/` 永远匹配不上 ⇒ 49 个文件当场全被判成纯格式化，是误伤方向的红）；② **耗时标记从行尾剥**而不是按固定列取路径。
  - 用例：`tests/check-reformat-only.test.ts` 新增「批量输出的三档语义」一组三条，判据是 **prettier 起了几次**（次数确定、耗时不确定）。反向核过三档：把 `(unchanged)` 当没有结论 ⇒ 第一条红；拿掉 stdin 兜底 ⇒ 忽略路径的两条红；不剥颜色码 ⇒ 第一条红。原有 17 条逐条照跑（文件自身 35s → 28s）。
  - **D 组的「组内串行」有意不改**（ISSUE #1610 实测）：真钩子档 D 并发收益 ≈0（与 C 的 4 个 vitest worker 抢核，44.7 / 43.6 / 44.1 / 43.6s 对串行 44.3s），峰值反而 +0.3GB；「隔离档 20.3s → 并发 4 档 18.4s」那 -50% 全部来自「8 核闲着」。钩子文件头与 D 组段落已把实测读数写进去，下一个人不必重量。
