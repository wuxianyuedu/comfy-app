## Added

- **仓库搬到 ReFS 开发盘之后，「这块盘能吃到多少红利」有了可复跑的判据**
  （`scripts/dev-drive-tune.mjs` = `pnpm dev:drive`，Windows 双击入口
  `tools/start/tune-dev-drive.ps1`，探测层 `scripts/dev-drive-probe.mjs`）。此前这件事
  只有一句口头结论（「搬到开发盘就快了」），落不到具体动作上；现在脚本每次运行都**实测**
  这块卷的三样能力（硬链接 / 块克隆 / 稀疏文件），再给出一张动作矩阵。

  判据本身有三条硬约束：
  - **块克隆只认「复制后源与目标是不是同一批物理簇」**，不认「强制克隆标志能不能用」。
    这条是踩过坑才定下来的：`fs.copyFileSync(..., COPYFILE_FICLONE_FORCE)` 在 Windows
    上一律返回 `ENOSYS`，但那测的是 **libuv 有没有实现强制克隆标志**，不是卷支不支持克隆 ——
    Windows 11 24H2 起受支持的复制操作（`CopyFile` 等）会**原生克隆**，实测复制一份
    4 MB 文件后源与目标落在同一批物理簇（LCN 相同），而同一台机器的 NTFS 卷上 LCN 不同。
    契约测试（`tests/dev-drive-tune.test.ts`）钉住了这一条：**同一份文件系统类型、
    实测共享与否要给出两种结论** —— 防止有人把结论写死成「ReFS 就有块克隆」。
  - **只落仓库级、可逆**的调优（`--apply` 写 `.git/config` 的索引格式与提交图）；
    需要管理员权限、或需要重格式化卷的动作**只打印命令、不代跑** ——
    前者动全局安全策略、后者动数据，判定权在人。
  - **读不到就记「不判」**，不猜：读不到物理簇信息、读不到 Defender 策略、
    读不到开发驱动器信任状态（`fsutil devdrv query` 要管理员）时，那一条的状态是
    「无关」而不是「通过」。

- **多读一层「卷上挂了哪些文件系统筛选器」**：Defender 的**性能模式只对 Defender 生效**，
  第三方端点防护（联想 / 火绒引擎这类客户端的过滤驱动）挂在开发卷上时，它并不吃那一套。
  脚本现在把筛选器清单单独列成一条杠杆。

  但**「挂着」不等于「在扫」** —— 这一条原先被当成了结论，本轮按实测改掉了：
  卷上那个第三方过滤驱动（`lnvscenter`，驱动文件签名主体是火绒）此刻确实在跑、
  也确实挂在开发卷上，但一次 1 GB + 5000 文件的负载窗口内，它的用户态引擎
  CPU 增量为 **0.000 秒**（同一窗口里 Defender 吃掉约 19 CPU 秒）——
  **它没有构成瓶颈**。所以这一条改成三档：**确实在扫**（才给「改安全策略」那两条路）、
  **没在扫**（明说不动）、**认不出对应进程**（不判，不猜）；
  没有实测到开销就不给「为了提速去改安全策略」的建议 —— 那是不可逆取舍。

- **新增 I/O 实测**（`pnpm dev:drive --bench`，实测层 `scripts/dev-drive-bench.mjs`）：
  同一段负载、同一份数据、同一个进程，分别测开发卷与参考卷（系统临时目录所在卷），
  并在负载窗口内按进程归因 CPU —— 回答「谁在吃这块盘的 CPU」。
  本机实测：第三方过滤驱动（联想 / 火绒引擎）的用户态引擎在负载窗口内 CPU 增量为
  **0.000 秒**，而 Defender 吃到约 19 CPU 秒 ⇒ **在扫的是 Defender，不是第三方引擎**，
  筛选器栈没有形成瓶颈。吞吐方面开发卷四项指标全面快于参考卷，
  但**那两块卷不在同一块物理盘上**（倍率里掺着硬件差），因此只作「整套组合不慢」的读数，
  不作「ReFS vs NTFS」或「筛选器栈」的归因。实测会真的写数据（每块卷几百 MB，跑完即删），
  因此是**显式开关**，默认不跑。

- **开发盘索引标记那条命令纠正**（工具与指南同批改）：`attrib +I /S /D "G:\"` 实测
  **什么也没做**（结尾的反斜杠被当字面量，直接吐「File not found」）；补上通配符后，
  它又会跟着 `node_modules` 里 pnpm 的**符号链接**递归 —— 实测对着仓库跑 15 分钟、
  CPU 208 秒，仓库内标记覆盖仍是 **0%**。改成「自己枚举 + 显式跳过 reparse point」
  的一行命令，实测整盘几分钟跑完、覆盖率 100%；并写明两条边界：标记只作用于
  当前已有的文件（新落盘的不继承），长期生效要靠搜索的「索引选项 → 排除项」。

- **开发盘红利指南**（`docs/guides/dev-drive-refs.md`）：把「卷是 ReFS」与
  「卷是开发驱动器」的差别、块克隆的真实门槛（复制路径有没有接上，而不是文件系统类型）、
  开发驱动器信任状态与 Defender 性能模式的关系、第三方过滤驱动的实测归因（挂着 ≠ 在扫）、
  以及文档里的硬限制
  （WSL `metadata` 不支持 ReFS、块克隆自身的簇对齐与 4 GB 上限、ReFS 更吃内存、
  不建议把 SDK 装在开发驱动器上）写在一处。

- **开发盘指南补上「把缓存目录搬走之后的连带动作」**（本轮实测踩出来的三条，
  原来指南只列了「设哪个环境变量」，没写搬完会坏在哪）：
  ① 改 `CARGO_HOME` 之后，`PATH` 里那条指向旧 `\.cargo\bin` 的条目**必须同步改** ——
  源目录被搬走的同时那条条目就指向了空处，`cargo` / `rustc` / `rustup`
  一起变成「不是内部或外部命令」；
  ② `robocopy /MOVE` 对「目标已存在且内容相同」的文件会判成同一份而**跳过复制、也就不删源** ——
  源目录会留下搬不走的残片，搬完要单独删源目录；
  ③ **已经在运行的进程仍用旧环境变量** —— 它们会继续往旧路径写，把刚搬走的源目录重新建出来；
  而「改注册表里的用户环境变量」**不等于**「所有新程序都读到了新值」：
  从桌面启动的程序继承的是资源管理器那个还没刷新的环境块，广播一次 `WM_SETTINGCHANGE`
  能让它刷新，注销重登最稳。
  另附一条容易搞混的边界：`npm_config_cache` 只对 **npm** 生效，**pnpm 不读它** ——
  pnpm 的 store 与 `pnpm dlx` 缓存是另外两个落点，搬它们要改 pnpm 自己的 `cache-dir`。

## Changed

- **`pnpm doc:check` 的文档集合新增这份指南**（`scripts/doc-facts.cjs`）：
  它引用的落点（pnpm store、四个缓存目录名、Defender 排除项的命令形态）
  都来自机器配置，漂了就会指着一个不存在的位置 —— 与 `sync-after-pull.md`
  同类，纳入校验。
- **指南补上「搬缓存」那节的三条实测**（本机真搬完三个缓存目录之后写进去的）：
  ① `robocopy /MOVE` 有两种「搬不干净」的形态 —— 「目标已存在且内容相同」的文件会跳过复制、
  因而不删源；遇到**符号链接**则因相对路径断链而复制失败、源链接也删不掉
  （实测 pnpm 缓存搬完，源侧还剩 **1,472 个符号链接 + 850 个空目录、0 个文件**）
  ⇒ 搬完必须把源目录整个删掉，或加 `/XJ` 不跟符号链接；
  ② **别的检出上的旧环境变量进程同样会重建源目录** —— 实测搬走并删净的浏览器目录，
  后来又被一批带旧环境变量的进程重建出 270 MB；
  ③ **pnpm 的 store 不是配置项，是「跟着检出所在卷走」的默认行为**（同机三个检出各自报
  `G:\.pnpm-store\v11` 与 `F:\.pnpm-store\v11`）⇒ 搬检出到开发盘这步 store 就到位了，
  真正要手搬的只有 `cache-dir` 那类缓存，而它是**用户级全局配置**。

## Fixed

- **判据层不再把「读不到卷类型」写成「不是 ReFS」**：查文件系统类型那条命令会**偶发
  返回空**（负载高时 `Get-Volume` 不给结果），判据层把类别一刀切成「非 refs」，
  于是报告里出现了「当前卷不是 ReFS」—— 而这块卷就是 ReFS（实测复制后源与目标落在
  同一批物理簇）。现在读不到时改**按实测判**（实测复制共享物理簇就判就位），
  措辞也不再误述。
- **探测层加一条不依赖卷管理服务的读法**：改用 `DriveInfo` 优先（不受系统语言影响、
  不依赖存储服务是否就绪），`Get-Volume` 退为兜底 —— 实测连续 5 次稳定读到 `ReFS|开发`。
  契约测试补两条，把「读不到 ≠ 不是」钉住。
- **检出目录不再在探测层硬拼**（master 新进的字面量扫描闸抓到的存量违规）：
  `scripts/dev-drive-probe.mjs` 原先把检出里的 git 目录当普通子目录拼出来，而
  「检出位置只有 `scripts/git-dir.mjs` 知道」是本仓的一条硬规则 —— 链接工作树里那还是
  **一个文件**，硬拼根本指不到它。改用 `resolveGitDir()` 拿 git 自己报的位置。
