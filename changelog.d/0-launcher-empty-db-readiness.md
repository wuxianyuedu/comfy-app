## Fixed

- **双击启动卡满三分钟、应用自己消失（库在、但一张表都没有）**：`ensureSchemaCurrent` 过去在「库文件缺失 / 哨兵表不在」时**提前返回 `missing`**，而自动同步只覆盖「指纹不一致」那一档——于是 `/api/health` 恒返回 503（`db: "empty"`），启动器的就绪判据只认 2xx、把 503 归进「普通未就绪」，空等满 `READY_TIMEOUT_MS` 后回收整棵进程树。§9.1 那句「跑 `pnpm db:push`」写在**页面状态栏**上，而页面要等就绪判定通过才会打开，提示永远到不了用户眼前。现在空库（含 `drizzle-kit` 在无 TTY 上留下的 0 字节库文件）与「指纹不一致」走同一条路径：dry-run 判出待执行语句全是 `CREATE TABLE` / `CREATE INDEX` 就自动应用并登记指纹，建不起来才如实报 `missing`（文案也改成「自动建表没能完成」，不再把责任推给用户）。

- **启动器把「服务已应答但库还没建」单独成档**：`classifyProbe` 新增 `schema-not-ready`（503 且响应体 `db ∈ {empty, unknown}`；`db: "down"` 仍按真故障处理，不许把「数据库起不来」说成「表还没建」）。服务活着、路由也在却持续 503 时，启动器连中 8 次即**在超时之前**把「后台正在按 schema 建表 / 长时间不就绪就手动跑一次 `pnpm db:push`」写进日志并推到启动页，超时出口另带「最后一次探测是哪一档」。

- **超时失败的取证不再只读 stderr**：新增 `readDiagnosticsTail`，按 **stderr → stdout → 应用服务转录**（`log/nextjs/nextjs-panel-*.log`，按本次启动时间排除上一次运行留下的文件）取第一个非空结果。实测现场：Next 的横幅与请求日志都走 **stdout**（同一现场 `nextjs-stdout-*.log` 事后是 31KB / 485 行 / 157 条 `503`），而超时分支过去只读 `nextErr`（那里通常只有 pnpm 打印的一行脚本横幅）；且重定向文件在子进程仍在写时可能读到 0 字节——「最近输出」于是永远是空的，用户只能对着空日志猜。
