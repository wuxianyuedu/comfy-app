## Added

- **`ship` 的留痕标签改成角色前缀，并补齐领取 / 结束释放 / 我的领取列表（ISSUE #2213）**：
  此前单子与 PR 上只有一枚 `dev:<短名>`，看不出这一枚说的是「谁提的」还是「谁在做」；
  名称还带着 `dev:` 的壳。现在名称一律取 `COMFYAPP_DEV_HANDLE` 的原值、**由角色决定前缀**：
  - 提单：单子标签 `提单人:<短名>`，PR 正文末尾的署名行同为 `提单人:<短名>`；
  - PR 标签 `处理人:<短名>`（建 / 复用 PR 后补打，`list-pull-labels` 独立回读）；
  - `pnpm ship --claim <号>`：先打 `处理人:<短名>`、再评论「开发者 <短名> 已接单，正在开发中。」
    （评论署名 `处理人:<短名>`）；
  - `pnpm ship --release <号>`：先评论「开发者 <短名> 开发结束。」、再撤标签
    （评论没落地就保留标签）；
  - `pnpm ship --claims`：列 `state=open` 且在自己名下的单子（分页到顶会念出来）。
  三条命令一次只做一件、不与 `--merge` / `--close-issue` / 提交面同跑；标签**不是锁**
  （平台没有 compare-and-set）：别人名下的单不领取，两个处理人同时挂上 ⇒ 当场落 `1` 让人裁定；
  评论不受限。所有写操作都**独立回读**（`get-issue` / `list-issue-comments`），回执不算结论；
  读不到列表落 `2`（没拿到结论 ≠ 没有）。关单验真后若处理人是你，同一套收尾会补结束评论并撤标签。
  为了让 `ship.mjs` 不撞 900 行硬闸，阶段 0 拆到 `ship-preflight.mjs`（装配层只留阶段顺序与退码记账）。
  规范 §13.10.10 / §13.10.11、`ship` Skill 与 `.env.example` 同步；回归见
  `tests/ship.test.ts` 的 `ship-claim` 组与 `main()` 单子动作组。
