## Fixed

- **任务日志 SSE 在任务结束后仍在每 3s 轮询一次数据库（`src/app/api/tasks/[id]/stream/route.ts`）**：
  三条退出路径（emitter 终态 / 轮询读到终态 / 客户端 abort）此前各清各的，而最常见的
  一条 —— emitter 的 `done` / `error` —— 只做 `controller.close()` + 退订，两个定时器
  句柄因声明在回调之后（TDZ）根本引用不到，于是 15s 心跳与 3s 的 `findById` 轮询一直
  跑到进程退出：客户端早已断连，服务端还在按「看过的任务数 × 每 3s」查库。「订阅之前
  任务就已终态」时更彻底 —— emitter 不会再发事件，而轮询那条「与上次发出的快照不同
  才动作」的判据又被初始回放喂成了恒假，两条路径都到不了。现在三条路径收进同一个幂等
  `cleanup()`（清两个定时器 → 关流 → 退订），句柄先于 `subscribe` 声明，并补上初始
  回放读到终态时的收口：日志与终态 `state` 都已回放完毕，此时关闭不丢数据。
