## Changed

- **设置页 ComfyUI 状态从「5s 一拍」改成「事件驱动为主、低频兜底」**：那条 5s 轮询
  当初是为「外部（桌面版 / 自己的终端）拉起的实例要被及时认出来」而收紧的，而现在
  这件事有了更直接的答案 —— 服务端**一发现运行态变化就推**（新增
  `GET /api/comfy/state` 长轮询通道），设置页收到立刻重问一次状态。发现延迟从
  「最多一个轮询间隔」变成「一次往返」；用户点「启动 / 关闭」也不必再等下一拍。

  变化的来源共有五条，都挂在**已经知道这件事的那一刻**（而不是靠猜文件系统）：
  - 用户点了「启动」（拉起动作先失效旧结论、再通知，收到通知的人吃不到旧缓存）；
  - 拉起流程落定（就绪 / 这次等待结束），通知写在单飞锁**放开之前** —— 否则那一问
    可能刚好落在「锁没了、还没探到就绪」的空窗上（`ISSUE #442` 那条来回跳）；
  - 用户点了「关闭」（关不干净也发：那同样是一次状态变化）；
  - 子进程退出（`child.on("exit")` 那条路径，与存活链的崩溃事件同一个事实源）；
  - ComfyUI 配置写入（路径 / 端口 / 启动参数 / 解释器 —— 判据变了才发，
    改「自动启动」这类偏好不发）。

  兜底那一拍**留着但换了身份**：它不再是「追事实」的主判据，而是「通道自己坏了」
  时的后备（长轮询断开 / 服务重启 / 事件没送到），因此从 5s 放到 30s。两条路各
  走各的（§12.12 的孪生判据只看实现重合，不看「同一个事实的两条路」），不共用计时器。

  通道只在设置页显示着时挂着（没人看就不占连接），切后台由 `startPollTimer` 暂停、
  回前台立刻补问一次。它**只推「变了」，不推「变成了什么」** —— 真正的四态仍由
  `setting.comfyStatus` 给出，视图层契约一个字都没改。

## Added

- `src/lib/comfyui/state-watch.ts`：运行态变化的进程内信号总线（单调纪元 + 订阅 +
  长轮询的等待侧），是「事件 → 客户端」通路的服务端一半。
- `src/app/api/comfy/state/route.ts`：把变化推给浏览器的长轮询端点（`?since=` 增量，
  窗口内无变化回 204；不带 `since` 则立刻回当前快照，让「刚打开页面」与「错过一次
  变化」是同一段代码）。
- `src/lib/comfy/comfy-state-client.ts`：客户端那一半（按 `seq` 去重、无订阅者时不
  建立连接、坏帧与网络异常静默降级）。
- `src/lib/comfyui/lifecycle-notice.ts`：拉起流程 → 变化通知的措辞收口
  （`lifecycle.ts` 已贴着文件长度硬闸，且这三句话不该在启动 / 就绪 / 失败三个分支里
  各写一遍）。
