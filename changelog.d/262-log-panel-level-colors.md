## Fixed

- **应用日志面板：警告/错误不再重复显示，级别色改由标签文字承担、且不再被切成省略号（ISSUE #262 五审）**。用户给的截图里行头有两处毛病：① 标题旁那块灰底胶囊写着 `警告 n · 错误 n`，与右侧级别按钮上的同名计数**同源**（同一个 `originCounts`），同一项数据说两遍；② 级别按钮的标签被切成了 `警…`，四位数字还被挤到下一行。现在胶囊**整块删除**——各类别条数只在级别按钮上（完整分类数含「信息」留在按钮的悬浮说明里），级别色由**标签文字**承担：「警告」黄（`text-amber-300`）、「错误」红（`text-rose-300`）、「信息」青；数字列固定中性灰（`w-[4ch]` + 右对齐 + 等宽数字），不再跟着级别染色，免得一行里两个高亮块互相稀释。省略号的三个前提一并拆掉：按钮 `min-w-0` → `min-w-fit`（取内容固有宽度，不再允许压到忽略固有宽度）、去掉 `overflow-hidden`（它是 `text-overflow: ellipsis` 生效的前提）、标签 `truncate` → `whitespace-nowrap`；「文字 + 四位数字」从此是**不可压缩的固定预算**，窄到放不下时整组折到第二行，而不是切字。`CountChip` 随之不再接收 `level`。
- **日志面板的颜色与宽度判据落到真实浏览器**：这两类都是布局结果——jsdom 不做布局、也不解析颜色空间（Tailwind v4 产出的可能是 `lab(...)`，直接切字符串会算出色相错值）。e2e 新增一条用例在 Chromium 里量：五个按钮宽 ≥ 56px、按钮与其两个子元素的 `scrollWidth <= clientWidth`（真正的不省略判据）、警告与错误的计算色不同且分别落在黄/红区间（经 2D 画布换算成 sRGB）、数字列颜色 ≠ 标签颜色、标题行第一行里不再含 `警告 n` / `错误 n`。
