## Added

- **构建缓存落常驻目录：换一个工作区路径再构建，不再从零编译（编译段 95s → 14.9s）** ——
  平台 runner 每个作业都新建一个带流水线 id 的工作区目录（形态由「工作区复用读数」定死），
  而 Turbopack 的持久缓存（`<distDir>/cache`）住在**工作区里** ⇒ 每次构建的编译段都从零开始。
  此前规范 §13.5.3.4.3 那张表把 `.next` 整格判成「键里带绝对路径 ⇒ 能省 0」；**实测把这一格拆
  成了两半**：`.next` 里的**产物**确实带绝对路径（搬不动，那一半结论不变），而**持久缓存的键
  是内容哈希、不含工作区路径** ⇒ 换一个工作区目录再构建，它照样命中。
  实测（同机、同源码、两次都先清掉 `.next`、只差「缓存目录冷/暖」这一个变量；`next build`
  自报的编译段）：**冷** `Compiled successfully in 95s`（墙钟 135.7s）／**暖**（用上一个工作区
  留下的常驻目录）`in 14.9s`（墙钟 55.0s）／**暖 + 改了源码** `in 14.8s`（墙钟 88.3s）——
  省的是**整个编译段**（6.4×）；第三跑那一行同时是**正确性**证据：改了源码再用同一份缓存重建，
  产物里出现了新源码的内容（18 个文件命中哨兵、0 个陈旧）。
  落成：
  - 机制 `scripts/ci-build-cache-slot.mjs`（四步，每一步都能单独不成立而不影响构建）：槽根与
    依赖面那套槽**同一个推导**（写在 `ci-cache-slot.mjs` 的 `resolveBuildCacheRoot` 里 ——
    两处各问一次 store 就会有两份「槽在哪」的答案）但**不同目录**；构建面指纹取四份输入的
    **内容** sha256（`pnpm-lock.yaml` / `package.json` / `next.config.js` / `tsconfig.json`，
    **不含源码** —— 源码变了不该换槽）；接槽靠 **junction**（`.next/cache` ← 常驻目录）；
    收尾在 `finally` 里摘链 + 放锁。
  - **边界逐条实测过**：平台那句 `Remove-Item -Path <workspace> -Recurse -Force` **不穿链**
    （链接在 `.next/cache` 与在 `.next` 两种嵌套形态各测一次）⇒ 常驻目录活得过作业结束；
    摘链摘的是「链接」不是「它指着的目录」（判据钉在「收尾摘链后槽里的文件仍在」那一条；
    三个候选原语 `rmSync` / `rmdirSync` / `unlinkSync` 各量过一次，三者都只删链接）。
  - 「那个路径上有东西」问 **lstat** 而不是 `existsSync`：后者跟链走 ⇒ 悬空链接被读成「不在」
    ⇒ 建链接撞 `EEXIST`（不损坏，但读数要靠人翻译）。
  - **失败即退回**：开关、槽根、指纹、空间四道门任一不成立，或那把单写锁没抢到（并发跑不共用
    一份缓存），就只打一行读数、照常构建 —— **缓存是加速，不是前提**。
  - 开关 `COMFY_CI_BUILD_CACHE=1`（**默认关**），只拨在平台「每日生产构建」那一格 —— 那是这台
    节点上唯一每天都会发生的构建（§13.5.25「先让判据在场，再把开关拨过去」：判据是
    `tests/ci-build-cache-slot.test.ts` 那一档机制形状的用例）。
  - 判据 `tests/ci-build-cache-slot.test.ts` 13 条（五道门分得开 / 面指纹不含源码 / 摘链不穿链 /
    失败即退回 / 槽根与依赖面那套同源不同目录）。
