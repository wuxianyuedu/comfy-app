## Changed

- **光晕从此是一个族，而且必须两态**：`--color-glow-success` / `-warning` / `-danger` / `-brand` 四颗，
  浅色档直接写成 `var(--color-success)` 等本体、深色档用 400 档浅彩（`#34d399` / `#fbbf24` /
  `#fb7185` / `#a78bfa`）。规则 = **色相走 glow token、强度由调用处 `color-mix(… N%, transparent)` 决定**。
- 这条**订正了 #1514 定下的档位形状**。那一刀签的是「保住浅彩色相」，但把它定成了**单值**，理由写着
  「原裸值没有 `.dark` 分叉」。把两个候选压到真实背景上算对比（α=0.8，bar 底浅色 `#ffffff` /
  深色 `#14141a`，success / warning / danger 依次）：

  | 光晕色 | 浅色档 | 深色档 |
  | --- | --- | --- |
  | 基准色 | 2.53 / 2.51 / 4.11 | 4.07 / 4.09 / 2.78 |
  | 400 档浅彩 | **1.71 / 1.51 / 2.23** | 6.47 / 7.37 / 4.74 |

  ⇒ 单一取值必然在某一态偏弱：浅彩压在白底只有 1.5–2.2:1，光晕等于看不见 —— 而被看见是它唯一的
  作用。**「旧代码只有一个值」不等于「设计上不需要两个值」**，那次是把事故当成了设计。
- 同一栏里两套配方并掉：`fpsDotColor` 三档从「基准色 α=1 实心光晕」改成与隔壁 devServer 点同一配方
  （glow 档 @80%）⇒ 浅色档色相不变、只柔和一档，深色档由 `#5be3c4` 变 `#34d399`（同明度家族）。
  点本体（`bg-success` 等，承载语义与对比度的那一层）一处没动。

## Fixed

- 5 处光晕裸值并进来：`canvas/CanvasSettingsButton.tsx` 的品牌点 `rgba(167,139,250,0.7)` →
  `--color-glow-brand` @70%（深色档就是原值，浅色档由 1.9:1 抬到可看见）；4 处连线光晕
  `rgba(124,92,252,0.6)` → `color-mix(… var(--color-primary) 60% …)`，**逐字节同值 ⇒ 零像素**
  （`#7c5cfc` 就是 124,92,252）。
- 判据从「禁某两个裸值」升级成**按形状归零**：`shadow-[0_0_…rgba(…)]`（光晕在几何上无偏移无扩散）
  与任何 `shadow-[…#hex]` 都判红。上一版的教训照抄进注释 —— 它曾把合法的角色色（`canvas-types.ts` /
  `HomePage.tsx` 的 `#34D399` 类别色）误报三处；新判据配两条反向样本钉边界：投影
  `shadow-[0_18px_40px_rgba(0,0,0,…)]` 不许被抓（实测按 `0_0_` 判 0 处、按「任意 shadow 带 rgba」判
  6 处），类别色不许被抓。另断言四颗 token 各自**声明两次**（`@theme` + `.dark`）—— 只数次数不抄
  hex，抄了就会和 CSS 各自漂移；取值由 Colors 表那条判编译产物。

## 视觉影响（如实记下，不含没跑的）

连线 4 处与 `--color-glow-*` 的浅色档 = **零变化**；有变化的是三处：状态栏 `fps` 三个点的实心光晕
变柔和一档、深色下色相微调，品牌点在浅色下明显变可见（这正是目的），devServer 点在浅色下由
`#34d399`→`#0ea472`（更可见）。这些都未做像素基线复看（`e2e/visual` 只覆盖登录页，本轮没有扩）。
