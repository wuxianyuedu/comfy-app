## Added

- **单子补一枚只增不删的 `参与人:<短名>`，`ship` 阶段 0 沿用启动器那条 `.env` 缺键读数（ISSUE #2215）**：
  - `pnpm ship --claim <号>` 现在打**两枚**标签：`处理人:<短名>`（当前谁在做，结束即撤）与
    `参与人:<短名>`（谁做过，只增不删）。两枚生命周期不同，不能合并 —— 拿 `处理人:` 兼任历史
    会让这张单永远显示「有人在做」，别人再也领不走。旧单已有 `处理人:` 但缺 `参与人:` 时
    只补后者，不重复打已有的那枚。
  - `pnpm ship --release <号>` 与关单收尾只撤 `处理人:`，`参与人:` 保留；撤标签的回读日志
    会明说「经手记录只增不删」。写后独立回读仍然两枚一起验（写后一次 `get-issue` 看得见
    才算打上）。
  - `pnpm ship --claims` 仍只按 `处理人:` 列当前领取中的单（`参与人:` 是历史，不参与这个列表）。
  - 阶段 0 复用 `scripts/env-preflight.mjs` 的 `envInitHint()`（与 `pnpm dev` / `pnpm start`
    同一份实现，#2205）念出 `.env` 缺的键与 `pnpm env:init`，并带这一份检出的绝对路径；
    它是读数、不参与退码，`.env` 齐全时不出声。
  规范 §13.10.10 / §13.10.11、`AGENTS.md` 硬规则 14、`ship` Skill 与
  `docs/guides/git-identity.md` §4 同步；回归见 `tests/ship.test.ts` 的角色标签组、
  `ship-claim` 组（含「旧单只缺参与人」那一格）与阶段 0 的 `.env` 读数用例。
