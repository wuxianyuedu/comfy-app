## Removed

- **删除仓库根的 `.cnb.yml`（一份匹配不到任何事件的死配置，ISSUE #1229）**。
  它由 `76275841`（2026-09-27）在 #623 删除后补回，意图是把本地核心门禁
  （eslint 零警告 / `tsc --noEmit` / `vitest run`）搬上平台当「第二执行者」，
  但顶层直接写 `stages:` / `jobs:`，**没有分支键、没有事件键** —— CNB 的形态是
  `分支: { 事件: [流水线] }`，声明成 0 条可触发的流水线等于什么都不跑。
  构建历史是判据：09-27 之后 `push` / `pull_request` 一条都没有，全部 4 条构建
  都由 NPC 评论触发（`issue.comment@npc`），比 #623 删除前更彻底地静默失效。
  这不只是「没接上」——一条自认为在守门、实际从不运行的门禁比没有门禁更坏：
  它让人以为 `--no-verify` 有服务端兜底。

## Changed

- **`docs/guides/PRODUCTION-GAPS.md` 的 P0-1 从「已建 .cnb.yml」改回未闭环**，
  并写明缺口的真实形状：不是「没写配置」而是**免费额度用不起**（#623 实测
  `cpus: 8` 下一次 PR 近 1 核时，160 核时/月几十次 PR 就见底），出路是规范
  13.5.4 的**按需召唤**（在 PR / Issue 里 `@` 评审 NPC 跑一轮全量单测 / 产物护栏 /
  E2E，不 `@` 就不花核时），而不是把配置贴回去。`changelog.d/0-p0-1-ci-pipeline.md`
  里「新增 `.cnb.yml` 解除 `--no-verify` 风险」那句随之作废，正确的结论以本片为准。
