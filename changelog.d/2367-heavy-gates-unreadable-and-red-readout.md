## Fixed

平台 `重档静态判据` 那一格的两处「红了报绿」：

- `runHeavyGates()` 交出来的 `unreadable`（注册表读不到）**没被 `main()` 解构**，
  于是它一路走到最后那句 `return 0` —— 账面上「合计 0 条、红 0」，读起来像
  「今天没有判据要跑」，而事实是一条都没判。现在它退 2，与 `main()` 开头那句
  「读不到注册表 ⇒ 不构成证据」逐字同口径。
- 红步的输出此前只转述尾部 12 行，而这一档动手之后有几百行 ⇒ 判决面
  （「改动面来自 …」）与结论都在前面，日志里一个字都没有。改成**头 5 行 + 尾 15 行**，
  省略中间段时明说省了第几行到第几行、共多少行。三态标签也与退出码对齐：
  那一步自己声明的 `notRunCodes`（仓库三态的 2）不再被打成「红」。

同一张单期望里的第二半 —— `依赖新鲜度` 自己把「没跑起来」读成了「判过了」：

- `runFreshnessCheck()` 在「拿不到 git 状态」那一支**直接 return**，把 ③（本地安装
  ⇄ 本检出声明）一起吞掉，而那一层与 git 无关、任何环境都判。出口是只剩一句
  「这里不是一个可信的检出」——读者据此以为「查完了」，而 `node_modules` 没装
  这件事一个字都没有。现在这一档退 2（**没跑起来**，与 0 绿 / 1 红 三态同口径），
  ③ 的读数照旧打出来，`--json` 里多一格 `envBroken` 把「结论不成立」与「本地那一层
  是什么」分开，标题也从「有漂移」改成「没跑起来」（没跑起来 ≠ 判出失败）。
- 判据默认判**当前工作目录那个检出**，不再退回脚本所在仓库根。此前在任何别的目录里跑，
  读数与仓库根一模一样且一个字都不说 —— 拿一个空目录问「我的依赖装对了吗」，
  答案变成了别的仓库那份。`git()` 与 `readAtRev()` 也不再在缺 `cwd` 时静默替换成
  仓库根：取不到就是取不到，回 `ok=false` 让调用方判「没跑起来」。
