## Added

- **CI 新增一档「工作区复用读数」（`scripts/ci-workspace-probe.mjs`），把「每次构建都要重新
  检出」这一格从**只有一句结论**变成**有机制读数**（无 ISSUE，承接 §13.5.20 那条「`Prepare`
  31.5s 是克隆」）**：本仓对这件事的全部已知是一个数字（`Prepare` ≈31.5s / 占整条 4.7%）与
  一句「自托管上没有 OverlayFS，所以每次都全量 clone」。但那个数字底下有三种互不相同的机制，
  而**没有任何一处日志能把它们分开**：

  | 那一种                              | 31.5s 的大头在哪       | 出路                                                   |
  | ----------------------------------- | ---------------------- | ------------------------------------------------------ |
  | ① 每次新 job 目录、对象库从零 fetch | 从零搬对象库（56 MiB） | 让对象库常驻（平台有 Pipeline 级 `git.enable: false`） |
  | ② 同目录、增量 fetch                | checkout 落盘 + 杀软   | `git.enable` 动不到成本，别为它改检出层                |
  | ③ 同目录但 `.git` 被重建            | 目录活着、对象库重造   | 常驻已有的一半，缺的是别清 `.git`                      |

  这一档读的就是那一格：打 `cwd` 与 `.git` / `.git/FETCH_HEAD` 的**出生时间**（平台每次真的
  重新 init 吗）、HEAD 形状（detached / `refs/heads` 条数 / 历史深度 / 浅不浅 / 有没有 remote）、
  对象库大小（只问 `git count-objects` 要现成的数，不自己 `du` —— `node_modules` 十几万个文件
  逐文件 stat 会把这一档从秒级推到分钟级），并把每次的对照记进**工作区之外**的账本
  （`COMFYAPP_CI_PROBE_DIR`，缺省退宿主 `LOCALAPPDATA`）—— 写进检出目录就成了未跟踪文件、
  被结构门禁那一套判，而这一档要的恰恰是「跨检出存活」。

  **顺带读第二格，它比克隆更贵**：`node_modules` 与 `.next` 在构建开始时是不是冷的。

## 它自己那一跑的读数（`cnb-f3v-1k57a1o1l`，5.7s 跑完）—— 三态当场定成 ①

- 工作区路径 `…\runner\<repoId>\cnb-f3v-1k57a1o1l-001~c5g\workspace`：**目录名带着本次流水线的
  id** ⇒ 每次构建一个新目录，不需要对照就能定；`.git` 与 `.git/FETCH_HEAD` 出现在 59s / 58s 前
  （那一跑 `Prepare` 是 35.5s）、HEAD detached、`refs/heads` 零条、浅克隆 false。
- **第二格一并定了**：`node_modules` / `.next` / `coverage` / `playwright-report` 四个全不在场
  ⇒ 这一跑的安装（59s）与 `next build`（131s）都从冷态起 —— 比克隆那 31.5s 大。
- 执行账号是 **SYSTEM**（账本实测落在 `C:\WINDOWS\system32\config\systemprofile\AppData\Local\`），
  与 §13.5.3.5 那条「Python 装在 `yuedu` 会话里、SYSTEM 够不着」同源。
- **两处随读数订正**（都是这一档自己写下的错）：① 头一版按开发机 `.git` 的总量写「搬 130 MiB
  pack」，而 CI 取的是协商后的单 ref，实测 **57168 KiB ≈ 56 MiB**，两个数不是一回事；② 平台检出
  的 HEAD 是 **merge 提交**（`d399bd34…`），它**不等于** `CNB_COMMIT`（源分支 head `f2325166…`）——
  所以那条「启用 `git.enable` 必须同批补的 HEAD 断言」要比对的是
  **`CNB_PULL_REQUEST_MERGE_SHA`**；拿 `CNB_COMMIT` 去断言会把绿的一跑判成红，而假红会教会所有人
  绕过这一档，比没有判据更坏。
- **`⇒` 与 `⚠️` 在平台日志里被打成 `?`** —— 而这正是「这一档的下一动作」那几行。按
  PowerShell `GetEncoding(936)` 的往返扫出三个坏码位（U+21D2 / U+26A0 / U+FE0F），改成 GBK 里
  站得住的 `→` 与 `※`，并留一条判据：这一档每一支会进日志的文案都不许含这三枚码位（判据用
  名单而不是「编一遍看坏没坏」—— Node 没有 GBK **编码器**，那正是 `ci-cp936-exit.mjs` 存在的
  理由，而用例在任何宿主上都要给同一答案）。

  **它是读数，恒退 0**（与 `镜像身份` 同一口径）：它判的是这台机器怎么被调度，那不是任何一次
  PR 的缺陷；而账本跨构建对照要**两跑**才成立，所以**它自己那一跑**报「未定」—— 这不是缺陷，
  是这一档刻意不肯拿一次观测猜结论。凭据一律只报「在场 + 长度」，值不进日志（平台单次构建日志
  另有 102400 字节的硬上限，整档输出有界）。

  判据 `tests/ci-workspace-probe.test.ts` 19 条：三态各自定性、空账本不许退化成「复用」、
  账本读不动 / git 问不到 / 写不进去三种故障都要照打正文、`CNB_TOKEN` 之类不许漏值、
  年龄分档（`0s / 2m / 1h / 57d`，开发检出那种几十岁不许退化成 `0d`）、上面那条 CP936 文案闸，
  以及一条**真机执行**它并断言退 0 且真的打出正文的自证。

  ⚠️ **这一档不启用 `git.enable`，只回答该不该启用它。** 真要动那一档时有一条同批的前提，
  写死在读数的下一动作里：必须同时补一条会红的断言 —— HEAD 等于本次检出的那个 sha（按上面的
  订正，变量是 `CNB_PULL_REQUEST_MERGE_SHA`）—— 少了它，「这一跑跑的是哪份源码」就没有任何
  执行者，而那正是 §13.5.3.4.2 当年判死「自己搓共享对象库」那条路的同一格。规范侧
  §13.5.3.4.2 与 §13.5.20 各补一句指路，`docs/generated/13-*` 同批重渲染。
