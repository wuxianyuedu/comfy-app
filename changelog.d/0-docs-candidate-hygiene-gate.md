## Added

- **新判据 `tests/docs-candidate-hygiene.test.ts`**：不读文本、也不读现成产物，而是拿引擎在
  两个钉死的扫描面上**各编一遍**（一遍只喂 `docs/**` + `tests/**`，一遍只喂 `src/**`），
  两侧候选名集合做差 —— 只有正文在供给的就是死规则，红。配套三条：登记表里的条目若已经
  不被引擎解出来也算红（不留「有豁免权、没有实物」的通道）；**占位形状单独立一条**（它同时
  出现在供给侧与消费侧，差集看不见，而 src 注释里那种「说明这里禁止什么」的写法正是这一类）；
  承重前提由系统临时目录里一份合成正文**当场问引擎**（写全会生成 / 内侧留空格不生成 /
  占位照样生成）。
- 判据为什么不能读现成的产物，写在文件头：`compiledGlobalsCss()` 那份把输入源收成 4 条
  utility（#1336 的耗时与可复现），**结构上看不见**「扫描面里多一枚候选会怎样」—— 第一版
  拿它当判据时报的是「一条 arbitrary 都没解出来」，那是正确形态的红：判据在空跑。
  所以 `tests/helpers/theme-tokens.ts` 多一个入口 `compiledCssPinnedTo(目录, 点名的类)`：
  保留 `source(none)`、按参数把扫描面钉回去，且**不**做 `@theme static` 与 utility 钉名那两个
  加工（它们都会改变产物形状）。实测本机：src 面 2.4s、docs+tests 面 4.0s、探针 0.2s。
- `docs/DESIGN.md` 的扫描边界那条按实测补齐：正文紧贴汉字时引擎抽不出候选（本轮据此删掉
  一条登记表条目），但**这不是可依赖的写法** —— 分隔符挪一位就重新成形；该用的仍只有内侧
  留空格与码 span 边界那两种。
