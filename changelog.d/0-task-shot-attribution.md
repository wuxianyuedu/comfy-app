## Changed

- **工坊生成任务现在带归属**：`task` 表新增可空列 `shotId`（这一镜），并把此前一直没传的 `projectId` 真正写进去 —— 三条按镜生成路径（分镜段的单镜生图、镜头生图段、视频段）统一经 `withGenerationAttribution(...)` 补这两个字段。目的只有一个：让「这一镜出过图吗」能由数据库回答，而不是只信草稿 JSON 里那个 `Shot.imageUrl` 字符串（草稿可能被改、被本地清掉、也可能根本没推给服务端）。
  - 索引按读取形状收敛为复合索引 `task_project_shot_idx (projectId, shotId)`，其最左前缀覆盖原先只按 `projectId` 过滤的查询，故不再单留 `task_project_idx`（与 `(status, finishedAt)` 那条同一处理口径）。
  - **空归属写 NULL、不写空串**：「没有归属」与「归属是空串」在库里必须是两件事，否则统计会把两者并成一类。
  - **历史行不回填，也不能回填**：提交时的 `params` 里没记镜头、`workflowSnapshot` 根本没写，任何按时间或按名称的反推都会把归属写错，而错一次的代价是健康度条从此长期报一个假数。唯一残留的逆向线索是草稿里 `shots[].taskId`（会被后续重跑覆盖、本地草稿可能从未推送、项目可能已删），它不足以支撑一次性回填。因此读侧的口径必须是：**NULL = 归属未知，不等于「这一镜没出过图」**。
  - 迁移方式：本仓库的 schema 变更由 `pnpm db:push` 同步（启动时按 schema 指纹自动补齐，无提交的 SQL 迁移文件）。新增列可空、无默认值改动，存量行保持 NULL，不需要数据搬迁。
  - 尚未接的两侧，留作后续：服务端另一条建行路径（`createWorkflowRunTask`，供成片编排与首帧使用）没加 `shotId`；画布节点级生成也不按镜。它们不是「无归属」，是**按当前语义本就没有镜头上下文**，健康度条在统计时要把这两类区分开，不能当成同一种空。

## Added

- 归属链路的三处用例：`generate` 路由器（带上时落库、缺省时落 NULL）、任务仓储（内存 SQLite 真库写入并读回，含旧形状调用点不受影响）、`withGenerationAttribution` 纯函数（空值不写成空串、不改原对象）。
