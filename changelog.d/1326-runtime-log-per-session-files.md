## Changed

- **四份常驻服务日志改成「一次启动一份文件」**（ISSUE #1326，用户原话：「comfyui-runtime.log / ollama-runtime.log / drizzle-studio-runtime.log / app-runtime.log 这四份也要改成每个文件只存储单次运行的历史，单次里如果执行多次也存放多个文件，这样看起来清晰」）：
  - 文件形态 `<来源>-<YYYYMMDD>-<HHmmss>.log`，如 `comfyui-runtime-20261005-093612.log`。**不带冒号**（Windows 下 `:` 非法 —— 按时间戳原样写会让 `appendFileSync` 静默失败，用户只看到文件一直没出现）；字典序 = 时间序，`ls` 一眼就是时间线。
  - **同一秒内第二次启动分叉 `-2` / `-3`**：「启动 → 秒退 → 再启动」在这四份日志上都很常见（端口被占、依赖缺失、用户连点两下），覆盖会让第一次的失败现场直接消失，而那次恰恰最该看。
  - **每个来源留最近 20 份**（启动时异步静默清）。数据来源从 `runs/` 的保留策略换到了这一条：文件不再随运行包归档 —— 一个运行包里同一个来源可能有几十份（ComfyUI 被重启多次），跟着 `runs/` 走会让包体量随「服务重启次数」线性膨胀。
  - **迁移前的旧固定名（`<来源>.log`）读侧照认**，在下拉里排最旧、文案「更早的日志」：用户盘上已经有它，改名迁移把它丢掉比留着一条历史糟得多（退回文件名当文案会让它读起来像「现在那一份」）。
  - **唯一实现**：命名与解析（纯函数）在 `src/lib/log/runtime-log-file.ts`，「本次该写哪一份」在 `src/lib/log/runtime-log-pack.server.ts`。四个写方（`comfyui/lifecycle` / `drizzle-studio/lifecycle` / 两条 ollama 路由 / `app-runtime-log`）都经这一层，不自己拼名字 —— 各自拼必然漂（有人写日期、有人写时分秒、有人忘掉同秒分叉），而漂开的表现是「日志列表里少了一次启动」。`tests/log-run-layout.test.ts` 加了一条形态判据扫这四个写方。

- **关闭动作写进最近一次启动那一份**（ollama 停止路由）：它是另一个请求、可能还是另一个进程，没有「本次启动」的句柄 —— 新开一份会产出一份只有两行 `[action] 关闭` 的空文件，而「为什么关得掉 / 关不掉」本该和那次启动的输出连在一起。

- **设置页「启动日志」下拉改成列这些份**（`GET /api/logs/sessions`）：列表 = 该来源在 `services/` 下的各份（新→旧，上限 30），正文 = **选中那一份整份**。列表被上限截断时如实回报 `total`，界面提示「该服务一共启动过 N 次，下拉只列最近 M 次」—— 不说的话用户会以为「只启动过这些次」（硬规则 4）。

## Removed

- **「正文 = 当前包 − 前一包」那整套切分判据随之一并删除**：上一版按**应用运行包**（`log/runs/<日期>_<时分秒>-<runId>/`）列表，正文要用「包 N ⊇ 包 N-1」这条来自归档复制语义的性质做长度减法（还要维护「基准不可得」与「前缀关系不成立」两个状态）。改成一次启动一份文件之后，「文件是谁」不依赖任何假设 —— `log-run-sessions.ts`（切分判据）与 `log-run-packs.server.ts`（读 `runs/` 的 IO）的唯一消费方就是那一版，因此一并删除。这是本次改造最实在的收益：**静默出错的机会少了一整类**（剪错会把真实内容切掉，而界面上看不出）。

- **会话横幅（`▶` / `■`）整条撤掉，写侧与读侧都不再存在**：横幅当初解决的是「一份文件里多次启动的行要能分清边界」（ISSUE #592）。边界现在由**文件名**承担 —— 写它等于往没人读的地方写字（§12.15 第二条）。`src/lib/session-banner.server.ts`（`buildSessionBanner` / `appendSessionBanner`）与色板 `BANNER_ANSI` 一并删除，它们已零消费方；`installStreamCapture` 不再往 app-runtime 写横幅。

- **`RUNTIME_LOG_FILES`（来源键 → 单个文件）与四个固定名常量**从 `log-paths.ts` 撤掉：一个来源不再对应一个文件，那一层现在是 `listRuntimeLogFiles()`。`log-paths` 只剩目录常量。

## Fixed

- **「应用日志」面板的会话起点裁剪对本族不再需要**：`app-runtime` 的文件天生只含本次运行，`app`（`nextjs-panel-<pid>-<ts>.log`）一直是每进程一份；本次进程还没落盘时读到上一个进程文件的情形由 `bootId` 的重启判据处理，比行时刻更准。`isSessionScopedOrigin` 的集合因此为空。
  - **机制本身保留**（`dropStaleEntries` / `setSessionStart` / 契约字段）：它是「某个来源将来变成跨运行累积」时的**唯一**出口，删掉它会诱使下一个人在面板里再写一遍时间线比较。集合为空时函数恒真、零开销，回归用例改成锁**口径**（null / 0 / undefined 的边界、只摘行不重排、幂等），而不是「哪个来源现在需要裁」——后者是本刀消掉的判据。
