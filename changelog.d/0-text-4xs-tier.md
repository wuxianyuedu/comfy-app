## Added

- **`--text-4xs: 9px` —— 微标签那一族往下补齐第三档**：9px 此前是 22 处字面量（`ui/badge` 的
  `xs` 档、时间轴与缩略图角标、mono 端点名、密集列表行的内联小徽标），与 11px / 10px 立档前
  完全同一个坑 —— 没有名字，「改一档全站跟手」对它不成立。档名照 t-shirt 刻度往下走，
  **单调性成立**（`4xs`=9 < `3xs`=10 < `2xs`=11），因此 `cn()` 认它是字号组成员、
  不会掉进「不认识的 `text-<名字>` 被归进颜色组」那个坑（同 `2xs` / `3xs` 的立档理由）。
  与另两档同规：**不乘 `--font-scale`、不配 `--text-*-line-height`** —— 只出 font-size，
  与替换前的 9px 字面量逐像素相同。

## Changed

- 22 处 9px 的字面量全部并入 `text-4xs`（15 个文件）；字号棘轮 **67 → 49**。
  差的 4 枚是账目口径：那 4 处在注释里（`ui/badge` 的 `xs` 说明、`ui/list-badge` 的分工表），
  而棘轮走的是**剥注释**的扫描 —— 注释本来就不计数，所以只降 18。注释与规范正文同样改写成不成候选名
  的措辞，为的是**不再新增出处**（`docs/**`、`tests/**`、`changelog.d/**` 都在 Tailwind 的源扫描面内，
  口径见契约 §Colors 那条扫描边界）。⚠️ 但产物里那条 9px 字面量规则**并不会因此消失**：编译对账实测
  它仍由三份历史碎片（`0-pr4-badge-family` / `1811-message-center-font-tier` /
  `716-workflow-library-header-and-list-condense`）点名留着 —— 碎片是账本，契约明令不改写，
  所以这一条落在「已接受的代价」那一格，**别把它报成「已清零」**。
- 判据侧不用改逻辑：第 3 刀那条「字面 px 等于具名档当前渲染值就红」的对称判据**自动**把 9px
  纳入射程（档表现读自 `globals.css`），以后谁再写 9px 的字面量就是红。量具自验那份名单因此
  多一颗 `[9, "4xs"]`。
- 顺带把 `docs/DESIGN.md` 微标签那节的两处 11px / 10px 完整候选名改成不成形的写法
  （它们正是「源码没有、产物却有」的那一类），并补上第三档的行。
