## Fixed

- **对外参数卡片连着线了：端点不再是点不动的装饰（ISSUE #355）**。用户点卡片右侧那颗圆点拉线，指针旁直接出现禁用标记，线拉不出来。三个成因都是「把能不能连线绑定在了别的东西上」：

  - **卡片节点被标成不可连接**。React Flow 的 `<Handle>` 把「这一端能不能拉线 / 能不能落线」算作 `handle.connectable && handle.connectableend`，而 `handle.connectable` 取自**宿主节点**的 `node.connectable || nodesConnectable`。卡片节点上写死 `connectable: false`（原意只是「卡片自己不可拖、不发起图连线」），于是每颗圆点都是手不可点的装饰。现在卡片端点显式授权到卡片自己身上，节点属性将来若被改回 false 也仍然连得上。
  - **连线闸门把「模式」当成硬条件**。这个闸门会被 React Flow 在连线过程中反复调用（预判悬停处能不能落线），锁模式等于「手势在连线画出来之前就被判非法」——指针旁立刻出现禁用标记。模式只决定这条线**归属哪个命名空间**，不决定拖线本身是否成立；「没有模式就不能连线」不再靠藏掉端点实现，而由写入路径处理（没有模式时写入是空操作）。
  - **端点画在一颗落不上去的句柄上**。候选端点此前直接取条目里的全部端口，而画布上组合参数已折叠成逐行参数、行是否可见取决于渲染态。现在宿主节点渲染时把「这一帧真的画出来的落点行」上报给编辑器（按节点归拢，卸载即撤回），候选端点与它取交 —— 画得出端点的地方一定连得上。

  顺带把卡片页脚补成一句话，说清这个口现在是「默认连线」还是「你改过的线」，以及该怎么拖；一颗空圆点在三种状态（默认 / 改过 / 一个候选都落不上）下长得一模一样，只能靠点一下再猜。
