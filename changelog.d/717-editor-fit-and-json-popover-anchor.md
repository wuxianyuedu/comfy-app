## Fixed

- **打开工作流编辑画布后不再「没聚焦」**：自动聚焦此前用 `document.querySelector(".react-flow")` 量容器尺寸，而页面上**不止一个** React Flow（工作流库详情面板的画布预览就在同一个 DOM 里、文档顺序还在编辑器之前），于是编辑器拿库预览的 843×458 当作自己的 1295×772 去算居中，算出的视口落不到内容上（实测 `translate(-751, -465.75) scale(0.35)`，正确值 `translate(-525, -308.75)`）。现在容器尺寸取自 React Flow **本实例的 store**（`useStoreApi()` 的 `width` / `height`），天然实例私有。
- **打开时真正「看得见整份工作流」**：聚焦的缩放此前被一层写死的下限（0.35）挡住，6700px 宽的图缩到 0.35 倍仍有一大半在视口外 —— 用户打开后还得自己滚轮缩小。现在聚焦只受**画布设置里的** minZoom / maxZoom 约束（默认 0.15），下限交给用户自己定；想放大依旧可以滚轮，想一键回到内容处有右上角的「居中」。
- **点节点右上角 `#id` 芯片弹出的 JSON 浮层不再超出窗口**：浮层从自搓定位收拢到 `ui/dialog` 时（#672）丢掉了锚点定位 —— dialog 的 Popup 基类自带 `top-1/2 -translate-y-1/2`，调用处的 `top-24` 覆盖不掉它，两者叠加把浮层推到视口之上（实测 `top: -174`），头部（标题 / 复制 / 关闭）与 JSON 开头整片裁在窗口外。现在浮层走 `ui/popover`：用户点下时冻结的锚点矩形包成虚拟锚点交给 base-ui 的 Positioner，**翻转与视口内收边由它负责**（实测 1295×900 下浮层落在 170~710、820×560 下落在 164~500，四边都在视口内）；Esc / 关闭按钮 / 点浮层外三条关闭路径不变。`ui/popover` 新增可选的 `anchor` / `collisionPadding` / `sticky` / `positionerClassName` 透传（都是 Positioner 的通用能力，默认行为不变）。
