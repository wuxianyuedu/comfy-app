## Fixed

`tests/shell-gate.test.ts` 里「找不到 cargo 时要说得出探了哪几处」那一格，在**装过 rustup
的开发机**上恒红 —— 它判的是「候选全部没命中」那一支，却只注入了 `PATH` 与 `CARGO_HOME`，
而 `~/.cargo/bin` 与 `~/.rustup/toolchains` 那几处全从**家目录**派生（默认取 `os.homedir()`）。
于是「这台机器上有没有 `~/.rustup`」决定这条用例红不红，而它看起来完全像一条代码断言；
平台 runner 的服务账号下那个目录不存在，反倒恒绿 ⇒ 本地红 / 平台绿这种方向相反的组合。
根因是 #2376 加第三处候选时没同批改用例的输入面 —— 判据侧是对的。

改法：那一格注入一个空的 `home`（同文件里 rustup 那一族已经是这个写法），并**自证注入生效**——
断言 `probes` 里有一处的 `detail` 带着注入的家目录路径；少了这一句，在没装 rust 的机器上
把 `home` 改回默认照样绿，隔离的丢失又是静默的。断言消息位带上 `probes` 原值（#2287 那一族）。

口径落在规范 11 §11.10.4.1（新增一处来自环境的候选 ⇒ 同批补齐「全部没命中」那格的注入面），
**没有新写门禁**（§12.20）：静态扫会把同文件里刻意走真实宿主的 `findCargo()` 那两格误报成违规。
