## Added

- **CI 的落点也指到开发盘了**（自托管节点在 `G:\runner`，而它以 **systemprofile 服务账号**跑
  —— 于是「用户级环境变量」那一整套对 CI 一条都不生效）。节点从 `F:` 搬到 `G:` 之后，
  检出工作区 / pnpm store / 缓存槽三样已经在开发盘上，而**临时目录**与**浏览器落点**
  还留在系统盘那一侧（实测落点：`C:\Windows\System32\config\systemprofile\AppData\Local\`）。
  现在 `.cnb.yml` 的**流水线级** env 里加三行（`TEMP` / `TMP` / `PLAYWRIGHT_BROWSERS_PATH`），
  都指到开发盘。

  两条要点写进了判据与规范：

  - **必须写在流水线级，不能写在某一格的 `env:` 里** —— 浏览器装在 `每日浏览器安装` 那一格、
    跑在 `每日全量E2E` 那一格，两格必须看**同一个**落点；写在某一格里 ⇒ 那一格看得到、
    另一格看不到 ⇒ **装好了，探不到**（而「明明装过」与「一件都没有」在日志里原本逐字同形，
    本仓最贵的那类红）。
  - **临时根必须事先存在** —— 临时根不存在时 Node 的 `os.tmpdir()` 仍会把它当临时目录返回，
    于是第一笔写就 ENOENT，而日志里读不出「目录没了」。所以 `环境前提` 那一格会把它
    **补出来**（幂等，缺了才建）并打印读数；补不出来（权限拒绝 / 盘符不存在）才判红。

- **落点判据同批改**：生效落点扑空时，判据会再问一次平台默认根，答「装在 <默认根>，
  而运行时只看 <生效落点>」。⚠️ **判据本身一个字没放宽** —— 默认根里有、而生效落点里没有时
  仍然判不过（运行时只看生效落点，判过它才是假的）；这一问只改**读数说的是什么**。
  而「装」与「判」之所以还能是同一个落点，靠的是**落点推导只有一份实现**：
  新模块 `scripts/ci-toolchain-browser-root.mjs` 承担推导与「在落点下找那一件」，
  `scripts/ci-toolchain-browser.mjs` 从它取（那一族三个文件已在 900 行硬闸边上）。

- **缓存槽的配额有了读数**（`缓存槽读数` 那一格多打一行）：键数、配额、超额的几个、
  其中被 TTL 挡着的几个、空槽几个。此前淘汰只发生在执行档里，而日志上只有一句
  「淘汰 N 个·超配额但留着 M 个」—— 于是「现在到底有几个键、超额的那几个是被闸门挡着
  还是真淘汰了」在日志里读不出来，而这一问正是「键无上限」这句话的落点。

- **缓存槽淘汰补了一档零风险的回收**：**空壳**（没有产物、没有指纹、没有锁、目录 mtime
  过了 TTL）直接回收，且**不受配额约束** —— 空壳不是「一个槽」，它是崩在半路的安装留下的渣，
  既不好用也永远不会自己好起来。配套两条：**淘汰在「命中」那条路上也跑**（此前只在「装槽」
  那条路上跑 ⇒ 「不再新建键 ⇒ 旧键永不回收」），以及**配额与 TTL 的数字搬到读数那一侧**
  （`scripts/ci-cache-slot.mjs`）由执行档取 —— 漂了之后的表现是「读数说够、执行按另一份算」，
  而淘汰那一刀是**会删盘**的动作。

- **两份契约测试**：`tests/ci-dev-drive-root.test.ts`（落点三行的形状与落点推导的单一出处）、
  `tests/ci-cache-slot-quota.test.ts`（策略只有一处、命中那条路也跑淘汰、空壳那一档的
  三个条件缺一不可、读数答得出那几项）。

## Changed

- **`PLAYWRIGHT_BROWSERS_PATH` 的那条判据收窄了，但没收掉**（`tests/ci-image-identity.test.ts`）：
  从「`.cnb.yml` 里不许出现 `PLAYWRIGHT_BROWSERS_PATH`」改成「**不许指向容器那个路径**」
  （`/ms-playwright` 只在 Playwright 镜像里成立，在 Windows 宿主上不存在 —— 留着它等于让
  落点判据去一个空目录找东西）。覆盖本身又合法回来了：指向开发盘上**真实存在**的落点，
  与容器无关。形状那一半（三行必须在流水线级、`TEMP` 与 `TMP` 成对、三者同卷）由新契约测试判。

- **缓存槽的「策略常量」有了唯一的住处**：配额（`MAX_SLOT_KEYS`）、TTL（`SLOT_TTL_MS`）、
  邮票文件名与「读一个槽的现状」都住在读数那一侧，执行档 `ci-slot-apply.mjs` 从那里取
  （旧名字照旧转出，旧调用点不必跟着改）。同理，`.cnb.yml` 里那三行是**给这台自托管节点**写的
  —— 换节点要跟着换。

- **规范与指南同批补记**：§13.5.3.4.3 补上「键有没有上限」那一段与配套三件事，
  新增 §13.5.3.4.4「落点也要跟着搬」；`docs/guides/dev-drive-refs.md` 新增「CI 侧」
  一节（服务账号读的是机器级 env 与 `.cnb.yml` 的 env、不读用户 HKCU）。

## Fixed

- **「读不到邮票的键一律留着」那条判据的用例补上了产物树**：它原先造的是一个**空目录**，
  而空壳另有一档（没有产物、没有锁、目录 mtime 过了 TTL ⇒ 回收）—— 两者混在一起时，
  这条用例会因「目录刚好是新建的」而假绿。现在它造的是「**有产物却读不到邮票**」的键，
  判的正是它要说的那句话。

- **一条把「自由空间」当成常量的断言改成松判**（`tests/ci-slot-apply.test.ts`）：那条用例
  断言「从不存在的路径读到的自由空间，与从存在的目录读到的**逐字节相同**」—— 而自由空间是
  **会动的**卷级事实，两读之间卷上可能有别的进程在写（本仓自己的测试夹具就在写临时目录）。
  实测抖过一次（两次读差 240 KB），并发跑整档时必红。现在它钉的是「两个都读得到」
  （**这一条真正要钉的**：空转的成因就是 `null`）+「量级一致」。
