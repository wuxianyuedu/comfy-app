## Fixed

- **点启动页右上角 ✕ 放弃本次启动后，仍会弹一个红色「应用启动失败：启动进程 dev-launcher.ps1 提前退出（exit=0）」**：这条路径本来就是设计内的——壳在「启动页收到关闭请求、而主窗还没显示」时按约定直接 `exit(0)`（不留下看不见的壳进程，dev server 由启动器以壳退出为锚点回收），启动器也确实把子进程收干净了、日志写着「启动器正常退出」；但启动器监控线程的判据只有「还没交接就退出 = 失败」，于是把用户自己的取消动作报成了失败（退出码是 0，与正常收尾无从区分）。现在该分支先判「本次启动是否被用户放弃」——读壳 stderr 里的 `launch abandoned` 标记，命中则写 `cancelled` 状态、直接收尾，既不再弹失败弹窗也不再返回失败码。判据取日志标记而非新退出码，是因为**这一行旧壳同样会写**，用户此刻跑的往往正是上一轮编出来的壳（新退出码在旧壳里不存在）；真正的失败路径（编译失败、端口占用、壳起不来等）仍走原弹窗与 `exit=1`，不受影响。
