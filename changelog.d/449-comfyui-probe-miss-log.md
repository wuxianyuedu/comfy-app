## Changed

- **端口探测落空不再报 error、也不再刷屏（ISSUE #449）**：以前 `resolveComfyBase()` 把所有候选地址都探完还没人应答时记一条 `error`，文案是 `Cannot reach ComfyUI on :8188 or any of [8189, …]`——用户看到「ComfyUI 明明已经在 8188 跑着，启动日志却冒出 error」的第一反应就是「这里有故障」，而这条链路其实只认识「配置地址 + 就近偏移 + 窗口地址」这一批地址，实例落在别的端口时同样落空。现在改为 **warn** 汇总，并把「已经问过哪些地址」逐个写清（配置端口 / 偏移端口 / ComfyUI 窗口端口 8000），文案里明确「这不代表实例没在运行——运行判据见设置页状态行，实例若落在其它端口请改『端口』」。同时这批地址的汇总行按**地址清单**静默 60s：`_resolvedBase` 只在探到时才缓存（实例随时可能起来，不能把会话钉死在连不上的地址上），所以运行期每次提交 / 上传 / 状态轮询都会重扫一遍、各写一条内容完全相同的日志——现在同一批地址只保留第一条，检测链接口与设置页状态判定的行为不变。
- **端口探测的候选清单补上 ComfyUI 窗口端口 8000**：Comfy Desktop 同机常驻 `:8000`（打开查看用的 Web UI）。此前那台机器上配错实例时，应用会一路探到 `8193` 全落空、只留一条 error，却不去看已经开着的窗口地址；现在探测以此为最后一项兜底，命中时记一条 warn 说明「配置地址不可达，回落到窗口地址」。
