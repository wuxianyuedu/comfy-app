## Added

- **翻闸删掉的旗标有了「还在被人教着跑」的机器判据**（ISSUE #1811 收尾复审第三轮，
  `scripts/check-gate-flag-claims.cjs` + `tests/gate-flag-claims.test.ts`，11 条）。

  ISSUE #1811 把 18 条棘轮翻成硬闸，每条都删掉 `--update` / `--strict` 与那份基线。
  上一轮（#1845）人工 grep 一遍翻出 8 处「指向已删命令的话」，并把
  「翻闸时顺手 grep 旧旗标」写成一个**动作** —— 而动作没有执行者，下一批翻闸必然再漂。
  这一轮把**能证明的那一半**机器化，三格：

  - **用法块承诺 ⇄ 实现**：脚本头部注释块里教人跑自己那一行承诺了 `--update` /
    `--strict`，而实现里一个字都读不到；
  - **棘轮归类表的陈词 ⇄ 事实**：`tests/ratchet-update-guards.test.ts` 的表里点名一份
    基线 = 断言「拥有它的脚本今天仍带 `--update` 落盘通道」（基线名经现算翻成脚本名，
    不抄第二份对照表）；
  - **命令清单 / 红话字面量里的旧旗标**：`node scripts/<已翻闸脚本> --update` 出现在
    钩子、规范门禁清单、或字符串字面量里 —— 后一种正是 #1845 那处最重的现场
    （用户可见的阻断输出叫人跑一条自己会拒绝他的命令）。

  **判据面刻意等于翻闸的风险面，不做「全仓 grep 有没有出现这个词」**：实测把口径放成
  「用法块里提到的任何旗标都得在实现里读得到」，全仓报出 17 处、16 处是假红
  （`argv.indexOf("--x")` / `flags.has(名字)` / 位置透传）——「实现里读不到」与
  「这个旗标不存在」是两件事，而前者的读法有无穷多种。沿革叙述（「曾经带 `--update`、
  翻闸时删掉」）也刻意不判：它与「写错」在文本上同形，判它会误报一片，而
  **会误报的判据活不过一次评审**（§11.18.4）。剩下的那一半（散文、跨行的「注释块描述了
  一个相邻调用没传的旗标」）写清在案 —— 是真不可判，不是漏了。

  已接进 `.githooks/pre-commit` 的 D 组（实测 < 0.3s，零网络、零子进程）与 C 组固定清单
  （它读的是**别的文件的文本**，import 图一概追不到，而「改一份判据脚本的用法块」恰恰
  就是它要抓的那种改动）。规范侧新增 13 §13.5.16，并收窄 §11.25.1 那句
  「散文这一半没有机器判据」——不是全部不可判，是可分的那一半此前没被分出来。
