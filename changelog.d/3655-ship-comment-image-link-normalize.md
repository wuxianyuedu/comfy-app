## Fixed

- `pnpm ship --comment` 遇带图正文恒判红的假红修掉（#3655）：平台存评论时会把**上传图片**
  的相对链接改写成绝对地址（正文里是 `/-/imgs/issues/<id>/<key>/<file>.png`，落库后每张图
  被加上 `https://<host>/<组织>/<仓库>` 前缀，#3623 那条截图回帖实测四张图各差 39 字），
  而 `sameCommentBody` 的逐字比对没归一这一改写 ⇒ 「发出去的」与「回读回来的」在这类正文上
  必然不同，恒退 1 且文案让人以为评论没发出去（可能重投造成重复评论）。
  修法是比对前把两边「指向 `/-/imgs/` 资产的绝对地址」剥回相对形态再比
  （`ship-comment.mjs` 的 `normalizeImageAssetLinks`，对称归一）—— 只覆盖这一类
  **平台会改写**的形状，其余差异（含别的 URL）仍逐字比对，不放宽成「包含即算命中」。
  同族的 PR 正文回读比对（`ship-pr-body.mjs` 的 `writePullBody`，也认逐字）一并归一：
  `--pr-body-file` 的正文带图时吃到同一改写，不修就是下一个假红。
  §13.12（UI 改动要截图回帖到诉求单）落地后每条回帖都带图，这一格从此不再挡正常回帖。
