## Fixed

**`Install dependencies` 一格挂到平台硬上限时，日志里一个字都读不出来**（PR #2350 首跑现场：
`cnb-c6r-1k5osfdl8` 上这一格跑了 **8640s** 才被掐断，整格 19 行、pnpm 自己的输出一行都没有，
留下的只有 `timeout of 8640000ms exceeded`；而同机同链上一跑是 `Done in 2m 42.7s`，
同机四跑读数 169s~275s ⇒ 这不是「装得慢」，是挂住了）。它一挂，整条流水线判红、
后面三十格全部 `skipped`（`分支守卫` / `类型检查` / `受影响用例` 一个都没跑）。

挂住的形态里 pnpm 的 stdout 是空的（进度条只在 TTY 上输出），所以「卡住」与「还在跑」
在日志上逐字同形。**判据一字未改**，改的是拿不到结论时的收场方式：

- 装那一跳自带墙钟（新增 `scripts/ci-install-deadline.mjs`，默认 12 分钟 ≈ 平台上限的
  1/12、节点读数的 2.6~4.3 倍）。用尽就收回子进程、退 **2（未判定）**，并打印
  「卡在第几秒 / 下一动作是什么」—— 不是红也不是绿（§13.6.2 的三态口径）。
- 每 30s 一行心跳：同一个死法下一次读得出它在第几秒停住的。
- `.cnb.yml` 五格（`Install dependencies` / `每日安装依赖` / 三条 `单跑*·安装依赖`）
  补 `timeout: 20m`，让**自己的**预算先到而不是平台先掐断；它仍远小于 8640s，
  卡死形态二十分钟内报出来（不是「抬预算换绿」，§11.13）。

判据：`tests/ci-install-deadline.test.ts`（新增：跑完原样透出 / 预算用尽退 2 + 收子进程 +
下一动作 / 起不来归 2 / 预算与心跳的默认值与覆盖），`tests/ci-install-deps.test.ts`
与 `tests/no-platform-ci-config.test.ts`（三份副本逐字相同）跟着改。
