## Added

- **AGENTS.md 新增硬规则 29：发现任何问题当场建单，动手前先有自己的单**（ISSUE #2243）。
  会话 / 评审 / 排障里读到的缺陷 / 坑 / 不规范 / 可优化点 / 漏洞，一律用
  `pnpm ship --new-issue` 当场立案，**可以不马上处理**——「立案」与「处理」是两件事，
  排不排期由人决定，在不在账上不由人决定。动手做改动前，若这次改动没有对应的单，先建单再改。
- 规范 §13.10.9 同批扩了两格：把「先立案」从 `## Fixed` 那一类扩到一切「要解决某个问题」的改动
  （含新增能力与治理口径变更），并把 `changelog.d/0-` 那条无号出口收窄到**确实没有诉求单**的那一类
  （纯排版、纯机械跟随），不再等于「这次懒得立案」。project Skill 的单子那条边界同步这一方向。
- **这条不新增机器判据**：`ship` 阶段 0 念的「单子」那一行仍是读数、不参与退码。
  做成硬闸的直接后果不是「大家都立案」，而是为了让屏幕念出个号而随手挂一张别人开着的单子
  （§13.10.8 记的那次事故），所以它靠「看得见」承重，不靠「被拦下」。
