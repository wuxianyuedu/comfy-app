## Added

- **首页「模型概览」卡**（`src/components/studio/HomeModelOverview.tsx`，与「本机算力」卡并成一行）。它回答开工前的另一半问题：算力卡说「后端在不在线、还剩多少显存」，这张说「库里到底有没有能用的东西」。
  - 数据只吃现成的 `model.configList`（按目录计数），视图层零新增 IO（规范 §17）。
  - 三种「没有内容可展示」的状态各说各的话：**加载中**给骨架、**取数失败**给一句说明并保留进模型库的出口、**真的没有模型**给一句能照着做的指引（放哪儿、再点什么）。三者混成一句，用户就分不出「等一会儿」「去设置里看看」「先放文件再同步」这三种完全不同的处置。
  - 只列有模型的目录（按数量降序），但**用一句话交代有几个目录是空的** —— 全空时界面不能看起来像功能没做。超过 5 类折成「另有 N 类未列出」，不把首页撑长。
  - 刻意不复用 `useModelFolderConfig`：那个 controller 还挂着启用/停用/重新扫描/删除四个写动作与它们的忙碌位、搜索与筛选状态，首页只要一份只读计数（§12.18 说的是「有等价实现就 import」，这里是**更宽**的实现，不是等价的）。两者读同一条 tRPC 查询，按 key 去重，不多一路请求。
- **首页「继续最近项目」大卡**（`ResumeProjectCard`）。小卡栅格回答「我有哪些项目」，回到首页的人第一句通常是「我上次做到哪儿了」—— 前者要扫，后者要一键回去。左侧是缩略图条（一张图都没有时落回类别图标块，不留空洞），右侧是类别徽标 + 项目名 + 副信息 + 更新时间。
  - 更新时间前写「最近动过」而不是加工成更精确的口径：`updatedAt` 由上层给成什么样就是什么样。

## Changed

- **同一条项目不再在同一页出现两次**：大卡占掉第一个位置，栅格改为取第 2~4 个。
- **「画布项目进画布视图、其余进 `/create/{id}`」这条判别收成一处**（`openRecent`）。它此前内联在小卡的 `onClick` 里，大卡要复用就得再抄一遍 —— 而两个入口对同一个项目做出不同行为，是最难被发现的一类漂移。

## Tests

- 新增 17 条：推导纯函数 7 条（降序、空目录计数、`total` 与列出行同口径、`0` 与「没有这一档」分开、首帧是 loading 不是 error、错误文案由模块给而不接受调用方传 Error）、概览卡 6 条（三种无内容状态各一支、折叠与空目录的交代、失败时保留出口）、首页项目区 4 条（大卡与小卡不重复、两个入口同一条规则、无项目时不出大卡、只有一条时不重复）。
- **一处真实的软测试被负向验证抓出来并修好了**：第一版「两个入口同一条规则」的用例，把栅格的 `onClick` 改回自己写一遍三元式之后**四条全绿** —— 因为当时栅格里只有非画布项目，两种写法结果相同。改成在栅格里放一条画布项目后，同一处改动立刻红（`expected "vi.fn()" to be called with arguments: [ 'c2' ]`），复原复绿。
- 登记：两个新文件两处同批改（推导函数满档、卡片按实测取 90 分支）；薄接线的那个 hook 刻意不登记 —— 给一行转交设门槛，数字看着严格而实际什么都不守。
