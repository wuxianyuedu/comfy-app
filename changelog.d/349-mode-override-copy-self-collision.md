## Fixed

- **IO 预览：切换 seed 行为后参数名不再掉回槽位别名（ISSUE #349 三审）**。切一次「固定值 / 随机值」名字就变回 `value_1` —— 根因不在取名链，而在**撞名去重认错了自己**：行渲染时若该条目在当前模式有覆盖（seedMode / required），会把条目派生一份拷贝（`{...entry, seedMode}`），而 `ioLabel` 的「排除自己」用的是对象身份，拷贝与原件被当成「两个同名条目 → 回退原始 pin 名」，于是**每一行都跟自己撞名**，封装槽位的名字一律掉回 ComfyUI 自动编号的 `value_1`。这解释了全部现象：另一模式没有覆盖所以正常、取消勾选再勾选因为库里的 modes 还在所以照旧、与「模式无关」并不矛盾。现在「同一个 pin」按对象身份 → `ioKey` → `节点 + 方向 + 槽位名` 三级判定，派生拷贝一律认作自己；真正的撞名（两个 pin 同名）保持原有回退行为，但**区分标记绝不再使用机器别名**：封装槽位的 `value_1` / 裸序号改用宿主节点标题（`Seed · Checkpoint settings`），连标题都没有时保留作者命名，不把平台编号产物当名字显示。
