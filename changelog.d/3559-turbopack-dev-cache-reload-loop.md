## Fixed

- 修复「启动后界面不断切换」（#3559）：页面每 ~2.3s 被整页硬重载一次（app-runtime 日志 `界面打开：首页` 每 2.1~3.0s 一条、dev server 每 cycle 打 `GET /workspace 200` + `✓ Compiled`、任务栏图标随每次加载完成闪烁），根因是 **Next 16.4.3 默认开启的 Turbopack dev 持久缓存（`turbopackFileSystemCacheForDev`，config-shared.js L293）与 turbopack-subscribe 的 hmrVersion 校验（上游 #97966 引入）组合出的整页 reload 死循环**：持久缓存恢复后主 client 入口 chunk list 首条消息为 restart，推送使服务端 `clientHmrVersion` 自增；页面随后发出的 `turbopack-subscribe` 携带构建时刻的旧版本，服务端判 mismatch 直接回 `RELOAD_PAGE`（hot-reloader-turbopack.js turbopack-subscribe 分支），客户端静默 `window.location.reload()`——新页面自己的路由请求又 bump 版本，下一轮订阅再次过期，无限循环。浏览器 console 零报错、无 CSP/ChunkLoadError，故长时间未被定位；壳侧 localhost/127.0.0.1 导航链路排查后确认与本环无关（`url_reachable` 走 std 全地址遍历能连通，`navigate_when_ready`/splash 3s 节流均被时序排除）。修复：`next.config.js` 显式设 `experimental.turbopackFileSystemCacheForDev: false`（上游 vercel/next.js #100267 记录的官方规避手段；代价是放弃 dev 暖启动编译缓存，上游修复后删除该行即回退）。新增 `scripts/verify-next-config-turbopack-cache.test.mjs` 契约测试钉住该键，防止未来被误删或回退。
