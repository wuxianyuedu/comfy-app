## Fixed

- **页签条的「当前页」在桌面壳里看不出来（用户直接指出）。** 标题行形态下选中态给的是 `bg-canvas/70`（iframe 页签给 `bg-canvas` + `text-ink-bright`），而暗色下 `--color-canvas` 是 `#0a0a0f`、标题行的底是 `--color-panel-deep` `#0f0f16` —— **选中比底还暗**，与未选中只差一档文字色，肉眼读不出哪张是当前页。
  - 现在选中态同时走两条通道：更亮的表面（`--color-surface`）+ 顶部一条 2px 品牌色条。只靠背景深浅在暗色下曾经不够，这是实测出来的结论，不是审美偏好。
  - 收成一个工具类 `.u-tab-active`，由「应用内视图页签」与「iframe 外部页签」**共用**：这两类页签并列在同一条标题行横条里（#1324 决策 ④(a)），选中态各长一张脸就是漂移。两处顺带补上 `relative`（色条是伪元素，要有定位祖先），并去掉原先基串里与选中态打架的 `text-ink-strong`。

## Changed

- 品牌渐变的**组成**收成一个 token `--gradient-brand`（三段 stop 的唯一一份排法）。此前它只活在 `.btn-gradient` 里，页签色条要用就得在第二处重抄一遍三个 stop —— 改一次品牌色就有一处跟不上。`.btn-gradient` 现在取这个 token，观感不变。
- 白名单登记 `--gradient-` 前缀（它不是颜色别名、也不属 `--color-` 家族，是「组成」）。同时去掉 `--container-` 被登记两次的重复行 —— 同一前缀留一条带理由的即可。

## Tests

- **补的是一条一直没人在管的洞**：页签的既有断言全部只看 `aria-selected`，于是「选中态比底还暗」这种问题**全绿通过** —— 无障碍语义是对的，眼睛读不出来。规范 §11.8 的口径正是这类事要读计算样式。
- 新增真浏览器判据：开第二页让场上同时有选中与未选中，两态各判一次 —— 选中页签的 `backgroundColor` 必须不同于未选中、`::after` 的 `height` 必须是 `2px` 且 `background-image` 含 `linear-gradient`，未选中的那条伪元素 `content` 必须是 `none`（否则当前态不再唯一）。
- 新增源码级判据 3 条：两个页签组件的 active 分支都只走 `.u-tab-active`、**不许在选中分支里自己写背景类**（那正是当初的形状），以及 `.u-tab-active` 不是空类（真的给了 surface 背景 + 一条取 `--gradient-brand` 的 2px 色条）。放源码上是因为**壳内形态在浏览器/dev 下不存在、e2e 走不到**，而缺陷恰好只在那条路径上。
- 反向验证做了实物证：把 `.u-tab-active` 改回「与未选中同底 + 色条高度 0」→ e2e 红在「暗色：选中页签的背景与未选中相同 = 没有可见的当前态」，源码判据红在「不是空类」那条。改回后两条都绿。
- 另核一件事：手写的 `.u-tab-active` 确实活到了编译产物里（读 Tailwind 真编的 CSS 命中该类与 `::after`）—— 源码判据只证明声明在场，不证明没被层/树摇掉。

## Notes

- 浅色态下这一改同样是「更亮表面 + 色条」：`--color-surface` 浅 `#ffffff` 对 `--color-panel-deep` 浅 `#f0f1f5`，与暗色同构，不是各写一套。
