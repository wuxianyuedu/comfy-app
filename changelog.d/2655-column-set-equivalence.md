## Fixed

- **`db:migrate ⇄ db:push` 的等价判据不再把「列的物理顺序」当成不等价**（ISSUE #2655，
  主干恒红的那一条）。`tests/db-migrate-equivalence.test.ts` 的「逐表逐列」把一张表的列
  拼成**有序串**再比，而两条建库路在机制上就产不出同一个顺序：`db:migrate` 给已存在的表补
  新列只能走 `ALTER TABLE … ADD COLUMN`（**追加在表尾**），`db:push` 按
  `src/server/db/schema.ts` 的声明序建表。于是 `production` / `task` / `workshopSession`
  这三张「刚被补过列」的表**列集相同、顺序不同**，判据报「迁移生成物与 schema.ts 漂开了」。
- **撤掉的只有一维，四维一个没动**：比较改成 `diffColumns` 的**列集**比对，每个 token 仍是
  `名:类型 [NOT NULL] [PK]` —— 名称 / 类型 / NOT NULL / 主键都在这一个串里；报的也是
  「migrate 侧缺哪几列 / push 侧缺哪几列」而不是「两个长串不相等」，读者一眼看得出少的是哪列。
- **放松那一维是否真的无损，由两条新用例自证**（少了它们，这一改就只是「把比较面改松让红消失」，
  而 `## Fixed` 那一类改动不许走这条路，§13.10.9）：
  ① `比较器本体` —— 构造样本钉「少列 / 换类型 / 丢 NOT NULL / 丢 PK 照样报」，
  而同一批 token 换序**不报**；
  ② `同一行数据在两个库里按名取回逐字段一致` —— 往两个库各插同一行，**各按自己的物理列序**
  `SELECT`，再按列名归一后比串；这条同时当场断言「两边列序确实不同」，否则它自己就是空对空。
  （取样时 `PRAGMA foreign_keys=OFF`：`node:sqlite` 默认开着外键，而这行孤立数据的引用列
  在临时库里没有对应行 —— 本格判的是列的读取，不是约束；且只动临时库。）
- **没有**去改 `drizzle/` 里的迁移凑顺序：版本化迁移的含义就是按时间累积 DDL，
  为了让判据舒服而把 `ADD COLUMN` 换成重建表，动的是出厂件。
