## Changed

- **代码索引不再常驻两份文档正文**（ISSUE #2761，规范 §12.20）：索引器吃的是自己那份
  `.qoderignore`，而它此前在 `docs/` 下只排了一条 `/docs/api/` —— 于是 38 份 `docs/generated/**`
  生成态镜像（与 `docs/standards/**` 逐字重复：13/18/12 章各只差文件头那行自动生成 banner，
  `diff` 实测 3 行）与 2.85 MB 的 `CHANGELOG-archive.md` 全量进索引，**任何一次文档检索都命中两份**，
  语义检索还会把同一句话的两份当成两个证据。新增一组「入库文字里刻意只出索引的那几份」：
  `/docs/generated/` + `/CHANGELOG-archive.md` 各带一句 `why`。
- **判据一条没动，动的只有扫描面**：镜像仍入库、仍给人读、仍由 D0 的
  `check-doc-mirror-pairing.cjs` 判「源 ⇄ 镜像同批」、`pnpm run doc:render` 与平台那两格照旧；
  `.qoderignore` 只被索引器读，门禁读的是 git 清单与源码树。归档的检索出口跟着改口径 ——
  查一条历史变更走 `grep`/`git`，`changelog.d/README.md` 与 `README.md` 那两行同批写清。
- **顺手修掉一处会推翻自己的头注**：`.qoderignore` 原先自称「这里列的目录本来也都被 `.gitignore`
  忽略着」——那句话在只有构建产物那几组时是真的，而它失效的方式很坏：读者拿它当结论，看到一条
  git 跟踪的路径被排除就判成漏配、把那条删掉（索引随即贵回去）。现改为显式回答「入库但只出索引」，
  并由两条新用例钉住：头注不许再出现那句自称、以及这一组里那两条**确实被 git 跟踪**
  （哪天镜像出库或归档被拆走，这条排除就该整条删掉，而不是留一句过期的理由占着排除面）。
- `MUST_COVER` 同批加这两条（一致判据只证「同步」、这条证「够宽」：谁把这一组删一半，
  盘上那份跟着删一半，「逐字相同」那条照样绿）。
