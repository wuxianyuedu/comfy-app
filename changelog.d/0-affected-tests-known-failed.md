## Changed

- **增量测试层跳过「已知基线红」，但把跳过打印出来**（`scripts/affected-tests.mjs` +
  `scripts/quality-gate-shared.mjs`，规范 §13.5.8 / §11.12）：沿 import 闭包解析时会把
  **别线**在 master 上本来就红的文件拉进面前，于是一笔无关改动被别人的红拦住 —— 第一次
  真撞上就是这次（改 `src/server/db.ts` 时解析出 111 个用例，其中壳线那两条红把提交挡下）。
  处理方式是复用既有机制，不另立第二份清单：`KNOWN_FAILED_FILES`（与 `run-tests.mjs` /
  一键质量门禁同一份，`check-ps1-consistency` 守着它只许单点定义）里的文件**只从增量面
  剔除**，钩子的 stderr 打印「跳过 N 个（+清单在哪）」，**固定清单不参与剔除**（那几条是
  全库不变量的唯一执行者）。清单从空变成 5 项，逐项写明归属与「别处更强的执行者」：
  壳（`check-file-structure` 两条：启动页副本漂移 + 陈旧壳回收，硬规则本体仍由 D 组的
  `check-file-structure.cjs` 每次执行）、启动器 2（形态探测与本机 pnpm shim 相关）、
  产物 1（读真 `.next`，缺一条 `node_modules/**/docs/**` 的 excludes）、主题 1（裸自定义
  属性白名单）。**粒度是文件**，一条红会连同一文件里其他断言一起放行 —— 这笔账写在清单
  注释与规范里，修好后立刻删登记（留着 = 永久静默跳过）。
  用例 +2：剔除只作用于增量面、固定清单不被剔除；另加一条漂移守卫 —— 登记的每个路径
  必须真实存在（写错路径 = 这一条永远命中不了，挡的东西悄悄放行，而清单看着还在）。
