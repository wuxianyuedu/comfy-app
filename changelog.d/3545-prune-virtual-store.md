## Added

- 新增 `pnpm deps:prune`（`scripts/prune-virtual-store.mjs`）：清掉 `node_modules/.pnpm/` 里**已不在当前依赖图**的条目目录。#3545 的现场是移掉依赖后 pnpm 不回收虚拟 store 的目录，`pnpm store prune` 只管全局内容寻址 store、`pnpm prune` 只管 `package.json` 里没声明的依赖，唯一的清法曾是手工 `rm -rf <条目>` 或整棵删掉 `node_modules` 重装（后者实测 5 分钟量级，还会带走常驻的 dev server）。现在这条动作有名字了：`pnpm deps:prune --dry-run` 先看清单，确认后 `pnpm deps:prune` 收掉。
- 权威源沿用 `scripts/lockfile/lock-diff.mjs` 的 `parseLockfile()` 读 `pnpm-lock.yaml` 的 `packages` 段（与 #3523 判据同一份解析，不另写 YAML 解析器）。**身份的主来源是条目自己的 `package.json`**：pnpm 12 会把带长 peer 串的目录名截断成 `…_<hash>`（本机 209 个），有的连 `@<version>` 都被切掉，只靠目录名会把它们全判成「判不准」；目录名只在能归一出 `name@version` 时做二次校验，两者对不上就判不准不删。安全栏：图内条目一律跳过、`.pnpm/node_modules` 一律不碰、只读得懂的目录与非符号链接才动、删除目标递归前再校验一次仍在 `.pnpm` 之下、删不掉的逐条报并给出口、三态退出码 `0` 收干净 / `1` 有事实是红的（删不掉 / 图读不到 / 判不准）/ `2` 用法错或前置不成立。
- 登记面同批跟上：`package.json` 脚本、`README.md` 常用脚本、`docs/standards/launch-and-build.md` §9.5 跨平台动作对照表及其 `docs/generated/` 镜像（`check-ps1-consistency.mjs` 已通过）；`scripts/check-allow-builds.cjs` 的 `printOrphans()` 不再让人手工删目录，改成先 `--dry-run` 再收掉。新增 `tests/prune-virtual-store.test.ts` 12 条用例，覆盖 `--dry-run` 只列不删、只删残留、hoisted 虚拟目录不碰、pnpm 12 截断哈希目录、peer 后缀与包名里的下划线、目录名与 `package.json` 身份不一致、`package.json` 读不到 / 不合法 / 缺身份 / 一目录两身份、依赖图读不到、前置与用法三态。
- 本机 `--dry-run` 读数：虚拟 store 条目 1385 个 · 图内 1077 · 残留 308（约 29 MB）· 判不准 0；另核对过 `snapshots` 段的 1385 个键其基身份全部落在 `packages` 段内，且 669 条 hoisted / 顶层符号链接**没有一条**指向被判为残留的目录。本次只跑 `--dry-run`，**没有对真实 `node_modules` 执行删除**；要收掉本机这 308 个残留，请自行确认清单后跑 `pnpm deps:prune`。
