## Added

- **设置页「启动日志」的下拉支持跨包翻转**（ISSUE #1326，用户原话：「保留跨包翻转」）：列表 = **本次运行**（`log/current/services/` 下该来源的份，恒在最前）+ 各**历史运行包**（`log/runs/<日期>_<时分秒>-<runId>/services/`）里的份，新→旧。此前只列 `current/` 那一处 —— 前一次运行的份被归档进 `runs/` 之后**没有任何界面能打开**，用户只能自己去文件管理器里翻。列表项文案 `09-30 19:36:12 · 正常退出 · a1b2c3`：时刻（同一次运行里多次启动的份只有它分得开）、退出形态（崩溃那次的日志末尾是断的，先标出来才知道在看什么）、runId（跨包 `grep <runId>` 的唯一入口）。

- **跨包这一层一条减法都没加回来**：`#1537` 把四份 runtime 日志改成「一次启动一份文件」之后，正文不再需要任何切分判据（「文件是谁」不依赖任何假设）—— 归档是整目录复制，**包内结构与 `current/` 逐字同构**，所以跨包就是「把各包里的文件排成一条时间线」，与包内那层用同一份判据。这正是当初删掉「正文 = 当前包 − 前一包」那套长度减法的红利：`runSlice` / `baselineMissing` / `log-run-sessions` 一个都不需要复活。

## Fixed

- **同一秒内多次启动的份顺序被读反**：文件命名是 `comfyui-runtime-20261005-093612.log` 与 `…-093612-2.log`，而 `.`（码位 46）比 `-`（45）大一位 —— **按名字比会把第二份排到第一份前面**。原先两处（`current/` 与包内）各自 `sort`，先按时刻、同时刻时按名字，正好踩这个坑；而「启动 → 秒退 → 再启动」在本仓库很常见（端口被占、依赖缺失、连点两下），那两份的顺序被读反意味着用户看到的「第一次的失败现场」其实是第二次的。
  - 顺序判据收进 `runtime-log-file.ts` 的 `compareRuntimeLogFiles`（三级：旧固定名最前 → 时刻升序 → **同秒按序号升序**），`current/` 与包内共用同一份 —— 两边各写一遍必然漂，而漂开的表现只是「某些项顺序不对」，不容易被注意到（§12.18 复用优先）。

- **「新一次启动自动切过去」永远切到最旧那一份**：`use-runtime-log-source` 读的是 `sessions[sessions.length - 1]`，而契约（`LogSessionMeta` 的注释、端点的 `selectedId` 缺省值）都是 `sessions[0]` 才是最新。跨包之后列表变长了，这个反向只会更明显 —— 现在取 `sessions[0]`，并把方向在契约注释里写死（列表方向只在契约里定义一次）。

- **会话 id 带包名**（`<包名>/<文件名>`）：两个包里可能同时存在同名文件（同一秒内两次启动的 `-2`、迁移前的旧固定名），不带包名会撞成一个 id。端点只接受两种已登记形态（裸文件名 / 包内相对路径），其余（含 `..` 一类穿越形态）一律回落最新那一份 —— 客户端缓存过脏 id 时不许拿它去拼路径。
