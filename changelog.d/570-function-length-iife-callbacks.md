## Changed

- **函数长度门禁纳入无名字的块体（IIFE / 回调 / 闭包）与跨行签名（ISSUE #570 第 7 项，
  规范 §12.13.2）**：`scripts/check-function-length.cjs` 此前只认「有名字的声明」，
  于是**把超长逻辑塞进 IIFE 或回调里能整条绕过门禁** —— 真实实例是
  `lib/comfyui/lifecycle.ts` 的 `ensureComfyUiReady`：外层 405 行能被抓住，它内部那个
  **288 行的 IIFE**（`st.starting = (async () => {…})()`）完全隐形，而让这个函数不可读、
  不可测的正是那 288 行。现在 `=> {` 与无名字的 `function (…) {` 走同一阈值、同一棘轮；
  长度从**声明行**算起；具名与匿名嵌套时**两条都报**（拆法不同：外层切分支、内层提具名）；
  字符串 / 模板 / 注释里的 `=>` 与 `function` 先剥离，大对象字面量不误报。
- **同一判据顺带补掉另一个静默漏报**：原正则要求「名字 + 同一行的 `(`」，因此**签名跨行
  的具名函数也看不见** —— `WorkflowSubgraphNode`（638 行，`React.memo(function …)` 包装）
  与 `GlobalStepLogPanel`（454 行）就是这样一路合法存在的。新判据按「声明行 → 配平后的
  函数体 `{`」定位，两者都在射程内。
- **棘轮基线新增「判据版本」，不许被静默放宽**：基线与脚本各带 `RULE_VERSION`，只有判据
  本身变了才允许 `--update` 一次性重记，其余情况数字只许下降（拒绝时给出「先改常数」的
  指引）。判据变更后未重记的基线会被直接拦下 —— 旧数字与新计数不是同一个量。
  本次按版本变更重记一次：**20 → 22**（新增的 2 条即上面那两个存量跨行签名组件，已登记进
  §12.13 的拆分清单）。
- **规范 §12.13.2「回调体与 IIFE 同受约束」（ISSUE #570 第 8 项）**：写明判据、给出两类
  超长块体的推荐拆法 —— 同构等待循环收敛为**接受策略对象的一个函数**（`wait` / `isDead`
  作为参数，重复的错误文案收敛到一处）、事件回调抽为**导出的具名纯函数**（把 `st` /
  `recentLog` 等宿主状态显式传参，从而可在测试里直接调用）。§12.13 的阈值表与 §18.1 /
  §18.5 / §18.7 的登记项同步；`tests/check-function-length.test.ts` 增 10 例（IIFE / 回调 /
  闭包参数 / 大对象字面量不误报 / 注释与模板不误报 / 判据版本三态）。

## Added
