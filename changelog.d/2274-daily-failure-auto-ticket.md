## Added

- **每日那一跑真失败时，自动立案的执行者上线了**（ISSUE #2274）：`.cnb.yml` 的每日链新增第一格
  `每日失败立案` → `node scripts/ci-daily-failure-issue.mjs --no-block`（`timeout: 5m`）。
  在此之前，「夜里那一跑红了」这件事只有一个**要有人跑才出结论**的判据
  （`pnpm check:daily-attendance` 按 §13.5.13 的口径自己不发网络请求）—— 没人问就等于没发生：
  现场 `cnb-8r8-1k5knrl91`（2026-10-23T16:00:17Z）红在 `每日生产构建`，四十分钟账上无单，
  而它一红就带下去四格 `skipped`，其中 `每日单元测试` / `每日全量E2E` 的唯一执行者就在这条链上
  （§13.5.21）⇒ 一天红 = 主干一天没有行为面读数，而账面全绿。
- **判决链一个字没另立**：取数复用 `fetchRecentBuilds()` / `isDailyDispatch()` /
  `fetchDailyDetails()`，定性复用 `classifyBuildOutcome()`，被带下去的格复用
  `downstreamSkipped()`，失败行摘录复用 `describeFailedStages()`（与 `pnpm ship --diagnose`
  同一条链），写单复用 `runNewIssue()`（建 → 补 `提单人:` → **独立回读**），执行身份复用
  `gitUser()`。本档只新增两件事：**「哪一跑算上一跑」**（排除此刻正在跑的那一跑 —— 它恰好是
  列表里最新那条，没有终态）与**「同一格不许天天建一张」**（去重键 = 标题里
  `ci(daily): 每日档红在「<格名>」` 那一串，不是标签 —— 动态标签词表要先在平台侧存在才落得下来，
  而加一枚没人筛的标签就是 §11.23 的「写了没有读者」）。人工按 §13.5.4 写的那张单只要带同一串
  前缀就自动进这一族、被同一套去重接住（#2273 就是这么并进来的）。
- **机器只报事实，不代写因果**：正文 = 症状 / 当场读数 / 出处 / 出口，并明写「根因未判定」，
  定性仍走 `--diagnose` 与 `base-check`。把判断自动化正是 §13.5.4 与 #2149 否掉过的形状。
- **两个反直觉的位置决定，都由判据钉住**：① 它必须排在**最前**（判的是上一跑；写在任何红格之后
  就会被那次红一起 `skipped`，而平台没有可依赖的条件语法 —— 本仓 `.cnb.yml` 今天只有 `ifModify`）；
  ② `--no-block` 把这一格自己的非零落成退 0，**但话术一句不少**：它坏掉时拦路等于用「后面四格
  没有读数」换「红被承认」，而那四格是每天唯一的执行者。本地不带这个旗标，照旧 0/1/2 三态。
- 新增用例 `tests/ci-daily-failure-issue.test.ts` 19 条（含真起进程跑生产入口：离线档强制只读、
  `--no-block` 的退码与话术同场、五种「不该写」的情形）；`tests/no-platform-ci-config.test.ts`
  同批加一条「每日链必须有一格点的是这个入口且排在最前」（名字还在、块被换成别的命令 ⇒ 那种绿
  不认，与「撤档 ≠ 撤账」同一族）。口径落在规范 §13.5.23 末节。
- ⚠️ 一处**未核**的外部前提：节点执行身份有没有建单权限。这一格不会因此把链拖红，但会在日志里
  念一句红话并给出粘贴命令 ⇒ 第一次每日档跑完要看一眼那一格；没权限就去补权限，
  **不要**把它改成「静默跳过当作没问题」。
