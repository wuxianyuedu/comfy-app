## Fixed

- **`dev-drive-probe.mjs` 不再硬拼 `.git`，改问 `git-dir.mjs`**（ISSUE #2072 那道闸的红，
  落在 master 上由平台 PR 的「受影响用例」那一格第一次爆出来）。
  `probeWorkdirs()` 里那份名单第五项是 `path.join(ROOT, ".git")` —— 在**链接工作树**里 `.git`
  是个文件而不是目录，于是探针报的是一个看起来存在、其实没有 `HEAD` / `MERGE_HEAD` 的落点，
  而它下面那句「真实落点（软链接要解开再判）」恰恰是这件事的判据该说反的地方。
  现在目标路径由 `resolveGitDir(ROOT)` 给；**解析不出就不出一条**，而不是拿名义路径假装量到了
  （消费侧只读 `exists` / `sameVolume`，少一条不影响 `workdirLever` 的 `na` 分支）。
- 顺手把那段逐项构造抽成 `workdirEntry()`（四条名义目录与 git 那一条同一个口径，不重抄）。
- ⚠️ 这条红**不在引入它的那条线上**：闸（#2072）与被判的文件（开发盘红利那批工具）是两笔
  各自合进 master 的提交，squash 合并都不跑本地钩子，所以从落地那一刻起**任何 PR 的
  「受影响用例」都会带上它**。修它的动作因此与两份改动都无关 —— 记在这里是为了下次有人
  问「为什么 master 上是红的」时有一句真话可查。
