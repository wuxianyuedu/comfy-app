## Added

- **桌包档不再在构建期现下 NSIS 工具：`scripts/tauri-tools-cache.mjs` + 清单里新增的
  `打包·桌包工具预置` 那一格（ISSUE #2525）**。

  补的是那条链上唯一一格「判据在场、执行者不在场」的东西：nsis 打包段要两件 GitHub release
  资产，而 bundler 的下载预算实测在 **22–23s**，本机直连取那份 2,363,925 B 的 zip 要 **48.4s**
  ⇒ 红的是网络，读数长得却像链坏了。官方镜像键实测把 zip 压到 **29.5s**（两份资产的 sha256 与
  直连逐字同值），**仍在那条预算之上**，所以配镜像不是结案。

  落法是一个**有名字的入口**（§12.20）：工具树按内容镜像在常驻根的第四个目录
  （`resolveToolRoot` ⇒ `<卷>\ci-tools\<包名>`，盘符照旧由 `pnpm store path` 推导；与两份缓存槽
  分开是必须的 —— 那里的淘汰器按 TTL 删键位，而这一份删了今天就没包）。本机 `--seed` 种一次，
  作业起手那一格 `ensure` 补齐：**已在场就一个字都不动**，拷过去之后**逐件复算哈希**，
  两边都没有就退 **2「没有结论」**并念出出口 —— 绝不放行给 bundler 去撞那条预算。
  `NSIS_PLAN` 里那两个哈希是钉死的：tauri 升 NSIS 版本时红的是「该升镜像」这句话，
  而不是又一次「今天取不到工具」。

  读数（2026-10-27 本机，删空缓存 → `ensure` → 只出 nsis 打一次包）：补齐 **2.5s**（442 件·6.8 MiB
  含逐件复算）⇒ `Running makensis` 6.0s ⇒ `Finished 1 bundle … (62.32 MiB)` 137.8s，
  打包段 **131.8s**、退 0，日志里没有 `Downloading` / `Recreating it` / `timeout: global`。
