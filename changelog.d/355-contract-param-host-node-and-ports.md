## Fixed

- **对外参数卡片与端点终于出现在编辑器画布上（ISSUE #355）**。五条反馈里有三条同源：对外参数条目改成**契约驱动**之后，条目的 `id` 是 `prompt` / `size`（与工作流无关）、`nodeId` 是空串 —— 而画布各处仍读 `nodeId`：

  - `placeParamNodes` 查 `hostPosById[""]` 查不到宿主坐标 → **一张卡片都渲染不出来**，画布上根本没有端点可以拖（「还是无法手动编辑端点连线」）；
  - `buildParamEdges` 的 `target` 写成空串、`sourceHandle` 写死 `pio-out` —— 两端 handle 都不存在，React Flow 直接丢弃边（「只看到默认连线，但线没有连接到端点上」）；
  - `isValidParamConnection` 拿空串与真实节点 id 比较 → 闸门对每一次拖拽都返回 false（「无法手动编辑端点连线」）。

  现在条目自带 `hostNodeId`（从候选端口派生，落点所在节点优先），卡片位置 / 映射线宿主端 / 连线闸门统一走它。连线的源端点也改为**当前落点那一颗**（卡片上每个候选一颗 `<Handle>`，id 就是 ioKey）。

- **「尺寸」不再只有一个出口：比例 / 像素 / 倍数各一颗端点（ISSUE #355）**。两处叠加：① `paramOutputPorts` 在有落点时只返回**一颗**端口，其余候选连端点都没有；② 对齐倍数（`multiple` / `倍数`）被判成 `other`，压根没进「尺寸」的候选。现在候选端口**始终全量列出**，当前落点那一颗标实心（拖任一颗即可改落点）；`multiple` / `倍率` / `对齐倍数` 归入尺寸语义，与比例、像素并列。三张口的类型各自取自端口自身声明（`aspect_ratio` COMBO、`megapixels` FLOAT、`multiple` INT）。

- **对外参数卡片去掉重复的那一段（ISSUE #355 复审）**。卡片此前既列「输入端口行」（`text  STRING`）又列「输出端口行」（`text  STRING  ●`）—— 同一批端口说两遍，用户圈出来要求去掉。现在卡片体只有输出端口这一段：**一行 = 端点 + 参数名 + 类型**，与用户给的示意图一致。卡片几何随之只计入头部 + 输出端口区。

- **收尾**：卡片不再列输入端口行之后，`workflow-param-input-rows` 整个模块（输入行派生 / 组合控件 handle id）成了死代码，一并删除；组合控件仍按「逐行参数」渲染，落点锚点直接用 ioKey。

- **工作流库的只读连线真的落在端点圆点上（ISSUE #355）**。线终点此前按「宿主行左沿 + 整行中线」量，而折叠成逐行参数后一行是「标签行 + 控件行」两段结构、圆点锁在标签行中线上 —— 线因此停在圆心下方十几像素处。端点圆点现在带 `data-port-dot`，连线优先量它的**圆心**。
