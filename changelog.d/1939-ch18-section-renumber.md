## Changed

- **`docs/standards/18-lib层规范.md` 的节号重排正序，全库 `§18.x` 引用与生成物同批跟改**（ISSUE #1939）。
  此前该章节号出现顺序是 `18.1…18.8 → 18.10 → 18.11 → 18.13 → 18.14 → 18.15 → 18.12`，
  三类确定性缺陷：**没有 §18.9**（18.8 之后直接跳）、**§18.12 的位置本该在 18.11 与 18.13 之间
  却被排到文末**、**文内顺序与号序不一致**（读文档的人按号找节会走空）。
  另一种修法是「只把文末速查搬回号序位置、保留现号」，但那会永久留下 §18.9 这个空洞、
  且 18.10 之前的号与「本节排在 §18.8 之后」这件事继续对不上，故取**彻底方案**：
  按文内顺序重编号，`18.10→18.9`、`18.11→18.10`、`18.13→18.11`、`18.14→18.12`、
  `18.15→18.13`、文末 `18.12（速查）→18.14`（子号一并跟改：`18.10.1/2→18.9.1/2`、
  `18.13.1~4→18.11.1~4`）。重编号后 18.1~18.14 **单调、无重号、无缺号**，文内顺序与号序一致。
  - **引用面全库同步**（`§18.x` 形式）：`docs/standards/{12,16,18}.md`、`docs/superpowers/specs/**`（2 份）、
    `src/lib/markdown/index.ts`、`src/server/{auth/request-user,lib/range-request}.ts`、
    `tests/lib-server-imports.test.ts`、`vitest.config.ts`、`AGENTS.md`（硬规则 11/22 与「强制先读」表）；
    `docs/generated/**` 经 `pnpm doc:render` 重生成（不手改）。**`§18.4` / `§18.6` 是最大引用面
    （源码注释 50 个文件 + `vitest.config.ts`），它们不在映射里、引用一字未动**——这一点刻意核对过，
    避免把「重编号」做成「全库注释大改」。
  - **`CHANGELOG-archive.md` 不动**：它按 `changelog.d/README.md` 的口径是「逐份收录、一字未改」
    的归档原文，改写它等于伪造历史证据（AGENTS 硬规则 14）。其中的 `§18.x` 停留在重编号前的号上，
    是**历史条目的本貌**，不是待修的失效引用。
  - **没有顺带加「章内节号唯一 / 单调 / 不跳号」的判据**：先说清「哪一级算节」——01~15 章的节是
    `### N.M`、16~18 章在 #1935 之后也已是 `## N.` 起（节是 `### N.M`），而本仓其它章存在刻意的
    留空号（历史删除），「跳号是否违规」需要单独裁决。判据口径没定就先接线，只会得到一条
    在别的章上误报一片的守卫，故本条只做「把 18 章的号排正 + 同步引用」（与 ISSUE #1939 评论里
    的第 2 问处置一致）。
