## Fixed

- **comfy-cli 跑子图工作流时报一批「值类型对不上」（`shape_mismatch`）**：根因是 comfy-cli 的提升控件（promoted widget）回写存在**槽位漂移**。子图宿主实例的 `widgets_values` 按「宿主自己 `inputs[].widget` 为真」逐项占位（ComfyUI 前端的序列化口径，实测数组长度与控件个数严格相等），而 comfy-cli 的 `promoted_inputs` 只按「边界连线的**内层目标**带不带 `widget` 标记」判定占位 —— 被转成输入插槽的引脚（宿主 `widget` 为 `null`）只要内层目标仍是控件就被它多算一格。于是它按 `widgets_values[i + 漂移]` 读值，再以「宿主优先」**覆盖**掉内层节点上的正确值：给 `clip_name` 读到 `5`、给 `shift` 读到 `true`、给 `steps_total` 读到 `'euler'`。

  修法不是去迎合它那个下标（那会把载荷绑死在一条有缺陷的规则上，它一修好我们反而错），而是让载荷的正确性只依赖**内层值**（那正是 ComfyUI 的真实语义：宿主值只是被提升出去的镜像）：先把宿主上所有控件型提升输入的值按我们的下标折进内层节点，再清空宿主实例的 `widgets_values` —— comfy-cli 的 `host_value` 因下标越界一律返回 `UNSET`，回写整段跳过。只在**确实检测到漂移**的子图实例上动手，不漂移的载荷一字不改；且只改提交用的临时载荷（本来就是深拷贝），库里的工作流不受影响。

  该缺陷在 **1.20.0 与 GitHub 主干 `5cd4b77` 上同样存在**（用 comfy-cli 自带的 `promoted` 模块在真实载荷上实测：修复前两侧下标不一致的引脚 35 个、漂移 +3；修复后 44/44 引脚回写取不到值，内层值全部保持正确）。
