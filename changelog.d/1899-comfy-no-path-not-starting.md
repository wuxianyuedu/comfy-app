## Fixed

- **没配 ComfyUI 路径点「启动 ComfyUI」，状态行不再谎报「正在启动…」（ISSUE #1899）**：路径那一栏是空的，点一下「启动 ComfyUI」就得到状态行「ComfyUI 正在启动…」+ 锁死的「启动中…」按钮，而同一屏里那句提示正写着「未配置——请填写 ComfyUI 路径」，一个进程都没被拉起。根因是 `ensureComfyUiReady()` 里 `markComfyStarting()` 落在了 `decideEnsureLaunch()` 判决表**之前** —— `skip-no-path` / `skip-autostart-off` / `skip-manual-stop` / 「上次自动启动已失败」这些**根本不打算拉起**的分支也把 `COMFY_STARTING_WINDOW_MS`（12s）点亮了；判决本身没错（返回值就是「请填写 ComfyUI 路径」），错的是同时还在说「启动中」，且窗口期内没有任何新事件来纠正它（前端状态走事件驱动 + 30s 兜底轮询，12s 窗口过期时没有人重问），于是这句话一直挂在屏幕上。修法是把落窗口的位置挪到判决**之后**：判决表把 `already-up` 与全部 `skip-*` 摘掉之后，剩下的只有「等已有实例就绪」与「按路径拉起」两条真会推进的路，窗口在那里落位才配得上「有启动在推进」这个语义。
- 回归测试改写在 `src/lib/comfyui/lifecycle.test.ts`：原先那条「手动点启动、路径判据直接返回、但已经算启动流程进行过 ⇒ 空窗不该闪回未运行」断言的正是**错的那一侧**（那条前提就是 bug 本身），现已翻成正向判据「未配路径 ⇒ `starting` 必须为 false」，另加一条自动来源同族分支的参数化用例，并补一条「真会拉起时窗口照旧落位」守住 ISSUE #442 的原始诉求不被这次修正推翻。规范 §5 排障表新增一行症状 → 根因 → 修法。

## Docs

- `docs/standards/launch-and-build.md` §5「ComfyUI 生命周期」对照表新增一行：症状「没配路径就说正在启动…」、根因「启动窗口被点在判决表之前」、修法与边界（拉起快速失败时窗口仍会亮满 12s，那与「拉起后慢慢才就绪」在时间上无法区分，#442 的闪回正源于此，不属本次改动）。
