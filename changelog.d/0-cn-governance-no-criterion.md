## Changed

- **`cn()` 治理这条不再立项**（规范 §16.2.3.3 记下实测数字）：任务清单上挂着的
  「`cn()` 40+ 分片治理（可加一条 P 棘轮）」在动手前把候选形态全量量了一遍，结论是
  **没有可立的判据**：
  - 视图层 `cn("单参数字面量")` = **0** 处（271 处 `cn(` 里一个没有）；
  - `cn(<单个标识符>)` = **4** 处，且全部落在 shadcn 装入的 `ui/` 基元里 —— 上游形态，
    与 `ui/` 那 7 处 `z-50` 同一处置口径（不并轨、不改上游）；
  - `className={模板串}` = **0**、直接 `clsx(` = **0**、直接 `twMerge(` = **0** ——
    出口本来就是单一的（`~/lib/utils` 的 `cn`）；
  - 字面量类串里自相冲突（tailwind-merge 本来要救的事故）：13,536 个类 token 里 **1** 处，
    而那处在普通 `className="…"` 上、不走 merge，写了就生效，无损失；
  - `cn()` 实参之间互相丢类（真·静默失效）= **0**（启发式报的 4 处逐条复核：3 处是互斥的
    三元分支、1 处是跨两次 `cn()` 调用的窗口误报）。
  立一条对象不存在的门禁，正是 §12.18 末尾警告的「会静默失效的清单」。`cn()` 真正的风险面
  早有判据：同族 token 堆叠由 `check-theme-colors.cjs` 与 §3.6.1 管，实参顺序是载荷写在
  §16.2.4 开头那条 ⚠️。数字与复量方法留在文档里，避免下一轮凭印象重新立项。
