## Fixed

- **注释语言棘轮的基线此前会与仓库自己的代码脱节，让门禁对下一个提交者报出与他无关的红**
  （ISSUE #672 续 / 规范 12 §12.4.6）。实测现场：4 个已合并的提交陆续引入了
  **7 个文件 / 20 行**英文注释，而 `scripts/.comment-language-baseline.json` **停在 0** ——
  `check-comment-language.cjs` 在 `pre-commit` 里确实报红（提交被拦），但那些代码
  已经在 `master` 上了，于是**下一个人做任何提交都会失败**，而失败原因与他的改动毫无关系。

  - 这批注释**逐条改写成中文**（`ui/expansion-set` / `ui/key-value-rows` /
    `ui/progress-bar` / `ui/wide-panel` / `lib/list-filter` / `lib/task-state` /
    `tests/check-file-structure`），**基线保持 0 / 0** —— 不用一个更宽的基线把红遮掉。
  - 新增判据 **「仓库里的基线覆盖仓库里的代码」**（`tests/comment-language.test.ts`）：
    直接跑本仓库的 `--report`，把实际命中数与基线逐项比对，不一致即失败。报错文案
    首选「改成中文」，其次才是 `--update` 收紧，并明写「不要用更宽的基线遮掉」。
  - 起因是棘轮的一个结构性盲区：临时工作区里的用例验证的是「**脚本判据**对不对」，
    而「**仓库的基线有没有跟上仓库的代码**」此前没有任何判据 —— `--update` 写出的
    数字只在提交时进历史，钩子被绕过或没跑就留下这段脱节。
