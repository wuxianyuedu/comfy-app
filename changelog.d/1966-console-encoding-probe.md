## Fixed

- **乱码这件事定到了层：抓取端按「宿主 ANSI 代码页」解码，改控制台设置动不了它**
  （ISSUE #1966，读数 `cnb-rrl-1k51u7hov` 的 `工具链自证`）。

  `工具链自证`（第一步，几秒）现在固定吐三行中文，分别由三层产出；读数如下 ——
  注意那三行是在**控制台已被钉成 65001 之后**打的：

  ```
  编码探针·PS 原生：中文一二三  → 缂栫爜鎺㈤拡路PS 鍘熺敓锛氫腑鏂囦竴浜屼笁
  编码探针·CMD：中文一二三      → 缂栫爜鎺㈤拡路CMD锛氫腑鏂囦竴浜屼笁
  编码探针·NODE：中文一二三     → 缂栫爜鎺㈤拡路NODE锛氫腑鏂囦竴浜屼笁
  ```

  三行**同一种乱法** ⇒ 抓取端不是按「当前控制台代码页」解码，而是按**宿主 ANSI
  代码页**（这台机器上 CP936），控制台对象上的设置改不动它。这否掉了
  `scripts/ci-console-encoding.mjs` 头注里此前那半句推论（「PowerShell 自己打的字
  是好的」—— 那只是**没钉 UTF-8 时**的形态）。

  出路两条：**机器侧把 ANSI 代码页改成 UTF-8**（改一处，三层同时对齐，首选）或
  仓库侧让每个字节都以 CP936 出口（每 stage 转码，Node 没有 GBK 编码器，只能靠
  PowerShell 的 `GetEncoding(936)` 包一层 —— 机器侧动不了时的下策）。
  在那之前，仓库侧「钉 65001」是**必要不充分**：宿主 ANSI CP 还是 936 时它只会把
  原本可读的那半也变成乱码。三行探针**留作常读读数**（换代码页 / 换 runner 一眼可见）。

## Changed

- 每个 stage 的脚本开头加 `$enc=[Text.Encoding]::UTF8; [Console]::OutputEncoding=$enc;`
  —— 它是上面那条出口（机器侧 UTF-8）的配套，不是替代。两处判据跟着放宽的是
  **「入口排在第几个词」**（`tests/ci-env-probe.test.ts` / `tests/no-platform-ci-config.test.ts`），
  不是判据本身；两处各自正向判一句「编码设置还在不在」。
