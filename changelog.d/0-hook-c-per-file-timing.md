## Added

- **pre-commit 的组 C 现在有分文件耗时读数了（`scripts/precommit-timing.mjs` +
  `scripts/run-affected-tests.mjs`），把「哪几条门禁非必要、该挪去平台侧」这个问题从印象
  变成有账**（无 ISSUE，承接 §13.5.8.3 第八笔账那条「只有时长没有面就是半条账」）：本机
  13 次提交的账本读数是**总时长中位 1110s / 组 C 中位 1108s** —— 整条钩子的钱几乎全在
  「跑测试」那一坨里，而那一坨在账本里**只有一个数**：51 条分步计时全部属于 A/B/D，
  其中单步最贵的才 31s。于是此前任何「砍哪几条」的说法都只能拿印象当判据，而这正是
  §13.5.8.2.1 反对的形态（「代价一律取稳态读数」）。A/B/D 与 C 并行，挪走它们省不到墙钟 ——
  要回答这个问题，必须先让 C 自己有明细。

  明细由 **vitest 自己**给（junit reporter 的内层 `<testsuite name="tests/x.test.ts" time=…>`
  就是逐文件时长；`json` reporter 的 `duration` 是逐用例的，拿它拼还得再自己聚合一遍），
  落在钩子的 `$LOGD` 里（每次新建、随 EXIT trap 删除、**不在检出内**），并由账本一侧
  新增一节「组 C 各文件（中位数，前 10）」。**判定一条没动**：不进 D0、不改任何退出码，
  `--junit-dir` 没递到时连一个字都不加（人自己跑 `node scripts/run-affected-tests.mjs`
  的形态与此前逐字相同）。

- **三条防「读数冒充结论」的形状，都配了判据**（这一族最容易做成另一张没人读的表）：
  - **分母**：同目录落一份「这次真正跑了哪些文件」的清单。没有它，「junit 里只有 88 份」
    与「清单本来就是 88 份」在账本里**逐字同形**，而前者意味着有两份文件一次都没被计时 ——
    现在缺的份数被点名，并明写**「不是 0 秒」**，不许被当成便宜的项砍掉；
  - **对账**：报表给「分文件之和 ⇄ 组 C 墙钟」两行对照。junit 的 `time` 只算**测试阶段**，
    不含 vitest 启动、收集 / transform 与 worker 拉起，所以这张表用来**排序**、不能当墙钟 ——
    一个不能对账的读数会被读成另一个刻度（同 §13.5.8.2.1 那句「记账自己的开销也要量，
    它会冒充判据的成本」）；
  - **合并规则**：每块、每遍各一个文件，按 `(块, 遍)` 升序、**后写的覆盖先写的** ⇒
    `--no-file-parallelism` 那遍赢。拿首跑（与 A/B/D 抢核）那组数排序会把**负载**读成
    **文件的成本**，而那正是 §13.6.4 立过案的那一族。
  - `--reporter=default` 与 `--reporter=junit` **两个都给**：只给 junit 会把人类可读的输出
    整个换掉，而真红那一屏是唯一能读的东西（加读数不许替代判定与输出）。

- **顺手修掉一条会因排版而红的判据**（这是本轮唯一动到的既有判据，且是把它**收紧**而不是
  放宽）：`tests/hook-affected-launch.test.ts` 那条「传进 vitest 的并发只许一处」原先按
  **行**取数（哪一行同时含 `spawn(` 与 `--maxWorkers=`）。给两次 spawn 各加一段读数参数后
  prettier 把数组折成多行，它当场读出 0 处 —— 而语义一个字没变。改为按**调用点**取
  （`spawn(entry, [ … ])` 那段实参），并加一条「提取落空 ⇒ 下面每条都在对着空数组比」的
  前置断言。判据因为排版而红，要修的是判据，不是把代码写回单行去迎合正则。

- **布局只有一份出处**：清单文件名与 junit 前缀定义在账本那一侧（`C_MANIFEST_NAME` /
  `C_FILES_PREFIX` / `cFileXmlName`），写的一侧 import 它。抄成两份的漂移形态是静默的 ——
  改名那侧照常跑、读的那侧从此读不到，而「读不到」在这一格等价于「这次没有读数」。
  往返判据直接拿写侧生成的路径喂读侧的解析器，改任何一边就红。

  ⚠️ 本轮**不砍线**：这一格只把明细拿出来。砍哪几条（恒跑核心 / 碰了才跑 / 整档交平台侧）
  等这份明细在机器空着的时候跑出一轮真实排序之后再定，口径走 §13.5.17（判据一字不改，
  改的是执行者）与 §13.5.18（按触发面收窄）。规范 §13.5.8.3 的「记什么」那一行与本节
  的「第九笔账」同批写上；`docs/generated/13-*` 同批重渲染。
