## Changed

- **工作流库「就地运行」的日志落盘：每来一行就整表序列化一次 → 合并窗口内只写一次（`src/lib/workflow/workflow-run-store.ts`）**：
  一次运行会一行一行推日志（SSE 每来一行一次），而每次 `notify()` 都把**整个登记表**
  `JSON.stringify` 一遍再同步 `localStorage.setItem`（32 条登记 × 最多 300 条日志，
  实测 **4.2ms / 683KB 一次**）。列表本身要立刻更新（React 等着渲染），所以合并的只有
  **落盘**这一半：250ms 窗口内的多次变更只写一次，写的是窗口结束时的最新全表。
  实测一段 20s 的日志流（2000 行）：**8109ms → 331ms（约 24.5×）**，落盘次数
  **2000 → 80**；窗口关掉前会 flush（`pagehide`），终态不会因合并而丢。
  同一函数里另两处 O(上限) 一并收窄：判重从扫满 300 条改为只看尾部 64 条
  （与 `stepLogCache` / `GlobalStepLogPanel` 同款口径，重复帧只会紧挨着原帧到达），
  追加路径从「先整份复制再切片」改为 `tailWindowAppend` 的原地搬移。
