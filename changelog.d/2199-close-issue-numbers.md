## Added

- **`pnpm ship --close-issue 2179`：给「早已落地、却还挂着」的单子开了一条补关路径（ISSUE #2199）**：
  过去 `--close-issue` 只是开合旗标，号只能从本轮落地那一行的标题本体里取 —— 于是变更随别人的 PR
  进了主干之后，那张单再也没有机器执行者去关，只能人手动 `cnb issues update-issue`。
  现在旗标收号（`2179` / `#2179` / 一次多张 / `--close-issue=2179,2186`），号有两种来源：
  - **本轮号**（标题本体里点名的）：前提仍是「本轮合并已验真」，口径一字未改；
  - **人点名的号**（命令行上给的）：前提换成「平台查得到它随某条**已合并**的 PR 落地」——
    反查 `pulls list-pulls --state closed` 后**逐条认 `is_merged`**（`--state merged` 实测回
    `400 bad request`，词表只有 `open|closed|all`；`closed` 里混着「合了」与「关了没合」），
    并先剥掉平台追加的 `(#<PR号>)` 再提号（PR 号与 issue 号共用编号空间，不剥会把一条 PR
    读成一张单）。

  只点名、不 `--merge` 时走**只补关**那一路：不跑 preflight / commit / push，只做关单与独立回读。
  两条通道共用同一条红线：**没有落地证明就不关**；查不到落地证明退 `2`（「没有结论」），
  不念成「没落地」，也不加 `--force-close` 这类绕过口。关完仍是一次独立的 `get-issue`，
  回读 `state` / `state_reason` / `closed_at` 三件原值（回执不算结论）。

- **`--close-issue` 后面跟了不像号的 token ⇒ 当场退 `2`**：过去它会被当成未知旗标收下，
  人真正想要的「补关」连被讨论都没被讨论；现在逐个点名「这里不像：…」并且一张单都不动。
