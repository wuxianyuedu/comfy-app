# 功能需求清单（Feature Catalog）

> 每个需求一条编号；「是什么、怎么算做完」的详述在
> [feature-specs.md](feature-specs.md) 对应条（同编号同标题）。
> 状态词义与变更规则见 §1；做改动前先读本文件定位，再进 specs 读验收口径。

## 1. 编号与状态词表

**编号**：`FR-<域>-<序号>`。域缩写与本文 §2 的分节一一对应。编号一经分配
不回收、不改义；退役不删行（改状态 + 注明去向）。

**状态词表**：

| 状态     | 词义                                                        |
| -------- | ----------------------------------------------------------- |
| 已上线   | 用户可用，行为即 specs 所写                                 |
| 灰度     | 已在场但默认不承重 / 只服务部分路径（开关或特定入口才生效） |
| 部分实现 | 需求拆成的多块只有部分落地；哪块已达标逐条见 specs 对应条   |
| 计划中   | 已立案未实现，或只落了配置层（运行时未接）                  |
| 已退役   | 曾存在、已撤；保留编号供历史追溯                            |

**已知问题不占状态**：实现与需求的偏差（缺陷 / 双实现 / 文档漂移）走 Issue，
索引见 §3；它们不是需求的「状态」。
