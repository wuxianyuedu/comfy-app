# 产品概述（Comfy-APP-T3）

## 1. 一句话定位

Comfy-APP-T3 是 **ComfyUI 的桌面创作工作台**：把 ComfyUI（本机 AIGC 生成引擎）
包进一个 Tauri 桌面壳，用「项目 → 项目画布 → 工坊 → 成片」的创作链路组织生成任务，
让使用者以**创作**（而不是调试节点）的方式使用 ComfyUI。

边界（它不是什么）：

- 不是 ComfyUI 的替代实现 —— 出图 / 出视频始终由本机 ComfyUI（或灰度中的独立宿主）执行；
- 不是云端服务 —— 默认本机单用户，数据落本机 SQLite 与本机产物目录；
- 不是节点调试器 —— 节点级调试仍用 ComfyUI 原生界面（本产品可一键打开它）。

## 2. 目标用户与典型场景

| 用户           | 场景                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| AIGC 创作者（主要） | 把灵感做成成片：剧本 → 角色 → 分镜 → 生图 → 生视频 → 合成；反复迭代中间产物；管理模型与工作流 |
| 工作流整理者   | 把 ComfyUI 里调试好的工作流导入库、配对外参数、打标签、就地试跑                            |
| 开发者 / 维护者 | 在本机跑质量门禁、看日志、管数据库（控制台视图）                                          |

三条主线对应文档：工坊流水线 → `docs/guides/feature-workshop-flow.md`；
工作流库 → `docs/guides/feature-workflow-library-flow.md`；
后端托管 → 本目录 `FR-CU`。

## 3. 产品形态

一个产品、两种用法、两种运行形态、一种账号默认：

| 维度     | 形态                     | 说明                                                                                       |
| -------- | ------------------------ | ------------------------------------------------------------------------------------------ |
| 用法     | 桌面壳（主形态）         | Tauri 壳是唯一启动入口；壳自己按「检出里有没有编排器」决定运行形态（判据见规范 §1.5）       |
| 用法     | 浏览器（开发态）         | `pnpm dev` 起 Next dev server，同一个应用                                                   |
| 运行     | prebuilt（开发检出）     | 壳起编排器 → dev server，前端 HMR                                                          |
| 运行     | standalone（分发副本）   | 壳经 Node sidecar 起内嵌 Next server，改动需重新构建                                       |
| 账号     | 本机单用户（默认）       | `loginRequired` 默认关，回落演示用户；可开邮箱密码 / GitHub OAuth（桌包内 OAuth 不可用，见 FR-AU-02） |

分发物卫生（密钥 / 数据库不进包）与两种运行形态的判据是**工程约束**，见
`docs/standards/launch-and-build.md` §7 与仓库 README；产品侧只承诺一件事：
**用户拿到的桌包开箱即用，不含开发机私密配置**。

## 4. 信息架构

产品主体是**工作区**（一个全屏容器：左侧导航 + 视图页签 + 命令面板）；
Next 路由只有登录与三个历史挂载点（§4.3）。

### 4.1 工作区视图（17 个）

注册表唯一出处：`src/components/studio/NavItems.tsx`（`NAV_ITEMS` /
`WorkspaceView`）。三个分区：

**全局项（10 个；侧栏列 9 个 —— 设置撤出侧栏，入口在顶栏应用菜单）**

| 视图           | 导航名   | 是什么                                       | 需求域   |
| -------------- | -------- | -------------------------------------------- | -------- |
| `home`         | 首页     | 应用首页：入口卡 + 最近项目 + 状态卡         | FR-WS    |
| `models`       | 模型     | 模型库（扫描 / 每目录启用管理）              | FR-MD    |
| `history`      | 历史     | 任务历史：分页 / 按日分组 / 筛选 / 详情弹窗  | FR-GN    |
| `queue`        | 队列     | 队列监视：在跑与排队的任务                   | FR-QE    |
| `comfyui`      | ComfyUI  | 出图后端自己的屏：状态 / 启停 / 启动日志     | FR-CU    |
| `workflows`    | 工作流库 | 工作流导入 / 管理 / 就地运行                 | FR-WF    |
| `model-adapters` | 模型适配 | 远端模型 × 模式的字段映射注册表            | FR-LM    |
| `mode-contract` | 模式契约 | 每种模式的统一输入 / 输出契约               | FR-LM    |
| `console`      | 控制台   | 仓库级预设命令的执行台（不是 shell）         | FR-CS    |
| `settings`     | 设置     | 应用级配置九分区（瞬时页签）                 | FR-ST    |

**项目页签（6 个；只在项目界面顶部的标签栏出现）**

| 视图       | 导航名 | 是什么                                   | 需求域 |
| ---------- | ------ | ---------------------------------------- | ------ |
| `project`  | 主页   | 项目状态总览 + AI 自主成片操纵台         | FR-WP  |
| `canvas`   | 画布   | 项目画布：生成单元节点编排创作流程       | FR-CV  |
| `workshop` | 工坊   | 六阶段创作流水线                         | FR-WP  |
| `library`  | 资源库 | 项目内资源管理                           | FR-CV  |
| `outputs`  | 产出   | 项目输出物汇总（虚拟网格）               | FR-OP  |
| `film`     | 成片   | 成片项目：逐镜 + ffmpeg 合成             | FR-OP  |

**项目入口（1 个）**：侧栏底部「项目」分组（`works`，作品相册，可展开列出已有项目）。

### 4.2 页签与入口规则

- 视图以**页签**打开，可同时开多个、切走保留编辑态；
  设置 / 模型适配 / 模式契约是**瞬时页签**（切走即关，不常驻页签条）；
- **命令面板**可打开全部全局视图（与侧栏、页签「+」菜单同一份注册表）；
- 项目类视图经「+」菜单 / 侧栏项目分组进入（项目内顶部切换器已退役）；
  没有活跃项目时，「+」菜单不放项目类视图（落了也是闸门）。

### 4.3 独立挂载路由（历史入口）

| 路由                  | 挂载                     | 口径                                                             |
| --------------------- | ------------------------ | ---------------------------------------------------------------- |
| `/login`              | 登录 / 注册             | 在役                                                             |
| `/workshop`           | 工坊界面的一个挂载点     | 地址栏直达与外部链接用；应用内入口走页签                         |
| `/models`             | 模型库界面的一个挂载点   | 同上；#2424 起**改挂工作区那份实现**（浏览版已退役，模型库只有 `studio/ModelLibrary` 一份实现） |
| `/settings`           | 设置界面的一个挂载点     | 同上（页面注释明确「应用内入口现在都走页签」）                   |

`/` 只做 `redirect("/workspace")`。

## 5. 核心概念

术语全表以 `docs/glossary.md` 为强制口径；产品侧最常用的八个：

| 概念                 | 一句话                                                 | 注意                                       |
| -------------------- | ------------------------------------------------------ | ------------------------------------------ |
| 工作区               | 主容器（左侧导航 + 视图 + 页签）                       | 不叫 workflow                              |
| 项目画布             | 编排创作流程的主画布，节点是生成单元                   | 与「工作流编辑器画布」是两回事（判别口诀见 glossary §2） |
| 工作流编辑器画布     | 把一份 ComfyUI 工作流摊开成图                          | 节点是 `class_type`                        |
| 工坊                 | 剧本 → 成片的六阶段流水线                             | 与「工作室」（组件命名空间）一字之差、指代不同 |
| 工作流库             | 工作流的导入 / 管理 / 就地运行                         | 导航名「工作流库」，不叫「流程库」         |
| 任务                 | 服务端真值：一次生成请求的记录                         | 前端叫「运行记录」，ComfyUI 内部叫「执行」 |
| 产出                 | 项目输出物汇总（虚拟网格）                             | 与「项目」相册视图（`works`）区分          |
| 成片                 | ffmpeg 合成的最终视频项目                             | 与工坊阶段⑥（客户端合成清单）是两条链路    |

## 6. 数据与账号

- **数据库**：SQLite（Drizzle ORM），schema 唯一出处
  `src/server/db/schema.ts` —— 共 **23 张表**：better-auth 4 张
  （`user` / `session` / `account` / `verification`）+ 业务 19 张。
  业务表按域分四组：
  - 任务与产物：`task` / `taskImage`；
  - 工作流族：`workflowTemplate` / `workflowModelTag` /
    `workflowModelTag_workflowTemplate`；
  - 创作族：`project` / `production` / `filmProject` / `filmShot` /
    `workshopSession` / `workshopDraft` / `skill`；
  - 模型与配置族：`model` / `userModelConfig` / `favorite` / `llmConfig` /
    `remoteModel` / `auditLog` / `post`（脚手架示例表：其 tRPC 口已按零消费治理退役，
    仓储层仍在）。
- **产物落盘**：普通任务 `generated/<taskId>`，项目任务
  `generated/projects/<projectId>/<taskId>`，成片 `generated/films/<id>.mp4`；
  读取经 `/api/generated/...`。路径规则唯一出处
  `src/lib/media/output-paths.ts` 与 `output-layout.ts`。
- **账号**：邮箱密码（最少 12 位）+ GitHub OAuth（桌包内不可用）；会话落
  `session` 表；默认本机单用户、回落演示用户（判决单点
  `src/lib/auth-server.ts`）。详见 FR-AU。

## 7. 非功能需求（总表）

| 类         | 需求                                                                 | 细则出处                                             |
| ---------- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| 性能       | 大列表虚拟化（产出 / 日志 / 模型库）；画布交互不卡；tsc / eslint 零警告 | `docs/standards/02-性能规范.md`、`11-测试与可观测性.md` |
| 可用性     | 明暗主题同一套 token；失败有降级与出口；空状态                         | `docs/standards/03-样式与-tailwind.md`、`10-错误处理与降级.md` |
| 无障碍     | aria-label / 焦点管理 / 对比度                                        | `docs/standards/06-无障碍访问-a11y.md`               |
| 可观测     | 日志落 `log/` 分区 + 应用内日志面板；失败路径有用户可见出口            | `docs/standards/07-日志系统.md`                      |
| 数据安全   | 备份恢复（保留最近 3 份、下次启动生效）；分发物不含开发机私密输入      | `docs/guide-database-backup.md`、`docs/standards/launch-and-build.md` §7 |
| 访问控制   | 机器面（控制台 / MCP）只监听回环地址；会话与限流在役                  | 本目录 FR-CS / FR-MC                                 |
| 跨平台     | 三平台入口与进程模型一致；平台判据只收两处                            | `docs/standards/launch-and-build.md` §9              |
| 陈旧实例   | 应用长开期间拉到新代码 → 应用内提示重载（白屏自救）                   | `docs/guide-stale-code.md`                           |
