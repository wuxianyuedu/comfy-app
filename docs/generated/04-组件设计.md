## 4. 组件设计

> 组件是产品代码的主要载体。本章给出拆分、组合、API 设计、性能优化的可操作规则。

### 4.1 单一职责：一个组件干一件事

| 组件 | 行数 | 干了 N 件事 | 评价 |
|------|------|-------------|------|
| `HistoryList` | 600+ | 8 | ❌ 必须拆分 |
| `CanvasArea` | 200+ | 5 | ⚠️ 应该拆分 |
| `BottomBar` | ~150 | 4 | ⚠️ 到了临界点 |
| `HomePage` | ~230 | 3 | ⚠️ 临界（230 行已超 200 阈值，下轮改动拆） |
| `LeftToolbar` | ~100 | 1 | ✅ 干净 |

**拆分阈值**：超过 200 行且包含 3+ 个独立功能 → 拆。超过 300 行无论功能数 → 拆。

### 4.2 数组驱动 UI，不要复制 JSX

```tsx
// ❌ 错误：复制粘贴 4 遍
<div className="card">...</div>
<div className="card">...</div>
<div className="card">...</div>

// ✅ 正确：数据驱动
const QUICK_ACTIONS = [
  { id: "canvas", label: "新建画布", icon: <Canvas size={22} /> },
  // ...
];
{QUICK_ACTIONS.map((action) => (
  <button key={action.id} onClick={() => onNavigate(action.id)}>
    {action.icon}
    {action.label}
  </button>
))}
```

**收益**：加新项只改配置数组，不改 JSX 结构；类型系统自动校验每项字段完整性。

### 4.3 消费方 API 类型安全

```tsx

```

### 4.4 事件隔离（React Flow 节点内组件必读）

```tsx
// ✅ 节点内按钮必须阻止事件冒泡到画布
<button
  onClick={(e) => { e.stopPropagation(); handleClick(); }}
  onMouseDown={(e) => e.stopPropagation()}
  onPointerDown={(e) => e.stopPropagation()}
  onDoubleClick={(e) => e.stopPropagation()}
>
```

**原因**：React Flow 画布监听 pointer/mousedown 用于框选、拖拽节点。节点内的按钮不隔离事件，会导致点击按钮时也触发画布交互（误选/拖拽）。

### 4.5 组件拆分目录结构

```
Feature/
├── index.tsx              ← 主组件：只管布局 + 组合
├── hooks/                 ← 业务逻辑 hook
│   └── useFeatureData.ts
├── components/            ← 子组件（每个 < 80 行）
│   ├── FeatureCard.tsx
│   └── FeatureToolbar.tsx
├── utils/                 ← 纯函数工具
│   └── format.ts
└── types.ts              ← 本功能专用类型
```

**导入规则**：`components/` 只导入同功能 `hooks/` 和 `utils/`；跨功能复用提升到 `components/studio/shared/` 或 `lib/`。

### 4.6 Props 设计：优先组合，避免巨型 props 对象

```tsx
// ❌ 错误：10+ 个可选 prop，调用方记不住
<HistoryList
  onOpenTask={...} onNavigate={...} onShowAllProjects={...}
  activeNav={...} recentProjects={...} onOpenCanvasProject={...}
/>

// ✅ 正确：分组为子对象或拆成多个小组件
interface HistoryListProps {
  navigation: { active: WorkspaceView; onNavigate: (v: WorkspaceView) => void };
  data: { projects: RecentProject[]; onOpen: (id: string) => void };
}
```

**Props 设计准则：**

1. **布尔 prop 语义正向**：`disabled`、`loading`、`open` 而非 `isNotLoading`、`hidePanel`。
2. **回调命名 `on<Event>`**：`onChange`、`onSend`、`onOpenTask`，统一动词前缀。
3. **避免 `children` 承载过多结构化内容**：超过 2 个具名插槽时改用命名 prop（`header`/`footer`/`sidebar`）。
4. **`as` polymorphism 谨慎用**：需要渲染为不同标签时（如 `as="a"`），用 `React.ElementType` 类型约束，避免 `any`。

### 4.8 用 React.memo + 稳定回调避免子组件无效重渲染

```tsx
// ✅ 正确：列表项用 React.memo，回调用 useCallback 保持引用稳定
const TaskItem = React.memo(function TaskItem({
  task,
  onClick,
}: {
  task: AgentTask;
  onClick: (id: string) => void;
}) {
  return <button onClick={() => onClick(task.id)}>{task.label}</button>;
});

function TaskList({ tasks, onTaskClick }: { tasks: AgentTask[]; onTaskClick: (id: string) => void }) {
  const handleClick = useCallback((id: string) => {
    onTaskClick(id);
  }, [onTaskClick]);
  return tasks.map((task) => <TaskItem key={task.id} task={task} onClick={handleClick} />);
}
```

**注意**：`React.memo` 只对 props 做浅比较。若父组件每次渲染都创建新对象/新函数传给子组件，`memo` 失效——先稳定数据源（Zustand selector / `useCallback`），再包 `memo`。

### 4.9 组件分类与对应规范

| 类型 | 示例 | 规范要点 |
|------|------|---------|
| 布局壳（Shell） | `AppShell`/`BottomBar` | 只排布区域 + 组合子组件；动画/显隐逻辑下沉到子组件 |
| 业务页面 | `HomePage`/`HistoryList` | 数据获取 + 组合业务子组件；超过 200 行拆 `components/` |
| 展示组件 | `TaskCard`/`AgentPanel` | 纯展示 + 回调；用 `React.memo` |
| 工具/原语 | `ModalDialog`/`DarkSelect` | 通用、无业务依赖；Props 设计覆盖常见变体 |
| 装饰组件 | `AuroraBackground` | `pointer-events-none` + `aria-hidden`；颜色/模糊提 Design Token |

### 4.11 状态样式映射收口为一个映射表

状态 → 圆点色、文字色、文案的映射必须收口进同一张 `Record`，不要映射表 + 内联三元链两份维护。

```tsx
// ❌ 错误：STATUS_MAP 管文字色，圆点色又是一串三元——新增状态要改两处，漏一处就是静默 bug
const STATUS_MAP: Record<Status, { color: string; label: string }> = { ... };
<span className={`h-1.5 w-1.5 rounded-full ${
  task.status === "running" ? "animate-pulse bg-amber-400" : task.status === "done" ? "bg-emerald-400" : ...
}`} />

// ✅ 正确：dot / color / label 收口进同一张映射表（参考 AgentPanel.tsx）
const STATUS_MAP: Record<TaskStatus, { dot: string; color: string; label: string }> = {
  pending: { dot: "bg-gray-600", color: "text-gray-500", label: "待开始" },
  running: { dot: "animate-pulse bg-amber-400", color: "text-amber-400", label: "运行中" },
  ...
};
<span className={`h-1.5 w-1.5 shrink-0 rounded-full ${st.dot}`} />
<span className={`shrink-0 text-[11px] ${st.color}`}>{st.label}</span>
```

**规则**：`Record<TaskStatus, …>` 让漏写新状态直接编译报错；映射表里的 Tailwind 类是字面量字符串，能被内容扫描正常生成。

### 4.11.1 映射表里的颜色也必须走语义 token

§4.11 的映射表解决了「状态 → 样式收口一处」，但收口之后**表里的值本身**还得是
语义 token，否则「改品牌色」依旧改不动 —— 表只是把 46 处散落的写死色值换成了
一处集中的写死色值。

```tsx
// ❌ 收口了，但颜色仍是字面量：改品牌色对这张表无效
const STATUS_STYLES = {
  RUNNING:
    "border-violet-500/30 bg-violet-500/10 text-violet-700 dark:text-violet-400",
  FAILED: "border-red-500/30 bg-red-500/10 text-red-700 dark:text-red-400",
};

// ✅ 语义 token（两态在 token 里取，不用再写 dark:）
const STATUS_STYLES = {
  RUNNING: "border-primary-500/30 bg-primary-500/10 text-primary-strong",
  FAILED: "border-destructive/30 bg-destructive/10 text-destructive",
};
```

`ui/status-badge.tsx` 是本条的正例（它此前是反例：44 处写死值，见 ISSUE #672）。
语义色 token 一览见 [03 §3.6.2](03-样式与-tailwind.md#362-品牌状态色必须走语义-tokenissue-672机器强制)。

### 4.12 主操作固定在滚动区外

列表容器 `overflow-y-auto` 内不要放主操作按钮——内容一多按钮就被推出视口，要滚动才能点到。

```tsx
// ❌ 错误：添加按钮在滚动容器内、列表之后
<div className="flex-1 overflow-y-auto p-3">
  {tasks.map((task) => <TaskRow key={task.id} task={task} />)}
  <button onClick={onAddTask}>+</button>
</div>

// ✅ 正确：滚动区 flex-1，主操作 shrink-0 固定 footer（参考 AgentPanel.tsx）
<div className="flex h-full flex-col">
  <div className="flex-1 overflow-y-auto p-3">{tasks.map(...)}</div>
  {onAddTask && (
    <div className="shrink-0 border-t border-white/6 px-3 py-3">
      <button onClick={onAddTask} aria-label="添加任务">…</button>
    </div>
  )}
</div>
```
