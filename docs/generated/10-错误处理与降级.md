## 10. 错误处理与降级

> 商业级应用要"优雅降级"而非白屏崩溃。本章给出错误边界、降级策略、用户提示规范。

### 10.1 三级降级策略

| 层级 | 策略 | 示例 |
|------|------|------|
| L1：功能降级 | 某子功能失败，整体页面仍可交互 | shiki 高亮失败 → 纯文本行号渲染 |
| L2：组件隔离 | 单个组件崩溃，不影响其他区域 | React ErrorBoundary 包裹画布/面板 |
| L3：全局兜底 | 整页崩溃兜底页 | `app/error.tsx` / `app/global-error.tsx` |

### 10.2 React Error Boundary

```tsx
// ✅ 类组件实现 Error Boundary（React 目前仅类组件支持）
class ErrorBoundary extends React.Component<
  { fallback: React.ReactNode; children: React.ReactNode },
  { hasError: boolean }
> {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error: Error) { console.error("ErrorBoundary caught:", error); }
  render() {
    if (this.state.hasError) return this.props.fallback;
    return this.props.children;
  }
}

// 使用：包裹独立区域
<ErrorBoundary fallback={<PanelFallback />}>
  <InspectorPanel />
</ErrorBoundary>
```

**规则**：画布/面板/第三方组件（shiki/JsonView）等独立区域用 ErrorBoundary 隔离；不要把整个页面包在一个 Boundary 里——那样等于没隔离。

### 10.3 Next.js App Router 错误文件

```
app/
├── error.tsx            ← 路由段错误兜底（必须是客户端组件，"use client"）
├── global-error.tsx     ← 全局根布局错误兜底
└── create/[id]/
    └── error.tsx        ← 创建页专属兜底
```

```tsx
// app/error.tsx（客户端组件）
"use client";
export default function RouteError({ error, reset }: { error: Error; reset: () => void }) {
  return (
    <div className="p-8 text-center">
      <h2 className="text-lg font-semibold">出错了</h2>
      <p className="text-sm text-gray-500">{error.message}</p>
      <button onClick={reset}>重试</button>
    </div>
  );
}
```

### 10.4 异步错误提示规范

```tsx
// ✅ 用户可感知的失败用 toast；错误含可读信息
async function cancelTask(id: string) {
  try {
    await cancelTaskMutation.mutateAsync({ id });
    toast.info("已发送取消请求");
  } catch (err) {
    toast.error("取消失败", err instanceof Error ? err.message : "请稍后重试");
  }
}
```

**规则**：
- 错误信息给用户看的部分要**友好可读**，技术细节（stack）只进 console/`ErrorBoundary`。
- 网络错误统一提示"网络异常，请检查连接"，不暴露内部错误码。

### 10.5 空状态设计

```tsx
// ✅ 空状态给出"下一步引导"，而非空白
{filtered.length === 0 ? (
  <div className="grid min-h-[300px] place-items-center rounded-2xl border border-dashed border-white/[0.08]">
    <div className="text-center">
      <p className="text-lg font-medium text-gray-300">暂无任务记录</p>
      <p className="mt-1 text-sm">在创作台生成内容后，历史记录会显示在这里。</p>
      <button onClick={onNewProject}>新建画布项目</button>
    </div>
  </div>
) : ...}
```

**规则**：空状态必须说明"为什么是空的"+"下一步做什么"，降低用户困惑。

### 10.6 功能降级示例：shiki 高亮失败

```tsx
// ✅ CodeBlock：高亮失败 → 纯文本行号兜底（不白屏）
try {
  const hl = await getHighlighter();
  // ... 分片高亮
  setTokens(acc);
} catch (err) {
  if (!cancelled) {
    setTokens(null); // 回到纯文本行号模式
    setError(err instanceof Error ? err.message : String(err));
  }
}
```

### 10.7 表单/输入容错

- 用户输入非法值（如 seed 超 INT 范围）→ 前端校验提示 + 后端校验兜底，不信任前端。
- 文件上传：校验类型/大小，超限给出明确提示"文件超过 50MB，请压缩后重试"。
- `JSON.parse` 用户输入：try/catch + 友好错误定位。

### 10.8 上报与可观测性（已接入 Sentry）

- 项目已安装 `@sentry/nextjs`（v10+）；关键错误用 `captureException` / `console.error` 上报，非关键错误不上报。
- 错误上报含上下文（任务 id、操作类型），便于排查但**不含敏感信息**（prompt 原文、文件路径脱敏）。
- 埋点/上报失败不影响主流程（try/catch 包裹）。
