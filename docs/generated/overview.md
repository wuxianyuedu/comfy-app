# 产品概述（Comfy-APP-T3）

## 1. 定位、北极星与成果定义

### 1.1 一句话定位

Comfy-APP-T3 是 **AI 多剧集影视动漫制作工作台**：把 ComfyUI（本机 AIGC 生成引擎）
包进一个 Tauri 桌面壳，用「系列 → 集 → 剧本 → 角色 → 分镜 → 生图 → 生视频 → 合成」
的创作链路组织生成任务，让**人与 AI** 以**创作**（而不是调试节点）的方式使用 ComfyUI。

### 1.2 北极星（最终目录）

> **用 AI 稳定地产出多剧集影视动漫作品** —— 不是「能生成几张图」，而是
> **一部接一部、一集接一集地交付成片**：角色跨集不换脸、风格跨集不漂、镜头可复用、
> 成片可直接看。

它定了三件事的优先级排序：**成片（可交付的成果） > 一致性（跨镜跨集的稳定） >
单张素材的惊艳度**。凡是让「下一集更难接上」的便利，一律让位。

### 1.3 成果定义（什么叫「做完了」）

| 层级 | 成果 | 判定口径（可核验） |
| --- | --- | --- |
| **作品 / 系列** | 一个系列下有多集，共享角色库、风格锚与场景设定 | 新增一集时可**直接引用**已有角色与风格，不必重造（`FR-SR-03`） |
| **集（成片）** | 一集 = 一个可播放的 MP4：镜头齐全、时长与分镜一致、带字幕与 BGM | 文件落 `generated/films/<id>.mp4`、能播、时长等于各镜之和（`FR-OP-04`） |
| **镜头** | 每个镜头有关键帧与片段，且都能追到生成参数 | `Shot.imageUrl` / `Shot.clipUrl` 非空，`taskId` + seed 可复现 |
| **一致性** | 同一角色跨镜跨集可辨；风格不漂 | 角色有生效定妆照且被下游引用（`FR-QA-02`）；风格经 `skill` 锚定 |

「高质量作品」在本目录里**只以上面这类可核验口径出现**，不写「效果好 / 观感佳」这类
不可判的词（README §5.4）。

### 1.4 边界（它不是什么）

- 不是 ComfyUI 的替代实现 —— 出图 / 出视频始终由本机 ComfyUI（或灰度中的独立宿主）执行；
- 不是云端服务 —— 默认本机单用户，数据落本机 SQLite 与本机产物目录；
- 不是节点调试器 —— 节点级调试仍用 ComfyUI 原生界面（本产品可一键打开它）；
- **不替人做审美决策** —— 生成与编排可全自动，但**质量停点由人拍板**（`FR-AG-02`）。

## 2. 操作者与典型场景

本产品有**两类操作者**，共用同一套状态与产物（不是两套功能）：**人**走界面，
**AI** 走自主 run 与 MCP。任一方改了东西，另一方接着跑必须看到同一份真值
（`FR-AG-01`）。

### 2.1 人（走界面）

| 角色           | 场景                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| AIGC 创作者（主要） | 把灵感做成成片：剧本 → 角色 → 分镜 → 生图 → 生视频 → 合成；反复迭代中间产物；管理模型与工作流 |
| 工作流整理者   | 把 ComfyUI 里调试好的工作流导入库、配对外参数、打标签、就地试跑                            |
| 开发者 / 维护者 | 在本机跑质量门禁、看日志、管数据库（控制台视图）                                          |

按创作分工看，一个人常常同时是：编剧（①）、美术 / 角色设计（②）、分镜（③）、
出图与出视频的执行（④⑤）、剪辑与合成（⑥）—— 六阶段的界面要能让**同一个人连着做**，
也要能让**不同的人各管一段**。

### 2.2 AI（走 run 与 MCP）

| 形态 | 入口 | 现状 |
| --- | --- | --- |
| **内置自主成片** | 项目主页「AI 自主成片」操纵台（`src/server/agent/run-engine.ts`） | 灰度（`FR-WP-08`）：能跑剧本 → 角色 → 分镜 → 生图 →（合并）成片；**无独立视频阶段、无审批停点** |
| **外部 Agent** | 工坊 MCP 17 工具（`src/server/mcp/workshop-mcp.ts`，stdio + http，只监听回环） | 已上线（`FR-MC-01`）：六阶段能力都在，但需外部 AI 按序多次调用，**没有「一键跑完六阶段」** |

AI 的边界：**能全自动执行，不能自己判定质量** —— 视觉评审尚未实现
（`src/server/agent/review.ts` 只评审文本），因而质量停点必须由人批准（`FR-AG-02`）。

三条主线对应文档：工坊流水线 → `docs/guides/feature-workshop-flow.md`；
工作流库 → `docs/guides/feature-workflow-library-flow.md`；
后端托管 → 本目录 `FR-CU`；六阶段契约与验收 →
[pipeline-stages.md](pipeline-stages.md)。

## 5. 核心概念与领域模型

### 5.1 术语速查（产品侧最常用）

术语全表以 `docs/glossary.md` 为强制口径；产品侧最常用的八个：

| 概念                 | 一句话                                                 | 注意                                       |
| -------------------- | ------------------------------------------------------ | ------------------------------------------ |
| 工作区               | 主容器（左侧导航 + 视图 + 页签）                       | 不叫 workflow                              |
| 项目画布             | 编排创作流程的主画布，节点是生成单元                   | 与「工作流编辑器画布」是两回事（判别口诀见 glossary §2） |
| 工作流编辑器画布     | 把一份 ComfyUI 工作流摊开成图                          | 节点是 `class_type`                        |
| 工坊                 | 剧本 → 成片的六阶段流水线                             | 与「工作室」（组件命名空间）一字之差、指代不同 |
| 工作流库             | 工作流的导入 / 管理 / 就地运行                         | 导航名「工作流库」，不叫「流程库」         |
| 任务                 | 服务端真值：一次生成请求的记录                         | 前端叫「运行记录」，ComfyUI 内部叫「执行」 |
| 产出                 | 项目输出物汇总（虚拟网格）                             | 与「项目」相册视图（`works`）区分          |
| 成片                 | ffmpeg 合成的最终视频项目                             | 与工坊阶段⑥（客户端合成清单）是两条链路    |

### 5.2 领域模型（作品结构：系列 → 成片）

北极星（多剧集）要求作品按**层级**组织。下表是目标结构与**当前实现位置**的对照 ——
「是否独立实体」一列是需求侧的账：**列 = 只是某张表里的 JSON 列，无法按它建索引、
无法跨集复用、无版本**。

| 层 | 实体 | 一句话 | 是否独立实体（现状） |
| --- | --- | --- | --- |
| 作品 | **系列** Series | 一部作品的顶层容器：多集共享角色库、风格锚、场景设定 | ❌ 无（`FR-SR-01` 计划中） |
| 作品 | **季** Season | 系列下的一个季度 | ❌ 无（`FR-SR-02` 计划中） |
| 作品 | **集** Episode | 一集 = 一次完整创作链路 + 一部可交付成片 | ⚠️ 近似承载：`project` / `production`（**一个项目 = 一份生产数据**，无集号 / 季号字段） |
| 内容 | **剧本** Script | `scriptMarkdown` + 拆出的 `Scene[]` | ⚠️ 列（`production` / `workshopSession` / `workshopDraft` 的 `scriptMarkdown`） |
| 内容 | **角色** Character | 角色卡 + 定妆照（一致性锚点） | ⚠️ JSON 列（`characters`） |
| 内容 | **分镜 / 镜头** Shot | 镜头表：景别 / 描述 / 提示词 / 运动 / 时长 / 转场 | ⚠️ JSON 列（`shots`）；成片链另有独立 `filmShot` 表 |
| 素材 | **镜图** Image | 镜头的关键帧 | ✅ 产物侧有 `task` / `taskImage`（含 seed、宽高） |
| 素材 | **镜视频** Clip | 镜头片段 | ⚠️ 任务侧有 `task`，镜头侧只是 `Shot.clipUrl` 字段 |
| 交付 | **成片** Film | 可播放的 MP4 | ✅ `filmProject` / `filmShot` + 服务端 ffmpeg |

**这张表最重要的一行是「角色 / 分镜 = JSON 列」**：它正是「跨集复用」与「版本管理」
上不去的根因 —— 一个角色跨集复用，需要它是**可被引用、可被索引**的实体，而不是
躺在某一行 JSON 里的对象。需求侧由 `FR-SR-03` 承接（本次不动代码）。

## 6. 数据与账号

- **数据库**：SQLite（Drizzle ORM），schema 唯一出处
  `src/server/db/schema.ts` —— 共 **23 张表**：better-auth 4 张
  （`user` / `session` / `account` / `verification`）+ 业务 19 张。
  业务表按域分四组：
  - 任务与产物：`task` / `taskImage`；
  - 工作流族：`workflowTemplate` / `workflowModelTag` /
    `workflowModelTag_workflowTemplate`；
  - 创作族：`project` / `production` / `filmProject` / `filmShot` /
    `workshopSession` / `workshopDraft` / `skill`；
  - 模型与配置族：`model` / `userModelConfig` / `favorite` / `llmConfig` /
    `remoteModel` / `auditLog` / `post`（脚手架示例表：其 tRPC 口已按零消费治理退役，
    仓储层仍在）。
- **产物落盘**：普通任务 `generated/<taskId>`，项目任务
  `generated/projects/<projectId>/<taskId>`，成片 `generated/films/<id>.mp4`；
  读取经 `/api/generated/...`。路径规则唯一出处
  `src/lib/media/output-paths.ts` 与 `output-layout.ts`。
- **账号**：邮箱密码（最少 12 位）+ GitHub OAuth（桌包内不可用）；会话落
  `session` 表；默认本机单用户、回落演示用户（判决单点
  `src/lib/auth-server.ts`）。详见 FR-AU。
