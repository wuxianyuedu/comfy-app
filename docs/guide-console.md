# 应用内控制台使用指南

> 一句话：左侧栏「控制台」开一块界面，直接跑那些**本来要另开一个终端窗口**的操作
> —— 跑质量门禁、推 schema、看端口占用、`git log` 查历史。命令在**项目根**执行，
> 输出实时回面板，关闭面板时命令与其子进程一并回收。

## 它解决什么

开发与排障里有一批动作用不上「开一个终端、cd 到项目根、敲命令」这套流程，但此前
**只有**那条路可走：`pnpm exec tsc --noEmit`、`pnpm db:push`、`pnpm run lint`、
`node scripts/app-port.mjs`……桌面壳长开时尤其别扭 —— 你要么在应用里点来点去，
要么切出去开一个控制台窗口。

控制台把这些收进一个面板：

- **左侧**是常用命令（按用途分组），点一下把命令**填进输入框**（不是直接跑）；
- **中间**是输出区，跟着最后一行滚，跑完给一条结论条（成功 / 失败 / 已停止）；
- **右侧底部**是输入行：回车执行，跑的过程中可以「停止」；
- 跑过的命令留在下方 chip 里，点一下再填回输入框。

## 预设命令覆盖什么

| 分组       | 例子                                                                        | 什么时候用                     |
| ---------- | --------------------------------------------------------------------------- | ------------------------------ |
| 质量门禁   | `pnpm exec tsc --noEmit` · `pnpm run lint` · `pnpm test` · `pnpm check:all` | 提交前自查                     |
| 数据库     | `pnpm db:generate` · `pnpm db:push` · `pnpm db:studio`                      | 改完 `src/server/db/schema.ts` |
| 启动与端口 | `pnpm run check:toolchain` · `node scripts/app-port.mjs`                    | 起不来、端口对不上             |
| 版本库     | `git status -sb` · `git log --oneline -20`                                  | 只读查询                       |
| 诊断       | 列出 `log/` 各分区文件与体积 · `node -v && pnpm -v`                         | 报环境问题时先看这些           |

预设表在 `src/lib/console/console-catalog.ts`，加一条只需要在那个数组里加一行
（有一条用例会核对「预设里的 pnpm 脚本真的在 `package.json` 里」，防止按钮点了报错）。

## 能敲什么、不能敲什么

**输入框不是 shell。** 它把一行拆成「可执行文件 + 参数数组」之后直接 `spawn`，
不经过 `cmd.exe` / `sh`：

- 支持空格分段、单/双引号、反斜杠转义空格；
- **不支持** `;` `|` `>` `&&` `$VAR` `%VAR%` —— 它们只是普通字符。

这条取舍是刻意的：两套平台 shell 的解析规则不同（`cmd` 认 `%VAR%`、`sh` 认 `$VAR`、
`^` 转义只有 cmd 有），同一行在两个平台上会跑出不同的东西，而界面只能有一份回显。
需要管道与重定向就写个小脚本（`node -e "…"` 或 `scripts/*.mjs`），那比在输入框里
叠一层 shell 更好读、也更好复用。

**写了控制符会怎样**：输入框下方会出现一条提示（点名命中的字符）。这不是拦你，
是提醒 —— 实测 `node -v && pnpm -v` 会变成「`node` 带上 `-v` `&&` `pnpm` `-v`
四个参数」，而 node 会**静默忽略**多余参数、以退出码 0 结束：界面上看起来一切
正常，你以为跑过了两条命令。提示就是为这个现象准备的。

## 边界：它只在**本机**可用

这条链能执行任意本机命令，所以有三道闸（顺序即成本，先便宜的后贵的）：

1. **回环检查**（`src/lib/console/console-guard.ts`）：`Host` 与 `Origin` 都必须是
   回环地址，否则 403。挡住的是「别的机器用本机 IP 访问这个服务」。
2. **会话**：与其余 REST 面同一条闸（`loginRequired` 打开时无会话即 401）。
3. **入参形态**：走上面的解析器，命令长度上限 512 字符。

**刻意不做「危险命令黑名单」**：那种清单拦不住 `node -e "…"`、`pnpm exec x`，
却会让读到它的人以为拦得住。真正的边界是「本机 + 有会话的用户」。

> ⚠️ **已知边界**（不是漏洞，是取舍）：若有反代在本服务前面，`Host` / `Origin`
> 都能被伪造成回环。本应用的分发形态是「桌面壳 + 本机 server」，不预置反代；
> 真要在反代后面跑，鉴权请由反代那一层负责。

## 一条命令在跑时

**同时只有一条**（与 ComfyUI 执行链一样是串行）。再提交会被拒绝，并告诉你
「已有一条命令在运行：X（已跑 Ns）」—— 而不是排队（排队会让人以为点了没反应）。

跑的过程中：

- 「停止」按钮掐**整棵进程树**（`killProcessTree`，硬规则 3）。`pnpm test` 起的
  vitest fork、`drizzle-kit studio` 起的服务都会一起收走，不留孤儿占着端口与日志文件。
- 「返回」（或切走视图）也会回收：面板一断连，服务端就杀掉那条命令。**不会**留下
  一条没人管的 `pnpm test` 在后台吃 CPU。
- 单条命令上限 10 分钟（`MAX_RUN_MS`），到点自动回收并在输出里说明。
- 输出转发上限 20 万字符，超了停发并提示；**命令继续跑完**（结论比日志重要）。

## 出问题时看哪里

| 症状                | 去哪看                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| 点了没反应 / 报 409 | 输出区与结论条；409 的文案会说清是哪条命令在跑                                                   |
| 命令起不来          | 输出区会有一行 `无法启动命令：…`（可执行文件不存在时给的就是它）                                 |
| 中文输出乱码        | 不该出现：子进程已强制 `PYTHONUTF8` / `PYTHONIOENCODING`；若出现请带上命令原文报障               |
| 命令的完整输出      | 面板只转 20 万字符；余量看输出区上方提示，长期日志看 `log/` 对应分区（规范 launch-and-build §4） |
