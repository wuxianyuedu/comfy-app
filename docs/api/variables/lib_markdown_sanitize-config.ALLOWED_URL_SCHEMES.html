    Variable ALLOWED_URL_SCHEMESConst

    ALLOWED_URL_SCHEMES: readonly string[] = ...

    允许在 href / src 上出现的 URL 协议。

    为什么 DOMPurify 的默认口径不够：它拦的是「可执行 / 可脚本化」的 scheme （javascript: / vbscript: / blob: / file: 实测都被剥），但放行 data: —— 对 href 它会拦（data:text/html,<script>… 实测被剥成 <a>x</a>），对 src 它不拦。而 src="data:image/svg+xml,…" 在浏览器里解析出来的 SVG 可以带脚本， 于是「markdown 里的图片」变成一条执行通道。便签与剧本预览里没有一处需要 data: 图片（上传走的是 blob: / 同源路径），因此这里按协议收口。

    前缀匹配发生在 DOMPurify 剥掉控制字符与首尾空白之后（它的 .data 钩子挂在 剪枝之后），因此 java\tscript: 这类绕过面不需要在这里再挡一次。
