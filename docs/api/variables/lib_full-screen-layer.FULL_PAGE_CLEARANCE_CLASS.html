    Variable FULL_PAGE_CLEARANCE_CLASSConst

    FULL_PAGE_CLEARANCE_CLASS: string = ...

    独立视觉页面（错误页 / 404 / 登录页）的「整屏」允许量：让出标题行、其余吃满。

    与 FULL_SCREEN_LAYER_CLASS 的区别在是否脱离文档流：全屏视图是浮层 （fixed），铺在内容区之上；而错误页 / 404 是路由页，自己就是那一屏 的内容，用 fixed 会让它失去与文档同流的滚动语义。

    又一处「铺满视口」的现场（ISSUE #1794）：错误页此前写 min-h-screen，在壳里 等于 100svh —— 从视口顶起算，把最顶端那条 36px 的标题行（页签 + 最小化 / 最大化 / 关闭）整条盖住。用户的原话正是 这个界面会挡住右上角的关闭按钮， 而它偏偏出现在「页面已经出错」的时候 —— 此刻关闭窗口往往是唯一还想做的事。

    ⚠️ 使用前提（ISSUE #1794 第二次修正）：本常量的「让位」假设标题行仍在 DOM 里。而错误页 / 404 / global-error / loading / 登录页是路由段 boundary，它们一显示就替换掉 app/layout 的整个 children —— ShellTabs 连同标题行一起卸载，让出来的是一条空带，窗口按钮整排消失。那些页面的正解 是自带精简标题行（components/studio/WindowTitleBar + components/studio/ShellFullPage），不是让位；本常量服务的是「标题行还在」 的场景。

    min-h-0 不是废话：挂在 ShellTabs 那个 flex-1 容器里的内容，默认的 min-height: auto 会让这个块撑到自身内容高度、把滚动条顶没；归零之后它才 恰好是内容区高度，多的部分自己滚。浏览器 / dev 形态下 top-title-bar 由 --spacing-title-bar（@theme 全局定义）给出 36px 空档。
