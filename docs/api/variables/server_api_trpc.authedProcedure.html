    需要登录（并带演示用户兜底）的 procedure。

    保证 ctx.user 不为 null。无会话时的放行与否由 ~/lib/auth-server 的 requireServerUser 一处判决（app-settings.json 的 loginRequired 是唯一开关）：

    • false（默认，本机单用户模式）→ 回落演示用户，与 REST 面一致；
    • true → 无会话抛 UNAUTHORIZED，不再无条件兜底。

    此前这里自带一份「无条件兜底 + 整体缓存 demo 用户」的实现，既让 loginRequired 开关在 tRPC 面形同虚设（REST 面拦、tRPC 面放——约 200 个 procedure 匿名可用），也复刻了 auth-server.ts 点名修掉的「缓存越过 数据库」缺陷（库行被重建/删除后仍返回不存在的 id）。收口到同一判决后， 两个 API 面的鉴权语义由 requireServerUser 单点持有。
