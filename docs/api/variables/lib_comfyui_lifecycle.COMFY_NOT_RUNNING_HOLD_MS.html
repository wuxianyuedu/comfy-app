    Variable COMFY_NOT_RUNNING_HOLD_MSConst

    COMFY_NOT_RUNNING_HOLD_MS: 10000 = 10_000

    「探明没在跑」的结论黏滞时长。

    为什么需要：comfyStatus 每 5s 轮询一次，而每次判定的成本是 「PowerShell 进程表查询（冷启动高负载时 ~2.5s、超时上限 10s）+ HTTP 探测」。 一次刚起来、还在加载模型的实例上，进程表查询经常超时 → 快照 unverified → 结论落「检测中…」；下一轮查询恰好成功但没命中（实例由 uv 起、命令行 里没有 main.py，见 status.ts 的判据链）→ 结论落「未运行」。于是状态行在 探针抖动里闪回「未运行」，即便进程与端口始终活着（ISSUE #442 的后半段）。

    10s 正好覆盖「一次慢探测 + 一次轮询间隔」：一处坐实，状态行不再被下一轮 的抖动打回。
