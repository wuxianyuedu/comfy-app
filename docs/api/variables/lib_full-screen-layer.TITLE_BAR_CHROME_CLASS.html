    TITLE_BAR_CHROME_CLASS: string = ...

    标题行作为应用级 chrome 的层级 class（relative z-chrome）。

    为什么让位之外还必须给层级（ISSUE #310 第三次回归）：几何让位只管「不被盖住、 不被压暗」，不管可点。第三方浮层不受本仓库的让位规则约束 —— base-ui 的 Dialog 在 modal 打开时往 body 注入 InternalBackdrop （position: fixed; inset: 0; z-index: auto; pointer-events: auto 的 div[data-base-ui-inert]），它铺满整个视口（含标题行），于是设置页「启动日志」 全屏后页签与右上角窗口按钮整排点不动。标题行是流内元素（z-index: auto）， 后出现在 DOM 里的定位元素必然在命中测试里压过它。

    修法：抬到刻度表的最高档 chrome（规范 16 §16.2.5，严格高于 toast）。 relative 不能省 —— z-index 对 position: static 的元素不生效（flex item 是特例，但依赖「父容器恰好是 flex」会让层级在布局重构后静默失效）。
