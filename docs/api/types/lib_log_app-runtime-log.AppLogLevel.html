    Type Alias AppLogLevel

    AppLogLevel: "info" | "warn" | "error" | "debug"

    应用运行操作日志（面板可见）。

    本日志器解决「中间操作看不到」问题：把应用运行期发生的业务操作 （tRPC 调用、生成、任务、工作流增删改等）以面板可解析的行格式 追加到 log/services/app-runtime.log，供应用内「应用日志」面板 经 GET /api/logs/current?source=app-runtime 实时轮询展示。

    与 comfyui-runtime / drizzle-studio-runtime 同一套「追加写 + 面板轮询」模式， 但覆盖的是应用自身操作而非外部常驻子进程输出。

    行格式 = [YYYY-MM-DD HH:mm:ss.mmm] [LEVEL] [ns] msg

    • 本地时区时间戳（面板展示给本机用户看，UTC 会差 8 小时）
    • LEVEL ∈ INFO / WARN / ERROR / DEBUG
    • ns 为命名空间（如 trpc、generate、task），可省略

    §18.4 三选一：本模块走第三类（P3 迁移第 1 期·lib 层地基批）。 摘掉 import "server-only" 后登记进 tests/lib-node-only-declarations.test.ts 的 PURE_NODE_HOSTS——上游 log-paths 已在 #1074 摘掉，本模块只依赖 Node 内建 (node:fs / node:path) + log-paths + time-format，形态与 kill-process-tree 同族；这一步是把 logger 链最后一层地基纯化：~/lib/core/logger 静态引本模块， 只要本模块带 server-only，纯 Node 里 await import("~/lib/core/logger") 就会 因这一层 throw 而 reject、comfyui 各模块（#1053 / #1068 / #1071）的 lazy 兜底 拿不到 logger、只能走 configureXxx 显式注入。摘掉后整链 logger 都能真加载。

    「面板/API 侧只读、不直接碰 DOM」这一层分工保留——它是消费者侧的约定 （API 路由把这份文件读出去给前端轮询），不是「本模块只能是 Next 专属」的意思； 写入方（Next server 与未来 executor host）都通过本模块，写入失败绝不阻塞业务。
