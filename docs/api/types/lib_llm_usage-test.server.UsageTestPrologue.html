    两个路由共用的请求前言：读 body → 取条目名 → 解析连接参数。

    为什么抽出来：POST /api/llm/test-usage 与 POST /api/llm/test-usage/query 的前言逐行相同（读 body、strField 取 name、把弹窗填的连接参数与已保存条目 一起交给 resolveUpstream），而且出错时都必须回答同一个信封 （{ ok:false, detail }）。此前两份各写一遍 —— 按行统计重合 ~79%，属规范 §12.12 的孪生对：改一处漏一处就是静默行为分叉（分叉的正是「密钥怎么解析」 与「错误文案长什么样」）。路由因此只剩「HTTP 形状」（包 NextResponse）。

    返回判别式联合而不是抛异常：调用方要原样把它翻成 200 + {ok:false,detail}， 抛异常会让「空接口地址」这类用户可修正的输入走成 500。
