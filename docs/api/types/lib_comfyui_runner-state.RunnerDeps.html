    Type Alias RunnerDeps

    runner-state 的宿主依赖注入接缝（P3 迁移第 1 期·第二/三步）。

    现状：本模块只剩一处真 IO —— persistLogs 里的 await taskRepository.replaceLogs 加失败分支的 logger.warn。这两条在加载时会牵进 server-only 链（repository 与 logger 各自带 import "server-only"），把整个 runner-state 拖回 Next 专属 上下文；纯 Node 宿主（未来的 scripts/executor-host.mjs）动态加载本模块时会撞 server-only 的入口 throw。P3 §5 第 3 步「摘 server-only」卡在这两条静态值 import 上。

    解法：deps 不再静态初始化，改为首次 persistLogs 时 lazy 解析：

    1. 若外部先 configureRunner({ taskRepo, log }) 注入了（executor host 走这条）， resolveDeps 直接返回；
    2. 否则 dynamic import() 拉 Next 侧的 taskRepository / logger 填默认 （Next server 走这条；scanner 的 parseImports 只识别静态 import 语句、 不识别 import() 表达式，因此 libOnlyReachable 与 clientReachable 两条判据都不会看见这条边）。

    类型刻意写成结构最小（只 replaceLogs / warn 两个方法），未来宿主不用 背整个 taskRepository 或 pino 的全部面。

    type RunnerDeps = {
        log: { warn(msg: string): void };
        taskRepo: {
            replaceLogs(taskId: string, entries: LogEntry[]): Promise<void>;
            replaceRawCli(taskId: string, lines: string[]): Promise<void>;
        };
    }
