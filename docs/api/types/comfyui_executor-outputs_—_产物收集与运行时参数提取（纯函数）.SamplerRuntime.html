    Type Alias SamplerRuntime

    从 ComfyUI history 的 prompt graph 里抽取本次执行实际使用的 KSampler 参数。

    为什么需要这个？KSampler 的真实 seed 来自 server 端的 control_after_generate 处理（randomize 时随机、increment/decrement 时上下浮动），写入 history 但不 出现在 entry.outputs 里（outputs 只有图像文件）。前端看到的工作流默认 seed 是 UI 元数据，对 randomize 节点而言不是真实执行值。

    形态参考（来自 0.33.1 history entry.prompt[2]）： "76:69": { "class_type": "KSampler", // 节点类型 "inputs": { "seed": 941524759465139, "steps": 25, "cfg": 4, ... } // 真实 seed 等 } // 上面 inputs 里就是本次真实执行用的参数

    一个工作流可能有多个采样节点（两段采样、放大链路各带一个 KSampler 等）。 这里把 graph 里每个采样节点按出现顺序收进 samplers，并把第一个作为「主 采样器」摊平到顶层字段——顶层那份是历史既有形态（种子落库 / manifest / 成功日志 都读它），保留它让下游零改动；要看全部采样器就读 samplers。
