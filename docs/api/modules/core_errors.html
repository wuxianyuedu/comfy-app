    Module core/errors

    errors.ts — 应用级错误体系（商业级错误分类 + HTTP 映射）

    为什么需要统一错误类型

    散落的 throw new Error("xxx") 无法被 ./api 可靠地区分「用户输入错误」 与「服务器内部错误」，导致：前端拿不到稳定的错误码、监控无法按类型聚合、 安全细节（堆栈）可能泄露给客户端。本文件定义一棵可扩展的错误类树， 每个错误自带 code（稳定字符串，给前端/日志用）与 httpStatus。

    分类约定

    错误类 HTTP 触发场景
    ValidationError 400 入参缺失/类型错误/业务规则不满足
    AuthError 401 未登录/会话失效
    ForbiddenError 403 已登录但无权访问该资源（越权）
    NotFoundError 404 资源不存在或不属于当前用户
    ConflictError 409 唯一约束冲突/并发写冲突
    DomainError 422 领域不变量被破坏（状态机非法迁移等）
    MethodNotAllowedError 405 HTTP 方法不被该资源允许（如 GET 收到 POST）
    IntegrationError 502 依赖的外部服务（ComfyUI 等）不可用
    AppError(基类) 500 未分类的内部错误（兜底）

    配合 ./api 的 toErrorEnvelope()：错误被序列化为 { error: { code, message, details? } }，绝不把堆栈下发到客户端。
