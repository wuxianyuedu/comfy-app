    Module lib/db-schema-ready

    db-schema-ready.ts -- runtime probe for "are the DB tables ready yet?"

    Why this exists

    A few modules run module-level side effects that read the database as soon as they are loaded -- the clearest example is the ComfyUI orphan-task reaper (src/lib/comfyui/reaper.ts): enqueue.ts pulls it onto the boot path with a bare import "./reaper", so a freshly started server immediately reclaims tasks abandoned by the previous lifetime.

    Those side effects have no notion of "is the DB usable yet":

    • next build loads the module graph in worker processes for every route during the collect-page-data / prerender phase, so the reaper also runs at build time;
    • on a clean checkout (CI, fresh clone) db.sqlite does not exist yet because pnpm db:push has not been run.

    The collision does not merely skip one reap -- it breaks the build: no such table: task / no such table: user escapes the worker as an unhandled rejection, Next aggregates it into a collect-page-data stage error, and the reported line points at an unrelated route file. That keeps the CI pnpm build gate red for reasons that have nothing to do with the route in the trace.

    Design

    • The probe is read-only and runs at most once (cached): it queries sqlite_master for a sentinel table, which is negligible and has no write side effect (drizzle-kit push is the only thing that creates tables);
    • The result is three-state (ready / missing / unknown) so callers own the semantics instead of this module swallowing everything: "DB is broken" and "tables do not exist yet" are different problems and only the latter should be skipped silently;
    • No new log file is introduced (spec sec.4); callers log a warn if they wish.

    NOTE (keep this file ASCII-only): Next's error code frame renderer (next-code-frame) computes highlight spans by byte offset and panics (end byte index N is not a char boundary) when a span lands inside a multi-byte character. Because this module sits on the build-time module graph it gets rendered into such a frame, taking the whole next build down with a Rust panic. Other docs in this repo are free to use Chinese; this particular file must not.
