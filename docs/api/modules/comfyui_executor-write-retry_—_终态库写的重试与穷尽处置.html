    Module comfyui/executor-write-retry — 终态库写的重试与穷尽处置

    executor-write-retry.ts — 「终态那一次库写」的重试与穷尽后的自处（ISSUE #1250）

    补的是执行链上最后一个「静默失效」口：终态写失败此前只留下一行 WARN （fireAndForget(fail(…), e => cliWarn(…))），既不重试也没有人接管 ⇒ 那一行 永久停在 RUNNING，pendingDispatch 还占着槽位（并发上限 1）把整条队列卡住， 界面上是「一直在生成」，而回收器每 30s 数到它却只打一句 checked。

    为什么是「重试 + 摘掉本进程足迹」而不是「把失败写进库里让别人接管」：写库正是失败的那件事 —— 任何依赖再写一行的接管信号在同一次故障里都不可靠。而摘足迹不需要写库： forgetTaskClaimEntirely 把 reaper.ts 的 isTaskClaimedInProcess 读的四样 一次清空（槽位、executedWorkflow、settled、comfy-cli 之外都在它管范围内），下一轮对账 就把这行判掉。只归还槽位是不够的（桌包实演量到：那一行在 RUNNING 上停了 11 分钟、 22 轮回收全打 checked 空转，因为 fail() 在抛出后再没机会清 executedWorkflow）。

    只重试锁族错误（isSqliteBusyError）：认不出原因就判不可重试，宁可少试一次， 也不要把一个真故障（例如 no such table）拖成四次同样的写入。
