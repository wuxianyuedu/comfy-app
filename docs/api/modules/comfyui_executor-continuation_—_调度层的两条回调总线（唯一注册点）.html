    Module comfyui/executor-continuation — 调度层的两条回调总线（唯一注册点）

    executor-continuation.ts — 调度层向外提供的两条回调总线（唯一注册点）

    为什么需要它

    executor 家族曾有一组互相递归的模块依赖（规范 12.7 禁止）：两条提交入口 （CLI 与 WS 通道）都流向收口层（complete / fail / finalize），收口层再流向 调度层「让队列继续跑」，而调度层执行任务时又必须回到通道层与 CLI 层——三步 首尾相接成环。当时只靠 executor.ts 的一句注释「加载期是安全的」维持， 没有任何测试。

    解法是依赖倒置：调度层在模块加载时把实现注册进来，收口侧与通道侧只调本文件 的两个出口，不再 import 调度层。依赖方向因此单向：

    dispatch → {cli, ws, finalize} → continuation（叶子）

    两条总线是同一件事的两个方向： • kickQueue —— 收口 / 取消之后「再领一次」（省掉等 2s 节拍）； • announceToQueuedTasks —— 通道层要告诉还在排队的任务「ComfyUI 正在 自动启动 / 已就绪」，而「谁在排队」只有调度层知道（内存队列删掉之后， 排队的真相在库里）。

    为什么这样是安全的（不是「差不多能用」）

    • 注册发生在调度层模块体里，而任何收口/通道调用都晚于它：入口是 enqueue.ts → ./executor → ./executor-dispatch，两侧的加载都先于第一次调用。 executor.ts 特意再导出 dispatch 的三个入口，就是为了让这条注册不依赖 src/instrumentation.ts 那条懒编译路径什么时候跑完。
    • 注册缺失（例如被纯单测单独加载某个收口模块）时不静默空转：调度层还有 2s 的常驻领取循环兜底，缺注册时各打一次 warn，避免「队列悄悄停住」无人察觉。
