    Module core/events

    events.ts — 类型化领域事件总线（Observer / Pub-Sub 模式）

    解决的痛点

    任务状态变化（创建 / 完成 / 失败）、项目更新等事件，当前要么靠 SSE 直接推前端， 要么散落在执行层（runner.ts）里用回调硬耦合。这导致：

    • 新增「任务完成时清理缓存」这类副作用，必须改执行层主流程；
    • 同一个事件的多消费者（日志、通知、SSE、缓存失效）相互纠缠。

    本总线把「事件发生」与「事件处理」解耦：生产者只 emit，消费者各自 on。 这是经典 Observer 模式 的类型安全实现。

    关键保障

    • 类型安全：事件名 → 载荷形状由 DomainEventMap 强约束， emit("task.completed", payload) 的 payload 类型由事件名推导；
    • 故障隔离：某个 listener 抛错不影响其他 listener 与 emit 调用方， 错误被捕获后走 ./logger，避免「一个订阅者崩溃拖垮整条链路」；
    • 可退订：on 返回 () => void 取消订阅函数，组件卸载时调用即可，无泄漏；
    • 零依赖：仅基于 Map + Set，无外部库。

    与 SSE / reaper 的关系

    执行层在关键节点 emit 领域事件；SSE 推送、缓存失效、审计日志等作为独立 listener 订阅。未来 reaper 也可订阅 task.expired 做统一回收， 不再把回收逻辑写死在单一模块。
