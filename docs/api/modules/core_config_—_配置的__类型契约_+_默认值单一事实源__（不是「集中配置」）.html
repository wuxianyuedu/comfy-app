    Module core/config — 配置的**类型契约 + 默认值单一事实源**（不是「集中配置」）

    config.ts — 配置的类型契约 + 默认值单一事实源（不是「集中配置」）

    本模块不承诺「所有配置都从这里读」。

    它的注释曾经写着「任何模块都应 import { config } from "~/lib/core" 后读取， 而不是再直接读 process.env」—— 而实测这句承诺与现状恰好相反：

    · src/lib 里直接读 process.env 的地方有 30+ 处（comfyui 实例端口与 executor、llm 密钥、app-settings、kill-process-tree、open-in-browser …）， 其中绝大多数改不动：config.ts 自己的 schema 只覆盖 7 个变量，而 真实用到的还有 COMFYUI_PATH / COMFY_CLIENT_ID / LLM_* / FFMPEG_BIN / COMFYAPP_TASKKILL 等一大批； · 于是「集中配置」只写在注释里，实际是第 N 条口径 —— 下一个人照着改， 只会再多一条。

    裁决（ISSUE #568）：删掉误导性承诺，把本模块降级为「契约 + 默认值」， 不假装收口。保留的三件事都是有消费方的：

    1. AppConfig / NodeEnv 类型契约（buildConfig() 的产物形状）；
    2. 被复用变量的类型化读取与默认值 —— CONFIG_ENV_DEFAULTS 导出的 COMFYUI_BASE_URL / COMFYAPP_PORT 默认值，前端设置页与后端各自读 process.env 时都从这里取（避免同一默认值在两侧漂移，规范 §12.14）；
    3. features 的开关型配置（REAPER_ENABLED / DEBUG_MODE_DEFAULT）—— 这两个变量的语义是「跑起来之后仍可能被读」的开关，与启动期固定的 连接串不同，收在这里读是合适的。

    校验失败行为

    若环境变量值非法（如 COMFYUI_BASE_URL 不是合法 URL），模块加载即抛出 带字段名的可读错误（fail-fast），而不是在第一次请求时崩溃。

    新增配置项时怎么选：与「连接 / 端口 / 库路径」有关的、两侧都要读的 变量，默认值放这里；纯启动期路径（如 COMFYUI_PATH）就地读 process.env 并写清为何不收口，不要为了「看起来集中」把它硬塞进来。
