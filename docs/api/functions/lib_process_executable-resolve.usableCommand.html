    • usableCommand(
          candidate: string,
          probeArgs?: string[],
          __namedParameters?: WhichCommandOptions,
      ): CommandUsability

      这个候选现在能不能被 spawn 起来。

      判据按形态分派（不是「一层层试」），任一路失败即落到同目录回退：

      1. fs.accessSync(X_OK) —— 权限位。POSIX 上这层就能拦下「文件在但不可执行」； Windows 上 Node 把 X_OK 当存在性检查（恒通过），所以形态判据才是主力。
      2. Windows 上的批处理（.cmd / .bat）不真起：它只有 cmd.exe 会解释， Node 起它必然 EINVAL。此前它与 .ps1 混成同一种 script 形态、被直接 认作「可用」，于是选中 pnpm.CMD（ISSUE #576 第二轮现场）—— 而 pnpm.ps1 就在旁边，回退目标稳定可得。POSIX 上 .cmd 是无谓形态，不受此条约束。
      3. 其余形态真起一次确认（binary / shebang / script / unknown）： 这是唯一能证明「Node 真能起它」的办法（spawnSync + stdio: "ignore"， --version 报错退出也算起得来），起不来再落回同目录 .ps1。 shebang 留在这里而不按形态一刀切：libuv 在 Windows 上不解析 shebang， 起不来会走回退；但机器上真配好了文件关联时它确实能用，不该被形态否掉。

      探测用的参数取自调用方真正要跑的第一个参数（whichCommand(..., { probeArgs })）。
