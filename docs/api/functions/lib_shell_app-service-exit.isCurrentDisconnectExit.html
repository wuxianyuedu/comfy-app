    • isCurrentDisconnectExit(
          record: AppServiceExitRecord,
          currentRunId: string | null,
          now: number,
      ): boolean

      记录「是不是这一次断开留下的」——断开那一刻读回时用的判据。

      与 isPreviousRunExit 恰好相反：那条判的是「记录说的是上一份进程」 （服务恢复后读回时的语义），而断开那一刻要判的正是「记录说的是刚刚没了的 这一份」。所以：

      · 两边 runId 都有值 → 相等才算（不等说明盘上留的是更早那一次的结论）； · 任一方为 null（老启动链路 / 手工 pnpm dev）→ 退回新鲜度判据： 记录是多久以前写的。刚断的这一刻，旁证人写下它不过几秒；盘上那份若是一小时 前的，它描写的是更早的一次结束，拿它当「这一次的原因」就是编。

      为什么必须有新鲜度这一档：这份文件是单槽的（每次结束覆盖写），所以「盘上有 一份记录」既可能是刚写的，也可能是几天前留下的。只判「存在」会把旧结论说成这一次 的原因——归因猜错比不归因更坏，它会把排查引向另一条路（同 describeAppServiceStart 的注释）。
