    Function sqliteAwareErrorText

    • sqliteAwareErrorText(error: unknown, action: string, fallback?: string): string

      捕获到的失败要写进日志时用它：是库失败就把驱动码与原因带上，其余一律走通用文案。

      为什么要有这一层，而不是让每处 catch 自己判断（ISSUE #1262 的直接起因）： errorText 的本职是「动作：详情」那一行字，它只取 message， 而 drizzle 把真实原因挂在 error.cause 上 —— 于是执行链上那些库写失败的捕获点 （领取、等待提示、回收器对账、续跑、收口异常）到今天为止都只打出一句 Failed query: update "task" set …，看现场的人分不清是锁、是没表、还是别的东西。 #1250 只把「终态那一次写」那一条修好了；剩下的路都还是瞎的。

      参数与 errorText(e, action, fallback) 逐位同形（换过去不改任何一处调用语义）： action 是动作名、一定会出现在结果里，fallback 只兜「详情取不到」那一半。

      三条分支： · 认得出码 ⇒ 动作：原句（SQLite: CODE / cause 消息）； · 是库失败但链上没码 ⇒ 同一句 + 明说取不到的尾巴 —— 空白会被读成「没有原因」， 而真实情况是「原因在链路里丢了」，这两件事必须区分开写； · 不是库失败 ⇒ 原样交给 errorText（网络错翻译那些本领一条不丢）。

      • action: string
      • fallback: string = "未知错误"
