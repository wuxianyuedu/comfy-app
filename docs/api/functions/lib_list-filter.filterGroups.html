      分组过滤：保组序 + 丢空组。

      两条语义各有一条反例作证：

      1. 组序按原数据，不按命中数重排 —— COSTUME_OPTIONS 的顺序（中式 / 日韩 / 西式…）是内容组织，用户搜「旗袍」时不该因为「日韩」命中更多就把它提到前面： 同一个关键字连输两次、分组顺序会跳，那是「界面在动」而不是「结果在变」。

      2. 空组必须丢 —— AttributeMultiSelect 此前只在全空时给「未找到匹配 项」，中间的空标题仍会渲染出来：搜「旗袍」时「中式」下面一条结果、 紧跟着的「日韩」下面什么都没有，却还是留着一个小标题。

      返回新对象数组，原数组不动 —— 调用处直接 map 是安全的。
