    Function describeSqliteWriteError

    • describeSqliteWriteError(error: unknown, fallback?: string): string

      一条带原因的失败文本：基础消息（SQLite: CODE / cause 消息）。

      基础消息取原错误的 message（drizzle 的 Failed query: … 保留了 SQL 与参数， 复现现场要用它），后括号里是给人看的原因。找不到任何 cause 信息时退化成 原 message 或 fallback —— 与本仓「失败路径必须有可读文案」（硬规则 4）同口径。

      预算先给原因，再给 head（ISSUE #1262 复演读数逼出来的顺序）：drizzle 的 head 里 连着 params:，参数一长就能吃掉整个 LOG_DETAIL_MAX —— dev 那一格实测 655 字的一行里 「工作流校验未通过…」的模型清单把 （SQLite: SQLITE_BUSY…） 挤成了省略号， 于是这一条改造刚承诺的「原因看得见」在长 head 下又失效。原因才是判「锁 vs 没表」的那一半， 永远不能被现场细节挤掉。

      • error: unknown
      • fallback: string = "SQLite 写失败"
