      建 host 片自己的仓储：libsql 文件库 + 那份共用 PRAGMA 清单，与 Next 侧同 schema。

      dbFile 由入口算好传来（绝对路径判据在入口那侧：ROOT 与 process.chdir 都在 它手里），这里不碰 process.cwd()，保证两种加载形态读到同一个库。 PRAGMA 走 ~/lib/sqlite-pragmas 那一份而不是本地再列两行：宿主与内嵌 server 写的 是同一个库文件。等待预算则只能由 timeout 这个客户端选项给：file: 客户端是 连接池，开机那条 PRAGMA busy_timeout 只落在它当时借到的那一条连接上，池后开的 连接没有预算（实测：那种形状撞锁 11ms 就抛；带 timeout 才会等）。 预算给在本侧、不给 Next 侧的理由见 sqlite-pragmas 文件头：同步等锁会占住本进程 事件循环，宿主是为执行而生的进程，Next 还要响应界面。 清单的应用走 applySqlitePragmas（撞锁有界重试）：三处站点要的是同一件事， 各写一遍就必然漏一处（ISSUE #1282）。
