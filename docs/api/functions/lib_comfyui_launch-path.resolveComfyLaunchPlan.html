    • resolveComfyLaunchPlan(
          installDir: string,
          exists?: (p: string) => boolean,
      ): ComfyLaunchPlan | { error: string }

      从 comfyuiPath 推导启动命令。

      comfyuiPath 语义（桌面版推荐配「实例根」）：

      • 便携版 / venv：指向「源码根」——目录直接含 main.py，python_embeded 或 .venv 与之同层（或 python_embeded 在便携根、main.py 在 ComfyUI/ 子目录）。
      • ComfyUI Desktop 实例根：目录含 ComfyUI/ 子目录（main.py 在其中） 与 standalone-env/（运行时解释器）。例如： ComfyUI-Installs/ComfyUI2/ ← 实例根 ├── ComfyUI/main.py ← 源码目录 └── standalone-env/python.exe ← 运行时解释器 把 comfyuiPath 配到实例根即可，无需精确到源码子目录。 也兼容反向配置（把 comfyuiPath 指向实例内的 ComfyUI/ 源码根）—— 解释器会向上到父级实例根查找。

      解释器选择（两段式）：在候选优先级之内，优先选 site-packages 里装有 torch 的环境——依赖位置随安装方式漂移，固定优先级会选中空壳解释器 （启动即 ModuleNotFoundError: No module named 'torch'）。全缺时按原 优先级返回并在 hasDeps=false 标记，由调用方提示用户。

      解释器一律解析为 python.exe（不用 pythonw.exe——后者吞掉 stdout/stderr， ComfyUI 启动出错时看不到任何日志，无法排查）。工坊/工作室只把 ComfyUI 当 后端服务（python.exe + main.py 起的是 server，不是桌面版 GUI）。

      • installDir: string
      • exists: (p: string) => boolean = fs.existsSync
