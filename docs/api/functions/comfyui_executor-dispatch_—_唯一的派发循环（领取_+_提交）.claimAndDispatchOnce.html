    • claimAndDispatchOnce(
          options?: { skipReadyGate?: boolean },
      ): Promise<string | null>

      一次领取尝试；返回领到并交棒给执行链的 taskId，没领到返回 null。

      一个 tick 最多推进一个任务（MAX_CONCURRENCY=1）。不抛：调用点是定时器与 收口后的续跑，任何异常都要变成「下一拍再来」而不是 unhandled rejection。

      顺序即判据，三步都不许调：

      1. 就绪门控（WS OPEN）——不就绪就不领行，行留在 QUEUED；
      2. 槽位（本进程在飞数 < MAX_CONCURRENCY）——满了也不领，同样是 QUEUED；
      3. 领取（单语句原子，见 impl 的 claimNextQueued）→ 重建 Job → 提交。 先领后判会把行翻成 RUNNING 却什么都不跑，那正是 §14 D1 要消灭的形态。

      skipReadyGate 只给 executor-host.mjs --claim-once 那个契约/排障钩子用： 它要验的是「领取与载荷重建的机械步骤」，而那在不跑真 ComfyUI 的机器上永远 过不了就绪门控。常驻循环与提交后的 kick 都不传它。
