    • buildRunScopedOptions(
          current: PackLogFile[],

      把「本次运行的份」与「各历史包里的份」拼成一条时间线（新→旧）。

      顺序口径

      先按次运行分组（本次在最前，历史包按名字倒序 = 时间倒序），每组里面再按 份的时间倒序。不能把两边混成一条扁平的按时刻倒序：那会让「本次运行的第 1 次 启动」夹在「上一包的第 3 次启动」与「上一包的第 2 次启动」之间 —— 用户是拿 这个下拉定位一次运行（run.json 的 runId 是 grep 的入口、退出形态是 「该不该看」的第一判据），分组语义比全局时刻序更有用。

      本次运行恒在最前

      即使它的时刻比某个历史包更早（时钟回拨、包名手改）也保持这个顺序：这一栏的 语义是「正在写的这一次」，位置固定比时刻准确更重要 —— 用户按「最上面那一项」 找到当下，是这条下拉最高频的用法。

      Parameters

      • current: PackLogFile[]

        current/ 里该来源的份（旧→新，与 listRuntimeLogFiles 同序）

      • packs: RunPack[]

        历史包（新→旧）

      • max: number

        列表条数上限（超出时取最新的那些）

      • total: number

        该来源跨包一共有几份（不受 max 影响；界面据此说明被截断）

      Returns { sessions: RunScopedOption[]; total: number }
