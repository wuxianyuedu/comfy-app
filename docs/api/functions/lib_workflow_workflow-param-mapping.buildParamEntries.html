      把 IO 条目聚合成统一对外参数条目（顺序 = 契约顺序，与工作流无关）。

      此前这里是「按节点 + 分类」聚类 —— 结果是一份跟着工作流走的清单：同一个 「提示词」在不同工作流里叫 text / positive_prompt / value_1，卡片列表于是 变成工作流内部参数名的大杂烩（value / value_2 / resolution_preset…）。 现在条目来自契约表（exposedParamsForMode）：对外有哪些参数只跟模式有关， 工作流只决定「每个统一参数落到哪一行端口」。

      · mode 给出时按契约过滤：契约里没有的口子（步数 / CFG / 采样器…）一律不出现； · 契约口一律常驻：契约列了哪些对外参数就返回哪些，工作流能不能承接是 落点问题（pins 为空 ⇒ 如实显示成「未配置」），不是「这一口存不存在」 的问题。这里不判断工作流的能力； · 不传 mode 时保持旧的「按节点 + 分类」聚类（供没有模式语境的调用方使用）。

          必须传的情形：模式契约被用户改过（契约编辑器里标「已改」）。内置默认只是 「没改过时」的回落 —— 拿它当口径会让画布多列出契约里没有的口（用户报的 「画布上有时长，模式契约里没有」），也会漏掉用户在契约里新增的口。
