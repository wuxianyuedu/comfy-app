      返回 NextResponse 而不是抛：调用处需要原样把它返回，而 try/catch 会把「格式错误」与「业务失败」混在同一条控制流里 —— 那正是 llm/route.ts 现在难读的原因。

      畸形 JSON 不再被当成空对象（custom-nodes / llm/test / workshop/logs 的旧写法）：坏请求回一句明确的「请求格式错误」，比让它走到「字段缺失」分支 回一句与病因无关的话要好。既有落点若确实依赖「空对象」语义（读字段处 都已按缺省处理），这一改动只是让错误更准确 —— 它们不会因此多出失败路径。
