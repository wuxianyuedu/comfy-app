    Function classifyLivenessPhase

    • classifyLivenessPhase(facts: LivenessFacts): LivenessPhase

      此刻该按哪个阶段给频率。

      判据顺序有意如此（最紧急的排最前）：

      1. verifying —— 崩溃复核不等下一拍，这一拍必须立刻发；
      2. hidden —— 用户看不见，先降到省资源档（此时发不发都不影响观感， 但不该因为「反正没人看」就完全不判活：最小化后 GPU 崩了、 切回来才发现，比慢一拍更坏）；
      3. starting —— 用户在盯着转圈，越快越好，且此时没有别的负载；
      4. generating —— GPU 繁忙，降压；
      5. 其余 = idle。

      「启动中」压在「出图」之前：一个刚拉起、模型还没加载完的实例队列里可能已经 有活儿（busy 为真），但此刻的主诉是「转圈要结束了吗」，而它没有生成 负载 —— 用出图档的 30s 会把「就绪」拖成半分钟。

      • facts: LivenessFacts
