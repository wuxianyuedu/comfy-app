    Function handleIdForIoKey

    • handleIdForIoKey(
          io: WorkflowIOMap | null | undefined,
          ioKey: string | null | undefined,
      ): string | null

      映射落点（resolved 的值，= ioKey）→ 画布渲染侧那条端口的 React Flow handle id。

      ⚠️ 现状：画布渲染侧直接用 ioKey 当 handle id（见 WidgetInputRow 的 handleId）。pin 名 这个旧口径在「两个节点 有同名 pin」时会让边接到同名 handle 的第一处 —— 表现就是「线连到了别的节点 上」。库内卡片圆点（paramOutputPorts 的 handleId）同样取 ioKey（尺寸卡取 子口 id），两处同键空间、不再需要换算函数。

      两个键空间必须分清（ISSUE #374）： · ioKey（<nodeId>::<kind>::<name>）是 workflowIO 的字典键，运行期 io[target] 回查靠它，落库的 paramMap.source.mode:<模式> 也存它； · handle id 是节点卡片上 <Handle id=…> 的 DOM id，画布渲染统一取 pin 名（= WorkflowIOEntry.name）。 谁拿错一方都查不到：React Flow 在 handleBounds 里找不到边引用的 id 时， 会丢弃整条边并逐条打 error#008（用户看到的是「线画不出来」）；拿端口名去 查条目表则必然落空，表现为手势被静默拒绝。

      ioKey 末尾的 name 段不保证可切分（pin 名本身可能含 ::），所以一律 经 io 反查 entry.name，而不是对字符串做 split。查不到（条目已被移除 / io 未就绪）时返回 null，调用方据此不画线。
