    Function resolveExistingPath

    • resolveExistingPath(candidate: string, exists?: ExistsProbe): string | null

      把候选收成最长存在前缀（不存在则 null）。

      为什么是「前缀」而不是「整串」：候选由文本判据扫出来，为 Program Files 这类 带空格的路径让过路，于是常常多带一点尾巴（F:\a\b.log。 的残留、裁开关留下的 半个词）。往回逐字符退，第一个在磁盘上真有的就是用户要的那个。

      退法只在最后一段内（不穿过分隔符、也不整段整段地退）。这条限制是刻意的： 整段退会退出一堆「路径片断」（F:\a、F:\a\b），它们可能真存在，于是 「打开到哪里」完全取决于哪一级先命中 —— 用户点 F:\a\b\c 却打开了 F:\a， 而界面上没有任何东西解释为什么。比不可点更糟（与文本判据里「不认相对路径」 同一条原则：宁可漏，不可指错）。

      那「多带了一整段」怎么办？—— 不需要这里管：候选里的多余内容一定落在最后一段 内。尾随标点、裁剩的开关、连进来的普通词都出现在最后一个分隔符之后 （…\dev-launcher.mjs --mode prebuilt 的 --mode prebuilt 就在最后一段里）。 真出现「整段多余」时结果为 null，用户拿到「路径不存在」的反馈（有出口、可纠正）。
