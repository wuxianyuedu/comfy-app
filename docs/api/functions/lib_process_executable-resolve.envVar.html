      读一个环境变量，按平台的大小写语义（windows 上不敏感）。

      为什么非要有这一层（ISSUE #1961，平台侧 E2E 的最后一格）

      Windows 上 process.env 是一个大小写不敏感的代理，而 { ...process.env } 出来的是普通对象 —— 键名按系统存的写法来（Windows 常把 PATH 存成 Path）。 于是同一份环境「直接读」与「复制一份再读」会得到不同答案：

      · resolvePython() 默认读 process.env（代理）⇒ env.PATH 拿得到； · checkPythonReady({ env: { ...process.env } }) 传下来的是复制品 ⇒ env.PATH 是 undefined ⇒ 这里扫一个空 PATH ⇒ 判「这台机没有 Python」。

      现场：同一个 stage 里 Python 探针读数 报 ok python → D:\Program Files\Python312\python.exe， 而 E2E 关键流程 报 PATH 上没有可用的 Python —— 差的正是「读的是代理还是复制品」。 判据在 tests/preflight-python-env-case.test.ts。

      POSIX 上环境变量大小写敏感（Path 与 PATH 是两个变量），所以那一边只认 精确写法 —— 这一层不改变 POSIX 的任何行为。
