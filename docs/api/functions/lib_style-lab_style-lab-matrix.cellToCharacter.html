      一格 → 一份能交给 buildCharacterPrompt 的角色卡。

      这一屏存的不是角色卡而是「组合」，但提示词的组装口只有角色卡那一份 （~/lib/workshop/prompt-builder：身份 → 氛围 → 风格标签 → 技能模板）。批量扇出 要复用那条顺序，就得把一格临时投影成一个 Character —— 投影而不是另写一份拼接： 拼接逻辑抄第二遍时，工坊那边改了顺序、这边还出旧秩序的提示词（§12.12）。

      几条刻意的取舍： · name 用风格标签占位。它只是这一格的展示替身，不是真人物角色的名字 —— 矩阵的语义就是「同一个座位换风格」，所以风格才是这一格的身份； · positivePrompt / negativePrompt 留空串。它们是 buildCharacterPrompt 的输出、不是输入：把已经拼好的句子再塞回角色卡，就有了两处真值（角色卡 里那份、格子里那份），而这一屏要存的提示词只在 styleExperimentCell.prompt 落一次； · 四个特征维度按固定轴 id 读（costume / appearance / personality / temperament，即 CHARACTER_ATTRIBUTES 去掉 styleTags 那几维）。这里只能 写死键名，因为 Character 的字段本来就是这四个一一对应的具名属性。

      已知限制（照此实现，不在这次改动里补 UI）：创建表单目前不收 ageGender、 也不收技能选择，所以这两个值只能来自试验的 params 快照 —— 快照里没有就是空 / 缺席。要给用户加这两栏，得先立「它存进 params 还是 traits」的口径，那不属于这一刀。
