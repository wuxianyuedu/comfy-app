    • parseSubgraphLinks(
          sub: RawSubgraphDef,
      ): {
          boundaryLinkInfoById: Record<number, BoundaryLinkInfo>;
          linkById: Record<number, SubgraphLinkEntry>;

      建一张 link-id → {src, slot, type, targetId, targetSlot} 的查找表， 好把原始格式的连线对象还原成 API 格式的 [srcId, srcSlot] 元组， 填进每个目标节点的输入。

      注意：较新的 ComfyUI 里 sub.links 是对象数组，不再是旧版的扁平元组 数组： { id, origin_id, origin_slot, target_id, target_slot, type }（字段名照旧） origin_id 为 -10 / -20 的是子图用来标记跨边界连线的哨兵「输入/输出」节点； 我们把它们排除在 API 图之外，画布上就显示成一段没有连接的内部端口。

      另外把每条带哨兵的连线记进 boundaryLinkInfoById， 路由响应便能交给画布一份精确的「边界 pin id ↔ 内部节点 handle」映射。 这一版取代了此前「按内部节点是否消费/产出边界连线，把它标成端点」的做法 —— 后者会在每个内部节点都恰好在边界上时出问题（例如一个小的 NOISE 子图， 10 个 RandomNoise 节点各自的 noise_seed 输入与 NOISE 输出都要穿封装节点）， 表现为内部节点 id 互相碰撞、中间的卡片整片消失。 干净的做法是把边界 pin（definitions.subgraphs[u].inputs / .outputs） 当作一等实体，见下面的 boundaryPins。
