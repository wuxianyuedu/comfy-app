      把「这套风格 × 这组特征」展开成整批座位（顺序 = 风格外层 × 组合内层）。

      两条与算式对齐的口径： · styles 为空时按「不约束风格」占一列（seat 的 style 是空串）。这与 combinationCount 给空维按 1 计同一条判据 —— 否则「只勾了特征、没勾 风格」会展开成 0 格，而界面上那句「N 风格 × M 特征 = K 格」按同一口径给的是 1 × M = M，两边各报一个数就是这一屏最难查的那类错。 · 结果长度恒等于风格数 × enumerateCombinations 的长度，因此也恒等于 界面预览的格数。

      落库的只有 style 与 traitKey 两列：seatKey 是读回来现算的比对键（重跑时 「这一格跑过了」判的就是它）。把组合键也存一列，等于给同一个事实两个真值 —— 改了一边、另一边仍在参与判重，就会静默少出一张图。
