    Function errorCode

    • errorCode(e: unknown): string | null

      从 unknown 抛值里取出 tRPC 错误码（FORBIDDEN / BAD_REQUEST / …）。

      为什么需要一个「取码」的出口：文案（errorMessage）回答「哪儿错了」， 码回答「我该不该再试」—— 前者是给人读的，后者是代码要分支的。全库此前只有 rawErrorDetail 在读码，而它把码拼进日志字符串就丢掉了，于是调用方想分 「服务端确定不收这个内容」与「此刻拿不到服务端」两种失败时，只能去匹配文案 ——文案一改判决就错。§11.2.1 第七条给服务端侧定了同一条口径（闸门要判整个信封、 含码），客户端侧此前没有对应的取值出口。

      取值优先级与 rawErrorDetail 共用一条链（data.code → shape.code → code）：tRPC 客户端把码放在 data，服务端 shape 里也有一份，裸 Error 上 可能有人自己挂了一个。取不到（不是字符串、或空串）返回 null。
