      把一个画布节点放进项目画布 —— 全库唯一的入口（规范 16 §16.2.4.38）。

      收口前的三处（右键菜单两个入口、媒体拖放与「加入画布」按钮）各写一遍同样 的四步，而每一步的判据都不一样：

      决定的 写法 A 写法 B
      落点从哪来 拖放用指针（e.clientX），按钮用视口中心 右键菜单用手写菜单坐标（menu.x / menu.y）
      screenToFlowPosition 的入参 有时传屏幕坐标（正确） 有时传画布坐标（错，节点会越点越远）
      视口中心怎么算 window.innerWidth / 2 两处逐字相同，第三处（工坊侧）用容器尺寸 —— 三份口径
      节点数据怎么补 { ...defaultData(kind), 媒体字段 } 少写 ...defaultData(kind) 会让新节点缺 20 个必需字段

      出口把四步收成一次调用：取落点 → 换算 → 组节点 → 追加。 「新节点带什么数据」仍由调用处给（data 是域判据：媒体节点带 mediaPath， 工作流节点带 workflowId），出口只负责基座（id / type / position）。

        • data: CanvasNodeData

          节点数据 —— 出口会把它铺在 defaultData 之上，缺字段由默认值兜住。

        • flow: CanvasPlacementContext

          画布坐标换算（useReactFlow().screenToFlowPosition）。

        • OptionalflowPosition?: XYPosition | null

          *已经在画布坐标里**的落点 —— 当坐标本身来自画布（如「源节点右侧 340px」） 时用它，出口就不再换算。与 point 二选一。

        • Optionalid?: string

          显式指定 id —— 只在调用处需要提前拿到它时给（自动连线要用同一个 id 建边：工作流跑完自动孵化下游节点时就是这种情形）。缺省由出口生成。

        • nodes: Node[]

          当前节点表（setNodes 的 updater 入参）。

          ⚠️ 类型刻意取 React Flow 的 Node[] 而不是 CanvasNodeType[]： 调用处的 setNodes 声明各式各样（useNodesState<CanvasNodeType> 给 CanvasNodeType[]，useReactFlow().setNodes 给 Node[]）， 而出口只做追加、不读节点结构的任何字段 —— 收成 CanvasNodeType[] 会逼着每个调用处写一句断言（eslint 又会把「不必要的断言」拦回去， 两边互相打架）。

        • Optionalpoint?: DropPoint | null

          落点（屏幕坐标）；缺省落在视口中心。
