      解析某一模式下生效的「对外参数 id → 目标 ioKey」表。

      判据只有一条：作者在这个模式里画的线（manualByMode[mode]）。没有线 的口子不出现在结果里 —— 调用方按「取不到 = 未配置」如实呈现，绝不替作者 猜一个落点（见文件头：猜错了用户看不出来）。

      manualByMode 的形状是 { [mode]: { [entryId]: ioKey | null } } —— 按 模式归拢，与落库的 source.mode:<模式> 一一对应；查一次即得该模式下 所有被作者改过的线。显式 null（作者断开）保留在结果里（值就是 null）， 它与「没连过」在语义上不同：前者是「这条口故意不接」，后者是「还没配」。 io 只用于校验落点仍然存在（端口被改名 / 移除后，一条指向不存在端口的 线会让运行期静默落不到值 —— 这种线按未配置处理，与画布上画不出线一致）。
