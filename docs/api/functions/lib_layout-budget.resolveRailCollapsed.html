      谁说了算，三档优先：

      1. 本次会话在当前这一档窗宽下表过态（点过开关）→ 听用户的；
      2. 否则窄窗 → 纪律接管，收起；
      3. 否则 → 用户存下来的偏好（cookie 读出的 defaultOpen）。

      为什么用「跨越次数」而不是「表态时是否窄窗」来判断过期：后者挡不住来回拖窗口 —— 用户在窄窗点开后放大、再缩回来，两次的「窄窗」标记相同，那次豁免就会永久否决纪律。 而窗口每跨越一次阈值，次数就变一次，语义正好是「再次跨越 → 纪律重新接管」。 这让生效态是纯推导的，不需要在 effect 里清标记（本仓库 lint 判据 react-hooks/set-state-in-effect 不容那种写法）。

      preferredOpen 是跨会话存下来的那一档：它相当于「宽窗档的一次表态」，所以只在 宽窗生效 —— 拿记忆去否决当次的窄窗让位，等于让偏好挡住布局纪律。
