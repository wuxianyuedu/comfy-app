    • withTimeoutResult<T>(

      与时间赛跑，但超时给兜底值而不是抛错。

      用于「拿不到就当没有」的探测类落点（端口探测 / 中介进程读 stderr）： 它们本来就把「超时」当成一种结果，包成异常只会让每个调用处都写一遍 try / catch 去把它转回值 —— 那正是收口前 resolve({code: -1, stderr: "timeout"}) 那两处的做法。

      fallback 是值不是工厂：调用处要「按当时的状态算出兜底」请自己包一层 （withTimeoutResult(p, ms, null).then((r) => r ?? computeFallback())）—— 出口不猜兜底值依赖什么。
