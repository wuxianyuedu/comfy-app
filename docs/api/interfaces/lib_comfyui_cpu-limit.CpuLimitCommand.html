    Interface CpuLimitCommand

    该档位要求施加的命令形态（off 返回 null = 什么都不做）。

    返回的是「要调用的可执行文件 + 参数」，而不是「去调哪个 API」：两条链路 （Windows 的 WMI/PowerShell、POSIX 的 renice/taskset）都是命令行能力， 而注入命令行是唯一能让用例在不起真进程的前提下断言形状的做法 （与 kill-process-tree 的 taskkillPath 注入同款）。

    三处平台事实集中在这里，不做「按平台 if 两遍」的散写： · Windows：powershell.exe -NoProfile -Command 走 WMI 的 Win32_Process 优先级属性。不用 Start-Process -Priority —— 那要求由 PowerShell 自己起进程，而保活路径的子进程是 spawnManaged 起的（Start-Process 的孙进程），拿不到它的句柄再改优先级；按 PID 改 是唯一对两条路径都成立的形态（bound 与 keepAlive 都拿得到 PID）。 · POSIX：renice 调优先级、taskset 调亲和性。两者都是 util-linux / BSD 基座的常备件，但仍可能缺失 —— 缺失时按「本档不生效」处理并 留一行日志，绝不让它把启动搞挂（见 apply）。
