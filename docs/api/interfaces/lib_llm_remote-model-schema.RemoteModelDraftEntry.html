    Interface RemoteModelDraftEntry

    弹窗草稿 → 条目字段。model → name 这一跳只在这里。

    为什么值得抽出来：这一跳过去在 submitDialog() 里写了两遍（新增与编辑各一遍）， 而它连的是两个各有名字的形状 —— 草稿叫 model（历史上也叫 name），条目叫 name； 改名或加字段时两边各改各的，中间没有任何东西知道它们该是同一枚模型。

    留空的两条既有口径都在返回值里说清，调用点不再各自拼： · baseUrl 空白 → null：新增与编辑在这一条上本来就同形（写入侧都折成 「跟随已保存的全局配置」），过去一边写 undefined、一边写 null 只是写法不同； · apiKey 空白 → 这一项不给意见（undefined，于是写入侧保留库里既有值）。 它不能折成 null：两态写法会让「没动过」被读成「清空密钥」，而设置页每次保存 都是整份覆盖（三态的理由见 ~/lib/llm/types 里 RemoteModelEntry 那段，台账 A11）。 显式清空由编辑侧的 clearApiKey 表达，它不在这里 —— 那是勾选框的意图， 不是草稿字段能算出来的事。
