    Optionalplatform

    platform?: Platform

    keepAlive 的两条平台分支的分叉判据。缺省 process.platform。

    为什么它是一个入参：process.platform 在 POSIX 宿主上是不可覆盖的 自有属性（实测 descriptor = {writable:false, configurable:true}， 值恒为宿主平台），于是「Windows 中介形态」那组判据在 Linux/CI 上根本 进不到被测分支 —— 实测 spawn 收到的是 POSIX 形态 （{detached:true, stdio:全 ignore}），而断言写的是 powershell.exe， 五条用例恒红；把判据搬到入参之后，两端机器判的是同一个结论。 注入的是判据的输入，不是把假信号发给真进程。

    OptionalredirectStdoutFile

    redirectStdoutFile?: string

    keepAlive 专用：把子进程 stdout / stderr 重定向到这两个按次命名的文件 （脱离进程树的进程没有管道可读，落文件才能保住启动日志）。 Windows 经 Start-Process -RedirectStandardOutput/-Error；POSIX 直接把 文件描述符交给 stdio。两文件必须不同路径。
