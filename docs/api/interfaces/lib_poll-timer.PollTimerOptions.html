    ms

    ms: number | (() => number | null) | null

    间隔毫秒数；null / 0 表示不跑。

    也可以给一个函数：每次跑完都重新问一次「下一拍等多久」。这是 「按阶段给频率」唯一的落点（ISSUE #1351）—— 存活探测在「启动等待 / 空闲 / 出图 / 隐藏」四档之间的间隔差一个数量级，而档位在运行中变 （用户点了生成、切走了窗口），一个创建时就定死的数字表达不了。

    为什么不让调用方自己 stop/start 来换间隔：那会把「停表 → 立刻先跑一次 → 重新装事件监听」这段每次都重放一遍，于是切一次档就多发一探测 （而出图档本来就该降压，这一下正好打在高峰期）。函数形态只在本拍跑完之后 生效，不会抢跑。

    函数返回 null 表示「下一拍不排」（调用方仍可经 stop() / 重建拉起）； 返回 0 表示「立刻再跑一拍」（事件驱动那一档）。两者不可混为一谈： 把 null 当 0 会成为忙等（实测一秒空转上万次）。

    onError

    onError: (err: unknown) => void

    轮询动作抛错时的通道，必填：本文件在 src/lib，那里不许直接 console.* 写日志（判据 tests/single-logger-channel.test.ts「日志实现只有一处」）。 所以通道由调用方给：视图侧外壳（useInterval）给浏览器控制台；库侧持有者给 业务语义的通道（例如把「本轮观测失败」并进同一条离线迟滞），而不是另开一条 日志通道。
