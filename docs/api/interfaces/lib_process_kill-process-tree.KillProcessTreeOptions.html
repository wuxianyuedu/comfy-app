    Optionaldetached

    detached?: boolean

    子进程是否以 detached 方式拉起。仅作为「连 ps 都拿不到 PGID」时的 兜底提示：为 true 且 pid 恰好是组长时仍可尝试 kill(-pid)。 不再是主判据 —— 组长归属由 OS 回答（见文件头）。

    Optionalmode

    mode?: KillProcessTreeMode

    回收模式：tree（默认）按 PID 杀整棵树；image 按映像名杀 （Windows /IM <name>、POSIX pkill -x <name>）。image 用于目标不是 本进程的直接子进程、只拿得到名字的场景（如外部拉起的 Ollama serve）。

    Optionalwait

    wait?: boolean

    派发回收命令后是否等到它真正结束（默认 false = 只派发）。

    服务生命周期不需要等：回收是尽力而为，随后由各自的「探测确认」收口。 但「派发完就退出」的调用方必须等 —— Windows 上 taskkill 是独立进程， 调用方立刻 process.exit() 会把还没跑起来的它一起带走，现象是 打印了命令、退出码 0、目标进程却还在（命令行入口 scripts/reap-process.mjs 正是这种形态）。
