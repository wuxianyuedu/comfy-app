    Interface StrictCanvasNodeData

    画布逻辑节点的严格字段声明（不含索引签名）。

    为什么拆成「严格声明 + 兼容类型」两层（ISSUE #320）：

    ReactFlow 的 Node<T> 要求 T extends Record<string, unknown>，所以交给 ReactFlow 的数据类型必须带索引签名。但索引签名会让字段名写错也编译通过 （d.promt 被解析成 unknown）——顶层类型检查里那层「保险」是假的： 过去 14 个画布文件全靠它蒙混，拼错字段名要到运行时才炸。

    因此拆开：

    • StrictCanvasNodeData（本接口）：所有画布业务代码用这个。字段少写、 名字拼错、类型用错都会在 tsc 阶段报错（含 "Did you mean" 提示）。
    • CanvasNodeData（下方 type）：仅用于交给 ReactFlow 类型参数的位置 （Node<CanvasNodeData, …> / CanvasNodeType）。它 = 严格声明 + Record<string, unknown> 兼容面。
    • 需要在 ReactFlow 与业务之间搬运数据时，走 asCanvasNodeData() 收口 （单点断言，替代散落的 as unknown as）。

    不使用「裸索引签名放在声明体里 + 靠人自觉」：那正是本次要修掉的状态。

    size

    size: SizeSpec

    尺寸表达（比例 + 分辨率 / 比例 + 百万像素 + 倍数，见 lib/size-presets）。

    发往只认字符串的老接口时才折算成 "WxH"（sizeSpecToWxH）；工作流节点的尺寸本来就由 它自己暴露的尺寸口决定（画布上的组合控件走同一套尺寸表），这个字段只服务 「没选工作流」的内置通道。

    旧数据（localStorage v1）里存的是 "1024x1024" 这类 WxH 字符串 —— 读的时候 统一走 toSizeSpec 归一，不要假定它一定是对象。
