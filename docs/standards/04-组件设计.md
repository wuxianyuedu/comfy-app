## 4. 组件设计

> 组件是产品代码的主要载体。本章给出拆分、组合、API 设计、性能优化的可操作规则。

### 4.1 单一职责：一个组件干一件事

| 组件 | 行数 | 干了 N 件事 | 评价 |
|------|------|-------------|------|
| `HistoryList` | 600+ | 8 | ❌ 必须拆分 |
| `CanvasArea` | 200+ | 5 | ⚠️ 应该拆分 |
| `BottomBar` | ~150 | 4 | ⚠️ 到了临界点 |
| `HomePage` | ~230 | 3 | ⚠️ 临界（230 行已超 200 阈值，下轮改动拆） |
| `LeftToolbar` | ~100 | 1 | ✅ 干净 |

**拆分阈值**：超过 200 行且包含 3+ 个独立功能 → 拆。超过 300 行无论功能数 → 拆。

### 4.2 数组驱动 UI，不要复制 JSX

```tsx
// ❌ 错误：复制粘贴 4 遍
<div className="card">...</div>
<div className="card">...</div>
<div className="card">...</div>

// ✅ 正确：数据驱动
const QUICK_ACTIONS = [
  { id: "canvas", label: "新建画布", icon: <Canvas size={22} /> },
  // ...
];
{QUICK_ACTIONS.map((action) => (
  <button key={action.id} onClick={() => onNavigate(action.id)}>
    {action.icon}
    {action.label}
  </button>
))}
```

**收益**：加新项只改配置数组，不改 JSX 结构；类型系统自动校验每项字段完整性。

### 4.3 消费方 API 类型安全

```tsx
// ❌ 错误：as 断言绕过类型检查
onNavigate?.(card.id as WorkspaceView);

// ✅ 正确：数组类型直接约束
const QUICK_ACTIONS: Array<{ id: WorkspaceView; label: string; ... }> = [
  { id: "canvas", ... }, // 类型不匹配时这里直接报错
];
```

### 4.4 事件隔离（React Flow 节点内组件必读）

```tsx
// ✅ 节点内按钮必须阻止事件冒泡到画布
<button
  onClick={(e) => { e.stopPropagation(); handleClick(); }}
  onMouseDown={(e) => e.stopPropagation()}
  onPointerDown={(e) => e.stopPropagation()}
  onDoubleClick={(e) => e.stopPropagation()}
>
```

**原因**：React Flow 画布监听 pointer/mousedown 用于框选、拖拽节点。节点内的按钮不隔离事件，会导致点击按钮时也触发画布交互（误选/拖拽）。

### 4.5 组件拆分目录结构

```
Feature/
├── index.tsx              ← 主组件：只管布局 + 组合
├── hooks/                 ← 业务逻辑 hook
│   └── useFeatureData.ts
├── components/            ← 子组件（每个 < 80 行）
│   ├── FeatureCard.tsx
│   └── FeatureToolbar.tsx
├── utils/                 ← 纯函数工具
│   └── format.ts
└── types.ts              ← 本功能专用类型
```

**导入规则**：`components/` 只导入同功能 `hooks/` 和 `utils/`；跨功能复用提升到 `components/studio/shared/` 或 `lib/`。

### 4.6 Props 设计：优先组合，避免巨型 props 对象

```tsx
// ❌ 错误：10+ 个可选 prop，调用方记不住
<HistoryList
  onOpenTask={...} onNavigate={...} onShowAllProjects={...}
  activeNav={...} recentProjects={...} onOpenCanvasProject={...}
/>

// ✅ 正确：分组为子对象或拆成多个小组件
interface HistoryListProps {
  navigation: { active: WorkspaceView; onNavigate: (v: WorkspaceView) => void };
  data: { projects: RecentProject[]; onOpen: (id: string) => void };
}
```

**Props 设计准则：**

1. **布尔 prop 语义正向**：`disabled`、`loading`、`open` 而非 `isNotLoading`、`hidePanel`。
2. **回调命名 `on<Event>`**：`onChange`、`onSend`、`onOpenTask`，统一动词前缀。
3. **避免 `children` 承载过多结构化内容**：超过 2 个具名插槽时改用命名 prop（`header`/`footer`/`sidebar`）。
4. **`as` polymorphism 谨慎用**：需要渲染为不同标签时（如 `as="a"`），用 `React.ElementType` 类型约束，避免 `any`。

### 4.8 用 React.memo + 稳定回调避免子组件无效重渲染

```tsx
// ✅ 正确：列表项用 React.memo，回调用 useCallback 保持引用稳定
const TaskItem = React.memo(function TaskItem({
  task,
  onClick,
}: {
  task: AgentTask;
  onClick: (id: string) => void;
}) {
  return <button onClick={() => onClick(task.id)}>{task.label}</button>;
});

function TaskList({ tasks, onTaskClick }: { tasks: AgentTask[]; onTaskClick: (id: string) => void }) {
  const handleClick = useCallback((id: string) => {
    onTaskClick(id);
  }, [onTaskClick]);
  return tasks.map((task) => <TaskItem key={task.id} task={task} onClick={handleClick} />);
}
```

**注意**：`React.memo` 只对 props 做浅比较。若父组件每次渲染都创建新对象/新函数传给子组件，`memo` 失效——先稳定数据源（Zustand selector / `useCallback`），再包 `memo`。

### 4.9 组件分类与对应规范

| 类型 | 示例 | 规范要点 |
|------|------|---------|
| 布局壳（Shell） | `AppShell`/`BottomBar` | 只排布区域 + 组合子组件；动画/显隐逻辑下沉到子组件 |
| 业务页面 | `HomePage`/`HistoryList` | 数据获取 + 组合业务子组件；超过 200 行拆 `components/` |
| 展示组件 | `TaskCard`/`AgentPanel` | 纯展示 + 回调；用 `React.memo` |
| 工具/原语 | `ModalDialog`/`DarkSelect` | 通用、无业务依赖；Props 设计覆盖常见变体 |
| 装饰组件 | `AuroraBackground` | `pointer-events-none` + `aria-hidden`；颜色/模糊提 Design Token |

  const params = (detail.params ?? {}) as Record<string, any>;
  const workflowInputs = Array.isArray(params.workflowInputs) ? params.workflowInputs : [];
  const fallbackPrompt = (() => { ... })();
  return ( ... );

// ✅ 正确：提取为独立组件或 hook
function PromptDisplay({ detail }: { detail: TaskDetail }) {
  const prompt = useMemo(() => resolvePrompt(detail), [detail]);

**判断标准**：如果 IIFE 内超过 5 行或有条件分支 → 必须提取。
