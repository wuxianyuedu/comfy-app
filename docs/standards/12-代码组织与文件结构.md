### 12.2 Barrel Export 规范

```ts

// ── Shared UI ──
```

- barrel 文件只做 re-export，不含逻辑。

- 内部重构（拆子目录）对外 API 不变 → barrel 稳定消费方零感知。

### 12.4 注释规范：只写「当前代码的 Why」

> **核心原则**：注释记录**当前代码为什么是这样**，不记录**代码是怎么变成这样的历史**。
> 历史交给版本控制 —— `git log` / `git blame` / commit message / PR 描述 / CHANGELOG。

#### 12.4.1 该留：决策与约束（Why）

代码只说 What，注释才解释 Why。以下信息**高度就近**，三个月后的维护者改到这行就能看到，
从而避免把已被否决的方案改回去：

| 该写 | 示例 |
|------|------|
| 架构 / 技术选型决策 | "用 Zustand 而非 Context：日志每秒数十次更新，Context 会触发全树 re-render" |
| **否决过的方案及原因** | "不用底部抽屉：压缩画布可用空间，且与 MiniMap / 状态栏重叠" |
| 反直觉代码的动机 | "SSE 断线不手动重建 EventSource：浏览器自动重连，close 会丢帧" |
| 隐式契约 / 前置条件 | "此字段由后端 runner 写入，前端只读不写" |
| 权衡取舍的边界值 | "300 条上限：低于此值用户感知不到丢失，高于则内存占用明显" |

其中「**否决过的方案**」价值最高 —— 它回答的是"为什么不用 B"，而这正是 `git log` 查不到、
且最容易被后人重蹈覆辙的信息。

#### 12.4.2 不该留：作者 / 日期 / 修改流水

| 不该写进代码 | 应该放哪 | 原因 |
|--------------|---------|------|
| 作者（`R-ardot122`）、日期（`2026-08-31`） | `git log` / `git blame` | 天然已有；写进注释会随代码搬迁而过期失真 |
| "谁改了什么"流水 | Commit message / PR 描述 | 同上，且重复维护成本 |
| 旧方案的完整代码 / 前后对比 | `git` 历史 | 无信息增量，只增加阅读负担 |
| 大段 changelog | `CHANGELOG.md`（仅记录用户可感知的对外差异，见 [13.10](13-提交与-code-review.md#1310-changelog-记录规范)） | 面向发布说明，不是代码读者 |

### 12.8.1 窗口标题行让位（ISSUE #310，机器强制）

页签搬到窗口标题行后，标题行是**应用级 chrome**：任何铺满**整个视口**的浮层都会把它
整条盖住——页签看不见、右上角的最小化/最大化/关闭也点不到。

判据（一句话）：**凡 `fixed` 且 `inset-0` 的顶层浮层，顶部都必须让位给标题行**，
写法统一为 `top-title-bar right-0 bottom-0 left-0`（`bottom-0` 必须显式，否则靠内容
高度撑开、拉伸不到底）。

- 取定位只用两处，不要手写：`overlayClass("modal", extra)`（模态弹窗 / 抽屉 / 遮罩，
  不铺满）与 `fullScreenLayerClass(z, extra)` / `FullScreenLayer`（全屏视图，铺满内容区）。
  判据本身是纯函数，在 `src/lib/full-screen-layer.ts`（规范 17 第①层），视图层只消费。
- 标题行高度定在 `globals.css` 的 `--spacing-title-bar`：tailwind v4 **只有
  `--spacing-<name>` 命名空间会生成间距类**，自定义名（如 `--title-bar-height`）产出
  0 个类、让位静默失效。
- **门禁**：`scripts/check-title-bar-clearance.cjs`（pre-commit 第 3 步 + CI
  `Title bar clearance`）扫描 `src/components/**`、`src/app/**`，命中 `fixed inset-0`
  即阻断。豁免仅 3 条，逐条写在脚本 `EXEMPT` 里并注明理由（判据模块自身的注释、装饰
  背景层、注释引用旧写法）；**新增豁免必须在脚本里写明「为什么它不是内容浮层」**，
  否则等于把门禁关掉。
- 判据自测在 `tests/check-title-bar-clearance.test.ts`（临时仓库跑真脚本，
  断言该拦的拦、不该误伤的放过），E2E 回归见 `e2e/critical-flows.spec.ts`
  「打开设置 / 打开应用日志面板后应用页签仍可见可点」。

> 为什么单独设门禁而不是靠 Code Review：`fixed inset-0` 是全项目最通用的弹窗写法
> （历史存量 25 处），首轮只改了「全屏视图」，弹窗类立刻二次回归。**靠人肉逐个文件翻的
> 判据必然漏**，能机器判的就别写进人脑。

### 12.8.2 内嵌第三方页面（iframe）先判「能不能嵌」，能开就自己开（ISSUE #310）

让出标题行解决的是「本应用自己的浮层盖住页签」；**被内嵌的页面自己能不能显示**是另一
类问题。这里踩过两次坑，成因与结论都必须写死。

**① 成因曾被记错。** 早先文档把空白页签记成「ComfyUI 发 `X-Frame-Options: DENY`，
跨源必然被拒」。**这个成因是错的**：ComfyUI（`server.py`）与 aiohttp 都不发这个头
（已用真实中间件实测复核）。真正的拦路虎是：ComfyUI 在**未开 CORS** 时挂的是
`create_origin_only_middleware()`，它对跨源请求（`Sec-Fetch-Site: cross-site`，
或回环地址下 `Host` 域名 ≠ `Origin` 域名）**直接返回 HTTP 403**（反 CSRF：防随机
网页 POST 127.0.0.1 排队）。iframe 内嵌正是跨源请求，403 响应体为空 → 一片白。
出错时把成因记错，会让修复方向整个偏掉（上一轮就因此退到了「另开窗口」）。

**② 开关握在自己手里，别绕道。** ComfyUI 是本应用 spawn 的，启动参数带上
`--enable-cors-header` 就会改挂 `create_cors_middleware()`——跨源不再 403，并回
`Access-Control-Allow-Origin`（`src/lib/comfyui/lifecycle-derive.ts` 的
`withEmbedClearanceFlag` / `COMFY_EMBED_FLAG`，在 `buildSpawnArgs` 里统一注入、
幂等不重复）。**正常路径下 ComfyUI 一定能被内嵌**，不应该出现「打不开就弹第二个
窗口」这种绕道（用户明确要求「不要打开另一个窗口，我只要多页签的形式」）。

因此约定：

- **探测必须模拟 iframe 视角**：`probeComfyEmbeddable` 的请求要带 `Origin` 头。
  裸探测（无 `Origin`）会拿到 200，把「会被 403」误判成「可嵌」——这正是上一轮
  观测盲区。判读优先级：`403` → 明确不可嵌并点明该开 `--enable-cors-header`；
  `Access-Control-Allow-Origin` 有值 → 可嵌；再退到 CSP `frame-ancestors` /
  `X-Frame-Options`；拿不到任何放行证据时**按不可嵌处理**（不赌）。
- **判据在服务端**：`src/lib/comfy-embed.ts` 纯函数（`judgeEmbeddable` /
  `frameAncestorsAllows` / `parseXFrameOptions`），经 tRPC `setting.comfyEmbeddable`
  暴露（宿主页把 `window.location.origin` 传上去做同源判定）。为什么不能放页面上：
  跨源读不到被嵌页响应头，iframe 的 `error` / `load` 事件都不带原因，「被拒」与
  「内容为空」在 JS 里长得一样。客户端网络层收口 `src/lib/comfy-tab-client.ts`。
- **「打开查看」这条决策路径只有两档，且都留在同一个窗口**：
  `decideComfyTabOpen` 返回 `embed`（内嵌页签）或 `blocked`（**仍在页签内**渲染
  可读说明：成因 + 下一步）。这条路径**不允许**另开独立窗口、也**不允许自动跳
  系统浏览器**——那违背「像文件管理器那样多页签」的目标。`blocked` 只用于
  「外部实例不受本应用参数控制」这类边缘情形。
  页签模型:`shell-tabs-store` 的 `ShellTab.blockedReason`，渲染见 `ShellTabs.tsx`
  的 `TabBlockedNotice`。
- **系统浏览器是用户主动点的并列出口，不是自动回落**（§12.8.3）：设置页另有
  「在浏览器打开」按钮，点它才跳浏览器；`openComfy()` 那条路径永远不碰浏览器。
- **新增任何内嵌第三方页面（iframe）时照此办理**：先探测、再决定渲染什么，
  不要无条件渲染 iframe —— 空白页签是最难排查的失败形态（没有报错、没有出口）。
- 回归测试：`src/lib/comfy-embed.test.ts`（判决表逐条钉住，含 403 与「探测必须带
  Origin」）、`src/lib/comfyui/lifecycle-derive.test.ts`（开关注入幂等）、
  `src/app/(main)/settings/hooks/use-settings-page.test.ts`（页签形态三例）、
  `e2e/critical-flows.spec.ts`（可嵌渲染 iframe / 不可嵌给说明，两条都断言不弹窗；
  另有「在浏览器打开」不碰页签一条，见 §12.8.3）。

### 12.8.3 「在浏览器打开」是与页签并列的出口，不是回落

12.8.2 定下「点『打开查看』只出页签」，那条结论容易被顺手读成「本应用永远不许调
系统浏览器」——**这是过度解读，会把用户真正需要的出口一起删掉**。此处把边界写清：

- **禁止的是「自动回落」**：内容嵌不进去就悄悄把用户甩到浏览器（或弹第二个窗口），
  用户既没得到内容、也不知道发生了什么。这是 12.8.2 要杜绝的形态。
- **允许的是「用户主动点的并列出口」**：同一个地址再交给系统默认浏览器打开，
  服务用户放大查看 / 装浏览器插件 / 多屏铺开的场景。它与页签内嵌**并存**，
  不替换、不切换页签、不影响页签那套行为。
- **落地位置**：设置页 ComfyUI 状态行的「在浏览器打开」按钮
  （`SettingsPageView.tsx`）→ controller hook `use-settings-page.ts` 的
  `openComfyInBrowser` → tRPC `setting.comfyOpen` →
  `src/lib/comfyui/lifecycle.ts` 的 `openComfyUi` → `src/lib/open-in-browser.ts`
  （`spawn` 命令 + 参数数组，不经 shell 二次引号解析）。
- **地址由服务端自己探**（`openComfyUi` 内部先 `probeComfyUi()`），不采信前端
  state 里的旧 `base` —— 用户点按钮时可能已经隔了很久，端口可能已经变了。
  这也是这个按钮不复用 `setting.openExternal` 的原因：那条端点的地址完全由
  调用方给定，前端拿着过期地址就会打开一个空白浏览器页。
- **视图层不新增 IO**：按钮只调 controller hook 暴露的 action，符合 §17 四层范式。
- 回归：`src/app/(main)/settings/hooks/use-settings-page.test.ts`（「在浏览器打开」
  三例：成功不碰页签 / 未运行的提示 / 打开失败的提示）、
  `e2e/critical-flows.spec.ts`（点它不新增也不切换页签、不弹窗）。
