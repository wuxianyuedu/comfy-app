## 12. 代码组织与文件结构

> 清晰的目录结构是大型项目可维护的前提。本章给出本项目约定与组织原则。

### 12.1 顶层目录约定（与主规范 §2.1 一致）

```
src/
├── app/                    ← Next.js App Router（路由/布局/页面）
│   ├── (main)/             ← 分组路由（无 URL 前缀：me/models/settings/workshop…）
│   ├── api/                ← Route Handlers（/api/logs/* 等）
│   ├── globals.css         ← 全局样式与主题 @theme（唯一入口，layout.tsx 引入）
│   ├── layout.tsx
│   └── error.tsx / global-error.tsx
├── components/
│   ├── layout/             ← 跨页面布局（Navbar）
│   ├── model/              ← 模型卡片（ModelCard/ModelLibrary）
│   ├── ui/                 ← 全局通用基础 UI（Icon/ErrorBoundary/Tooltip/Button）
│   ├── workshop/           ← 工作坊（CharacterDesigner/StoryboardPlanner/LLMContext…）
│   ├── workflow-canvas/    ← 旧画布（CustomNodesSettings/WorkflowCanvas/graph-utils）
│   └── studio/             ← 工作室组件库（barrel index.ts + 域子目录）
│       ├── AppShell.tsx / TopBar.tsx / …      ← 壳层与一级页面组件留在根
│       ├── canvas/         ← 节点画布（CanvasArea/WorkflowSubgraphNode/FlowNode*…）
│       ├── workflow-editor/ ← 工作流编辑器（Canvas/Inner/Nodes/Topbar/WorkflowStores…）
│       ├── workflow-library/ ← 工作流库（Library/Header/Card/actions/import…）
│       ├── history/        ← 历史记录（List/TaskCard/DetailModal/types/utils）
│       ├── logs/           ← 日志（LogPanel/LogProvider/log-store）
│       ├── debug/          ← 调试链（DebugChainFooter/debug-store）
│       ├── project-canvas/ ← 项目画布组件群
│       ├── shared/         ← 跨组件共享（WorkflowFormControls/EditableLabel…）
│       └── ui/             ← studio 私有基础 UI（ModalDialog/DarkSelect/CodeBlock…）
├── config/                 ← 常量与静态配置
├── lib/                    ← 纯工具函数（无 React、无服务端依赖）
│   ├── project-canvas/     ← 项目画布的逻辑层（canvas-store / canvas-types /
│   │                          canvas-helpers 纯函数 / canvas-api 网络客户端）
│   └── <domain>-client.ts  ← 各域浏览器侧网络客户端（规范 17 §17.2 第②层）
├── server/                 ← 服务端逻辑（db 客户端、repository、服务）
└── trpc/                   ← tRPC router（聚合、context、受保护 procedure）
```

> **跨层搬家的连带检查（2026-09-04，P4 教训）**：一个文件从 `components/` 迁到
> `lib/` 时，它依赖的类型/常量必须一起搬——lib 不得 import components
> （规范 17 的 H1 依赖倒置）。`canvas-store.ts` 迁到 `src/lib/project-canvas/`
> 时就是因为依赖 `canvas-types.ts`，后者也必须跟着迁。

> 2026-08-29 文件组织审查修订：路由组实为 `(main)`（原文档误写 `(studio)`）；全局样式实际位于
> `app/globals.css`（原 `src/styles/globals.css` 为无引用孤儿，已删除）；`HistoryList/` 拆目录
> 曾作为示例写入，现状是 `HistoryList.tsx` + `HistoryTaskCard.tsx` 平铺——**组件拆目录是可选
> 演进模式**（单文件超 ~300 行且有明显子结构时再拆），不是强制现状。

### 12.2 Barrel Export 规范

```ts
// ✅ 分组注释 + 统一路径风格（components/studio/index.ts）
// ── Layout Shell ──
export { AppShell } from "./AppShell";
export { TopBar } from "./TopBar";

// ── Canvas & Workflow ──
export { CanvasArea } from "./CanvasArea";

// ── Shared UI ──
export { ModalDialog } from "./ui/ModalDialog";
```

**规则**：
- barrel 文件只做 re-export，不含逻辑。
- 路径风格统一（本项目用 `@/components/studio` 别名）；同一 barrel 内不混用相对/别名路径。
- 内部重构（拆子目录）对外 API 不变 → barrel 稳定消费方零感知。

### 12.3 迁移期文件名反映实际内容

```ts
// ❌ 名不副实：文件里已经没有 Context 了

// ✅ 重命名反映实际

```

### 12.4 注释规范：只写「当前代码的 Why」

> **核心原则**：注释记录**当前代码为什么是这样**，不记录**代码是怎么变成这样的历史**。
> 历史交给版本控制 —— `git log` / `git blame` / commit message / PR 描述 / CHANGELOG。

#### 12.4.1 该留：决策与约束（Why）

代码只说 What，注释才解释 Why。以下信息**高度就近**，三个月后的维护者改到这行就能看到，
从而避免把已被否决的方案改回去：

| 该写 | 示例 |
|------|------|
| 架构 / 技术选型决策 | "用 Zustand 而非 Context：日志每秒数十次更新，Context 会触发全树 re-render" |
| **否决过的方案及原因** | "不用底部抽屉：压缩画布可用空间，且与 MiniMap / 状态栏重叠" |
| 反直觉代码的动机 | "SSE 断线不手动重建 EventSource：浏览器自动重连，close 会丢帧" |
| 隐式契约 / 前置条件 | "此字段由后端 runner 写入，前端只读不写" |
| 权衡取舍的边界值 | "300 条上限：低于此值用户感知不到丢失，高于则内存占用明显" |

其中「**否决过的方案**」价值最高 —— 它回答的是"为什么不用 B"，而这正是 `git log` 查不到、
且最容易被后人重蹈覆辙的信息。

#### 12.4.2 不该留：作者 / 日期 / 修改流水

| 不该写进代码 | 应该放哪 | 原因 |
|--------------|---------|------|
| 作者（`R-ardot122`）、日期（`2026-08-31`） | `git log` / `git blame` | 天然已有；写进注释会随代码搬迁而过期失真 |
| "谁改了什么"流水 | Commit message / PR 描述 | 同上，且重复维护成本 |
| 旧方案的完整代码 / 前后对比 | `git` 历史 | 无信息增量，只增加阅读负担 |
| 大段 changelog | `CHANGELOG.md`（仅记录用户可感知的对外差异，见 [13.10](13-提交与-code-review.md#1310-changelog-记录规范)） | 面向发布说明，不是代码读者 |

#### 12.4.3 推荐写法

```tsx
"use client";

/**
 * GlobalStepLogPanel —— 全局执行步骤日志面板
 *
 * 设计决策（Why 弹窗而非底部抽屉）：
 *   1. 底部抽屉会压缩画布可用空间；
 *   2. 与右下 MiniMap、底部状态栏容易重叠。
 * 故采用「应用日志」同款的居中弹窗。
 *
 * 交互约定：
 *   - 「调试模式」开关仅控制入口按钮显隐；
 *   - 弹窗打开后不受该开关影响，避免操作中突然消失。
 */
export function GlobalStepLogPanel() {
  // ... 组件实现
}
```

❌ 反面（历史流水 + 废话注释）：

```tsx
/* ── R-ardot122 (2026-08-31) ─────────────
 * 之前是底部可拖动面板，现在改成弹窗。
 * 2026-08-18 新增取消按钮，2026-08-20 修了折叠…
 */
// 设置 active 状态
setActive(true);
```

#### 12.4.4 门禁：pre-commit 自动拦截（R10）

`scripts/check-file-structure.cjs` 的 **R10** 规则会在提交时扫描 `src/**` 的
**整行注释**，命中下列任一形态即阻断提交：

| 形态 | 例子 |
|------|------|
| 日期 | `2026-08-17` |
| 改动编号 | `R-ardot114`、`R83`、`R-Next`、`R-T3-phase4` |
| 任务批次号 | `T12-3`、`T16` |

只扫注释行，代码里的日期字面量 / 缓存键（如 `` `wfdetail:R6:v2` ``）不受影响。
回归测试见 `tests/check-file-structure.test.ts`。

#### 12.4.5 一句话判据

写注释前自问：

> **"这条信息，三个月后的维护者在 `git log` 里也能查到吗？"**

能查到 → 删掉；只有当前决策者知道的「为什么」 → 留下。

### 12.5 工具函数与组件目录分离

| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| `lib/` | 纯函数、框架无关工具（`isVideo`、Zod schema、`timeAgo`）、Zustand store 实现 | React 组件、服务端逻辑 |
| `config/` | 常量与静态配置（`src/config/`） | 业务逻辑 |
| `server/` | 服务端逻辑（db client、repository、服务，`src/server/`） | 客户端代码 |
| `trpc/` | tRPC router / context / 受保护 procedure（`src/trpc/`） | 业务组件 |
| `components/studio/ui/` | 无业务依赖的通用基础 UI（`ModalDialog`、`DarkSelect`） | 业务组件（`HistoryList`、`AgentPanel`） |
| 组件目录内 `hooks/` | 单组件私有的自定义 hook（如 `use-project-manager.ts`） | 跨功能复用 hook |

> **注意**：本项目**没有**顶层 `src/hooks/`、`src/stores/`、`src/types/` 目录（与主规范 §2.1 一致）。跨功能复用的 hook 若确需共享，就近放入 `lib/` 或组件目录，禁止新建顶层目录制造分裂。

### 12.6 文件命名约定

| 类型 | 命名 | 示例 |
|------|------|------|
| 组件文件 | PascalCase | `AppShell.tsx` / `BottomBar.tsx` |
| 非组件模块 | kebab-case | `workflow-types.ts` / `log-store.ts` |
| 类型文件 | 同名或 `types.ts` | `HistoryList/types.ts` |
| 测试文件 | 同名 + `.test.ts(x)` | `format.test.ts` |
| 目录索引 | `index.tsx`（组件）/ `index.ts`（模块） | — |

> **`src/components/ui/` 命名约定（2026-09-02）**：该目录承载 shadcn/ui 组件，统一采用
> **kebab-case**（如 `button.tsx`/`dialog.tsx`/`select.tsx`），与本项目其它目录的 R1（PascalCase）
> 相反——这是 shadcn 官方约定，目的是让后续 `shadcn add` 直接落盘不冲突。
> **迁移计划**：目录内历史遗留的 PascalCase 文件（`Icon.tsx`/`Tooltip.tsx`/`Skeleton.tsx`/
> `EmptyState.tsx`/`ErrorBoundary.tsx`/`StatusBadge.tsx`/`Button.tsx`）需重命名为 kebab-case
> （`icon.tsx` 等）；完成后预提交脚本把 ui/ 从「软豁免」改为「硬强制 kebab」，杜绝回潮。
> 其它业务组件目录仍须 PascalCase。

### 12.6.1 变量命名硬约束（对齐主规范 §3）

- **禁止单字母变量**（循环索引 `i`/`j`/`k`、catch 参数 `e`、占位符 `_` 除外）。
- 事件参数 `e` 需语义化（`event`/`evt`）；状态简写 `s`、接口数据 `d`、动态 import `m` 等一律改语义名。
- 常量用 `UPPER_SNAKE_CASE`（模块级）/ `camelCase`（函数内 const）；组件文件名 PascalCase、模块 kebab-case。

### 12.7 循环依赖预防

- 组件目录内的 `index.tsx` 不反向 import 父级业务模块；跨功能复用走 `components/studio/ui/` 或 `lib/`。
- Zustand store 不 import 组件；组件订阅 store。
- `lib/` 不 import `components/`；`components/` 可 import `lib/`。

### 12.8 文件组织卫生（2026-08-29 审查新增）

- **禁止时间戳备份文件进 `src/`**（如曾出现的 `workflow-detail_20260829_121552_764.ts`）。版本
  回退靠 git 历史，重构前需要安全网就开分支；此类文件已清理，勿再产生。
- **运行时产物与本地工具目录已 gitignore**：`/log/`、`/run/`、`/temp/`、`/python-venv/`、
  `__pycache__/` —— 运行产物不入仓库，也不要在 `src/` 里写运行时文件。
- **新增 git-忽略的产物/临时目录时须同步 eslint ignores**：`.gitignore` 与
  `eslint.config.js` 顶层全局 `ignores` 需保持一致——凡 `.gitignore` 新增忽略的
  产物/临时目录（`coverage/`、`out/`、`dist/`、`node_modules.old/`、`.pnpm-store/`、
  `log/`、`run/`、`test-results/`、agent 索引目录等，可能落 `.ts/.tsx/.js` 或物理存在含
  海量 JS），必须同步补进 eslint ignores，否则 `pnpm lint`（`eslint .`）会把目录内临时
  文件扫进去误报/拖慢，甚至目录被清理后 eslint 9 walk 报 ENOENT 崩溃。
- ** comfy-cli 临时工作流文件** 统一写入 `temp/comfy-cli/`，Python 虚拟环境统一建在
  `python-venv/comfy-cli/`，禁止再使用 `.workbuddy/` 这类分散目录。
- **`scripts/` 是混合语言开发脚本区**（`.mjs`/`.cjs`/`.ps1`/`.py`），允许异构；其构建/运行产物
  （`__pycache__` 等）不入库。项目级迁移/诊断脚本沉淀在此（`tw4-canonical-codemod.cjs`、
  `force-ipv4-dns.cjs`），用法写入 [DEV-QUERIES](../guides/DEV-QUERIES.md)。
- **同名不同物就近隔离**：`studio/` 的 workflow-node 家族与 `project-canvas/WorkflowNode.tsx`
  分属两个画布体系，靠目录区分；新增文件前先确认所在目录没有语义撞车。
- **提交防线（不让违规文件进门）**：`.githooks/pre-commit`（`git config core.hooksPath .githooks`
  启用）运行 `scripts/check-file-structure.cjs`——R1 组件 .tsx 必须 PascalCase（Next 保留文件名、
  `src/trpc/react.tsx`、目录索引 `index.tsx`、**`src/components/ui/` shadcn 官方 kebab-case 约定**
  豁免）；R2 `.ts` 禁止 PascalCase（`src/components/ui/` 软豁免，待存量 PascalCase 重命名后改为硬强制 kebab）；R3 禁止时间戳备份；R4 `lib/` 禁止
  .tsx；R7 仓库内禁止 `.bat` / `.cmd` / `.vbs`（Windows 入口一律 `.ps1`，见
  [launch-and-build.md](../standards/launch-and-build.md) §8）；R8 `scripts/`
  `tools/` 下含中文的 `.ps1` 必须 UTF-8 BOM；R9 根目录禁止散落 `.ps1` 双击入口
  （ISSUE #29，入口归 `tools/<分类>/`，启动类归 `tools/start/`）。
  超 900 行的组件打印拆分提醒。
  规则详情与本文件 §12.6/§12.8 对应，提交门槛流程见 §13.5。
