## 6. 无障碍访问 (a11y)

> 目标是让屏幕阅读器、键盘用户、晕动症用户都能正常使用。本项目是生产力工具，a11y 不是"加分项"而是基本素养。

### 6.1 可交互元素必须可识别

```tsx
// ❌ 错误：只有图标，屏幕阅读器读不懂
<button title="通知"><BellIcon /></button>

// ✅ 正确
<button aria-label="通知" title="通知">
  <BellIcon />
</button>
```

**规则**：图标按钮必须 `aria-label`；纯装饰图标用 `aria-hidden`。

### 6.2 Tooltip 不要和 title 同时用

```tsx
// ❌ 错误：原生 tooltip 和自定义 tooltip 同时出现，闪烁
<button title="首页">
  <HomeIcon />
  <span className="group-hover:block">首页</span>
</button>

// ✅ 正确：只用 aria-label，自定义 tooltip 加 role
<button aria-label="首页">
  <HomeIcon />
  <span role="tooltip" className="...">首页</span>
</button>
```

### 6.3 语义化标签

```tsx
// ✅ 用语义标签表达结构
<header>      {/* 顶部栏 */}
<nav>         {/* 导航（侧边栏/工具栏） */}
<main>        {/* 主内容区 */}
<aside>       {/* 侧边面板/属性面板 */}
<section>     {/* 内容分组（日期分组标题） */}
<footer>      {/* 底部栏 */}
<button>      {/* 可交互 */}
<div role="region" aria-label="属性面板">  {/* 无语义容器补 role */}
```

**规则**：面板/抽屉/属性栏用 `<aside aria-label="属性面板">`（aside 默认 complementary role，无需显式声明）；不要用一堆 `<div>` 堆叠失去语义。

### 6.4 焦点管理（模态/抽屉必做）

```tsx
// ✅ 模态打开时焦点进入面板，关闭时焦点回到触发按钮
useEffect(() => {
  if (open) {
    panelRef.current?.focus();
  } else {
    triggerRef.current?.focus(); // 回到触发源
  }
}, [open]);
```

**清单**：

- [ ] Esc 键关闭模态
- [ ] 焦点陷阱（Tab 在模态内循环，不跑到背后页面）
- [ ] 打开时 `aria-modal="true"`
- [ ] 关闭时焦点回归触发按钮
- [ ] 背景内容 `inert` 或 `aria-hidden`（防屏幕阅读器读到背后）

> 自建模态易漏项，**优先用 Radix Dialog 原语或 shadcn/ui `Sheet`**，自带焦点管理、Esc、焦点回归。

### 6.5 装饰元素可访问性

```tsx
// ✅ 装饰背景/光晕
<div aria-hidden className="pointer-events-none ...">

// ✅ 装饰性 SVG 图标
<svg aria-hidden focusable="false" ...>
```

### 6.6 颜色对比度

- 正文文字对比度 ≥ **4.5:1**（WCAG AA）；大字号（≥18px 或 ≥14px bold）≥ **3:1**。
- 状态色（红/绿/琥珀）不要只靠颜色传达信息，须配文字或图标：`text-red-400` + 文字"失败"。
- 用 [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) 验证关键文字色对背景色。

### 6.7 动画与晕动症

```css
/* ✅ 尊重用户偏好 */
@media (prefers-reduced-motion: reduce) {
  .panel {
    transition: none;
    animation: none;
  }
  .aurora-blob {
    animation: none;
  }
}
```

**规则（三档分治）**：不是「所有 `transition` / `animation` 一律降级」——那条写法
在本仓的实测存量面前等于一句空话（`src/**` 有 128 行 `transition-*`，其中只有 13 行带
显式时长）。按**运动量级**分三档，各档要求不同：

| 档         | 覆盖什么                                                       | 要求                                                                       | 实测存量                            |
| ---------- | -------------------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------- |
| ① 循环动画 | `animate-spin` / `animate-pulse` / 自定义 `infinite` keyframes / **每秒重播的 `.value-tick`** | **必须停**（`animation: none !important`），且停掉后仍要有非动画的等价表达 | 8 处 / 7 文件                       |
| ② 大位移   | 抽屉/面板的滑入滑出、整块内容横扫                              | **必须去掉位移**、保留淡入/缩放（`translate: none`）                       | 2 处（sheet、navigation-menu 面板） |
| ③ 短程反馈 | hover / focus 的底色与边框过渡（位移量为 0）+ **用户显式动作后的一次性闪烁** | **明确豁免**，不要求降级                                                   | 其余全部（115 行走默认 150ms）      |

③ 为什么留：这类过渡**没有位移**，与 WCAG 2.3.3 关心的大面积/视差运动不是一回事；
全局关掉会让悬停态变成「无过渡直接换色」，代价大于收益。

**落点**：`src/app/globals.css` 末尾的 `@media (prefers-reduced-motion: reduce)` 块
（顶部注释写明每一档的取舍与为什么必须 `!important`）。

滑入抽屉默认 200-300ms，不超过 500ms。

> **`.value-tick`（值变了闪一下）为什么算第 ① 档而不是第 ③ 档**：它是**一次性**
> 动画（不是 `infinite`），但它长在被轮询刷新的读数上 —— `key` 每变一次就重播一次，
> 于是真实观感是「每秒亮一下」。第 ③ 档豁免的是「指针移上去那一档底色」（位移为 0
> 且**由用户动作触发**）；这里的触发是**机器在跑**，与晕动症那条判据关心的
> 「不受控的持续变化」同形，所以按第 ① 档停掉。停掉之后旧值→新值的切换照常发生，
> 只是没有淡入 —— 信息一个字都不丢。

> **① ② 里有两处必须用 `!important`，不是风格问题**：`ui/progress-bar.tsx` 的不确定条与
> `workshop/AgentOverlay.tsx` 的运行中圆点都是**内联 `style={{ animation: … }}`**，
> 行内样式压过层外一切规则 —— 不加 `!important` 这两处会**静默不降级**（系统开了减弱动态
> 而它们照转，且没有任何东西会报）。选择器一律挂 `data-slot`，不要按 class 字面量匹配。

> **刻意例外（AutoAnimate 条目级过渡）**：历史记录列表等「列表条目级增删/排序换位」的轻量过渡（`@formkit/auto-animate`，250ms + `ease-out`，仅 `transform`/`opacity`）**故意不降级**——已开启 `disrespectUserMotionPreference: true`，在系统开启「减弱动态效果」时仍保留适量动画。此为产品决策：允许适量动画而非完全禁用。它属于上面第 ③ 档的口径，不受本条约束。

> **另记一笔不属于本条的账**：实测有 **8 处动画挂在 layout 属性上**（`ui/progress.tsx`、
> `ui/sidebar.tsx` ×4、`ui/navigation-menu.tsx` ×3、`canvas/RgthreeBodies.tsx`）。
> 那是**渲染成本**的账、不是晕动症的账（与 `prefers-reduced-motion` 无关），
> 两者**同一处站点、不同判据**，别混在同一个 PR 里改。
> **该账已在 [02 §2.7.1](02-性能规范.md#271-表现-vs-性能的裁决口径存量-8-处的实测结论) 逐条裁决**：
> 8 处共同特征是「用户显式点击 + 一次性 + 受影响子树小或脱离文档流」，
> 表现收益盖过性能代价，**全部保留、不改**；本条只负责它们的减弱动态降级。

### 6.8 表单与输入

- `<input>` / `<textarea>` 必须关联 `<label>`（显式 `htmlFor` 或包裹在 `<label>` 内）。
- 错误提示用 `aria-describedby` 关联到输入框。
- 必填字段用 `required` + `aria-required="true"`。
- 自定义控件（如下拉选择器）实现键盘可达：`ArrowUp`/`ArrowDown` 导航、`Enter` 选中、`Esc` 关闭。

### 6.9 图片与媒体

- `<img>` 必须 `alt`；纯装饰图 `alt=""` + `aria-hidden`。
- 视频控件用原生 `<video controls>` 或确保自定义控件键盘可达。

### 6.10 交互元素必须真的可交互

可选回调驱动的按钮，未传回调时不得渲染成"可聚焦、点击无反应"的按钮；同时 CSS `:hover` 对 `disabled` 按钮依然生效，hover 态必须用 `enabled:` 变体限定。

```tsx
// ❌ 错误：onTaskClick 未传时按钮仍可聚焦，点击无任何反应
<button onClick={() => onTaskClick?.(task)} className="... hover:bg-white/4">

// ✅ 正确：无 handler 时显式禁用；hover 用 enabled: 限定（参考 AgentPanel.tsx）
<button
  disabled={!onTaskClick}
  onClick={() => onTaskClick?.(task)}
  className="... enabled:hover:bg-white/4"
>
```

**规则**：`disabled={!handler}` 让禁用态对键盘/读屏用户可感知；不用 `pointer-events-none` 伪装禁用（仍可聚焦、读屏不知情）。

### 6.12 `jsx-a11y` 的规则开关：官方 `recommended` 全开，方言逐条登记（`check-a11y-rules.cjs`）

`eslint-plugin-jsx-a11y` **装着 39 条规则**，而 `eslint-config-next` 只启用
**6 条**、且全是 `warn`。剩下那批里有一批是**本来会响的真形态**：锚点没有可访问
内容、`<video>` 没有字幕轨、`autoFocus`、组件化 `<label>` 的关联、非原生元素上的
交互 —— 以前它们**一条判据都没有**。

而「半开」这件事本身此前**没有任何东西在数**：`grep -c jsx-a11y eslint.config.js`
是 **0**（配置在 `eslint-config-next` 里，本仓那份一个字都没写），
`grep -c a11y scripts/check-*.cjs` 只有 §6.11 那一处**形态**判据。也就是说
「哪条规则开着、哪条关着、关掉的理由是谁在守」这一整格，**一个执行者都没有**。
这与 §13.5.12 的立案现场（判据自称在跑、实际没有执行者）同族，只是这次的「判据」
是一条 npm 包里的规则。

#### 口径：两层，不是二选一

**第一层 —— 官方 `recommended` 集合全开。** 由 `oxlint.parity.config.mjs` 的
`a11yRecommendedRules()` **从插件自己的那份数据当场算出来**（不是在这里抄一份规则
表：抄一份就会漂，插件升版加了新规则我们这边一个字都不会变）。四条刻意的处理：

- 官方给 `"off"` 的（`anchor-ambiguous-text` / `label-has-for`）**不带进来**
  —— 带进来会在「开了没有」的判据里被算成「开着」；
- 需要参数的规则（`control-has-associated-label` / `interactive-supports-focus` …）
  **原样带上官方那份 options**。少了它规则退回默认档、结论不同（实测
  `control-has-associated-label` 的官方 options 里 `includeRoles` 有
  `dialog` / `alert`，默认档没有）；
- 全部升成 `error`：本仓 `lint` 带 `--max-warnings 0`，两者等价，但编辑器里
  `error` 更醒目，也不会有人以为「warn 可以先放着」；
- 插件对象从 **`next` 配置里已经装好的那一个**取：本仓没有
  `eslint-plugin-jsx-a11y` 直接依赖，pnpm 严格布局下顶层与 `import.meta.resolve`
  都解析不到（符号链接的真实路径不在解析链上）。

**第二层 —— 方言逐条登记。** 本仓与官方默认不同的每一处（关掉一条、改一条的
选项档、某个文件里就地 `eslint-disable`）都必须写进
`scripts/.a11y-rule-ledger.json`，并答出**两件事**：

| 栏位 | 回答什么 |
| --- | --- |
| `why` | 为什么本仓这一档与官方不同（空理由没有记账价值） |
| `keeper` | **谁在守它** —— 关掉一条判据却不答出替代者，等于把它从面上删掉 |

当前三条方言：

| 规则 | 决定 | 为什么 | 谁在守 |
| --- | --- | --- | --- |
| `no-autofocus` | `off` | 桌面应用里 `autoFocus` 是**刻意的**：内联重命名输入框、弹层里唯一的输入位，一打开就该把光标放进去。官方那条针对的是**页面加载时**抢焦点（移动端会把键盘顶起来）—— 不是同一件事 | 4 处站点在源码注释里逐条写明理由；本节这张表 |
| `label-has-associated-control` | `off` | 规则**看不穿组件化的 label**：`ui/label` 的 `Label` 把 `htmlFor` 经 `{...props}` 透传给底层 `<label>`，规则只读这一处 JSX，看到的永远是「没关联」。它数的不是「关联有没有做」，而是「关联有没有**写在这一处 JSX 上**」 | `check-form-field-wiring.cjs`（D 组「FormField 标签⇄控件接线」，§16.2.4.26.1）+ `ui/field` 的 Base UI 语义 |
| `prefer-tag-over-role` | `off` | 规则判「用了 ARIA `role` 却没换原生标签」，但**给不出能用的替代**：实测 27 处全是有意取舍（Base UI 的复合控件 pattern、shadcn 修 Safari 列表语义的 `role="list"`、`role="status"` 的 live region）。换成它建议的原生标签会把控件改坏。**但「不开」不等于「没问题」** —— 它照出的真缺陷族（`role="radiogroup"` 没方向键契约）已收口，见下一节 | `ui/radio-group` 基元给复合控件契约；形态判据 `check-click-keyboard.cjs`（§6.11）；收口后的契约由 `AppearanceSection.test.tsx` 钉住 |

#### 第三档：**官方两份配置谁都没提到**的规则（本批补）

上面「两层」的口径有个洞，本批堵上：插件的 `configs.recommended` / `strict`
**不是**「除废弃外全开」，而是 `lib/index.js` 里**手写的静态清单**。实测 39 条里
**有 5 条两边都没被提到**：

| 规则 | 官方的态度 | 本仓裁决 |
| --- | --- | --- |
| `accessible-emoji` | ❌ `meta.deprecated` | 不开（尊重官方） |
| `no-onchange` | ❌ `meta.deprecated` | 不开（尊重官方） |
| `label-has-for` | ❌ deprecated + 明写 `off`（被 `label-has-associated-control` 取代） | 不开（尊重官方） |
| `anchor-ambiguous-text` | 明写 `off`（提到过） | 不开（尊重官方） |
| `lang` | **两边都没提** | **开** |
| `no-aria-hidden-on-focusable` | **两边都没提** | **开** |
| `prefer-tag-over-role` | **两边都没提** | **不开**（但照出的真缺陷已收口，见下） |

前四条是官方**做过决定**的（废弃 / 明写 off），尊重它即可。后三条
**既非废弃、也非明写 off** —— 它们只是被两份清单漏掉了，于是
「该不该开」**从来没有人决定过**，也没有任何东西会响。这与「官方 `recommended`
里被悄悄关掉」是同一个洞的另一面：**「没列进来」同样等于「没人守」**。

三条各自的裁决：

- **`lang` 与 `no-aria-hidden-on-focusable` —— 开。** 全仓实测 **0 处**
  （`layout.tsx` 已是 `<html lang="zh-CN">`；没有 `aria-hidden` 落在可聚焦元素上的
  形态），所以它们是**零成本的真判据** —— 防的是「新增一处写错」，不是「现存有
  多少」。生效性当场核过（植入违规两条都会报）。
- **`prefer-tag-over-role` —— 不开，但「误报」不是结论。** 它判「用了 ARIA `role`
  却没换原生标签」，实测 27 处逐条看完，全部是**有意取舍**：Base UI 的复合控件
  pattern（`combobox` / `listbox` / `option` / `radio` / `checkbox`）、shadcn 的
  `role="list"`（**修 Safari 的列表语义**：`list-style: none` 会让 Safari 丢掉
  list/listitem 角色，官方推荐的修法正是补回 `role="list"`）、`role="status"` 的
  live region（规则建议换 `<output>`，但 `<output>` 的语义是「计算结果」，
  一个自转的加载指示器不是它）。**换成它建议的原生标签会把控件改坏**。
  但它确实**照出了一个真缺陷族** —— 见下。

#### 复合控件 ⇄ 键盘契约（`prefer-tag-over-role` 照出来的那一族）

规则本身不开，但它指向的形态是真的：`role="radiogroup"` 声明了，
**方向键契约没人给**。`AppearanceSection` 两处（主题卡、圆角/字阶档位行）此前是
手写的 `role="radiogroup"` + `role="radio"` 挂在 `<Button>` 上 —— 读屏知道
「这是个单选组」，Tab 进得来、聚焦得到，但**组内方向键没反应**，而且两个项
都留在 Tab 序列里（没有 roving tabindex）。ARIA 的 radiogroup 契约要求：

- **方向键（`ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight`）在组内移动并选中**；
- **roving tabindex**：只有选中项 `tabIndex=0`，Tab 一次进出整组。

**修法不是手写方向键处理，而是用基元。** `ui/radio-group`（Base UI 的
`RadioGroup` / `Radio.Root`）已经实现了这套契约，用 `render` 把卡片交给它渲染：

```tsx
<RadioGroup value={theme} onValueChange={setTheme} aria-label="主题外观">
  <RadioGroupItem
    value="dark"
    nativeButton                       {/* 渲染目标是真 <button>，必须给 */}
    render={<Button variant="ghost" className="… data-checked:… data-unchecked:…" />}
  >
    深色
  </RadioGroupItem>
</RadioGroup>
```

`Radio.Root` 负责 `role` / `aria-checked` / `data-checked` / roving tabindex 与
方向键；调用处只给样式。**别自己手写 `role="radio"` + `aria-checked`** ——
那样等于「声明了契约却没有实现」，正是本条要拦的形态。

契约由 `AppearanceSection.test.tsx` 钉住（roving tabindex、方向键选中；
**改回手写形态这两条会红** —— 钉的是「收口真的发生了」，不是「现在绿」）。

#### 就地豁免：规则开着，某个文件里是误报

第二档是 `inlineExemptions`：规则**开着**、但某个文件的某一处就地
`eslint-disable` 了。配置层完全看不见这类豁免，所以它也必须登记（文件 + 规则 +
理由 + keeper）。当前 12 条，三族：

- **规则认不出属性展开**（实测：把同一份 `{...simpleKeyHandler([...], fn)}` 换成
  字面量 `onKeyDown={fn}`，`click-events-have-key-events` 当场不报）——
  页签行、选项行那批的键等价物**正是** `simpleKeyHandler`，由 §6.11 的判据认它；
- **转发通道**：`ui/pagination` 的锚点内容经 Base UI 的 `render` 通道从
  `<Button>` 落到 `<a>`，规则看到一个空 `<a />`；
- **本基元的形态不适用**：`ui/media-thumbnail` 的 `<video>` 是**缩略图 / 预览**
  （`muted` 默认 `true` + `autoPlay` + 几百像素），ComfyUI 产出的 mp4 无音轨
  —— 配一个空的 `<track kind="captions">` 只是让规则闭嘴，读屏器会读到一条
  **假字幕轨**。

#### 判据：`check-a11y-rules.cjs`（四向 + 双向）

接进 pre-commit 的 **D 组**，纯本地、零网络、零子进程（读那份配置约 1.1s ——
它要经 `eslint-config-next` 把 next 全配置求值一遍）。五件事：

1. **官方 `recommended` 的每一条都必须开着**、且 options 与官方逐字一致；
2. **台账里登记的每一处方言必须是真的关着** —— 登记了却开着 ⇒ 红
   （台账是负债，不是赦免名单）；
3. **官方 recommended 里被关掉的必须登记** —— 悄悄关掉一条真判据，且没有任何
   东西会响，正是这一格要拦的动作；
4. **就地豁免的文件要存在、`why` 与 `keeper` 都要写全**；登记了不存在的规则
   ⇒ 红（改名 / 换插件后留下的孤儿条目）；
5. **官方两份配置谁都没提到、且未被标记废弃的规则，本仓必须有一笔裁决** ——
   要么开着（写进 `oxlint.parity.config.mjs` 的第三档），要么在台账 `dialect` 里登记「为什么
   不开」与「谁在守它」。两条都不满足 = **没有人决定过**，与「没登记就关掉一条真
   判据」同罪。废弃状态**从插件的 `meta.deprecated` 读**，不在判据里抄一份废弃名单。
   （新建规则时插件常先不加进那两份手写清单 —— 正是「没人决定过」的高发处。）

⚠️ **这一条与 §6.11 是两条维度、互不替代**：§6.11 管「**这一处**点击有没有键
等价物」（形态判据、能点名行号），本条的「规则开关」那一半管「**这个判据有没有
开着**」。两条都红的时候（实测：非原生元素上的 `onClick` 会同时被
`jsx-a11y/no-static-element-interactions` 与 §6.11 的脚本报出来）**不要去动
`oxlint.parity.config.mjs` 把它关掉** —— 那是把一个「说得出哪一行」的判据换成一个
「什么都不说」的。

`--report` 会把 39 条规则逐条打出来（`*` 生效 / `·` 关掉），用来回答「这盏灯
现在是什么颜色」。规则条数**别写在文档里**（会漂），要看实时读数就跑它。

`--ledger <path>` 是给**门禁自测**的口子：默认不传就用仓库里那份
`scripts/.a11y-rule-ledger.json`，传了就把它当台账读。它存在的理由只有一条 ——
自测要拿十来份**不同的台账**各判一次，而没有这个口子时用例只能「备份真台账 →
覆盖 → 跑 → 还原」，那是**共享可变状态**（用例之间不能并发，失败路径上也不保证
还原）。台账路径是**被测输入**，所以它是个显式入参，不是环境变量。缺值退 **2**：
静默退回真台账会让「用例以为在判自己的夹具、其实在判真库」，是那种**绿得毫无
意义**的失效。

至于「十来份台账各判一次」这件事**怎么付得起**：这条链上的成本只有一个来源 ——
求值真的判决配置（**#2777 PR-C 之前**是 `eslint.config.js`，它 import 了整个
`eslint-config-next`；#3157 起该文件已删，判决面只剩 `oxlint.parity.config.mjs`）。
**首次**求值在干净检出上 40s+、`.next/` 热时 ~1.1–1.7s（这是当时的读数，现在这份
小配置的求值在 1s 级）。33418b72 那轮先按「~1.1s / 次」把它算成
「该进钩子」（那个数在热态下是对的），于是自测相对那时的写法省下了「十来次等待
不再首尾相接」；但它同时把**冷检出**上的成本乘了十来倍 —— 十来个子进程各自求值一遍，
而钩子每次提交都是新进程、必然冷（ISSUE #1623 的现场，实测 10/10 超时）。
现在的形状是：**共进程 + 一次性真加载**（判据是 CJS ⇒ `require()` 拿到同一个模块
实例、`import()` 也只求值一次），`it.concurrent` 全部撤掉。派生链、两个数字的出处、
以及「剩下那一半为什么买不到」写在 §11.19.1 的档 E。

⚠️ 由此得到一条**硬约束**：读过本节的用例文件里，**不许再起一个会求值这份配置的
子进程**（那等于把成本乘回去）。真要覆盖 `process.exit` 的退出码，用一条在它上面
**停住、不求值配置**的调用（`--ledger` 缺值退 2）—— `tests/check-a11y-rules.test.ts`
的 bin 形态那一条就是这么做的。
