# 17. UI 与逻辑分离

> 本章是**分离战役的作战图**：先定义"什么算 UI、什么算逻辑"，再给出机器可判定的
> 护栏（棘轮脚本），最后排好**分批推进顺序**与**每批的验收标准**。
> 与 [§16.2.1 四层范式](16-shadcn-ui与表单校验.md#1621-落地范式controller-hook--纯展示视图)
> 是同一套东西——16 章讲**单个组件怎么拆**，17 章讲**全库怎么推进、怎么防回潮**。
>
> 配套脚本：`scripts/check-ui-logic-separation.cjs`（护栏）
> + `scripts/.ui-logic-baseline.json`（基线，只许降不许升）
> + `.githooks/pre-commit` 第 3 步与 CI `quality` job。

## 17.1 为什么要分离（与收益）

| 现状 | 分离后 |
|---|---|
| 组件里 `useState` 十几个 + `fetch` + tRPC + JSX 混在一个 700 行文件 | 逻辑在 hook 里可单测，视图只收 props |
| 想改视觉得通读业务分支；想改业务得穿过 JSX | 视图可由 `shadcn`/工具重生成（§16.2），业务不受影响 |
| 行为测试必须 `render()` 整个组件 + mock 网络 | 逻辑直接 `renderHook` / 纯函数断言，秒级 |
| 谁在发请求、失败怎么提示，全靠人肉看代码找 | 请求集中在一个 `<domain>-api.ts`，失败路径一处改全库生效 |

**判定标准一句话**：*这段代码删掉 JSX 还能不能跑测试？* 能 → 逻辑；不能 → UI。

## 17.2 四层归属（沿用 §16.2.1，补机器判定）

| 层 | 位置 / 命名 | 允许 | 禁止 |
|---|---|---|---|
| ① 配置 | `<feature>/<feature>-config.ts` | 常量、纯派生函数 | React、副作用、DOM |
| ② 逻辑 | `<feature>/hooks/use-*.ts`、`src/lib/<domain>/*.ts` | state、持久化、拉取、流程编排 | JSX、`alert`、直接操作 DOM |
| ③ 视图 | `<feature>/<Name>.tsx` | props + 组合 `ui/` 原语 | `fetch`、`vanillaApi`、`api.*.useQuery` |
| ④ 容器 | `<feature>/<Feature>.tsx` | 取 controller → 传视图 → 挂弹层 | 任何业务规则 |

**跨界红线（硬规则，立即阻断）**

- **H1**：`.ts` 逻辑模块不得 `import` `.tsx`。逻辑层反引视图层 = 依赖倒置，
  会让"纯函数可测"直接失效。
  > 注：`*-render-chain.ts` 里的 `.tsx` 是调试用**路径字符串常量**（点击复制路径），
  > 不是模块说明符——脚本只匹配 `import/export/from` 里的说明符，不会误伤。
- **H2**：`src/lib/**` 不得使用 React（`R4` 已禁 `.tsx`，此条补齐 `.ts`）。
  lib 是"无 React 的纯工具层"，跨功能复用的 hook 放 `components/<feature>/hooks/`
  （§12.5：顶层不建 `src/hooks/`）。

## 17.3 棘轮护栏（只许降不许升）

### 三条计数指标

| ID | 指标 | 说明 |
|---|---|---|
| **S1** | 视图内裸 `fetch(` | 应下沉到 `src/lib/<domain>-api.ts` 或 `<feature>/hooks/` |
| **S2** | 视图内 `vanillaApi.*` | 应经 controller hook 暴露成 action |
| **S3** | 视图内 tRPC hook（`api.x.y.useQuery/useMutation`） | 应经 controller hook 暴露数据 |

**不计入**的合理例外（脚本已排除）：

- `src/app/api/**` — Route Handler 是服务端入口，服务端本就该发请求。
- `<feature>/hooks/**` — 这正是第②层，hook 里出现 IO 是合规的。
  *治理一个组件的正确动作就是把逻辑搬进 `hooks/`，搬完指标自动归零*——
  棘轮因此能真实反映进度，而不是逼人先把 IO 藏起来。
- `*.test.*` — 测试里的 fetch mock 不算违规。

**仅提示不计数**：视图内内联 `async` 事件处理器（S4）。多数是纯 UI 交互
（复制路径、下载 blob），下沉反而绕；人工判断是否搬。

### 命令

```bash
node scripts/check-ui-logic-separation.cjs            # 检查（有下降仅提示）
node scripts/check-ui-logic-separation.cjs --strict   # 有下降也失败（CI 用）
node scripts/check-ui-logic-separation.cjs --update   # 治理后收紧基线
```

`--update` 有三道自我保护：① 有 H1/H2 硬违规拒绝更新；② 总数上升拒绝更新
（*棘轮只许降不许升*，禁止用更新基线掩盖新增违规）；③ 只在下降或持平时写入。

## 17.4 分批推进计划

> **排序原则**：先摘**投入产出比最高且风险最低**的——独立弹层/面板（消费方少、
> 有测试兜底）→ 中大组件 → 遗留旧画布 → 最后收拾 8000 行的项目画布。
> 每批**独立 PR、独立 `--update`**，不搞一次性大爆炸（§13.7 禁止无关全文件变更）。

### 每批固定 SOP（照抄即可）

1. **读原文件**，标出：① 状态声明 ② 副作用/`fetch`/tRPC ③ 派生计算 ④ 事件处理器 ⑤ JSX。
2. **抽出** `hooks/use-<feature>.ts`（② ③ ④）与 `<feature>-config.ts`（① 中的常量/纯函数）。
3. **改视图**为纯 props；容器只做「取 controller → 传视图 → 挂弹层」。
4. **补测试**：优先测逻辑层（`hooks/` 的 `renderHook` 或纯函数断言）；
   视图层若原有测试则保持通过（用 `mockFetch` 之类已 stub 的网络，见 §11）。
5. **过门禁**：`pnpm exec tsc --noEmit` + `pnpm exec eslint .` + `pnpm run test`
   + `node scripts/check-ui-logic-separation.cjs --update`。
6. **容器对外 API 保持不变**（props / 导出名 / 类型名），消费方零改动
   ——`WorkshopPipeline`、`DynamicWorkflowForm` 两次实战都是靠这条做到零感知。

### 17.5.4 通用坑：动作错误会被后台刷新吞掉

`use-material-library` 最初只有一个 `error` 状态，结果：上传失败 → 提示条出现
→ 防抖期内的后台拉取成功 → `setError(null)` → **提示条闪一下就消失了**，
用户以为上传成功了。

修法：**拆成两条错误通道**——`actionError`（上传/删除）与 `loadError`（拉取），
展示取 `actionError ?? loadError`，只有用户点「重试」才清 `actionError`。
全量测试里这条是唯一被抓出来的真实缺陷（局部单测跑绿、全量跑红，
因为并发时序不同）。**后续批次凡有"动作 + 自动刷新"的组合都要走这个模式。**


## 17.6 常见坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 为了过护栏把 `fetch` 改名 | 指标消失，耦合还在 | Review 时看 `hooks/` 是否真的承接了逻辑；护栏只是计数器，不是证明 |
| 把全部 `useState` 塞进一个巨型 controller | 逻辑层变成第二个 700 行文件 | 按职责拆多个 hook 组合（`useXxxData` + `useXxxActions` + `useXxxUi`），controller 只做聚合 |
| 视图需要 hook 里没有的中间态 | 硬塞 prop 透传几十个 | 直接把整个 controller 传给视图（`<Body controller={controller} />`，§16.2.1 已验证） |
| 拆分时顺手改视觉 | diff 爆炸、回归难定位 | 本战役**只搬不改**；视觉改动另开 PR（§13.7） |
| `--update` 被用于掩盖新增违规 | 基线数字上涨 | 脚本拒绝上升并 exit 1；CI 用 `--strict`，下降未收紧直接失败 |
| 动作错误被后台刷新吞掉 | 提示条闪一下就没了 | 拆 `actionError` / `loadError` 两条通道，见 §17.5.4 |
