## 8. 异步与副作用

> 异步逻辑是 bug 高发区（竞态、内存泄漏、错误处理）。本章给出数据获取、副作用清理、并发控制的规范。

### 8.1 竞态请求：用 cancelled 标志或 AbortController

```tsx
// ✅ 方案 A：cancelled 标志（useEffect 内常见）
useEffect(() => {
  let cancelled = false;
  (async () => {
    const data = await fetchData();
    if (cancelled) return; // 组件已卸载或依赖变化，丢弃旧结果
    setData(data);
  })();
  return () => { cancelled = true; };
}, [dep]);

// ✅ 方案 B：AbortController（标准方案，可真正中止 fetch）
useEffect(() => {
  const ctrl = new AbortController();
  fetch("/api/tasks", { signal: ctrl.signal })
    .then((r) => r.json())
    .then(setTasks)
    .catch((e) => { if (e.name !== "AbortError") console.error(e); });
  return () => ctrl.abort(); // 卸载/依赖变化 → 中止请求
}, [dep]);
```

**判断**：简单"丢弃旧结果"用 `cancelled` 足够；需要节省带宽/避免后端无效计算用 `AbortController`。

### 8.2 tRPC / React Query 条件查询

```tsx
// ✅ 用 enabled 控制查询时机；用 isSuccess/isPending 派生 UI 状态
const detailQ = api.task.detail.useQuery(
  { id: detailId ?? "" },
  { enabled: !!detailId } // id 为空时不发请求
);
const detail = detailQ.isSuccess ? detailQ.data : null;
const loading = detailQ.isPending;
```

**规则**：不要用 `if (!id) return null` 包裹整个组件来跳过查询——让 `enabled: !!id` 控制，组件结构保持一致。

### 8.3 乐观更新

```tsx
// ✅ tRPC mutation + 乐观更新
const deleteTask = api.task.delete.useMutation({
  onMutate: async ({ id }) => {
    await queryClient.cancelQueries({ queryKey: api.task.list.getQueryKey() });
    const prev = queryClient.getQueryData(api.task.list.getQueryKey());
    // 乐观移除
    queryClient.setQueryData(
      api.task.list.getQueryKey(),
      (old: { tasks: Task[] } | undefined) =>
        old ? { ...old, tasks: old.tasks.filter((t) => t.id !== id) } : old
    );
    return { prev };
  },
  onError: (_err, _vars, ctx) => {
    // 失败回滚
    if (ctx?.prev) queryClient.setQueryData(api.task.list.getQueryKey(), ctx.prev);
  },
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: api.task.list.getQueryKey() });
  },
});
```

**规则**：乐观更新必须配 `onError` 回滚 + `onSettled` 失效重拉，保证最终一致性。

### 8.4 禁止 monkey-patch 全局 API

```tsx
// ❌ 错误：monkey-patch history.pushState（BrowserStatusBar 旧写法）
history.pushState = function (...args) {
  originalPushState.apply(this, args);
  update();
};

// ✅ 正确：用 Next.js 的 usePathname() / useSearchParams()
const pathname = usePathname(); // 路由变化自动 re-render，无需手动监听
```

**原因**：monkey-patch 在 StrictMode 下执行两次会互相覆盖原始引用；多个实例挂载会冲突；`popstate`/`hashchange` 已能覆盖多数场景。

### 8.5 useEffect 依赖与清理

```tsx
// ✅ 依赖完整 + cleanup 清理副作用
useEffect(() => {
  const handler = () => setMenu(null);
  window.addEventListener("pointerdown", handler);
  return () => window.removeEventListener("pointerdown", handler);
}, [menu]); // menu 变化重新绑定
```

**规则**：
- 依赖数组写全（eslint `react-hooks/exhaustive-deps` 开启）。
- 所有订阅（`addEventListener`、setInterval、外部库监听）必须在 cleanup 中取消。
- `setInterval` 必须 `clearInterval`；轮询组件卸载时停止。

### 8.6 避免 useEffect 内 setState 触发循环

```tsx
// ❌ 错误：effect 里 setState 且依赖含该 state → 无限循环
useEffect(() => { setCount(count + 1); }, [count]);

// ✅ 正确：用函数式更新 + 条件守卫，或放到事件回调里
useEffect(() => {
  if (shouldIncrement) setCount((c) => c + 1);
}, [shouldIncrement]); // shouldIncrement 是独立 boolean 状态
```

**React 19 注意（强制）**：React 19 严格 hooks 规则已移除 set-state-in-effect 豁免，**effect 内同步 `setState`（含函数式更新）会触发 `react-hooks/set-state-in-effect` lint error**。上述"✅ 正确"示例若在 effect 内同步提交仍会报错，需改用主规范 §4.6 的两种规范写法：

```tsx
// 规范写法一（渲染期对比 + 渲染期 setState，React 19 允许且自动重渲染）
const [count, setCount] = useState(0);
const latestRef = useRef(0);
if (latestRef.current !== shouldIncrement) {
  latestRef.current = shouldIncrement;
  setCount((c) => (shouldIncrement ? c + 1 : c));
}

// 规范写法二（setTimeout 延迟到 render 提交后，纯 effect 场景）
useEffect(() => {
  const t = setTimeout(() => setCount((c) => c + 1), 0);
  return () => clearTimeout(t);
}, [shouldIncrement]);
```

禁止用文件级 `/* eslint-disable react-hooks/set-state-in-effect */` 掩盖违规；lint 修复与功能改动分提交。

### 8.7 异步错误处理统一

```tsx
// ✅ 顶层 await 用 try/catch；事件回调里 catch 静默错误需注释原因
async function loadData() {
  try {
    const data = await fetchData();
    setData(data);
  } catch (err) {
    toast.error("加载失败", err instanceof Error ? err.message : String(err));
  }
}
```

**规则**：用户可感知的失败用 `toast.error` 提示；静默忽略只在确实无影响时（如非关键日志加载），且必须注释说明。

### 8.8 并发请求：用 Promise.all / Promise.allSettled

```tsx
// ✅ 独立请求并发，缩短总耗时
const [tasks, projects] = await Promise.all([
  fetchTasks(),
  fetchProjects(),
]);

// ✅ 部分失败不影响其他（加载历史日志等多文件场景）
const results = await Promise.allSettled(files.map((f) => fetchFile(f)));
results.forEach((r, i) => {
  if (r.status === "rejected") console.warn(`加载 ${files[i].name} 失败`, r.reason);
});
```
