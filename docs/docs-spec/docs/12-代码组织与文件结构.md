## 12. 代码组织与文件结构

> 清晰的目录结构是大型项目可维护的前提。本章给出本项目约定与组织原则。

### 12.1 顶层目录约定

```
src/
├── app/                    ← Next.js App Router（路由/布局/页面）
│   ├── (studio)/           ← 分组路由（无 URL 前缀）
│   ├── api/                ← Route Handlers（/api/logs/* 等）
│   ├── layout.tsx
│   └── error.tsx / global-error.tsx
├── components/
│   └── studio/             ← 本项目工作室组件库（barrel + 子目录）
│       ├── AppShell.tsx
│       ├── BottomBar.tsx
│       ├── HistoryList/    ← 复杂组件拆目录
│       │   ├── index.tsx
│       │   ├── components/
│       │   ├── hooks/
│       │   └── types.ts
│       └── ui/             ← 通用基础 UI（ModalDialog/DarkSelect/NumberField）
├── lib/                    ← 框架无关工具（media、comfyui/validation、utils）
├── hooks/                  ← 跨功能复用的自定义 hook
├── stores/                 ← Zustand store 集中管理
├── styles/                 ← 全局 CSS / 主题 CSS
└── types/                  ← 全局类型定义
```

### 12.2 Barrel Export 规范

```ts
// ✅ 分组注释 + 统一路径风格（components/studio/index.ts）
// ── Layout Shell ──
export { AppShell } from "./AppShell";
export { TopBar } from "./TopBar";

// ── Canvas & Workflow ──
export { CanvasArea } from "./CanvasArea";

// ── Shared UI ──
export { ModalDialog } from "./ui/ModalDialog";
```

**规则**：
- barrel 文件只做 re-export，不含逻辑。
- 路径风格统一（本项目用 `@/components/studio` 别名）；同一 barrel 内不混用相对/别名路径。
- 内部重构（拆子目录）对外 API 不变 → barrel 稳定消费方零感知。

### 12.3 迁移期文件名反映实际内容

```ts
// ❌ 名不副实：文件里已经没有 Context 了
// wf-contexts.tsx

// ✅ 重命名反映实际
// wf-io.tsx 或 wf-io-registry.tsx
```

### 12.4 注释要解释"为什么"，不只是"是什么"

```tsx
// ❌ 废话注释
// 设置 active 状态
setActive(true);

// ✅ 解释架构决策/历史原因
// 2026-08-22: 右上角展示「短序号」#1/#2…（按 detail.nodes 列表顺序），
// 完整 nodeId 保留在 title / aria-label / data 属性中，JSON 查看器仍按完整 id 查询。
```

### 12.5 工具函数与组件目录分离

| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| `lib/` | 纯函数、框架无关工具（`isVideo`、Zod schema、`timeAgo`） | React 组件、hook |
| `hooks/` | 跨功能复用的自定义 hook（`useAutoResize`、`useOpenFolder`） | 单组件私有的 hook（放该组件目录 `hooks/`） |
| `components/studio/ui/` | 无业务依赖的通用基础 UI（`ModalDialog`、`DarkSelect`） | 业务组件（`HistoryList`、`AgentPanel`） |
| `stores/` | Zustand store 工厂 + selector | 组件内局部 state |

### 12.6 文件命名约定

| 类型 | 命名 | 示例 |
|------|------|------|
| 组件文件 | PascalCase | `AppShell.tsx` / `BottomBar.tsx` |
| 非组件模块 | kebab-case | `workflow-types.ts` / `log-provider.tsx` |
| 类型文件 | 同名或 `types.ts` | `HistoryList/types.ts` |
| 测试文件 | 同名 + `.test.ts(x)` | `format.test.ts` |
| 目录索引 | `index.tsx`（组件）/ `index.ts`（模块） | — |

### 12.7 循环依赖预防

- 组件目录内的 `index.tsx` 不反向 import 父级业务模块；跨功能复用走 `components/studio/ui/` 或 `lib/`。
- Zustand store 不 import 组件；组件订阅 store。
- `lib/` 不 import `components/`；`components/` 可 import `lib/`。
