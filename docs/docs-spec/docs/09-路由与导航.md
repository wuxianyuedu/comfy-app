## 9. 路由与导航

> 本项目是 Next.js 16 App Router + Tauri 桌面端。本章给出客户端组件边界、路由状态、跨组件通信规范。

### 9.1 "use client" 边界

```tsx
// ✅ 客户端组件标注在直接被客户端页面 import 的组件上
"use client"; // AppShell 被客户端页面消费 → 保留 "use client"

// 若某个页面是纯 Server Component，应把 AppShell 作为 children 传入，
// 而不是直接 import（Server Component 不能 import Client Component 的 hook）。
```

**规则**：
- 含 `useState`/`useEffect`/`useQuery` 等 hook 的组件必须 `"use client"`。
- 纯布局/展示组件（无 hook、无事件）可不标注，作为 Server Component 渲染。
- 组件库 barrel（`index.ts`）本身不含逻辑，不标 `"use client"`；由消费页面决定。

### 9.2 路由跳转：router.push / replace / 浅路由

| API | 行为 | 适用 |
|-----|------|------|
| `router.push(href)` | 压入历史栈，可后退 | 普通导航 |
| `router.replace(href)` | 替换当前历史项，不可后退 | 登录后跳首页、重定向 |
| `router.refresh()` | 重新请求当前路由的 Server Component | 数据变更后刷新服务端渲染 |
| `router.prefetch(href)` | 预取（Link 默认自动 prefetch） | 关键入口提前预热 |

```tsx
// ✅ 导航后不需要返回上一页 → replace
router.replace("/create/" + id);

// ✅ 普通进入 → push
router.push("/history");
```

### 9.3 URL State vs Zustand State

| 状态类型 | 存哪 | 理由 |
|---------|------|------|
| 可分享/可刷新保留（任务 id、筛选条件） | URL searchParams | 复制链接可复现 |
| 临时 UI 状态（面板开关、抽屉 open） | Zustand | 不需进 URL，刷新可重置 |
| 跨页表单草稿 | Zustand + `persist(sessionStorage)` | 刷新保留、关闭清除 |

```tsx
// ✅ 筛选条件进 URL，可分享
const [filter, setFilter] = useState<FilterKey>("ALL");
// 同步到 searchParams
router.push(`/history?filter=${filter}`);
// 读取
const filter = (searchParams.get("filter") as FilterKey) ?? "ALL";
```

### 9.4 跨组件通信：CustomEvent vs 状态提升

```tsx
// ⚠️ 谨慎使用：CustomEvent 是全局事件，难追踪来源
window.addEventListener("open-task", handler);
window.dispatchEvent(new CustomEvent("open-task", { detail: taskId }));

// ✅ 优先：状态提升到最近公共父组件 / Zustand store
// 仅当跨多层、且无共同父组件（如全局快捷键触发展开面板）时用 CustomEvent
```

**规则**：CustomEvent 仅用于"真正的全局事件"（快捷键、Tauri 外部触发）；业务状态用 Zustand。CustomEvent 监听须在 cleanup 中 `removeEventListener`。

### 9.5 Link vs 编程式导航

```tsx
// ✅ 静态链接用 <Link>（自动 prefetch、可访问性）
<Link href="/create/task-123">查看任务</Link>

// ✅ 需要逻辑判断后用 router.push
<button onClick={() => { if (canOpen) router.push("/create/" + id); }}>
```

### 9.6 动态路由参数

```tsx
// ✅ App Router：useParams / page.tsx 的 props
// app/create/[id]/page.tsx
export default function CreatePage({ params }: { params: { id: string } }) {
  return <WorkflowCanvasEditor taskId={params.id} />;
}
```

**规则**：动态参数用 Zod 校验（如 `id` 格式约束），非法值重定向到 404/列表页。

### 9.7 路由懒加载与代码分割

- Next.js App Router 按路由自动代码分割，无需手动 `lazy`。
- 重型第三方库（shiki、react18-json-view）用**动态 `import()`** 按需加载，避免首屏体积膨胀：

```tsx
// ✅ shiki 懒加载（CodeBlock）
let highlighterPromise: Promise<Highlighter> | null = null;
function getHighlighter() {
  if (!highlighterPromise) {
    highlighterPromise = import("shiki/dist/bundle-web.mjs").then((s) =>
      s.createHighlighter({ themes: ["one-dark-pro"], langs: [...] })
    );
  }
  return highlighterPromise;
}
```
