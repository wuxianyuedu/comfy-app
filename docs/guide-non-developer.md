# 非开发人员本地运行上手指南

> 本指南面向**不写代码、不熟悉命令行与编译环境**的普通用户。
> 目标是：拿到本项目源码后，用最少的步骤在本地把它跑起来。
>
> 适用平台：Windows 10/11。项目团队平时用 Windows 开发，本指南也以 Windows 为例。

---

> **占位符约定**：本文中 `{{...}}` 形式的占位符代表文档引用的真实值（如可执行文件名、地址），
> 真实值由 `pnpm doc:check` 运行时从源码/配置动态提取并核对。占位符语义见
> [`docs/reference-facts.md`](reference-facts.md)。


## 1. 一句话结论

**普通用户请走「浏览器模式」**：它只需要装 2 个软件（Node.js + pnpm），
然后双击 `tools/start/run-local.ps1` 自动完成初始化，再双击 `tools/start/start-web.ps1` 启动，
最后用控制台打印的地址打开即可（形如 `http://localhost:<端口>`）。

> ⚠️ **端口不是固定的，别照抄 3100**：`pnpm dev` 的端口由 `.env` 的
> `COMFYAPP_PORT` → **按检出路径推导（3200~3999）** → 兜底 3100 三步决定
> （见 [规范 §1.1](../docs/standards/launch-and-build.md#11-端口统一配置comfyapp_port)）。
> 缺省（没在 `.env` 里固定）时拿到的是**路径推导值**，同一台机器上不同目录可能
> 是 3200~3999 里的任意一个，`3100` 只是异常兜底。**以启动窗口打印的
> `[dev.mjs] COMFYAPP_PORT=<端口>` 为准**；照文档写死的 3100 去打开，
> 典型现象就是浏览器 `ERR_CONNECTION_REFUSED`（看着像「服务没起来」）。

> ⚠️ 不需要装 Rust、不需要编译、不需要会敲命令。如果你想要的是**独立桌面窗口**
> （启动后弹出原生应用窗口），也完全可行——只需向开发人员要一份**即开即用桌面包**
> （独立版），解压后双击 `tools/start/start-desktop.ps1` 即可，同样不需要装任何开发环境
> （详见第 6 节）。

**先看你要的是哪一条路：**

- **要「独立桌面窗口」（最接近成品体验）** → 直接找开发人员要一份**即开即用桌面包**
  （**请指定要独立版**），解压后双击 `tools/start/start-desktop.ps1` 即可，**本指南剩余步骤都不用看**，
  跳到第 6 节。
- **手头只有这份源码仓库、想先在浏览器里跑起来** → 继续往下，走浏览器模式
  （装 Node → `tools/start/run-local.ps1` → `tools/start/start-web.ps1`）。

## 2. 先确认你要不要继续往下做

本地运行这个项目需要在本机安装一些开发软件，**这不是绿色免安装软件**。
如果只是「想用成品」，等团队发布安装包或成品 exe 更省事；
如果是要「看这份源码/在自己电脑上调试运行」，请按本指南操作。

---

## 3. 准备工作：确认你的电脑

请先确认系统是 **Windows 10 或 11**，并确保能联网（首次安装依赖需要下载）。

### 你总共要做的事（概览）

| 步骤 | 做什么 | 谁来执行 | 大约耗时 |
|------|--------|----------|----------|
| ① | 安装 Node.js（LTS 版） | 你（可让 `tools/start/run-local.ps1` 提示/代装） | 2~5 分钟 |
| ② | 开启 pnpm（Node 自带的 corepack） | `tools/start/run-local.ps1` | 1 分钟 |
| ③ | 安装项目依赖 | `tools/start/run-local.ps1` | 3~10 分钟 |
| ④ | 生成本地配置文件 `.env` | `tools/start/run-local.ps1` 自动完成 | 秒级 |
| ⑤ | 启动 | 双击 `tools/start/start-web.ps1` | 1~2 分钟 |
| ⑥ | 打开浏览器使用 | 你 | 秒级 |

## 4. 一步一步操作

### 4.0 解压 / 放好项目文件夹

把从代码仓库下载（或别人拷贝给你）的项目文件夹放到一个**路径不含中文和空格**的位置，
例如 `C:\apps\Comfy-APP-T3`。路径含空格/中文容易在个别脚本里出问题，尽量避开。

### 4.1 安装 Node.js（只装这一个就行）

1. 打开官网 <https://nodejs.org/>；
2. 下载 **LTS（长期支持）版** Windows 安装包（.msi）；
3. 一路点「下一步」默认安装即可（不要改选项）；
4. 装完**重启一次命令提示符**或电脑，让环境变量生效。

> Node.js 版本建议 ≥ 22（本项目 `.nvmrc` 用 24）。官网默认下载的就是 LTS，
> 满足要求。

### 4.2 双击 `tools/start/run-local.ps1`（一键初始化）

进入项目文件夹里的 `tools\start\` 目录，找到 **`run-local.ps1`**，**双击**它。

它会自动帮你：
- ✅ 检查 `node` 是否装好（没装会提示你先装，见 4.1）；
- ✅ 检查 `pnpm` 是否可用，缺失时用 Node 自带的 `corepack` 自动开启；
- ✅ 检查 pnpm 版本是否与项目要求一致（`package.json` 的 `packageManager`），不一致时自动用 corepack 切换到正确版本；
- ✅ 检查依赖是否已安装，未安装则自动执行 `pnpm install`（会下载较久，**别关窗口**）；
- ✅ 自动从 `.env.example` 生成一份 `.env`（已存在则跳过，不会覆盖你的配置）；
- ✅ 最后提示你接下来双击 `tools/start/start-web.ps1`。

> 窗口最末尾如果出现绿色的 `[OK]` 或类似「初始化完成」提示，就说明成功了。

### 4.3 双击 `tools/start/start-web.ps1`（启动）

回到 `tools\start\` 目录，**双击 `start-web.ps1`**。

- 会出现一个黑色控制台窗口，里面滚动日志（这一步它在启动本地服务）；
- 先看窗口里打印的 `[dev.mjs] COMFYAPP_PORT=<端口>` 这一行——**它就是本次的端口**；
- 再看到类似 `Local: http://localhost:<端口>` 或「已就绪」字样，服务就起来了；
- **注意：启动后不要关闭这个黑色窗口**，关掉就等于关了服务。

### 4.4 打开浏览器使用

- 打开 Chrome / Edge 等浏览器；
- 地址栏输入 4.3 里那个端口，形如 `http://localhost:<端口>`（把 `<端口>` 换成你窗口里看到的数字）；
- 回车即可进入应用。

> 提示：**照抄任何文档里出现的端口数字**（包括这一篇）是最容易踩的坑 —— `3100` 只是
> 「异常兜底值」，路径推导值落在 `3200~3999`；窗口里看到的是哪个就用哪个。
> 端口被占时窗口还会往后试端口（`<端口>`、`<端口>+1`、`<端口>+2`），
> 也一律以窗口打印为准。

> 需要登录 GitHub 等功能属于账号相关，本地没有团队配置时可能不可用，
> 但浏览/使用主要界面不受影响。

---

## 5. 我要关掉它 / 重新启动

- **关闭**：直接关掉 4.3 那个黑色控制台窗口即可（服务随之停止）。
- **重新启动**：再次双击 `tools/start/start-web.ps1`。
- **换台电脑/重装依赖**：重新执行 4.1 ~ 4.3。

## 6. 桌面版：非开发人员也能运行的独立窗口

> 说明：桌面版就是启动后弹出的**独立原生应用窗口**（区别于浏览器标签页），和浏览器版是同一套
> 应用、不同的打开方式。只要拿到开发人员构建好的**独立版「即开即用桌面包」**，双击
> `tools/start/start-desktop.ps1` 即可使用，**不需要你装 Node/pnpm/Rust**；而不是拿只有源码的仓库。

### 6.1 先分清几种东西

| 你拿到的东西 | 是什么 | 能不能直接运行 |
|--------------|--------|----------------|
| **源码仓库**（一堆 .ts/.rs 文件） | 原始代码 | ❌ 没有编译产物，需整套开发环境，**不适合非开发人员** |
| **即开即用桌面包**（完整构建好的成品目录） | 由开发人员产出、可直接双击的成品 | ✅ 解压后双击 `tools/start/start-desktop.ps1`（或对应 exe）即可 |

> 判断口诀：桌面包目录里有没有 **`scripts\dev-launcher.mjs`**、以及能不能找到
> `src-tauri\target\release\{{shell.app.exe}}`？
> **有 = 成品，双击就能用**；没有 = 源码，只能走上面的浏览器模式。

> ⚠️ 关于「免装环境」的一句话说清楚：
> 桌面包里的启动器就是 **`{{shell.app.exe}}` 本身**（不再有第二层 exe），它有两种形态：
> - **独立版（standalone，推荐给非开发人员）**：把前端静态资源 + Node 运行时都内嵌好，
>   运行时不连 dev server，**真正免装任何开发环境**。壳的判据是「检出里没有编排器」。
> - **prebuilt 版**：运行时会起一个 Node dev server，因此**仍需本机装有 Node/pnpm**，
>   更适合开发人员日常用。
>
> 给非开发人员分发时，**请务必分发独立版**（完整目录，别只拷一个 exe），否则对方仍会被
> 要求装 Node。要最省事，直接用下方的 `tools/start/start-desktop.ps1`——它会自检并自动
> 选择可用的壳。

### 6.2 谁来产出「即开即用桌面包」

桌面包由**开发人员**在一台 Windows 电脑上构建生成：

- 构建独立版（推荐分发）：运行 `tools\build\build-standalone.ps1`（完整生产构建壳 +
  standalone 资源），产出 `src-tauri\target\release\`（含 `{{shell.app.exe}}` / `server.js` /
  `.next` / `binaries\`）；
- 或运行 `tools\build\build-all.ps1` 产出 prebuilt 版（只有壳，需对方装 Node，见上）。

随后把成品目录（含随附的 `tools/start/start-desktop.ps1`）打成 zip 发给普通用户。
**你作为非开发人员不需要碰构建这一步。**

### 6.3 拿到桌面包后怎么运行

1. 把桌面包目录解压到一个**路径不含中文和空格**的位置（如 `C:\apps\Comfy-APP`）；
2. 双击 **`tools/start/start-desktop.ps1`**——它会先自动检查桌面包是否完整、缺了什么会给中文提示；
3. 自检通过后会自动启动：先弹出一个「正在启动」的加载画面，稍等出现主窗口即成功；
4. 关掉主窗口即退出（日志保留在 `log\` 目录，方便出问题时发给团队）。

> 不想用 `tools/start/start-desktop.ps1`，也可直接双击桌面包里的
> `src-tauri\target\release\{{shell.app.exe}}`。

### 6.4 桌面包没运行起来怎么办

- 双击 `tools/start/start-desktop.ps1` 时若提示「未找到桌面壳/缺少文件」→ 按提示的说明对照 6.2，多半是
  桌面包不完整（少了 `server.js` / `binaries\` 等运行资源），重新完整解压即可；
- Windows 10/11 已内置 WebView2，一般无需单独装；
- 仍失败：把 `log\` 下的日志发给开发人员即可（详见第 8 节）。

> 想深入了解桌面包构建流程的开发人员，见 `README.md` 与 `docs/standards/launch-and-build.md`。

## 7. 常见问题（FAQ）

| 现象 | 可能原因 / 解决办法 |
|------|---------------------|
| 双击 `tools/start/run-local.ps1` 提示「找不到 node」 | Node.js 没装或装完没重启电脑，先完成 4.1 |
| 双击 `tools/start/run-local.ps1` 报 `pnpm` 相关错误 | 可先手动重装依赖：在项目根打开终端执行 `pnpm install` 再双击启动 |
| 双击 `tools/start/run-local.ps1` 时 `pnpm install` 失败，报 `'sh' is not recognized as an internal or external command` / `ERR_PNPM_EXECUTOR_LIFECYCLE_SCRIPT_FAILED` | 旧版本用 `sh` 起安装后的钩子脚本，而 Windows 的 cmd 没有 `sh`（ISSUE #636）。**先拉取最新代码**（改成纯 Node 入口后即可正常安装）；仍失败再按上一条处理 |
| 再双击 `tools/start/run-local.ps1` 直接显示「依赖已就绪、跳过安装」，但应用仍起不来 | 依赖**装过**但可能不是当前代码要求的版本（拉了更新没重装）。启动器现在会比对 lockfile 并自动补装、补装后复核；若报「依赖补装后仍未就绪」，照提示删掉 `node_modules` 后重新双击本脚本 |
| 应用一直开着、期间拉到新代码，打开某功能变成白屏 / 点了没反应（控制台报 `xxx is not a function`） | 「界面比代码旧」：已打开的界面不会因代码变化重建自己。**按 `Ctrl+R` 重载一次即恢复**；仍不行就关掉应用重新双击启动入口。详见 [`guide-stale-code.md`](guide-stale-code.md) |
| 团队更新了代码后启动报错 / 拉取更新后怎么同步环境 | 见 [`guides/sync-after-pull.md`](guides/sync-after-pull.md)：先关掉运行中的窗口，重双击 `tools/start/run-local.ps1`；报 pnpm 相关错误则删 `node_modules` 后重双击 |
| 启动时提示「pnpm 版本不匹配 / pnpm 有更新」 | 启动器会自动检测并在必要时用 corepack 对齐，**通常无需手动操作**；若自动对齐失败，窗口/日志会给出提示，手动执行一次 `corepack enable && corepack prepare pnpm@12.4.1 --activate`（版本号以提示为准）即可 |
| 双击 `tools/start/start-web.ps1` 报「数据库/表不存在」 | 首次会自动建库；如仍异常，先双击 `tools/start/run-local.ps1` 补齐依赖与 `.env` 后重试 |
| 浏览器打不开页面（`ERR_CONNECTION_REFUSED`） | 先看地址栏端口是不是照抄了 `3100`——实际端口是窗口打印的 `[dev.mjs] COMFYAPP_PORT=<端口>`（见 4.3~4.4）；再确认 `tools/start/start-web.ps1` 的控制台窗口还开着；首次编译较慢，多等一会再刷新 |
| 端口被占用起不来 | 启动器会先清理**本检出端口族**（`COMFYAPP_PORT` 及 +1/+2）的残留进程，并自动往后找一个空闲端口；仍失败可重启电脑后再试 |
| 想彻底重置环境 | 删除项目里的 `node_modules` 文件夹和 `.env` 文件后，重新执行 4.1~4.3 |
| 依赖下载很慢 / 失败 | 网络原因；可重试，或用团队提供的镜像源 |
| 双击 `tools/start/start-desktop.ps1` / 启动器没反应 / 提示缺文件 | 大概率是桌面包解压不完整（缺 `_internal` 等），重新完整解压，见 6.4 |
| 桌面包提示要装 Node / 起 dev server | 你拿到的可能是 prebuilt 版；找开发人员要**独立版**桌面包即可免装（见 6.1） |
| 桌面包想升级 / 找最新版 | 找开发人员重新要一份新构建的即开即用桌面包即可 |
| 不知道我要的是浏览器版还是桌面版 | 想要「独立窗口像装好的软件一样」→ 桌面版（第 6 节）；只是想先看效果 → 浏览器版（第 3~4 节） |

> 更多面向开发者的启动故障排查，见 `docs/standards/launch-and-build.md` 第 5 节
> 「症状 → 已知根因对照表」。

## 8. 需要帮助时

- 把项目根目录下 `log\` 文件夹里的日志发给团队（截图或文件都行）；
- 说明你在第几步、看到了什么报错文字。

团队会根据日志帮你定位，通常是环境或依赖问题，不影响你继续尝试。
